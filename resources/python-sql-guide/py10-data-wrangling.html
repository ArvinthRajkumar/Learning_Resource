Rows, columns and the shape of data

Most data is a table: rows are records, columns are fields. In Python the basic representations are:

RepresentationExampleGood for
List of dicts[{"id": 1, "city": "Pune"}, ...]Small data, JSON, readability
List of tuples / namedtuples(1, "Pune")Compact, immutable rows
Dict of lists (columns){"id": [1, 2], "city": ["Pune", "Goa"]}Column operations, how pandas stores data
DataFrame (pandas)pd.DataFrame(...)Labelled, vectorised operations on large tables
Array (NumPy)np.array([[1, 2], [3, 4]])Numeric work with fast vector maths

Filter, map and select

rows = [{"order": 1, "country": "IN", "amount": 120.0}, {"order": 2, "country": "US", "amount": 80.5}, {"order": 3, "country": "IN", "amount": 45.0}, {"order": 4, "country": "DE", "amount": None}]
big = [r for r in rows if r["amount"] is not None and r["amount"] > 50]                   # filter (WHERE)
projected = [{k: r[k] for k in ("order", "amount")} for r in rows]                          # select columns
with_tax = [{**r, "gross": round(r["amount"] * 1.18, 2) if r["amount"] is not None else None} for r in rows]   # new column
print([r["order"] for r in big]); print(projected[0]); print([r["gross"] for r in with_tax])

Output

[1, 2]
{'order': 1, 'amount': 120.0}
[141.6, 94.99, 53.1, None]

pandas equivalents (not run here):

big = df[df["amount"] > 50]                         # boolean mask (NaN compares False)
projected = df[["order", "amount"]]
df["gross"] = (df["amount"] * 1.18).round(2)        # vectorised: one operation, no Python loop

Vectorisation means applying an operation to a whole column at once in compiled code, usually 10 to 100 times faster than a Python loop. If you write for row in df.iterrows(), ask whether a vectorised expression exists.

Group and aggregate

GROUP BY is: split rows by a key, apply an aggregate to each group, combine into a result ("split-apply-combine").

from collections import defaultdict
from statistics import mean
rows = [("IN", 120.0), ("US", 80.5), ("IN", 45.0), ("DE", None), ("US", 200.0), ("IN", 30.0)]
groups = defaultdict(list)
for country, amount in rows:
    if amount is not None: groups[country].append(amount)                      # skip missing, as SQL aggregates do
summary = {c: {"n": len(v), "total": sum(v), "mean": round(mean(v), 2), "max": max(v)} for c, v in groups.items()}
for c in sorted(summary, key=lambda c: -summary[c]["total"]): print(c, summary[c])
print("groups with no valid amount are absent:", "DE" not in summary)

Output

US {'n': 2, 'total': 280.5, 'mean': 140.25, 'max': 200.0}
IN {'n': 3, 'total': 195.0, 'mean': 65.0, 'max': 120.0}
groups with no valid amount are absent: True
# pandas
df.groupby("country")["amount"].agg(n="count", total="sum", mean="mean", max="max").sort_values("total", ascending=False)
# SQL
# SELECT country, COUNT(amount), SUM(amount), AVG(amount), MAX(amount) FROM orders GROUP BY country ORDER BY SUM(amount) DESC;

Notice how count skips missing values; size counts rows. Always decide how missing values should be treated.

  • Joining No.

pandas groupby and SQL GROUP BY follow it.

  • Count them as zero No.
  • Ignore them (count counts non-missing values) Correct.
  • Raise an error No.
  • Replace them with the mean No.

That is why count(column) can differ from the number of rows.

Joins

A join matches rows from two tables on a key. The hash join idea: build a dictionary of one side, probe it with the other.

customers = [{"id": 1, "name": "ana", "tier": "gold"}, {"id": 2, "name": "bo", "tier": "silver"}, {"id": 3, "name": "cy", "tier": "silver"}]
orders = [{"order": 10, "cust": 1, "amount": 50}, {"order": 11, "cust": 2, "amount": 70}, {"order": 12, "cust": 1, "amount": 20}, {"order": 13, "cust": 9, "amount": 15}]
by_id = {c["id"]: c for c in customers}                                           # build side
inner = [{**o, **{"name": by_id[o["cust"]]["name"]}} for o in orders if o["cust"] in by_id]
left = [{**o, "name": by_id.get(o["cust"], {}).get("name")} for o in orders]       # keep unmatched orders
anti = [o["order"] for o in orders if o["cust"] not in by_id]                      # orders with no customer
print("inner:", [(r["order"], r["name"]) for r in inner])
print("left :", [(r["order"], r["name"]) for r in left])
print("orders without a customer:", anti, "| customers without orders:", [c["name"] for c in customers if c["id"] not in {o["cust"] for o in orders}])

Output

inner: [(10, 'ana'), (11, 'bo'), (12, 'ana')]
left : [(10, 'ana'), (11, 'bo'), (12, 'ana'), (13, None)]
orders without a customer: [13] | customers without orders: ['cy']
orders.merge(customers, left_on="cust", right_on="id", how="left")        # pandas: how in {"inner","left","right","outer"}

Check cardinality after a join: an unexpected increase in rows means a many-to-many key (use validate="m:1" in pandas). Joining on a column with duplicates multiplies rows, the same fan-out trap as SQL.

How this gets asked

You join two tables and the row count unexpectedly grows. What is the likely cause?

  • Sorting No.
  • Duplicate keys on both sides (many-to-many) multiply rows Correct.
  • Wrong dtype only No.
  • Missing indexes No.

Check key uniqueness and use validation.

Which join keeps all left rows even without a match?

  • Inner Drops unmatched.
  • Left Correct.
  • Anti Keeps only unmatched.
  • Cross All combinations.

Unmatched right columns become missing.

Sort, rank and window

sales = [("north", "2024-01", 100), ("north", "2024-02", 120), ("north", "2024-03", 90), ("south", "2024-01", 80), ("south", "2024-02", 95), ("south", "2024-03", 130)]
by_region = {}
for region, month, amount in sorted(sales):                                     # sorted by region then month
    by_region.setdefault(region, []).append((month, amount))
for region, series in by_region.items():
    running, prev, out = 0, None, []
    for month, amount in series:
        running += amount
        change = None if prev is None else round(100 * (amount - prev) / prev, 1)
        out.append((month, amount, running, change)); prev = amount
    print(region, out)
ranked = sorted(sales, key=lambda r: -r[2])
print("top 2 overall:", [(r[0], r[1], r[2]) for r in ranked[:2]])

Output

north [('2024-01', 100, 100, None), ('2024-02', 120, 220, 20.0), ('2024-03', 90, 310, -25.0)]
south [('2024-01', 80, 80, None), ('2024-02', 95, 175, 18.8), ('2024-03', 130, 305, 36.8)]
top 2 overall: [('south', '2024-03', 130), ('north', '2024-02', 120)]
df["running"] = df.groupby("region")["amount"].cumsum()                    # window: running total per group
df["pct_change"] = df.groupby("region")["amount"].pct_change() * 100
df["rank"] = df.groupby("region")["amount"].rank(ascending=False)
df["roll3"] = df.groupby("region")["amount"].transform(lambda s: s.rolling(3).mean())

Self-check

What do cumsum, rank and rolling do per group?

They are window operations: running totals, ordering within the group and moving aggregates over neighbouring rows.

Reshape: pivot and melt

Wide tables have a column per category; long tables have a row per observation. Analysis and plotting libraries prefer long (tidy) data; reports prefer wide.

long = [("ana", "q1", 10), ("ana", "q2", 15), ("bo", "q1", 7), ("bo", "q2", 9), ("bo", "q3", 12)]
quarters = sorted({q for _, q, _ in long})
wide = {}
for name, q, v in long: wide.setdefault(name, dict.fromkeys(quarters)); wide[name][q] = v
print("wide:", wide)
melted = [(name, q, v) for name, cols in wide.items() for q, v in cols.items() if v is not None]
print("back to long:", melted == sorted(long) or sorted(melted) == sorted(long))

Output

wide: {'ana': {'q1': 10, 'q2': 15, 'q3': None}, 'bo': {'q1': 7, 'q2': 9, 'q3': 12}}
back to long: True
wide = df.pivot_table(index="name", columns="quarter", values="value", aggfunc="sum")
long = wide.reset_index().melt(id_vars="name", var_name="quarter", value_name="value").dropna()

How this gets asked

What is a 'long' table?

  • Many columns That is wide.
  • One row per observation, with a column naming the variable Correct.
  • A very large file No.
  • A sorted table No.

melt converts wide to long; pivot does the reverse.

Cleaning and missing data

Real data is messy. A checklist before analysing:

  1. Types: numbers stored as text, dates as strings, mixed types in a column.
  2. Missing values: None/NaN/empty string/"N/A"/-1 sentinel. Decide: drop, fill with a constant, fill with mean or median, forward-fill, or model it. Understand why it is missing.
  3. Duplicates: exact duplicates and duplicates by key.
  4. Outliers and impossible values: negative ages, dates in the future, a price of 99999.
  5. Inconsistent categories: "India", "india ", "IN". Trim, lowercase, map.
  6. Units and time zones: dollars versus cents, local versus UTC.
  7. Schema drift: new columns or renamed fields between files.
import re
from statistics import median
raw = [{"id": "1", "price": "$1,200.50", "country": " India", "joined": "03/01/2024"},
       {"id": "2", "price": "n/a",       "country": "IN",     "joined": "2024-03-02"},
       {"id": "2", "price": "90",        "country": "india ", "joined": "2024-03-02"},
       {"id": "3", "price": "-5",        "country": "US",     "joined": "2024-03-04"}]
COUNTRY = {"india": "IN", "in": "IN", "us": "US"}
def parse_price(s):
    cleaned = re.sub(r"[^0-9.\-]", "", s)
    return float(cleaned) if cleaned not in ("", "-", ".") else None
def parse_date(s):
    m = re.fullmatch(r"(\d{2})/(\d{2})/(\d{4})", s)
    return f"{m[3]}-{m[1]}-{m[2]}" if m else s                                # assume MM/DD/YYYY here, a documented decision
clean = []
for r in raw:
    price = parse_price(r["price"])
    clean.append({"id": int(r["id"]), "price": price if price is not None and price >= 0 else None,
                  "country": COUNTRY[r["country"].strip().lower()], "joined": parse_date(r["joined"])})
seen, deduped = set(), []
for r in clean:                                                                # keep the first row per id
    if r["id"] not in seen: seen.add(r["id"]); deduped.append(r)
fill = median(r["price"] for r in deduped if r["price"] is not None)
for r in deduped: r["price_filled"] = r["price"] if r["price"] is not None else fill
for r in deduped: print(r)

Output

{'id': 1, 'price': 1200.5, 'country': 'IN', 'joined': '2024-03-01', 'price_filled': 1200.5}
{'id': 2, 'price': None, 'country': 'IN', 'joined': '2024-03-02', 'price_filled': 1200.5}
{'id': 3, 'price': None, 'country': 'US', 'joined': '2024-03-04', 'price_filled': 1200.5}

Record each cleaning decision in code (not by hand-editing) so the analysis is reproducible, and keep the raw data untouched.

  • The analysis becomes reproducible and auditable, and new data can be processed the same way Correct.
  • Editors are unavailable No.
  • To use more memory No.

Keep the raw data untouched.

Dates and time series

Parse strings to real dates early; resample by period; align on a calendar.

from datetime import date, timedelta
from collections import Counter
events = ["2024-03-01", "2024-03-01", "2024-03-03", "2024-03-06", "2024-03-06", "2024-03-06"]
counts = Counter(date.fromisoformat(e) for e in events)
start, end = min(counts), max(counts)
series = [(start + timedelta(days=i), counts.get(start + timedelta(days=i), 0)) for i in range((end - start).days + 1)]   # fill gaps with 0
print([(d.isoformat()[5:], n) for d, n in series])
window = 3
print("3-day moving sum:", [sum(n for _, n in series[max(0, i - window + 1): i + 1]) for i in range(len(series))])
weekly = Counter((d - timedelta(days=d.weekday())).isoformat() for d in (date.fromisoformat(e) for e in events))
print("per ISO week (week start):", dict(weekly))

Output

[('03-01', 2), ('03-02', 0), ('03-03', 1), ('03-04', 0), ('03-05', 0), ('03-06', 3)]
3-day moving sum: [2, 2, 3, 1, 1, 3]
per ISO week (week start): {'2024-02-26': 3, '2024-03-04': 3}

NumPy: arrays and broadcasting

NumPy stores numbers in a typed, contiguous block and loops in C. Key ideas:

  • Shape and dtype: a.shape == (3, 4); one dtype per array (float64, int32).
  • Vectorised operations: a * 2, a + b, np.sqrt(a) work element by element.
  • Broadcasting: arrays with compatible shapes combine automatically: a (3, 1) array plus a (1, 4) array gives (3, 4).
  • Slicing and views: a[1:, ::2] is a view (no copy); boolean masks and fancy indexing make copies.
  • Axis: a.sum(axis=0) collapses rows (column sums); axis=1 collapses columns.

The essential idea of broadcasting, shown with plain lists:

col = [[1], [2], [3]]                              # shape (3, 1)
row = [[10, 20, 30, 40]]                           # shape (1, 4)
broadcast_sum = [[c[0] + r for r in row[0]] for c in col]       # result shape (3, 4)
print(broadcast_sum)
matrix = [[1, 2, 3], [4, 5, 6]]
col_sums = [sum(r[j] for r in matrix) for j in range(3)]        # like axis=0
row_sums = [sum(r) for r in matrix]                             # like axis=1
mean = [s / len(matrix) for s in col_sums]
centered = [[v - m for v, m in zip(r, mean)] for r in matrix]   # subtract each column's mean from its column
print(col_sums, row_sums, centered)

Output

[[11, 21, 31, 41], [12, 22, 32, 42], [13, 23, 33, 43]]
[5, 7, 9] [6, 15] [[-1.5, -1.5, -1.5], [1.5, 1.5, 1.5]]
import numpy as np
a = np.array([[1, 2, 3], [4, 5, 6]], dtype=float)
a.sum(axis=0); a.mean(axis=0)
a - a.mean(axis=0)                    # broadcasting: (2,3) - (3,) -> (2,3)
(a > 2) & (a < 6)                     # boolean mask
a[a > 2]                              # selects elements, returns a 1-D copy
np.dot(a, a.T)                        # matrix product, (2,3) @ (3,2) -> (2,2)

Performance and memory

  • Prefer vectorised operations and built-ins over Python loops.
  • Use the right dtypes (int32 instead of int64, category for repeated strings) to cut memory.
  • Read big files in chunks (pd.read_csv(..., chunksize=...)) or use columnar formats (Parquet) and read only the columns you need.
  • Avoid growing a DataFrame row by row; collect rows in a list and build once.
  • For data larger than memory consider DuckDB, Polars or Spark; DuckDB can run SQL directly over Parquet or CSV files on your laptop.
  • Measure with timeit and profile before optimising.
import timeit
n = 200_000
data = list(range(n))
loop = timeit.timeit(lambda: [x * 2 + 1 for x in data], number=5)
builtin = timeit.timeit(lambda: sum(data), number=5)
print("a Python-level loop over 200k items is more costly than one built-in aggregation:", loop > builtin)
row_by_row = timeit.timeit("res = []\nfor i in range(20000): res = res + [i]", number=1)
collect = timeit.timeit("res = []\nfor i in range(20000): res.append(i)", number=1)
print("building a list by repeated concatenation is slower than append:", row_by_row > collect)

Output

a Python-level loop over 200k items is more costly than one built-in aggregation: True
building a list by repeated concatenation is slower than append: True
Key idea

Every analysis is filter, group, join, window and reshape. Think in columns, not rows; vectorise; treat cleaning as code; check row counts before and after each join; and choose columnar, typed storage when data grows.

How this gets asked

Why is repeated res = res + [i] slow?

  • It uses more threads No.
  • Each concatenation copies the whole list, giving quadratic time Correct.
  • It is invalid No.
  • It disables GC No.

Use append (amortised O(1)).

Interview questions: Data wrangling

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What is vectorisation?

Applying an operation to a whole array or column at once in compiled code instead of looping in Python, usually much faster.

Basic What is split-apply-combine?

Split data into groups by a key, apply a function to each, and combine the results; GROUP BY in SQL and groupby in pandas.

Medium How do missing values behave in aggregates?

Most aggregates ignore them, so count(column) counts non-missing values; decide explicitly whether to drop, fill or model them.

Medium A join unexpectedly multiplies your row count. Why?

Duplicate keys on both sides (many-to-many) create all pairings. Check key uniqueness and validate the expected cardinality.

Medium What is broadcasting in NumPy?

A rule that lets arrays of compatible shapes combine by virtually stretching the smaller one, such as subtracting a column mean from every row.

Medium View versus copy in NumPy?

Basic slicing returns views that share memory; boolean masks and fancy indexing return copies.

Medium Wide versus long data and how to convert?

Wide has a column per category, long has a row per observation. pivot or pivot_table goes long to wide; melt goes wide to long.

Medium How do you compute a running total per group?

Sort then use a window or groupby cumulative sum, such as df.groupby(key)[col].cumsum() or SUM() OVER (PARTITION BY key ORDER BY time).

Advanced How do you process a file larger than memory?

Stream in chunks, select only needed columns, use columnar formats like Parquet, or use an engine such as DuckDB, Polars or Spark that works out of core or in parallel.

Advanced Why avoid iterrows and row-by-row appends in pandas?

They are slow Python loops; use vectorised expressions, and build a list of rows then create the DataFrame once.

Advanced How do you make a cleaning pipeline reproducible?

Keep raw data immutable, express every cleaning decision in versioned code, log row counts at each step and test with expectations on the output.

Advanced How do you reduce DataFrame memory use?

Downcast numeric dtypes, convert repeated strings to category, drop unused columns and load only what is needed.

Advanced How do you handle time zones and resampling in time series?

Store timestamps in UTC, convert to the business zone before bucketing by day, resample to a regular index and decide how to fill gaps.

Advanced How does a hash join work in data wrangling?

Build a dictionary on the smaller table's key, then probe it with each row of the larger table, giving O(n + m) time.
