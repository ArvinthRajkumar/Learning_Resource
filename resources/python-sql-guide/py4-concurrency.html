Concurrency: threads, processes and asyncio

A program that waits on networks or disks wastes most of its time. Concurrency lets other work proceed while one task waits. This part explains the three models Python offers and how to pick between them.

Advanced~3 hours

Concepts

Concurrency versus parallelism

  • Concurrency: structuring a program as several tasks that make progress in overlapping time periods (one cook alternating between dishes).
  • Parallelism: tasks literally running at the same instant on several cores (several cooks).

I/O-bound versus CPU-bound

  • I/O-bound: time is spent waiting (HTTP calls, database queries, file reads). Overlapping the waits gives big speedups, even on one core.
  • CPU-bound: time is spent computing (image processing, number crunching). Only more cores help.
WorkloadBest tool in CPython
Many network or disk waits, simple codeThreads (ThreadPoolExecutor)
Very many connections (thousands), modern librariesasyncio
Heavy computationProcesses (ProcessPoolExecutor, multiprocessing) or native code
MixedAsync or threads for I/O, process pool for CPU

Because of the GIL (PY3), threads do not speed up pure Python computation.

Threads

A thread pool is the easy way

import time
from concurrent.futures import ThreadPoolExecutor

def fetch(n):
    time.sleep(0.2)               # pretend this is a network call
    return n * n

start = time.perf_counter()
with ThreadPoolExecutor(max_workers=5) as pool:
    results = list(pool.map(fetch, range(5)))
elapsed = time.perf_counter() - start
print(results, "fast:", elapsed < 0.6)          # five 0.2s waits overlap, about 0.2s total

Output

[0, 1, 4, 9, 16] fast: True

Race conditions and locks

Two threads doing counter += 1 can interleave (read, add, write), losing updates. Protect shared state with a lock.

import threading

counter = 0
lock = threading.Lock()

def work(n):
    global counter
    for _ in range(n):
        with lock:                # only one thread at a time in this block
            counter += 1

threads = [threading.Thread(target=work, args=(10000,)) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()
print(counter)

Output

40000

Primitives: Lock, RLock (re-entrant), Semaphore (limit N concurrent), Event (signal), Condition, Barrier. Avoid deadlock by acquiring multiple locks in a fixed order.

Queues: the safe way to share

Instead of sharing variables, pass messages through a thread-safe queue.Queue (producer and consumer pattern).

import queue, threading

q, results = queue.Queue(), []

def consumer():
    while True:
        item = q.get()
        if item is None:           # sentinel: stop
            break
        results.append(item * 2)
        q.task_done()

t = threading.Thread(target=consumer)
t.start()
for i in range(5):
    q.put(i)
q.put(None)
t.join()
print(results)

Output

[0, 2, 4, 6, 8]

Mark threads as daemon=True only for background helpers. Do not share mutable state without a lock; prefer immutable data and queues.

Processes

Real parallelism

Each process has its own interpreter and memory, so there is no shared GIL. Cost: starting a process is heavier and data must be pickled to move between processes.

from concurrent.futures import ProcessPoolExecutor

def is_prime(n):
    if n < 2: return False
    i = 2
    while i * i <= n:
        if n % i == 0: return False
        i += 1
    return True

if __name__ == "__main__":          # required on Windows and macOS (spawn start method)
    nums = [1_000_003, 1_000_033, 1_000_037, 1_000_039]
    with ProcessPoolExecutor(max_workers=2) as pool:
        print(list(pool.map(is_prime, nums)))

Output

[True, True, True, True]

Tips: use the if __name__ == "__main__" guard, keep work chunks large enough to outweigh the overhead, pass small arguments, and use shared memory or files for big data. multiprocessing.Pool, Queue and Manager offer lower-level control.

How this gets asked

  • It speeds things up No.
  • It disables the GIL No.

The spawn start method imports the script in each child.

asyncio

Cooperative multitasking on one thread

async def defines a coroutine. await pauses it until the awaited thing is ready, and lets the event loop run other coroutines meanwhile. Tasks yield control only at await, so no locks are needed for ordinary variables, but one blocking call stalls everything.

import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)            # non-blocking wait
    return f"{name} done"

async def main():
    results = await asyncio.gather(fetch("a", 0.3), fetch("b", 0.2), fetch("c", 0.1))
    print(results)                         # results keep the input order

asyncio.run(main())

Output

['a done', 'b done', 'c done']

Tasks, timeouts and cancellation

import asyncio

async def slow():
    await asyncio.sleep(5)
    return "never"

async def main():
    task = asyncio.create_task(asyncio.sleep(0.05, result="background"))
    print("main continues")
    print(await task)
    try:
        await asyncio.wait_for(slow(), timeout=0.1)
    except asyncio.TimeoutError:
        print("timed out and cancelled")
    async with asyncio.timeout(1):
        print("inside timeout block")

asyncio.run(main())

main continues
background
timed out and cancelled
inside timeout block

Producer and consumer with asyncio.Queue and a semaphore

import asyncio

async def worker(name, q, out, sem):
    while True:
        item = await q.get()
        async with sem:                   # limit concurrency
            await asyncio.sleep(0.01)
            out.append((name, item))
        q.task_done()

async def main():
    q, out, sem = asyncio.Queue(), [], asyncio.Semaphore(2)
    workers = [asyncio.create_task(worker(f"w{i}", q, out, sem)) for i in range(3)]
    for i in range(6): q.put_nowait(i)
    await q.join()                        # wait until all items are processed
    for w in workers: w.cancel()
    print(sorted(item for _, item in out))

asyncio.run(main())

Output

[0, 1, 2, 3, 4, 5]

Rules for async code

  • Use async libraries (aiohttp, httpx.AsyncClient, asyncpg) for I/O. A normal blocking call (time.sleep, requests.get) freezes the whole loop; if you must, use await asyncio.to_thread(blocking_fn).
  • Always await coroutines (a forgotten await creates a coroutine that never runs).
  • Do not mix many event loops. One asyncio.run at the top.
  • Handle cancellation (asyncio.CancelledError) and use try/finally for cleanup.
  • Use asyncio.TaskGroup (3.11+) to run tasks together and propagate errors.
import asyncio

async def job(n):
    await asyncio.sleep(0.01)
    return n * 10

async def main():
    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(job(i)) for i in range(3)]
    print([t.result() for t in tasks])

asyncio.run(main())

Output

[0, 10, 20]

Practical advice

  • Measure first. Concurrency adds complexity, so be sure the program is actually waiting.
  • Bound concurrency (pools, semaphores) so you do not overload a server or run out of connections.
  • Put timeouts on everything that waits on the outside world.
  • Make operations idempotent so retries are safe.
  • Test with small timings and deterministic fake delays, not real network calls.

Interview questions: Python concurrency

9 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic Concurrency versus parallelism?

Concurrency is overlapping progress of tasks, possibly on one core. Parallelism is simultaneous execution on multiple cores.

Basic When use threads, processes or asyncio?

Threads for modest I/O-bound work with blocking libraries, asyncio for very many I/O-bound connections with async libraries, processes for CPU-bound work.

Medium How do you avoid race conditions with threads?

Protect shared state with locks, use thread-safe queues to pass messages, or avoid shared mutable state.

Medium How does asyncio work?

A single-threaded event loop runs coroutines; await suspends a coroutine until its operation completes, letting others run. Blocking calls stall the loop.

Medium What does asyncio.gather do?

Runs awaitables concurrently and returns their results in the order passed. Use TaskGroup for structured error handling.

Medium Why must multiprocessing code use the __main__ guard?

On Windows and macOS, child processes import the main module (spawn); without the guard they would start processes recursively.

Advanced How do you call blocking code from async code?

Use asyncio.to_thread or loop.run_in_executor so the blocking call runs in a thread pool and does not freeze the event loop.

Advanced What is a deadlock and how do you avoid it?

Threads waiting on each other's locks forever. Acquire locks in a consistent global order, use timeouts, or reduce shared locks.

Advanced How do you limit concurrency?

Semaphores or bounded worker pools (ThreadPoolExecutor with max_workers, asyncio.Semaphore, bounded queues) so you do not overload dependencies.
