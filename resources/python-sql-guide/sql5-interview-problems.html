SQL interview problems with tested solutions

These are the patterns interviewers keep coming back to. Try each problem first: read the statement, think about the tables in the earlier parts, write your own query, then compare. Every solution was executed and its result is shown.

MediumAdvanced~5 hours

How to approach SQL problems

  1. Restate what one output row represents ("one row per department").
  2. Identify the tables and join keys; decide which side must keep unmatched rows.
  3. Decide filter before or after grouping (WHERE vs HAVING).
  4. For ranking, running totals, previous row or top N per group, think window function.
  5. Build the query in CTE steps and check each step on a few rows.
  6. State edge cases: ties, NULLs, empty groups, duplicates, time zones.

Datasets: shop (customers, products, orders, order_items), hr (departments, employees) and events (logins, daily_sales, sessions), as in the earlier parts.

Self-check

What do you do before writing a SQL query in an interview?

Restate what one output row is, find tables and keys, decide outer joins, filter placement, and consider windows and edge cases.

Ranking and top N

1. Second highest distinct salary

Return the second highest distinct salary (or NULL if none).

SELECT (SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1) AS second_highest;

Result

second_highest
120000

General form for the Nth highest with ties handled by DENSE_RANK:

SELECT DISTINCT salary AS third_highest
FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS r FROM employees)
WHERE r = 3;

110000

6. Median salary

The median is the middle value (or the average of the two middle values). With window functions:

WITH ranked AS (
  SELECT salary,
         ROW_NUMBER() OVER (ORDER BY salary) AS rn,
         COUNT(*) OVER () AS cnt
  FROM employees
)
SELECT AVG(salary) AS median_salary
FROM ranked
WHERE rn IN ((cnt + 1) / 2, (cnt + 2) / 2);

Result

median_salary
105000.0

PostgreSQL offers PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY salary).

7. Best selling product in each category by units

WITH sold AS (
  SELECT p.category, p.name, SUM(i.qty) AS units
  FROM order_items i JOIN products p ON p.id = i.product_id
  JOIN orders o ON o.id = i.order_id AND o.status = 'paid'
  GROUP BY p.id
)
SELECT category, name, units FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY category ORDER BY units DESC, name) AS r FROM sold
) WHERE r = 1 ORDER BY category;

Result

categorynameunits
electronicsHeadphones4
furnitureChair2
stationeryPen70

How this gets asked

Salaries 100, 100, 90. The second highest distinct salary is:

  • 100 That is the highest.
  • 90 Correct.
  • NULL A second distinct value exists.
  • 190 No.

Use DENSE_RANK or SELECT DISTINCT ... OFFSET 1 so ties do not hide it.

Which function gives exactly one row per group when there are ties?

  • RANK Ties share a rank.
  • DENSE_RANK Ties share a rank.
  • ROW_NUMBER Correct.
  • NTILE No.

ROW_NUMBER assigns distinct numbers, so filtering rn = 1 gives one row.

Self-check

Top N per group pattern?

Rank with a window function partitioned by the group in a subquery or CTE, then filter rank <= N.

13. Customers who bought from every category (relational division)

Count the distinct categories per customer and compare to the total.

SELECT c.name
FROM customers c
JOIN orders o ON o.customer_id = c.id AND o.status = 'paid'
JOIN order_items i ON i.order_id = o.id
JOIN products p ON p.id = i.product_id
GROUP BY c.id
HAVING COUNT(DISTINCT p.category) = (SELECT COUNT(DISTINCT category) FROM products);

Result

name
(no rows)

Customer 1 bought electronics and stationery but no furniture in a paid order, so nobody buys from every category: an empty result. Change the comparison to >= 2 to see who bought from at least two.

SELECT c.name, COUNT(DISTINCT p.category) AS categories
FROM customers c
JOIN orders o ON o.customer_id = c.id AND o.status = 'paid'
JOIN order_items i ON i.order_id = o.id
JOIN products p ON p.id = i.product_id
GROUP BY c.id HAVING COUNT(DISTINCT p.category) >= 2
ORDER BY categories DESC, c.name;

15. Average order value per city

WITH totals AS (
  SELECT o.id, o.customer_id, SUM(i.qty * p.price) AS total
  FROM orders o JOIN order_items i ON i.order_id = o.id JOIN products p ON p.id = i.product_id
  WHERE o.status = 'paid' GROUP BY o.id
)
SELECT COALESCE(c.city, 'unknown') AS city, COUNT(*) AS orders, ROUND(AVG(t.total), 2) AS avg_order_value
FROM totals t JOIN customers c ON c.id = t.customer_id
GROUP BY c.city ORDER BY avg_order_value DESC;

Result

cityordersavg_order_value
Mumbai1950.0
Paris3725.0
London3655.0
unknown1100.0

Aggregating order totals before grouping by city avoids double counting order lines.

How this gets asked

Find customers with no orders. Which is correct?

  • INNER JOIN ... WHERE o.id IS NULL An inner join has no unmatched rows.
  • LEFT JOIN ... WHERE o.id IS NULL (or NOT EXISTS) Correct.
  • CROSS JOIN No.
  • UNION No.

The anti-join pattern keeps left rows that found no match.

In relational division (customers who bought every category) what do you compare?

  • COUNT(*) to 1 No.
  • The customer's COUNT(DISTINCT category) to the total number of categories Correct.
  • MAX to MIN No.
  • SUM to AVG No.

If a customer's distinct category count equals the total, they covered all.

Self-check

How do you list rows with no match?

LEFT JOIN with IS NULL on the right key, or NOT EXISTS.

16. Monthly revenue with running total

WITH monthly AS (
  SELECT strftime('%Y-%m', o.order_date) AS month, SUM(i.qty * p.price) AS revenue
  FROM orders o JOIN order_items i ON i.order_id = o.id JOIN products p ON p.id = i.product_id
  WHERE o.status = 'paid' GROUP BY month
)
SELECT month, revenue, SUM(revenue) OVER (ORDER BY month) AS running_total FROM monthly ORDER BY month;

17. Month over month growth

WITH monthly AS (
  SELECT strftime('%Y-%m', o.order_date) AS month, SUM(i.qty * p.price) AS revenue
  FROM orders o JOIN order_items i ON i.order_id = o.id JOIN products p ON p.id = i.product_id
  WHERE o.status = 'paid' GROUP BY month
)
SELECT month, revenue,
       LAG(revenue) OVER (ORDER BY month) AS prev,
       ROUND(100.0 * (revenue - LAG(revenue) OVER (ORDER BY month)) / LAG(revenue) OVER (ORDER BY month), 1) AS growth_pct
FROM monthly ORDER BY month;

The first month has no previous value, so growth is NULL, not zero.

20. Merge overlapping sessions

Overlapping or touching intervals should become one. Track the maximum end seen so far; a new group starts when the next start is after it.

WITH ordered AS (
  SELECT user_id, started, ended,
         MAX(ended) OVER (PARTITION BY user_id ORDER BY started ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS prev_max_end
  FROM sessions
), flagged AS (
  SELECT *, CASE WHEN prev_max_end IS NULL OR started > prev_max_end THEN 1 ELSE 0 END AS new_group FROM ordered
), grouped AS (
  SELECT *, SUM(new_group) OVER (PARTITION BY user_id ORDER BY started) AS g FROM flagged
)
SELECT user_id, MIN(started) AS merged_start, MAX(ended) AS merged_end
FROM grouped GROUP BY user_id, g ORDER BY user_id, merged_start;

Result

user_idmerged_startmerged_end
12024-03-01 09:002024-03-01 10:00
12024-03-01 11:002024-03-01 11:15
22024-03-01 09:002024-03-01 09:10

How this gets asked

In MoM growth with LAG, what is the first month's growth?

  • 0 There is no previous value, so it is unknown.
  • NULL Correct.
  • 100 No.
  • An error No.

LAG returns NULL when there is no previous row.

Logins on days 1,2,3,6,7 form how many streaks?

Days 1-3 and days 6-7 are separate consecutive runs.

Self-check

How do you merge overlapping intervals?

Track the running maximum end, flag a new group when start exceeds it, running-sum the flags, then group.

Cleaning and tricky patterns

21. Find duplicate emails

CREATE TABLE person (id INTEGER PRIMARY KEY, email TEXT);
INSERT INTO person (email) VALUES ('a@x.com'), ('b@x.com'), ('a@x.com'), ('c@x.com'), ('b@x.com'), ('a@x.com');
SELECT email, COUNT(*) AS n FROM person GROUP BY email HAVING COUNT(*) > 1 ORDER BY email;

22. Delete duplicates, keeping the smallest id

CREATE TABLE person (id INTEGER PRIMARY KEY, email TEXT);
INSERT INTO person (email) VALUES ('a@x.com'), ('b@x.com'), ('a@x.com'), ('c@x.com'), ('b@x.com'), ('a@x.com');
DELETE FROM person WHERE id NOT IN (SELECT MIN(id) FROM person GROUP BY email);
SELECT id, email FROM person ORDER BY id;

Result

idemail
1a@x.com
2b@x.com
4c@x.com

Safer on large tables: DELETE ... WHERE id IN (SELECT id FROM (SELECT id, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn FROM person) WHERE rn > 1).

24. Swap values with CASE, and conditional totals

Swap the values 'm' and 'f' in one statement (no temporary column):

CREATE TABLE people (id INTEGER PRIMARY KEY, sex TEXT);
INSERT INTO people VALUES (1, 'm'), (2, 'f'), (3, 'm');
UPDATE people SET sex = CASE sex WHEN 'm' THEN 'f' WHEN 'f' THEN 'm' END;
SELECT * FROM people ORDER BY id;

Result

idsex
1f
2m
3f

How this gets asked

Which is the standard way to keep one row from each duplicate group?

  • DISTINCT on the whole table without deleting Does not remove rows.
  • Delete rows whose id is not the MIN(id) per group (or ROW_NUMBER > 1) Correct.
  • TRUNCATE Deletes everything.
  • ORDER BY No.

Identify the survivor per group and delete the others.

Self-check

How do you delete duplicates keeping one?

Keep MIN(id) per duplicate key and delete the rest, or delete rows with ROW_NUMBER > 1.

Checklist for the interview

  • Say your assumptions about ties, NULLs and duplicates out loud.
  • Name the pattern: anti-join, window ranking, running total, gaps and islands, relational division, recursive CTE.
  • Check the grain after each join (did rows multiply?).
  • Mention indexes you would add and how you would read the plan (SQL4).
  • Say the dialect you are writing for and how it would differ.

Interview questions: SQL problems

10 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic Write a query for the second highest salary.

Use DENSE_RANK and filter rank = 2, or SELECT DISTINCT salary ORDER BY salary DESC LIMIT 1 OFFSET 1.

Medium Find duplicate emails.

SELECT email, COUNT(*) FROM person GROUP BY email HAVING COUNT(*) > 1.

Medium Delete duplicates keeping the lowest id.

DELETE FROM person WHERE id NOT IN (SELECT MIN(id) FROM person GROUP BY email), or delete rows with ROW_NUMBER over email greater than 1.

Medium Employees who earn more than their manager.

Self join employees e to employees m on e.manager_id = m.id and filter e.salary > m.salary.

Medium Customers who never ordered.

LEFT JOIN orders and keep rows where the order id IS NULL, or NOT EXISTS.

Medium Running total of monthly revenue.

Aggregate to months in a CTE then SUM(revenue) OVER (ORDER BY month).

Advanced Month over month growth.

Use LAG(revenue) OVER (ORDER BY month) and compute (revenue - prev) / prev, remembering the first month is NULL.

Advanced Longest consecutive login streak.

Compute date minus ROW_NUMBER per user as a group key, count per group, then take the maximum per user.

Advanced Customers who bought every product category.

Join to categories, GROUP BY customer and compare COUNT(DISTINCT category) to the total number of categories (relational division).

Advanced Merge overlapping intervals in SQL.

Order by start, track the running maximum end with a window frame, flag a new group when the start exceeds it, running-sum the flags and aggregate.
