Part PY8

Python internals: objects, names, bytecode, memory, the import system and the data model

Knowing the mechanism turns Python's surprises into predictions. This part explains the model underneath the syntax, with experiments you can reproduce, so you can answer interview questions about why, not only what.

Advanced~5 hours

Everything is an object

Every value (numbers, functions, classes, modules) is an object with an identity (id), a type and a value. A variable is a name bound to an object, not a box holding a value. Assignment binds a name; it never copies.

a = [1, 2, 3]
b = a                       # binds a second name to the same list
b.append(4)
print("a:", a, "| same object:", a is b, "| equal copy is a different object:", a is list(a), a == list(a))
x = 10
def show(n): return id(n) == id(x)
print("function parameters bind to the same object:", show(x))
print("types:", type(3).__name__, type(len).__name__, type(type).__name__, type(None).__name__, "| a function is an object with attributes:", hasattr(show, "__code__"))

Output

a: [1, 2, 3, 4] | same object: True | equal copy is a different object: False True
function parameters bind to the same object: True
types: int builtin_function_or_method type NoneType | a function is an object with attributes: True

is compares identity, == compares value (via __eq__). Use is only for singletons (None, True, False).

Small integers and interning

CPython caches small integers (-5 to 256) and may intern some strings, so is can appear to work and then fail. Never rely on it.

a = int("256"); b = int("256")
c = int("100000"); d = int("100000")
print("256 shared:", a is b, "| 100000 shared:", c is d, "| values equal either way:", a == b, c == d)
s1 = "hello world"; s2 = "".join(["hello", " ", "world"])
print("equal strings, different objects:", s1 == s2, s1 is s2)
import sys
print("interned explicitly:", sys.intern(s1) is sys.intern(s2))

Output

256 shared: True | 100000 shared: False | values equal either way: True True
equal strings, different objects: True False
interned explicitly: True

Names, scopes and LEGB

Python resolves a name by searching Local, Enclosing function, Global, then Built-in scopes. A name assigned anywhere in a function is local to that function for the whole function body, which explains UnboundLocalError.

x = "global"
def outer():
    x = "enclosing"
    def inner():
        return x                 # found in the enclosing scope
    return inner()
def broken():
    try:
        print(x)                 # x is assigned later in this function, so it is local, and not yet bound
        x = "local"
    except UnboundLocalError as e:
        return f"UnboundLocalError: {e}"
def counter():
    n = 0
    def inc():
        nonlocal n               # rebind the enclosing variable
        n += 1
        return n
    return inc
c = counter(); c(); c()
print(outer(), "|", broken(), "| closure state:", c())

Output

enclosing | UnboundLocalError: cannot access local variable 'x' where it is not associated with a value | closure state: 3

Mutable default arguments

Defaults are evaluated once, when the function is defined, and stored on the function object.

def append_to(item, bucket=[]):
    bucket.append(item); return bucket
print(append_to(1), append_to(2), append_to.__defaults__)
def append_safe(item, bucket=None):
    bucket = [] if bucket is None else bucket
    bucket.append(item); return bucket
print(append_safe(1), append_safe(2))

Output

[1, 2] [1, 2] ([1, 2],)
[1] [2]

How this gets asked

What causes UnboundLocalError?

  • Using a global No.
  • Reading a name that is assigned later in the same function, so it is local but unbound Correct.
  • Typos That is NameError.
  • Recursion No.

Assignment anywhere in the function makes the name local throughout.

When are default argument values evaluated?

  • On every call No.
  • Once, when the function is defined Correct.
  • When first used No.
  • At import of the caller No.

That is why mutable defaults are shared between calls.

Attribute lookup and the data model

obj.name runs a defined search: data descriptors on the type, then the instance __dict__, then non-data descriptors and class attributes along the method resolution order (MRO), then __getattr__. Functions on classes are descriptors that produce bound methods.

class A:
    kind = "class attribute"
    def who(self): return "A.who"
class B(A):
    def who(self): return "B.who -> " + super().who()
class C(A):
    def who(self): return "C.who -> " + super().who()
class D(B, C): pass
print([k.__name__ for k in D.__mro__])
print(D().who())
d = D()
print("instance dict empty:", d.__dict__, "| lookup finds class attribute:", d.kind)
d.kind = "instance attribute"
print("now shadowed on the instance:", d.kind, "| class unchanged:", D.kind)
m = d.who
print("bound method has __self__:", m.__self__ is d, "| underlying function:", m.__func__.__qualname__)

Output

['D', 'B', 'C', 'A', 'object']
B.who -> C.who -> A.who
instance dict empty: {} | lookup finds class attribute: class attribute
now shadowed on the instance: instance attribute | class unchanged: class attribute
bound method has __self__: True | underlying function: B.who

C3 linearisation gives D -> B -> C -> A -> object, so super() follows the MRO, not only the parent.

Special methods make objects behave like built-ins

len(x) calls type(x).__len__(x); x + y calls __add__; with calls __enter__/__exit__; for calls __iter__/__next__. Special methods are looked up on the type, not the instance.

class Vec:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self): return f"Vec({self.x}, {self.y})"
    def __add__(self, o): return Vec(self.x + o.x, self.y + o.y)
    def __eq__(self, o): return isinstance(o, Vec) and (self.x, self.y) == (o.x, o.y)
    def __hash__(self): return hash((self.x, self.y))
    def __bool__(self): return bool(self.x or self.y)
    def __len__(self): return 2
v = Vec(1, 2)
print(v + Vec(3, 4), "| equal:", v == Vec(1, 2), "| usable in a set:", len({v, Vec(1, 2)}) == 1, "| truthiness:", bool(Vec(0, 0)), "| no __dict__:", not hasattr(v, "__dict__"))

Output

Vec(4, 6) | equal: True | usable in a set: True | truthiness: False | no __dict__: True

If you define __eq__ you should define __hash__ consistently (equal objects must have equal hashes), or the class becomes unhashable.

Memory: reference counting and garbage collection

CPython frees most objects with reference counting: when the count of references hits zero the object is destroyed immediately. Reference cycles need the cyclic garbage collector (gc).

import sys, gc, weakref
x = object()
print("refcount after creating, one name plus the call argument:", sys.getrefcount(x))
y = x
print("after a second name:", sys.getrefcount(x))
del y
class Node:
    def __init__(self): self.other = None
a, b = Node(), Node()
a.other, b.other = b, a                     # a reference cycle
ref = weakref.ref(a)
del a, b
print("alive after del (cycle keeps it):", ref() is not None)
gc.collect()
print("alive after gc.collect():", ref() is not None)

Output

refcount after creating, one name plus the call argument: 2
after a second name: 3
alive after del (cycle keeps it): True
alive after gc.collect(): False

weakref references do not keep objects alive (used by caches). __del__ runs when an object is destroyed but its timing is not guaranteed on other implementations; use context managers for cleanup.

Bytecode and execution

Python compiles source to bytecode for a stack-based virtual machine, cached in __pycache__. The dis module shows it. Exact opcodes change between versions, so treat them as illustration.

import dis
def add(a, b): return a + b
ops = [i.opname for i in dis.get_instructions(add)]
print("add() uses a small stack machine; instruction kinds include load and return:", any(o.startswith("LOAD") for o in ops), any("RETURN" in o for o in ops))
code = add.__code__
print("argument names:", code.co_varnames, "| argument count:", code.co_argcount, "| constants:", code.co_consts)

Output

add() uses a small stack machine; instruction kinds include load and return: True True
argument names: ('a', 'b') | argument count: 2 | constants: (None,)

Consequences: every function call creates a frame; attribute and global lookups cost dictionary lookups (so binding local_append = items.append speeds hot loops); recent versions specialise bytecode adaptively for speed.

The import system

import m finds m via sys.modules (cache), then finders on sys.path; it executes the module once and binds the module object. Circular imports fail when a module is used before it finishes executing.

import sys, importlib, types
mod = types.ModuleType("demo_mod")
exec("VALUE = 42\ndef hello(): return 'hi from demo_mod'", mod.__dict__)
sys.modules["demo_mod"] = mod                     # register it like a normal import would
import demo_mod
print(demo_mod.VALUE, demo_mod.hello(), "| cached:", "demo_mod" in sys.modules, "| same object on re-import:", importlib.import_module("demo_mod") is demo_mod)
print("__name__ of the main script:", __name__, "| so `if __name__ == '__main__'` runs only when executed directly")

Output

42 hi from demo_mod | cached: True | same object on re-import: True
__name__ of the main script: __main__ | so `if __name__ == '__main__'` runs only when executed directly

Self-check

Why does a module run only once on import?

It is cached in sys.modules, and later imports return the cached module object.

The GIL and threads, revisited

The Global Interpreter Lock lets one thread run Python bytecode at a time in CPython, protecting reference counts. Consequences: CPU-bound threads do not speed up (use processes), I/O-bound threads do (the lock is released while waiting), and C extensions (NumPy) can release it. Recent Python versions offer an optional free-threaded build; check your version's documentation before relying on it. See PY4.

How this gets asked

  • I/O-bound work such as network calls Correct.

The lock is released while waiting for I/O.

Descriptors, properties and metaclasses in one view

property, classmethod, staticmethod and bound methods are all descriptors: objects with __get__. Classes are objects created by type (the default metaclass); __init_subclass__ and class decorators handle most needs that once required metaclasses.

class Positive:
    def __set_name__(self, owner, name): self.name = "_" + name
    def __get__(self, obj, owner=None): return self if obj is None else getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0: raise ValueError("must be positive")
        setattr(obj, self.name, value)
class Product:
    price = Positive()
    def __init__(self, price): self.price = price
p = Product(5)
try: p.price = -1
except ValueError as e: print("validation via descriptor:", e, "| price still", p.price)
class Registry:
    items = []
    def __init_subclass__(cls, **kw): Registry.items.append(cls.__name__)
class Plugin1(Registry): pass
class Plugin2(Registry): pass
print("subclasses registered automatically:", Registry.items, "| type of a class:", type(Product).__name__)

Output

validation via descriptor: must be positive | price still 5
subclasses registered automatically: ['Plugin1', 'Plugin2'] | type of a class: type

Performance mental model

  1. Algorithms and data structures dominate (list scan versus set lookup above).
  2. Avoid work in hot loops: hoist attribute lookups, use comprehensions and built-ins implemented in C (sum, sorted, str.join).
  3. Measure with timeit, cProfile, tracemalloc before optimising.
  4. Use the right tool for the job: NumPy or pandas for vectorised numerics, multiprocessing for CPU-bound work, asyncio for many network waits, Cython or Rust extensions for tight kernels.
Key idea

Names refer to objects; assignment shares, never copies. Name resolution follows LEGB, attribute lookup follows descriptors, instance dict and the MRO, and memory is reference counted with a cycle collector. When behaviour surprises you, ask which object a name points to and which scope or class is searched.

Interview questions: Python internals

15 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What does it mean that everything in Python is an object?

Values, functions, classes and modules all have identity, type and value, and names are references to them.

Basic is versus ==?

is tests whether two names refer to the same object; == tests value equality. Use is for None.

Basic Why is a mutable default argument a bug?

The default is created once at function definition and shared across calls, so mutations persist. Use None and create the object inside.

Medium Explain LEGB.

Names are resolved in Local, Enclosing function, Global then Built-in scopes. nonlocal and global declare which scope to rebind.

Medium What is the MRO and how is it computed?

The method resolution order is the linearisation of a class and its bases using C3, used by attribute lookup and super(). Inspect it with Class.__mro__.

Medium How does attribute lookup work?

Data descriptors on the type, then the instance __dict__, then non-data descriptors and class attributes along the MRO, then __getattr__ as a fallback.

Medium How does CPython manage memory?

Reference counting frees objects immediately at zero, and a cyclic garbage collector reclaims reference cycles.

Medium What is the GIL and what does it imply?

A lock allowing one thread to execute Python bytecode at a time in CPython. CPU-bound threads do not speed up; I/O-bound threads do. Use multiprocessing or native extensions for CPU work.

Medium Why define __hash__ with __eq__?

Equal objects must hash equally for dict and set correctness. Defining __eq__ alone makes instances unhashable.

Advanced What is a descriptor?

An object with __get__, __set__ or __delete__ stored on a class that controls attribute access. property, methods, classmethod and staticmethod are descriptors.

Advanced What are __slots__ for?

They replace the per-instance dict with fixed attributes, reducing memory and preventing arbitrary new attributes, at some cost in flexibility.

Advanced How does import work?

Python checks sys.modules, then uses finders on sys.path to locate and load the module, executes it once and caches it, which is also why circular imports can see partially initialised modules.

Advanced Why is s += x in a loop slow for strings?

Strings are immutable, so each concatenation can copy the whole string (O(n^2) total). Collect pieces and use ''.join().

Advanced What are weak references used for?

To refer to an object without keeping it alive, for caches, observers and parent pointers, avoiding leaks from cycles.

Advanced What does the dis module show?

The bytecode instructions the interpreter runs for a function. Useful for understanding evaluation order and cost; opcodes vary between versions.
