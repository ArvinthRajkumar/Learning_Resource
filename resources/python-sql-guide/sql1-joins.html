Joins, subqueries, set operations and expressions

Real questions need several tables at once. Joins combine them; subqueries and set operations compose queries. This is the core of everyday SQL and of most interview questions.

BasicMedium~4 hours

Joins

Intuition

A join pairs rows from two tables whenever a condition holds, usually "the foreign key equals the primary key". Think of laying two lists side by side and connecting matching entries.

SELECT o.id AS order_id, c.name, o.order_date, o.status
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id
ORDER BY o.id
LIMIT 5;

Always qualify columns with table aliases (o.id, c.name) when tables share column names.

The join types

INNER versus LEFT

Customers who never ordered disappear in an inner join but stay in a left join.

SELECT c.name, COUNT(o.id) AS orders
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name
ORDER BY orders DESC, c.name;

WHERE versus ON in outer joins

Filtering the right table in WHERE turns a left join into an inner join, because NULL rows fail the test. Put the condition in ON to keep unmatched left rows.

SELECT c.name, COUNT(o.id) AS paid_orders
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.status = 'paid'   -- condition in ON
GROUP BY c.id, c.name
ORDER BY c.id;

Join pitfalls

  • Row multiplication: joining a customer to orders and then to items repeats the customer columns. Aggregating afterwards can double count; aggregate in a subquery first.
  • Missing join condition produces a Cartesian product (rows x rows) and silently huge results.
  • Joining on non-unique columns multiplies rows.
  • Use USING (col) as shorthand when both tables share the column name.
-- Wrong: SUM(p.price) is repeated once per item, and orders are repeated per line
SELECT COUNT(*) AS rows_after_join, COUNT(DISTINCT o.id) AS real_orders
FROM orders o JOIN order_items i ON i.order_id = o.id;

Result

rows_after_joinreal_orders
1610

How this gets asked

Which join returns all customers, even those who never ordered?

  • INNER JOIN Drops customers without orders.
  • LEFT JOIN from customers to orders Correct.
  • CROSS JOIN Cartesian product.
  • UNION Not a join.

A left join keeps every left-side row and fills NULLs where no match exists.

You LEFT JOIN orders and add WHERE o.status = 'paid'. What happens?

  • Unmatched customers are kept They have NULL status, which fails the test.
  • It behaves like an inner join Correct.
  • Syntax error No.
  • Duplicates are removed No.

Put the condition in ON to preserve unmatched left rows.

Table A has 4 rows and table B has 5 rows. How many rows does A CROSS JOIN B produce?

4 x 5 = 20.

Which can cause unexpected row multiplication? Select all.

  • Joining on a non-unique column
  • A missing join condition
  • Joining orders to order_items then summing order-level totals
  • Using table aliases

Aliases only rename; the others multiply rows or double count.

Self-check

Inner versus left join?

Inner keeps only matching pairs; left keeps all left rows and NULLs for non-matching right columns.

How do you find rows with no match?

LEFT JOIN and filter right key IS NULL, or NOT EXISTS.

Correlated subqueries

A correlated subquery refers to the outer row, so it conceptually runs once per outer row.

SELECT p.name, p.category, p.price
FROM products p
WHERE p.price = (SELECT MAX(p2.price) FROM products p2 WHERE p2.category = p.category)
ORDER BY p.category;

Result

namecategoryprice
Laptopelectronics1200.0
Deskfurniture300.0
Notebookstationery5.0

This returns the dearest product in each category. (Window functions in SQL2 often do this more clearly and fast.)

EXISTS and NOT EXISTS

EXISTS (subquery) is true if the subquery returns at least one row. It stops at the first match, and it is safe with NULLs.

SELECT c.name
FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id AND o.status = 'cancelled');

How this gets asked

Why is NOT EXISTS safer than NOT IN with a subquery?

  • It is always faster Not always.
  • A single NULL in the subquery makes NOT IN return no rows; NOT EXISTS is NULL-safe Correct.
  • NOT IN is deprecated No.
  • There is no difference There is.

x NOT IN (..., NULL) is never true.

Self-check

What is a correlated subquery?

A subquery referencing columns of the outer query, evaluated per outer row.

How this gets asked

Which set operator keeps duplicates?

  • UNION Removes them.
  • UNION ALL Correct.
  • INTERSECT Removes them.
  • EXCEPT Removes them.

Self-check

UNION versus UNION ALL?

UNION deduplicates (extra work); UNION ALL concatenates.

SELECT c.name,
       COALESCE(SUM(i.qty * p.price), 0) AS spent
FROM customers c
LEFT JOIN orders o     ON o.customer_id = c.id AND o.status = 'paid'
LEFT JOIN order_items i ON i.order_id = o.id
LEFT JOIN products p    ON p.id = i.product_id
GROUP BY c.id, c.name

Interview questions: SQL joins

10 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic Explain INNER, LEFT, RIGHT and FULL joins.

Inner returns matching rows only. Left keeps all left rows with NULLs for missing right matches. Right is the mirror. Full keeps unmatched rows from both sides.

Basic What is a self join?

Joining a table to itself with aliases, for example employees to their managers.

Basic UNION versus UNION ALL?

UNION removes duplicates (extra work); UNION ALL keeps all rows and is faster.

Medium How do you find rows in A with no match in B?

LEFT JOIN and filter B's key IS NULL, or NOT EXISTS. Prefer NOT EXISTS over NOT IN when NULLs are possible.

Medium IN versus EXISTS?

IN compares to a list or subquery result; EXISTS checks whether a correlated subquery returns any row, stops early and is NULL-safe.

Medium Why does a WHERE filter on the right table turn a LEFT JOIN into an INNER JOIN?

Unmatched rows have NULLs in right columns, which fail the condition. Put the condition in the ON clause instead.

Medium What is a CROSS JOIN and when is it useful?

The Cartesian product of two tables. Useful for generating combinations such as all dates by all products.

Advanced How does row multiplication happen and how do you avoid double counting?

Joining one-to-many tables repeats the parent row. Aggregate the child table in a subquery or CTE first, then join the result.

Advanced What is a correlated subquery and what are alternatives?

A subquery referencing the outer row, evaluated per outer row. Alternatives are joins to a pre-aggregated derived table or window functions.

Advanced Explain NOT IN with NULLs.

If the subquery returns any NULL, x NOT IN (...) is never true, so no rows return. Use NOT EXISTS or filter NULLs out.
