Working with data formats and the web: CSV, XML, URLs, HTTP clients and servers

Most Python programs read data in one format and hand it to another system. This part covers the formats, how to validate untrusted input, and how HTTP works by building a tiny server and client on your own machine.

MediumAdvanced~5 hours

CSV done properly

CSV looks simple and is full of traps: quoting, embedded commas and newlines, encodings, missing values and types (everything is text). Use the csv module, never str.split(",").

import csv, io
raw = 'id,name,city,amount\n1,"Smith, Ana",London,10.5\n2,Bo,"Paris\nFrance",\n3,Chloe,,7\n'
rows = list(csv.DictReader(io.StringIO(raw)))
for r in rows: print(r)
total = sum(float(r["amount"]) for r in rows if r["amount"])
print("total:", total, "| rows with missing amount:", [r["id"] for r in rows if not r["amount"]])
out = io.StringIO()
w = csv.DictWriter(out, fieldnames=["id", "name"], extrasaction="ignore", lineterminator="\n")
w.writeheader(); w.writerows(rows)
print(out.getvalue().strip().replace("\n", " / "))

Output

{'id': '1', 'name': 'Smith, Ana', 'city': 'London', 'amount': '10.5'}
{'id': '2', 'name': 'Bo', 'city': 'Paris\nFrance', 'amount': ''}
{'id': '3', 'name': 'Chloe', 'city': '', 'amount': '7'}
total: 17.5 | rows with missing amount: ['2']
id,name / 1,"Smith, Ana" / 2,Bo / 3,Chloe

Rules: open real files with newline="" and an explicit encoding (often utf-8-sig for files from Excel); convert types explicitly; treat empty strings as missing; stream large files row by row; check the header before trusting columns.

How this gets asked

Why not parse CSV with line.split(',')?

  • It is slower Not the reason.
  • Quoted fields can contain commas and newlines Correct.
  • Python forbids it No.
  • CSV has no commas No.

The csv module handles quoting and embedded delimiters.

Self-check

Which three arguments matter when opening CSV files?

newline='', an explicit encoding, and the dialect or delimiter if it is not a comma.

JSON, safely

import json
doc = '{"user": {"id": 7, "tags": ["a", "b"]}, "score": 9.5, "active": true, "note": null}'
data = json.loads(doc)
print(data["user"]["tags"], data["active"], data["note"], type(data["score"]).__name__)
print(json.dumps(data, sort_keys=True, separators=(",", ":")))
print(json.dumps({"name": "café", "n": 1}, ensure_ascii=False), "|", json.dumps({"name": "café"}))
try:
    json.loads("{'bad': 'quotes'}")
except json.JSONDecodeError as e:
    print("invalid JSON:", e.msg, "at column", e.colno)
try:
    json.dumps({"when": __import__("datetime").date(2024, 1, 1)})
except TypeError as e:
    print("not serialisable:", e)

Output

['a', 'b'] True None float
{"active":true,"note":null,"score":9.5,"user":{"id":7,"tags":["a","b"]}}
{"name": "café", "n": 1} | {"name": "caf\u00e9"}
invalid JSON: Expecting property name enclosed in double quotes at column 2
not serialisable: Object of type date is not JSON serializable

Handle custom types with default= in dumps or object_hook in loads. JSON keys are always strings; integers larger than 2^53 lose precision in JavaScript; there is no date type (use ISO 8601 strings). Never parse untrusted data with pickle or eval: json is safe because it only builds plain data.

Validating untrusted input

Parse, then validate the shape and types before using it. Libraries such as pydantic and jsonschema do this; the idea in plain Python:

def validate_user(obj):
    errors = []
    if not isinstance(obj, dict): return ["body must be an object"]
    if not isinstance(obj.get("name"), str) or not obj["name"].strip(): errors.append("name: non-empty string required")
    age = obj.get("age")
    if not isinstance(age, int) or isinstance(age, bool) or not 0 <= age <= 150: errors.append("age: integer 0..150 required")
    email = obj.get("email", "")
    if "@" not in email or email.startswith("@") or email.endswith("@"): errors.append("email: invalid")
    extra = set(obj) - {"name", "age", "email"}
    if extra: errors.append(f"unknown fields: {sorted(extra)}")
    return errors
print(validate_user({"name": "Ada", "age": 36, "email": "ada@example.com"}))
print(validate_user({"name": " ", "age": True, "email": "nope", "admin": True}))

Output

[]
['name: non-empty string required', 'age: integer 0..150 required', 'email: invalid', "unknown fields: ['admin']"]

XML

xml.etree.ElementTree handles the common cases. For untrusted XML be aware of entity-expansion attacks; use the defusedxml package.

import xml.etree.ElementTree as ET
xml = """<catalog>
  <book id="b1"><title>Learning Python</title><price currency="USD">29.5</price></book>
  <book id="b2"><title>SQL Basics</title><price currency="EUR">19</price></book>
</catalog>"""
root = ET.fromstring(xml)
for b in root.findall("book"):
    print(b.get("id"), "|", b.findtext("title"), "|", b.find("price").get("currency"), float(b.findtext("price")))
new = ET.SubElement(root, "book", id="b3")
ET.SubElement(new, "title").text = "Algorithms"
print(ET.tostring(root, encoding="unicode").count("<book"), "books after adding one")
print(root.findall(".//price[@currency='EUR']")[0].text, "(XPath-like query)")

Output

b1 | Learning Python | USD 29.5
b2 | SQL Basics | EUR 19.0
3 books after adding one
19 (XPath-like query)

URLs and query strings

from urllib.parse import urlparse, parse_qs, urlencode, quote, urljoin, urlunparse
u = urlparse("https://user@example.com:8443/search/items?q=red+shoes&page=2&tag=a&tag=b#top")
print(u.scheme, u.hostname, u.port, u.path, u.fragment)
print(parse_qs(u.query))
print(urlencode({"q": "red shoes & socks", "page": 3}), "|", quote("a b/c?d", safe=""))
print(urljoin("https://example.com/docs/guide/", "../api/v1"), "|", urlunparse(("https", "example.com", "/x", "", "a=1", "")))

Output

https example.com 8443 /search/items top
{'q': ['red shoes'], 'page': ['2'], 'tag': ['a', 'b']}
q=red+shoes+%26+socks&page=3 | a%20b%2Fc%3Fd
https://example.com/docs/api/v1 | https://example.com/x?a=1

Build URLs with these helpers, never by string concatenation, so special characters are encoded correctly (and injection is avoided). Validate redirect targets and outbound URLs to prevent SSRF.

How this gets asked

Why build query strings with urlencode?

  • It is shorter No.
  • It percent-encodes special characters correctly Correct.
  • It is faster No.
  • It adds auth No.

Concatenation breaks on & = spaces and enables injection.

HTTP in 5 minutes

HTTP is request and response text over TCP. A request has a method, path, headers and optional body; the response has a status code, headers and body.

StatusMeaning
200 / 201 / 204OK / Created / No content
301 / 302 / 304Moved / Found / Not modified
400 / 401 / 403 / 404 / 409 / 422 / 429Bad request / Unauthenticated / Forbidden / Not found / Conflict / Unprocessable / Too many requests
500 / 502 / 503 / 504Server error / Bad gateway / Unavailable / Gateway timeout

Methods: GET reads (safe, idempotent), POST creates or acts, PUT replaces (idempotent), PATCH partially updates, DELETE removes (idempotent). Safe retries need idempotent methods or an idempotency key.

A tiny server and a client, on your machine

The standard library can run a real HTTP server. Below a server runs in a background thread on a free local port, and a client calls it.

import json, threading, urllib.request, urllib.error
from http.server import BaseHTTPRequestHandler, HTTPServer
ITEMS = {"1": {"id": 1, "name": "pen"}}
class Handler(BaseHTTPRequestHandler):
    def _send(self, code, payload):
        body = json.dumps(payload).encode()
        self.send_response(code); self.send_header("Content-Type", "application/json"); self.send_header("Content-Length", str(len(body))); self.end_headers()
        self.wfile.write(body)
    def do_GET(self):
        key = self.path.rsplit("/", 1)[-1]
        if self.path.startswith("/items/") and key in ITEMS: self._send(200, ITEMS[key])
        else: self._send(404, {"error": "not found"})
    def do_POST(self):
        length = int(self.headers.get("Content-Length", 0))
        try:
            obj = json.loads(self.rfile.read(length))
            ITEMS[str(len(ITEMS) + 1)] = {"id": len(ITEMS) + 1, **obj}
            self._send(201, ITEMS[str(len(ITEMS))])
        except (json.JSONDecodeError, TypeError):
            self._send(400, {"error": "invalid JSON"})
    def log_message(self, *a): pass
server = HTTPServer(("127.0.0.1", 0), Handler)
port = server.server_address[1]
threading.Thread(target=server.serve_forever, daemon=True).start()
base = f"http://127.0.0.1:{port}"
def call(method, path, body=None):
    req = urllib.request.Request(base + path, method=method, data=json.dumps(body).encode() if body is not None else None, headers={"Content-Type": "application/json"})
    try:
        with urllib.request.urlopen(req, timeout=3) as r: return r.status, json.loads(r.read())
    except urllib.error.HTTPError as e: return e.code, json.loads(e.read())
print(call("GET", "/items/1"))
print(call("GET", "/items/99"))
print(call("POST", "/items", {"name": "book"}))
print(call("GET", "/items/2"))
server.shutdown()

Output

(200, {'id': 1, 'name': 'pen'})
(404, {'error': 'not found'})
(201, {'id': 2, 'name': 'book'})
(200, {'id': 2, 'name': 'book'})

Real services use frameworks (FastAPI, Flask, Django) for routing, validation, auth and concurrency, but the protocol is exactly this.

Calling APIs reliably

Network calls fail. A robust client sets timeouts, retries idempotent requests with exponential backoff and jitter, respects 429 Retry-After, and distinguishes retryable errors (timeouts, 502/503/504, 429) from permanent ones (400, 401, 404).

import random
random.seed(1)
class Flaky:
    """Fails twice with a 503, then succeeds."""
    def __init__(self): self.calls = 0
    def get(self):
        self.calls += 1
        if self.calls <= 2: return 503, None
        return 200, {"ok": True}
def with_retries(fn, attempts=5, base=0.1):
    delays = []
    for i in range(attempts):
        status, body = fn()
        if status < 500 and status != 429: return status, body, delays
        delay = random.uniform(0, base * 2 ** i)               # full jitter
        delays.append(round(delay, 3))                          # a real client would time.sleep(delay)
    return status, None, delays
f = Flaky()
status, body, delays = with_retries(f.get)
print("final:", status, body, "| attempts:", f.calls, "| back-off delays (s):", delays)

Output

final: 200 {'ok': True} | attempts: 3 | back-off delays (s): [0.013, 0.169]

With the popular requests or httpx libraries the same ideas apply: timeout=(3.05, 10), a Session for connection reuse, raise_for_status(), and a retry adapter. Never call external services without a timeout; the default is to wait forever.

How this gets asked

Which errors should an HTTP client retry?

  • All of them No.
  • Timeouts, 429 and 502/503/504, with backoff and for idempotent requests Correct.
  • 400 and 404 Permanent errors.
  • None Misses transient failures.

Retrying a 400 will never help.

Self-check

What is exponential backoff with jitter?

Retry delays that grow exponentially with random variation so clients do not retry in lockstep.

Compression and archives

import gzip, zipfile, io, json
payload = json.dumps([{"id": i, "text": "repeat " * 20} for i in range(200)]).encode()
gz = gzip.compress(payload)
print(f"gzip: {len(payload):,} -> {len(gz):,} bytes ({len(gz) / len(payload):.1%}) | round trip ok: {gzip.decompress(gz) == payload}")
buf = io.BytesIO()
with zipfile.ZipFile(buf, "w", zipfile.ZIP_DEFLATED) as z:
    z.writestr("a.txt", "hello " * 50); z.writestr("dir/b.txt", "world")
with zipfile.ZipFile(io.BytesIO(buf.getvalue())) as z:
    print("zip members:", z.namelist(), "| read b:", z.read("dir/b.txt").decode())

Output

gzip: 32,890 -> 647 bytes (2.0%) | round trip ok: True
zip members: ['a.txt', 'dir/b.txt'] | read b: world

When extracting archives from untrusted sources, check member paths for .. (zip slip) and sizes (zip bombs).

Self-check

What is zip slip?

An archive member with ../ in its path that writes outside the target directory on extraction.

pickle.loads executes whatever the data tells it to. Use JSON or a schema-based format for data crossing a trust boundary. The same goes for yaml.load (use safe_load) and eval.

Key idea

Use the right parser, validate everything from outside, build URLs with helpers, set timeouts and retries on every network call, and pick a serialisation format for its reader: JSON for interchange, Parquet for analytics, never pickle across trust boundaries.

Interview questions: Data formats and web

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic Why use the csv module instead of split(',')?

Fields may be quoted and contain commas, quotes and newlines. The csv module implements these rules and dialects.

Basic What types does JSON support?

Objects, arrays, strings, numbers, booleans and null. There is no date, bytes or set type, so serialise those explicitly.

Basic What do 200, 201, 204, 400, 401, 403, 404, 409, 429 and 500 mean?

OK, created, no content, bad request, unauthenticated, forbidden, not found, conflict, too many requests, server error.

Medium Which HTTP methods are idempotent and which are safe?

GET, HEAD and OPTIONS are safe; GET, HEAD, PUT, DELETE and OPTIONS are idempotent. POST is neither and PATCH is not guaranteed idempotent.

Medium How do you build a URL with query parameters safely?

Use urllib.parse.urlencode and urljoin or a client library's params argument so special characters are percent-encoded.

Medium What makes an HTTP client robust?

Timeouts on every call, retries with exponential backoff and jitter for transient errors on idempotent requests, respect for Retry-After, connection reuse, and clear handling of non-2xx responses.

Medium Why is pickle unsafe for untrusted data?

Unpickling can call arbitrary functions, so loading attacker-supplied bytes can execute code. Use JSON or a schema-based format.

Medium How do you validate incoming JSON?

Parse, then check structure, types, ranges and unknown fields with a schema library such as pydantic or jsonschema, returning specific errors.

Medium What is zip slip?

An archive entry with ../ in its path writes outside the extraction directory. Resolve and verify each target path before extracting.

Advanced How would you parse a 20 GB CSV?

Stream rows with csv.reader or pandas chunks, process incrementally, avoid holding everything in memory, and write results in a columnar format such as Parquet.

Advanced SSRF: what is it and how do you prevent it?

A server fetches a user-supplied URL and is tricked into reaching internal services or cloud metadata. Allow-list hosts, resolve and check IPs, block private ranges and disable redirects or re-validate them.

Advanced REST versus gRPC versus GraphQL in one line each?

REST uses resources over HTTP and is cacheable and simple; gRPC uses Protobuf over HTTP/2 for fast typed service calls; GraphQL lets clients specify exactly the fields they need from one endpoint.

Advanced How does an HTTP server handle many clients in Python?

Using threads, processes, or an async event loop (ASGI servers such as uvicorn); the framework routes requests while the server manages concurrency.

Advanced Why are XML parsers a security concern?

Entity expansion (billion laughs) and external entity (XXE) features can exhaust memory or read files. Use defusedxml for untrusted input.
