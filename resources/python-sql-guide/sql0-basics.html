SQL from scratch: tables, queries, filtering and aggregation

SQL is the language for asking questions of data stored in tables. This part starts from what a table is and builds up to grouped reports. Every query on this page was run against a real database (SQLite) and its result is shown.

Basic~4 hours

What a relational database is

Intuition

A relational database stores data in tables, like spreadsheets with rules. A row is one record, a column is one attribute with a fixed type. Tables are linked by keys: an order row stores the id of its customer instead of copying the customer's details, so each fact lives in one place.

SQL (Structured Query Language) is declarative: you describe what result you want, and the database decides how to get it. The same ideas work in PostgreSQL, MySQL, SQL Server, Oracle and SQLite, with small dialect differences noted in SQL4.

How this gets asked

In which order does a database logically evaluate a query?

  • SELECT, FROM, WHERE SELECT comes later.
  • FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY Correct.
  • WHERE, FROM, SELECT No.

NULL and three-valued logic

What NULL means

NULL means unknown or missing, not zero and not an empty string. Any comparison with NULL is unknown (neither true nor false), and WHERE keeps only rows where the condition is true.

SELECT name, city FROM customers WHERE city = NULL;

Result

namecity
(no rows)

That returns nothing: city = NULL is never true. Use IS NULL.

SELECT name, city FROM customers WHERE city IS NULL;

Result

namecity
EliNULL

Handling NULL

SELECT name,
       COALESCE(city, 'unknown') AS city,
       city IS NULL AS missing
FROM customers
WHERE id IN (4, 5);

Result

Trap

NOT IN (subquery) returns no rows if the subquery produces any NULL, because x <> NULL is unknown. Use NOT EXISTS instead (SQL1).

How this gets asked

What does SELECT * FROM t WHERE x = NULL return?

  • Rows where x is null That needs IS NULL.
  • No rows Correct: the comparison is unknown.
  • All rows No.
  • An error No.

Any comparison with NULL is unknown, so the row is not selected.

Self-check

What is three-valued logic?

Conditions can be true, false or unknown (when NULL is involved); WHERE keeps only true.

Aggregation: COUNT, SUM, GROUP BY, HAVING

Aggregate functions

An aggregate collapses many rows into one value.

SELECT COUNT(*) AS products,
       MIN(price) AS cheapest,
       MAX(price) AS dearest,
       SUM(price) AS total,
       ROUND(AVG(price), 2) AS average
FROM products;

Result

GROUP BY

GROUP BY splits rows into groups and computes aggregates per group.

SELECT category, COUNT(*) AS n, ROUND(AVG(price), 1) AS avg_price
FROM products
GROUP BY category
ORDER BY n DESC, category;

Result

categorynavg_price
electronics3716.7
furniture2240.0
stationery23.5

Rule: every column in SELECT must either be in GROUP BY or be inside an aggregate.

WHERE versus HAVING

WHERE filters rows before grouping. HAVING filters groups after aggregation.

SELECT customer_id, COUNT(*) AS orders
FROM orders
WHERE status = 'paid'
GROUP BY customer_id
HAVING COUNT(*) >= 2
ORDER BY orders DESC;

Result

customer_idorders
22
12

Conditional aggregation

SELECT customer_id,
       COUNT(*) AS total,
       SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END) AS paid,
       SUM(status = 'cancelled') AS cancelled
FROM orders
GROUP BY customer_id
ORDER BY customer_id;

Result

customer_idtotalpaidcancelled

CASE WHEN ... THEN ... ELSE ... END is SQL's if-else; combining it with SUM gives conditional counts ("pivoting").

How this gets asked

If a column has values 10, 20, NULL, 30, what is AVG(column)?

AVG ignores NULL: (10 + 20 + 30) / 3 = 20.

Which clause filters groups after aggregation?

  • WHERE Filters rows before grouping.
  • HAVING Correct.
  • ORDER BY Sorts.
  • LIMIT Restricts count.

HAVING can use aggregates; WHERE cannot.

COUNT(col) counts:

  • All rows That is COUNT(*).
  • Rows where col is not NULL Correct.
  • Distinct values That needs DISTINCT.
  • Rows where col is NULL No.

COUNT(col) skips NULLs.

CREATE TABLE with constraints

CREATE TABLE accounts (
    id        INTEGER PRIMARY KEY,
    email     TEXT    NOT NULL UNIQUE,
    balance   INTEGER NOT NULL DEFAULT 0 CHECK (balance >= 0),
    owner_id  INTEGER REFERENCES accounts(id),
    created   TEXT    DEFAULT CURRENT_DATE
);
INSERT INTO accounts (email, balance) VALUES ('a@x.com', 50), ('b@x.com', 0);
SELECT id, email, balance FROM accounts;

Always check your WHERE

UPDATE or DELETE without WHERE changes every row. In real work run the same condition as a SELECT first, and use a transaction (SQL3) so you can roll back.

ALTER and DROP

ALTER TABLE customers ADD COLUMN vip INTEGER DEFAULT 0;
UPDATE customers SET vip = 1 WHERE id IN (1, 3);
SELECT name, vip FROM customers WHERE vip = 1;

Result

namevip
Ada1
Chloe1

DROP TABLE t removes a table and its data; TRUNCATE (not in SQLite) empties it quickly.

How this gets asked

Which constraints can you declare on a column? Select all.

  • NOT NULL
  • UNIQUE
  • CHECK (balance >= 0)
  • FOREIGN KEY ... REFERENCES

All are standard column or table constraints enforced by the database.

An UPDATE without a clause changes every row.

Always include a WHERE clause, and test it with SELECT first.

Self-check

Name four constraints.

PRIMARY KEY, NOT NULL, UNIQUE, CHECK, FOREIGN KEY, DEFAULT.

Interview questions: SQL basics

10 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What is the difference between WHERE and HAVING?

WHERE filters rows before grouping; HAVING filters groups after aggregates are computed.

Basic Difference between DELETE, TRUNCATE and DROP?

DELETE removes selected rows (logged, can be rolled back, fires triggers). TRUNCATE removes all rows quickly (resets state, limited rollback in some engines). DROP removes the table itself.

Basic What are primary and foreign keys?

A primary key uniquely identifies a row. A foreign key references another table's key and lets the database enforce referential integrity.

Basic What is NULL and how do you test for it?

NULL means unknown or missing. Comparisons with it are unknown, so use IS NULL and IS NOT NULL, and COALESCE to supply defaults.

Medium COUNT(*) versus COUNT(column) versus COUNT(DISTINCT column)?

COUNT(*) counts rows, COUNT(column) counts non-NULL values, COUNT(DISTINCT column) counts distinct non-NULL values.

Medium What is the logical order of query evaluation?

FROM and JOIN, WHERE, GROUP BY, HAVING, SELECT, DISTINCT, ORDER BY, LIMIT.

Medium What are the SQL constraint types?

PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK and DEFAULT.

Medium What is the difference between CHAR and VARCHAR, and why use DECIMAL for money?

CHAR is fixed length and VARCHAR variable length. DECIMAL is exact, while floating point types are approximate and cause rounding errors.

Advanced Why can SELECT without ORDER BY return rows in different orders?

SQL tables are unordered sets; the order depends on the plan, indexes and storage. Always specify ORDER BY (with a unique tiebreaker) when order matters.

Advanced Explain three-valued logic.

A condition can be true, false or unknown. Comparisons with NULL are unknown; AND, OR and NOT follow truth tables for three values, and WHERE keeps only true rows.
