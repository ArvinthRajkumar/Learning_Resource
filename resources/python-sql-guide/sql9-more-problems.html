More SQL interview problems: set two

A second set of problems for practice after SQL5. Each states the task, names the technique, gives a solution that was run on the dataset, and lists the common mistake. Cover the solution and write your own query first.

MediumAdvanced~5 hours

How to use this set

Datasets: shop (customers, products, orders, order_items), hr (departments, employees), events (logins, daily_sales, sessions) and app (users, events). Schemas appear in the earlier parts. For each problem: restate it, state the grain of the result (one row per what?), write the query, then test edge cases such as ties, NULLs and empty groups.

Ranking and comparisons

1. Second highest salary (with ties handled)

Use DENSE_RANK so equal salaries share a rank. Mistake: LIMIT 1 OFFSET 1 returns the second row, not the second distinct value.

SELECT DISTINCT salary FROM (
  SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS r FROM employees)
WHERE r = 2;

Result

salary
120000

2. Employees who earn more than their manager

Self-join employees to their manager.

SELECT e.name AS employee, e.salary, m.name AS manager, m.salary AS manager_salary
FROM employees e JOIN employees m ON m.id = e.manager_id
WHERE e.salary > m.salary;

Result

employeesalarymanagermanager_salary
Eve95000Dan90000

Check that the join key is right; the inner join silently drops the top of the tree (no manager), which is what you want here. An empty result would also be a valid answer.

3. Departments with no employees

Anti-join with NOT EXISTS.

SELECT d.name FROM departments d
WHERE NOT EXISTS (SELECT 1 FROM employees e WHERE e.dept_id = d.id);

4. Highest paid employee per department, with ties

RANK keeps all tied top earners.

SELECT department, name, salary FROM (
  SELECT d.name AS department, e.name, e.salary, RANK() OVER (PARTITION BY d.id ORDER BY e.salary DESC) AS r
  FROM employees e JOIN departments d ON d.id = e.dept_id)
WHERE r = 1 ORDER BY department, name;

5. Salary compared with the department average

Window average beside each row, no self-join needed.

SELECT name, salary,
       ROUND(AVG(salary) OVER (PARTITION BY dept_id)) AS dept_avg,
       salary - ROUND(AVG(salary) OVER (PARTITION BY dept_id)) AS diff
FROM employees WHERE dept_id IS NOT NULL
ORDER BY dept_id, salary DESC;

How this gets asked

Which function finds the second distinct highest value even with ties?

  • ROW_NUMBER Counts duplicates separately.
  • DENSE_RANK Correct.
  • LIMIT 1 OFFSET 1 Returns the second row, which may repeat the highest.
  • COUNT No.

Dense rank has no gaps for ties.

Self-check

ROW_NUMBER vs RANK vs DENSE_RANK?

ROW_NUMBER is unique; RANK leaves gaps after ties; DENSE_RANK has no gaps.

7. Customers who bought every electronics product under 1000 (relational division)

Count distinct matches and compare with the total.

SELECT c.name
FROM customers c
JOIN orders o ON o.customer_id = c.id AND o.status = 'paid'
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON p.id = oi.product_id AND p.category = 'electronics' AND p.price < 1000
GROUP BY c.id, c.name
HAVING COUNT(DISTINCT p.id) = (SELECT COUNT(*) FROM products WHERE category = 'electronics' AND price < 1000);

9. Pairs of colleagues in the same department

Self-join with a.id < b.id so each pair appears once and nobody pairs with themself.

SELECT a.name AS person_a, b.name AS person_b, d.name AS department
FROM employees a JOIN employees b ON a.dept_id = b.dept_id AND a.id < b.id
JOIN departments d ON d.id = a.dept_id
ORDER BY d.name, a.name, b.name;

How this gets asked

Which query pattern finds rows with no match in another table?

  • INNER JOIN Only matches.
  • LEFT JOIN with IS NULL or NOT EXISTS Correct.
  • UNION No.
  • GROUP BY No.

That is an anti-join.

How do you express relational division ('all of')?

  • DISTINCT No.
  • Group and compare the distinct matched count with the total required count Correct.
  • ORDER BY No.
  • LIMIT No.

HAVING COUNT(DISTINCT x) = total.

Self-check

Why prefer NOT EXISTS to NOT IN?

NOT IN returns nothing if the subquery contains a NULL; NOT EXISTS is NULL-safe.

Aggregation and pivots

10. Orders above the average order value

Compare per-order totals with the overall average using a CTE.

WITH totals AS (
  SELECT o.id AS order_id, SUM(oi.qty * p.price) AS total
  FROM orders o JOIN order_items oi ON oi.order_id = o.id JOIN products p ON p.id = oi.product_id
  WHERE o.status = 'paid' GROUP BY o.id)
SELECT order_id, total FROM totals WHERE total > (SELECT AVG(total) FROM totals) ORDER BY total DESC;

12. Percent of total revenue by category

A window over the grouped result.

SELECT p.category, SUM(oi.qty * p.price) AS revenue,
       ROUND(100.0 * SUM(oi.qty * p.price) / SUM(SUM(oi.qty * p.price)) OVER (), 1) AS pct_of_total
FROM order_items oi JOIN orders o ON o.id = oi.order_id AND o.status = 'paid'
JOIN products p ON p.id = oi.product_id

13. Median salary

No MEDIAN in SQLite: average the one or two middle rows.

WITH r AS (SELECT salary, ROW_NUMBER() OVER (ORDER BY salary) AS rn, COUNT(*) OVER () AS n FROM employees)
SELECT AVG(salary) AS median_salary FROM r WHERE rn IN ((n + 1) / 2, (n + 2) / 2);

14. Top 2 products per category by revenue

Group first, then rank within category.

SELECT category, name, revenue FROM (
  SELECT p.category, p.name, SUM(oi.qty * p.price) AS revenue,
         ROW_NUMBER() OVER (PARTITION BY p.category ORDER BY SUM(oi.qty * p.price) DESC) AS rn
  FROM order_items oi JOIN orders o ON o.id = oi.order_id AND o.status = 'paid'
  JOIN products p ON p.id = oi.product_id GROUP BY p.id)
WHERE rn <= 2 ORDER BY category, revenue DESC;

Result

How this gets asked

How do you compute a percent of total in one query?

  • Two queries only Not required.
  • Divide a group sum by a window SUM over all groups Correct.
  • Use LIMIT No.
  • Use DISTINCT No.

SUM(SUM(x)) OVER () works over grouped output.

Self-check

How do you pivot rows to columns?

Conditional aggregation: SUM(CASE WHEN ... THEN 1 ELSE 0 END) per column.

Time and sequences

15. Cumulative revenue per customer over time

Running sum partitioned by customer, ordered by date.

SELECT c.name, o.order_date, SUM(oi.qty * p.price) AS order_total,
       SUM(SUM(oi.qty * p.price)) OVER (PARTITION BY c.id ORDER BY o.order_date) AS cumulative
FROM orders o JOIN customers c ON c.id = o.customer_id
JOIN order_items oi ON oi.order_id = o.id JOIN products p ON p.id = oi.product_id
WHERE o.status = 'paid'
GROUP BY c.id, o.id ORDER BY c.name, o.order_date;

17. Longest login streak per user

Subtract a row number from the date to label consecutive-day groups.

WITH d AS (
  SELECT user_id, day, julianday(day) - ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY day) AS grp FROM logins),
s AS (SELECT user_id, grp, COUNT(*) AS streak FROM d GROUP BY user_id, grp)

How this gets asked

How do you label consecutive-day streaks?

  • ROW_NUMBER alone Not enough.
  • Subtract a row number from the date; equal results mark a streak Correct.
  • COUNT(*) No.
  • MAX(day) No.

Self-check

What does LAG do?

Returns a value from a previous row in the window order, for comparisons and deltas.

Hierarchies and cleaning

20. Management chain with levels

A recursive CTE walks the tree from the top.

WITH RECURSIVE chain AS (
  SELECT id, name, manager_id, 0 AS level, name AS path FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.id, e.name, e.manager_id, c.level + 1, c.path || ' > ' || e.name
  FROM employees e JOIN chain c ON e.manager_id = c.id)
SELECT level, name, path FROM chain ORDER BY path;

21. Find and remove duplicates, keeping the lowest id

Show duplicates first, then delete all but the minimum id.

CREATE TABLE contact (id INTEGER PRIMARY KEY, email TEXT, name TEXT);
INSERT INTO contact VALUES (1,'a@x.com','A'),(2,'b@x.com','B'),(3,'a@x.com','A2'),(4,'a@x.com','A3'),(5,'c@x.com','C');
SELECT email, COUNT(*) AS copies FROM contact GROUP BY email HAVING COUNT(*) > 1;
DELETE FROM contact WHERE id NOT IN (SELECT MIN(id) FROM contact GROUP BY email);
SELECT id, email FROM contact ORDER BY id;

22. Find gaps in an id sequence

Compare each id with the next one.

CREATE TABLE seq (id INTEGER PRIMARY KEY);
INSERT INTO seq VALUES (1),(2),(3),(7),(8),(12);
SELECT id + 1 AS gap_starts, next_id - 1 AS gap_ends FROM (
  SELECT id, LEAD(id) OVER (ORDER BY id) AS next_id FROM seq) WHERE next_id - id > 1;

Result

How this gets asked

How do you delete duplicates but keep one row?

  • DELETE all Loses data.
  • Delete rows whose id is not the MIN(id) of its duplicate group Correct.
  • DROP TABLE No.
  • TRUNCATE No.

Always preview with a SELECT first.

Self-check

How does a recursive CTE end?

When the recursive step returns no new rows (or a condition stops it).

A checklist for these problems

  1. Write the grain of the answer in a comment first.
  2. Handle ties deliberately (ROW_NUMBER vs RANK vs DENSE_RANK).
  3. Decide whether missing groups should appear (LEFT JOIN) or not.
  4. Watch NULL semantics in NOT IN, comparisons and aggregates.
  5. Aggregate before joining to avoid fan-out.
  6. Test with an empty table, one row and duplicates.
  7. State the complexity and which index would help for large tables.
Key idea

Most interview SQL is a handful of patterns in disguise: window ranking, anti-join, conditional aggregation, self-join, running totals, gaps-and-islands and recursion. Name the pattern, define the grain, then write the query.

Interview questions: More SQL problems

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic Find the second highest salary.

Rank with DENSE_RANK() OVER (ORDER BY salary DESC) and pick rank 2, or use a subquery on MAX(salary) < MAX; LIMIT/OFFSET fails with ties.

Basic Find customers with no orders.

LEFT JOIN orders and filter orders.id IS NULL, or use NOT EXISTS.

Medium Why prefer NOT EXISTS over NOT IN?

NOT IN yields no rows if the subquery returns any NULL because of three-valued logic. NOT EXISTS is NULL-safe.

Medium Find employees who earn more than their manager.

Self-join employees e to employees m on e.manager_id = m.id and filter e.salary > m.salary.

Medium Get the top N rows per group.

Number rows with ROW_NUMBER() OVER (PARTITION BY group ORDER BY metric DESC) in a subquery and keep rn <= N; use RANK to keep ties.

Medium Pivot rows into columns.

Conditional aggregation: SUM(CASE WHEN category = 'x' THEN value END) AS x for each column, grouped by the row key.

Medium Compute percent of total.

Divide each group's sum by SUM(sum) OVER (), or by a scalar subquery of the total.

Medium Delete duplicate rows keeping one.

DELETE rows whose id is not the MIN(id) of its duplicate group, or use ROW_NUMBER() PARTITION BY the duplicate key and delete rn > 1; preview first.

Advanced Find the longest consecutive login streak.

Subtract ROW_NUMBER() per user from the date to get a group key for consecutive runs, then count rows per group and take the maximum.

Advanced Relational division: customers who bought all products in a set.

Join and group by customer, then HAVING COUNT(DISTINCT product) equals the number of products in the set.

Advanced Find gaps in a sequence of ids.

Use LEAD(id) OVER (ORDER BY id) and report where next_id - id > 1.

Advanced List the management chain for each employee.

A recursive CTE: start at employees with no manager, join children each step, tracking level and path.

Advanced Find the median.

ROW_NUMBER and COUNT windows, then AVG of the rows at positions (n + 1) / 2 and (n + 2) / 2 (integer division), or percentile_cont where available.

Advanced Compare each row with the group average without a self-join.

Use AVG(x) OVER (PARTITION BY group) beside each row.
