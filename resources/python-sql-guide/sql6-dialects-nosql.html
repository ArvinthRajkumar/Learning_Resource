SQL dialects (PostgreSQL, MySQL, SQL Server, SQLite) and when to use NoSQL

The SQL you learned is mostly portable, but real projects use a specific engine, and interviews love dialect questions. This part lists the differences that bite, shows portable alternatives that run here, and explains when a non-relational store is the better tool.

MediumAdvanced~4 hours

One standard, many dialects

SQL is standardised (ANSI/ISO), but each engine extends or deviates. The core (SELECT, joins, GROUP BY, CTEs, window functions) is portable; the edges are not. Write standard SQL first, then isolate engine-specific bits.

Pagination across dialects

Offset pagination degrades with large offsets in every engine. Prefer keyset pagination, which is portable:

-- page 2 of products ordered by id, 3 per page, using the last id seen on page 1
SELECT id, name FROM products WHERE id > 3 ORDER BY id LIMIT 3;

5Chair

NULL ordering and collation

NULLS FIRST/LAST is supported by PostgreSQL, Oracle and SQLite 3.30+, but not MySQL or SQL Server (use ORDER BY x IS NULL, x). Collation controls comparison and sorting of text (case, accents, language): define it deliberately because it affects UNIQUE constraints and LIKE.

SELECT name, city FROM customers ORDER BY city IS NULL, city, name;

How this gets asked

Which clause limits rows in SQL Server?

  • LIMIT Not in T-SQL.
  • TOP (or OFFSET ... FETCH) Correct.
  • ROWNUM Oracle.
  • FIRST No.

T-SQL uses TOP n.

In MySQL default settings, what is 7 / 2?

  • 3 That is PostgreSQL.
  • 3.5 Correct; use DIV for integer division.
  • 4 No.
  • Error No.

Dialects differ on integer division.

Why is keyset pagination preferred over large OFFSETs?

  • It is shorter No.
  • The database can seek using an index instead of scanning and discarding skipped rows Correct.
  • It needs no ORDER BY It needs one.
  • It works only in MySQL No.

Cost stays flat for deep pages.

Self-check

Which dialect clause returns generated rows after an insert?

RETURNING in PostgreSQL and SQLite; OUTPUT in SQL Server; MySQL has no direct equivalent.

How do you upsert in MySQL?

INSERT ... ON DUPLICATE KEY UPDATE.

PostgreSQL features worth knowing

These are shown as text because the sandbox here runs SQLite.

-- JSONB with an index
CREATE TABLE doc (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, data jsonb NOT NULL);
CREATE INDEX doc_gin ON doc USING gin (data);
SELECT * FROM doc WHERE data @> '{"type": "invoice"}';

-- Array and unnest
SELECT unnest(ARRAY[1,2,3]);

-- DISTINCT ON: first row per group
SELECT DISTINCT ON (customer_id) customer_id, order_date, total
FROM orders ORDER BY customer_id, order_date DESC;

-- FILTER and percentile_cont
SELECT count(*) FILTER (WHERE status = 'paid') AS paid,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY total) AS median
FROM orders;

-- Prevent double booking with an exclusion constraint
CREATE EXTENSION btree_gist;
ALTER TABLE booking ADD EXCLUDE USING gist (room WITH =, during WITH &&);

-- Partial and expression indexes
CREATE INDEX ON orders (customer_id) WHERE status = 'open';
CREATE INDEX ON users (lower(email));

-- LATERAL join: top 3 per group
SELECT c.id, o.* FROM customers c
CROSS JOIN LATERAL (SELECT * FROM orders WHERE customer_id = c.id ORDER BY order_date DESC LIMIT 3) o;

The SQLite equivalents you can run: FILTER is supported, and "first row per group" uses a window function.

How this gets asked

What does DISTINCT ON do in PostgreSQL?

  • Removes all duplicates That is DISTINCT.
  • Keeps the first row for each distinct key according to ORDER BY Correct.
  • Creates an index No.
  • Sorts descending No.

A convenient top-1-per-group.

Self-check

What is an exclusion constraint for?

Preventing overlapping ranges, such as double-booked rooms, inside the database.

MySQL and SQL Server notes

  • MySQL: storage engine matters (InnoDB for transactions, row locks, foreign keys); sql_mode controls strictness (always use STRICT_TRANS_TABLES so invalid data errors instead of truncating); utf8mb4 is real UTF-8; ON DUPLICATE KEY UPDATE for upserts; GROUP BY quirks (ONLY_FULL_GROUP_BY); replication is binlog based. Window functions and CTEs arrived in 8.0.
  • SQL Server: T-SQL with @variables, BEGIN ... END, TRY ... CATCH, TOP, MERGE, OUTPUT, temp tables #t, ROW_NUMBER windows, clustered versus nonclustered indexes, snapshot isolation option.
  • Oracle: ROWNUM/FETCH FIRST, DUAL, NVL, '' is NULL, sequences, PL/SQL packages.
  • Warehouses (BigQuery, Snowflake): nested/semi-structured types, QUALIFY to filter window results, no row-level indexes, partition and cluster keys instead, cost proportional to data scanned.
-- QUALIFY (Snowflake/BigQuery) simulated with a subquery: the most expensive product per category
SELECT category, name, price FROM (
  SELECT category, name, price, RANK() OVER (PARTITION BY category ORDER BY price DESC) AS r FROM products)
WHERE r = 1 ORDER BY category;

Portable SQL habits

  1. Use explicit JOIN ... ON, never comma joins.
  2. Use COALESCE and CASE (standard) instead of IFNULL, ISNULL, NVL.
  3. Use CAST(x AS type) rather than shortcuts like x::int.
  4. Avoid vendor functions in the core of your queries, or wrap them in views or a small data-access layer.
  5. Quote nothing unless forced; use lowercase snake_case names.
  6. Use standard date literals (DATE '2024-01-31') where supported.
  7. Test against the production engine; a green SQLite test suite does not prove PostgreSQL behaviour (type strictness, locking, collation).

NoSQL is a family of stores that relax some relational features to gain scale, flexibility or speed for a specific access pattern.

Modelling the same data both ways

Relational: normalise and join. Document: embed what you read together, reference what grows without bound or is shared.

import json, sqlite3
# Relational: three tables joined at read time
db = sqlite3.connect(":memory:")
db.executescript("""
CREATE TABLE orders(id INTEGER PRIMARY KEY, customer TEXT);
CREATE TABLE lines(order_id INT, sku TEXT, qty INT, price REAL);
INSERT INTO orders VALUES (1, 'ana');
INSERT INTO lines VALUES (1, 'pen', 3, 2.0), (1, 'book', 1, 15.0);""")
rel = db.execute("SELECT o.id, o.customer, SUM(l.qty * l.price) FROM orders o JOIN lines l ON l.order_id = o.id GROUP BY o.id").fetchone()
# Document: the order is one self-contained document, read in a single lookup
doc = {"_id": 1, "customer": "ana", "lines": [{"sku": "pen", "qty": 3, "price": 2.0}, {"sku": "book", "qty": 1, "price": 15.0}]}
total = sum(l["qty"] * l["price"] for l in doc["lines"])
print("relational result:", rel)
print("document total   :", (doc["_id"], doc["customer"], total))
print("document as stored:", json.dumps(doc))

Output

relational result: (1, 'ana', 21.0)
document total   : (1, 'ana', 21.0)
document as stored: {"_id": 1, "customer": "ana", "lines": [{"sku": "pen", "qty": 3, "price": 2.0}, {"sku": "book", "qty": 1, "price": 15.0}]}

Trade-off: the document is one read and fits an aggregate, but "total quantity of pens sold across all orders" now scans documents (or needs an index on an array field), and shared data (product names) is duplicated and can go stale.

Choosing {choose}

Caching and low-latency countersRedis

Full-text relevanceSearch engine

Most systems end up polyglot: a relational system of record, Redis for caching, a search engine for text, a warehouse for analytics, kept in sync through events or change data capture. Start with PostgreSQL unless a requirement clearly points elsewhere; it covers JSON, search, queues and geospatial well enough for a long time.

CAP and consistency, briefly

Under a network partition a distributed store must choose consistency or availability. Many NoSQL stores (Cassandra, DynamoDB) default to eventual consistency with tunable quorums; many relational clusters favour consistency. Details in the System Design guide (consistency).

Key idea

Learn the standard core, know the dialect differences that matter for your engine, and choose a data store from the access pattern, consistency need and scale. PostgreSQL is a strong default; add specialised stores when a measured need appears.

Interview questions: SQL dialects and NoSQL

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic How do you limit rows in MySQL, PostgreSQL, SQL Server and Oracle?

LIMIT n in MySQL, PostgreSQL and SQLite; TOP n or OFFSET FETCH in SQL Server; FETCH FIRST n ROWS ONLY (or ROWNUM) in Oracle.

Basic What is an upsert and how is it written in different engines?

Insert or update on conflict: ON CONFLICT DO UPDATE in PostgreSQL and SQLite, ON DUPLICATE KEY UPDATE in MySQL, MERGE in SQL Server and Oracle.

Medium Name PostgreSQL features not in standard SQL that you find useful.

JSONB with GIN indexes, arrays, DISTINCT ON, range types and exclusion constraints, partial and expression indexes, LATERAL joins, extensions such as PostGIS.

Medium Why does 7/2 differ between engines?

Some engines do integer division for integer operands (PostgreSQL, SQL Server, SQLite give 3) while MySQL gives 3.5 and uses DIV for integers. Cast explicitly.

Medium How does collation affect queries?

It defines text comparison and sort order (case, accents, language), affecting ORDER BY, LIKE, UNIQUE and joins. Choose it deliberately and consistently.

Medium Why is OFFSET pagination a problem and what replaces it?

Large offsets scan and discard rows. Keyset pagination uses WHERE (key) > last_seen ORDER BY key LIMIT n with an index for constant-cost pages.

Medium When would you choose a document database?

For varied, nested records read and written as a unit, with a flexible schema and few cross-document joins.

Medium When would you choose a key-value store?

For simple lookups by key at very high throughput and low latency: sessions, caches, counters, feature flags.

Medium What is a wide-column store good at?

Huge write volumes and time-series-like data with known query patterns, partitioned by key, as in Cassandra and Bigtable.

Advanced Relational versus document modelling: embed or reference?

Embed data read together and owned by the parent; reference data that is shared, large or unbounded. Embedding speeds reads and complicates updates of duplicated data.

Advanced What is polyglot persistence?

Using several specialised stores, such as a relational database, a cache, a search engine and a warehouse, kept consistent through events or change data capture.

Advanced How does MySQL's sql_mode matter?

Strict modes make invalid data raise errors instead of being silently truncated or coerced; ONLY_FULL_GROUP_BY rejects ambiguous aggregates.

Advanced What is QUALIFY?

A clause in warehouses such as Snowflake and BigQuery that filters on window function results without a subquery.

Advanced Does eventual consistency mean data may be lost?

No. It means replicas may temporarily disagree and converge later; conflicts need a resolution rule, and durability is a separate property.
