Classes, dataclasses, typing and modules

Object-oriented programming bundles data with the behaviour that works on it. Python's object model is simple and very flexible. This part covers it fully, plus type hints and how code is organised into modules and packages.

Medium~4 hours

Classes and objects

Intuition

A class is a blueprint; an object (instance) is something built from it. A bank account has data (owner, balance) and actions (deposit, withdraw). A class keeps both together.

class Account:
    bank = "PyBank"                       # class attribute, shared by all instances

    def __init__(self, owner, balance=0): # initialiser, runs on creation
        self.owner = owner                # instance attributes
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("amount must be positive")
        self.balance += amount
        return self.balance

    def __repr__(self):
        return f"Account({self.owner!r}, {self.balance})"

a = Account("Ada", 100)
a.deposit(50)
print(a, a.bank, Account.bank, a.balance)
b = Account("Ben")
print(b, a is b)

Output

Account('Ada', 150) PyBank PyBank 150
Account('Ben', 0) False

self is the instance the method is called on. a.deposit(50) is shorthand for Account.deposit(a, 50).

Instance, class and static methods

class Temp:
    unit = "C"
    def __init__(self, deg): self.deg = deg
    def to_f(self):                       # needs the instance
        return self.deg * 9 / 5 + 32
    @classmethod
    def from_f(cls, f):                   # alternative constructor; gets the class
        return cls((f - 32) * 5 / 9)
    @staticmethod
    def is_valid(deg):                    # no self or cls; just grouped here
        return deg >= -273.15

t = Temp.from_f(212)
print(t.deg, t.to_f(), Temp.is_valid(-300))

Output

100.0 212.0 False

Properties: controlled attributes

class Circle:
    def __init__(self, r): self._r = r
    @property
    def radius(self): return self._r
    @radius.setter
    def radius(self, v):
        if v < 0: raise ValueError("radius must be non-negative")
        self._r = v
    @property
    def area(self): return 3.14159 * self._r ** 2     # computed on access

c = Circle(2)
c.radius = 3
print(c.radius, round(c.area, 2))
try:
    c.radius = -1
except ValueError as e:
    print("error:", e)

Output

3 28.27
error: radius must be non-negative

Python has no private keyword. A leading underscore (_r) means "internal, please do not touch". A double underscore (__x) triggers name mangling to avoid accidental clashes in subclasses.

How this gets asked

What is self?

  • The class itself That is cls in a classmethod.
  • The instance the method was called on Correct.
  • A keyword It is only a convention.
  • The parent class No.

Methods receive the instance as their first argument; by convention it is named self.

A method decorated with @ receives the class as its first argument.

classmethod is used for alternative constructors.

Self-check

Instance, class and static methods?

Instance methods get self, classmethods get cls, staticmethods get neither.

Special (dunder) methods

Making objects behave like built-ins

Methods with double underscores let your class plug into Python syntax.

class Vector:
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self): return f"Vector({self.x}, {self.y})"
    def __add__(self, o): return Vector(self.x + o.x, self.y + o.y)
    def __mul__(self, k): return Vector(self.x * k, self.y * k)
    def __eq__(self, o): return isinstance(o, Vector) and (self.x, self.y) == (o.x, o.y)
    def __hash__(self): return hash((self.x, self.y))
    def __len__(self): return 2
    def __iter__(self): yield self.x; yield self.y
    def __bool__(self): return bool(self.x or self.y)
    def __getitem__(self, i): return (self.x, self.y)[i]

v = Vector(1, 2) + Vector(3, 4)
print(v, v * 2, v == Vector(4, 6), len(v), list(v), v[0], bool(Vector(0, 0)))
print({v: "ok"}[Vector(4, 6)])

Output

Vector(4, 6) Vector(8, 12) True 2 [4, 6] 4 False
ok

How this gets asked

You define __eq__ on a class and want its instances usable as dict keys. What else must you define?

  • __len__ No.
  • __hash__ Correct.
  • __iter__ No.
  • Nothing Defining __eq__ alone sets __hash__ to None.

Equal objects must have equal hashes.

Self-check

Name five dunder methods and their uses.

__init__ (create), __repr__ (debug text), __eq__ (equality), __iter__ (loops), __enter__/__exit__ (with).

Inheritance and composition

Inheritance and super

class Animal:
    def __init__(self, name): self.name = name
    def speak(self): return "..."
    def intro(self): return f"{self.name} says {self.speak()}"

class Dog(Animal):
    def speak(self): return "Woof"

class Puppy(Dog):
    def __init__(self, name, age):
        super().__init__(name)            # call the parent initialiser
        self.age = age
    def speak(self): return super().speak() + "!"

for pet in (Animal("Generic"), Dog("Rex"), Puppy("Bit", 1)):
    print(pet.intro())
print(isinstance(Puppy("a", 1), Animal), issubclass(Puppy, Dog))

Output

Generic says ...
Rex says Woof
Bit says Woof!
True True

This is polymorphism: intro works for any Animal and calls the right speak.

Multiple inheritance and the MRO

A class can have several parents. Python resolves which method to use by the method resolution order (MRO), computed with the C3 linearisation: children before parents, parents in the listed order.

class A:
    def who(self): return "A"
class B(A):
    def who(self): return "B>" + super().who()
class C(A):
    def who(self): return "C>" + super().who()
class D(B, C):
    pass
print(D().who())
print([k.__name__ for k in D.__mro__])

Output

B>C>A
['D', 'B', 'C', 'A', 'object']

super() follows the MRO, not only the direct parent. Prefer composition (an object that has other objects) and mixins (small classes adding one capability) to deep hierarchies.

Abstract base classes

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

class Square(Shape):
    def __init__(self, s): self.s = s
    def area(self): return self.s ** 2

try:
    Shape()
except TypeError:
    print("cannot instantiate an abstract class")
print(Square(3).area())

Output

cannot instantiate an abstract class

Duck typing and protocols

Python cares about behaviour, not declared type: "if it walks like a duck and quacks like a duck". Any object with the needed methods works. typing.Protocol lets you describe such an interface for type checkers.

How this gets asked

What does super() follow in multiple inheritance?

  • Only the first parent No.
  • The method resolution order (MRO) Correct.
  • Alphabetical order No.
  • Random order No.

super() proceeds to the next class in the MRO of the instance's type.

Self-check

Composition versus inheritance?

Composition (has-a) is more flexible and less coupled; inheritance (is-a) should model genuine specialisation.

Dataclasses and enums

Dataclasses

@dataclass generates __init__, __repr__ and __eq__ from annotated fields.

from dataclasses import dataclass, field, replace

@dataclass(order=True, frozen=True)
class Item:
    name: str
    price: float
    tags: tuple = ()

@dataclass
class Cart:
    items: list = field(default_factory=list)    # never use [] directly
    def total(self): return sum(i.price for i in self.items)

a, b = Item("pen", 2.5), Item("book", 12.0, ("paper",))
cart = Cart([a, b])
print(a, cart.total(), a < b, replace(a, price=3))

Output

Item(name='pen', price=2.5, tags=()) 14.5 False Item(name='pen', price=3, tags=())

frozen=True makes instances immutable and hashable; order=True adds comparisons; slots=True saves memory.

Enums

from enum import Enum, auto

class Status(Enum):
    PENDING = auto()
    PAID = auto()
    SHIPPED = auto()

s = Status.PAID
print(s, s.name, s.value, Status["SHIPPED"], [m.name for m in Status])
print(s is Status.PAID, s == Status.PENDING)

Output

Status.PAID PAID 2 Status.SHIPPED ['PENDING', 'PAID', 'SHIPPED']
True False

Enums give named constants that cannot be confused with plain numbers or strings.

How this gets asked

Why does field(default_factory=list) exist?

  • It is faster Not the reason.
  • A literal [] default would be shared by all instances Correct.
  • It freezes the list No.
  • It sorts the list No.

Mutable defaults are shared, so a factory creates a fresh one each time.

Self-check

What does @dataclass generate?

__init__, __repr__ and __eq__ (and optionally ordering, hashing and slots) from annotated fields.

Type hints

What they are

Type hints annotate expected types. Python does not enforce them at runtime. Tools such as mypy and pyright and editors check them, catching bugs early and documenting intent.

from typing import Optional, Callable, Iterable, TypeVar, Protocol

T = TypeVar("T")

def first(items: Iterable[T]) -> Optional[T]:
    for x in items:
        return x
    return None

def apply(fn: Callable[[int], int], xs: list[int]) -> list[int]:
    return [fn(x) for x in xs]

class Drawable(Protocol):
    def draw(self) -> str: ...

class Box:
    def draw(self) -> str: return "[]"

def render(d: Drawable) -> str: return d.draw()

print(first([]), first("abc"), apply(lambda n: n + 1, [1, 2]), render(Box()))

Output

None a [2, 3] []

Common forms (Python 3.10+): int | None, list[str], dict[str, int], tuple[int, ...], Callable[[int], str], Literal["a", "b"], TypedDict, generics with TypeVar. Add hints to public functions first, run a checker in CI.

How this gets asked

Does Python enforce type hints at runtime?

  • Yes, always No.
  • No, they are for tools and readers (unless a library like pydantic checks them) Correct.
  • Only for ints No.
  • Only in functions No.

Hints are annotations; checkers like mypy verify them separately.

Modules, packages and imports

Modules

A module is a .py file. import runs it once, caches it in sys.modules, and gives you its names.

import math
import json as j
from collections import Counter
from os.path import join, basename as bn
print(math.sqrt(16), j.dumps([1]), Counter("aab"), bn(join("a", "b.txt")))
import sys
print("math" in sys.modules, type(math).__name__)

Output

4.0 [1] Counter({'a': 2, 'b': 1}) b.txt
True module

Packages

A package is a directory of modules (with __init__.py, or a namespace package without it).

shop/
  __init__.py          # makes it a package; can re-export names
  models.py
  services/
    __init__.py
    billing.py         # from shop.services.billing import charge

Inside a package prefer absolute imports (from shop.models import Order) and use relative imports (from .models import Order) sparingly. Avoid circular imports by moving shared code to a third module or importing inside a function.

The __main__ guard

def main():
    print("running as a script")

if __name__ == "__main__":     # true only when run directly, not when imported
    main()

Output

running as a script

Where Python looks for modules

sys.path: the script's directory, then PYTHONPATH, the standard library and site-packages (installed packages). Use a virtual environment per project (PY5).

How this gets asked

Which are true about if __name__ == '__main__':? Select all.

  • The block runs when the file is executed as a script
  • The block runs when the file is imported
  • It lets a file be both importable and runnable
  • It is required in every file

On import, __name__ is the module's name, not '__main__'.

Self-check

What is the difference between a module and a package?

A module is a single .py file; a package is a directory of modules.

Interview questions: Python OOP

10 questions. Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What is self?

The instance the method is called on, passed automatically as the first argument.

Basic Class attribute versus instance attribute?

Class attributes are shared by all instances; instance attributes belong to one object. Assigning through an instance creates an instance attribute that shadows the class one.

Medium Explain @staticmethod, @classmethod and instance methods.

Instance methods receive self, classmethods receive the class (alternative constructors), staticmethods receive neither and are just namespaced functions.

Medium What are dunder methods? Give examples.

Special methods that integrate classes with the language: __init__, __repr__, __eq__, __hash__, __len__, __iter__, __enter__ and __exit__, __call__.

Medium What does @dataclass give you?

Generated __init__, __repr__ and __eq__ from annotated fields, plus options for ordering, immutability (frozen) and slots. Use field(default_factory=...) for mutable defaults.

Medium What is duck typing?

Behaviour matters, not declared type: an object works if it has the needed methods. Protocols describe such interfaces for type checkers.

Advanced Explain the method resolution order and super().

The MRO is the C3 linearisation: children before parents, parents in the declared order. super() delegates to the next class in the instance's MRO, which makes cooperative multiple inheritance work.

Advanced Composition or inheritance?

Prefer composition (has-a) for flexibility and loose coupling. Use inheritance for genuine is-a relationships and shared behaviour, and keep hierarchies shallow, using mixins sparingly.

Advanced Do type hints enforce types?

No. They are annotations checked by tools such as mypy and pyright, and used by libraries like pydantic or dataclasses, but the interpreter does not enforce them.

Advanced What does __hash__ need when you define __eq__?

Equal objects must have equal hashes. Defining __eq__ alone sets __hash__ to None, making the class unhashable; define both for set and dict use, based on immutable fields.
