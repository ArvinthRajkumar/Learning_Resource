What gives an exactly-once effect for a side-effecting API call over an unreliable network?

  • At-most-once delivery May lose the call.
  • At-least-once delivery (retries) plus idempotent processing keyed by an idempotency key Correct: duplicates are absorbed by the server.
  • A longer timeout The outcome is still ambiguous on timeout.
  • Exactly-once delivery from TCP TCP does not give application-level exactly-once across retries and crashes.

Exactly-once is achieved as an effect, not as delivery.

Which errors are generally safe to retry with backoff (assuming idempotency keys for writes)? Select all.

  • 503 Service Unavailable Transient.

For beamSearch's tie rule (higher score first, then the lexicographically smaller sequence), which sort key does it in one step?

  • sorted(c, key=lambda x: x[0], reverse=True) on (score, seq) Leaves ties in insertion order.
  • sorted((score, seq), reverse=True) Also reverses the sequence tie-break, so the larger sequence wins ties.
  • max over score only Ignores ties.
  • sorted((-score, seq)) ascending Correct: higher score first, then the smaller sequence.

Negate the score and sort ascending. Lists compare lexicographically.
