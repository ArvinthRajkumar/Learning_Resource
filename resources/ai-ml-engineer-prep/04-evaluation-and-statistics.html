Part 04

Evaluation and statistics

"Prompt B scored 81%, prompt A 78%, ship B?" is a statistics question in disguise. This page teaches the paired test that answers it, by hand, and the tools around it: intervals, bootstrap, power and judge bias.

One question, many disguises~2 hours

Basics first: classic metrics for text and LLMs

Intuition

Before LLM judges, text outputs were scored by overlap with reference answers. These metrics are cheap and reproducible, but they measure surface similarity. A correct answer phrased differently can score low, and a fluent wrong answer can score high. Know what each one measures and where it breaks.

MetricMeasuresGood forWeakness
Exact match (EM)normalized string equalityshort answers, classification, math final answersharsh on paraphrases
Token F1 (SQuAD style)word overlap precision and recallextractive QAignores meaning and word order
BLEUn-gram precision with a brevity penaltymachine translationweak correlation for open-ended text
ROUGE-1/2/Lunigram, bigram and longest-common-subsequence overlap (recall-oriented)summarizationrewards copying, misses paraphrase
BERTScoreembedding similarity of tokensparaphrase-tolerant overlapstill reference-bound, can miss factual errors
Perplexityhow well a model predicts held-out textcomparing language models on the same tokenizernot a measure of answer quality. Not comparable across tokenizers.
LLM judge / human ratingrubric-based qualityopen-ended outputscost, bias, needs validation (see below)
Two quick computations
  1. ROUGE-1: reference "the cat sat on the mat", candidate "the cat is on the mat". Clipped unigram overlap: the x 2, cat, on, mat = 5. Recall 5/6 = 0.8333, precision 5/6 = 0.8333.
  2. Token F1: prediction "Paris France", gold "Paris". Overlap 1. Precision 1/2, recall 1/1, F1 = 2(0.5)(1)/(1.5) = 0.6667. EM = 0.

How this gets asked

Why are BLEU and ROUGE weak for evaluating a chatbot's free-form answers?

  • They are too slow They are fast.
  • They measure n-gram overlap with references, so valid paraphrases score low and fluent wrong answers can score well Correct.
  • They require GPUs No.
  • They only work in English Not the main issue.

Use task-specific checks, validated LLM judges or human ratings for open-ended outputs.

Self-check

BLEU vs ROUGE orientation?

BLEU is precision-oriented (with a brevity penalty). ROUGE is recall-oriented.

Token F1 of "Paris France" vs gold "Paris"?

0.6667 (precision 0.5, recall 1).

Why is perplexity not comparable across models with different tokenizers?

It is per token, and tokens differ in size, so the same text has different token counts.

Paired comparison: McNemar and the exact sign test

Intuition

Both prompts answered the same 200 questions. On most questions they agree: both right or both wrong. Those questions say nothing about which prompt is better, just as a tied game says nothing about which team is stronger. Only the questions where they disagree carry information. If the prompts were equally good, each disagreement would be a coin flip: B-wins or A-wins with probability 1/2 each.

So the question becomes: is 18 heads out of 30 coin flips surprising? Not very. That happens more than a third of the time with a fair coin, counting both directions.

The mechanism: the 2x2 table

B rightB wrongTotal
A right144 (both)12 (c: A wins)156
A wrong18 (b: B wins)26 (both)44
Total16238200
 Reconstructed from the question: 156 and 162 correct, 30 disagreements, B right on 18 of them. Both right = 156 - 12 = 144, both wrong = 200 - 144 - 18 - 12 = 26.

Accuracy difference = (162 - 156)/200 = (b - c)/200 = 6/200 = 3 points. The concordant cells (144 and 26) cancel out of the difference entirely. That is the algebraic reason only discordant pairs matter.

The formulas

Exact sign test (binomial test on discordant pairs)
n = b + c, X ~ Binomial(n, 1/2) under H0 p_two_sided = 2 * P(X >= max(b, c)) = 2 * sum_{k=max(b,c)}^{n} C(n, k) / 2^n (capped at 1)
b
questions only B got right
c
questions only A got right
H0
both prompts have the same accuracy, so each disagreement is a fair coin
McNemar's test (chi-square approximation of the same idea)
chi2 = (b - c)^2 / (b + c) 1 degree of freedom chi2_cc = (|b - c| - 1)^2 / (b + c) with continuity correction

Worked example: the assessment question, by hand

b = 18 (B only), c = 12 (A only), n = 30
  1. Under H0, X = number of B wins ~ Binomial(30, 0.5). Observed X = 18.
  2. Upper tail: P(X >= 18) = sum over k = 18..30 of C(30,k) / 2^30 = 194,129,627 / 1,073,741,824 = 0.180797.
  3. Two-sided (the difference could have gone either way): p = 2 x 0.180797 = 0.3616.
  4. McNemar without correction: (18 - 12)^2 / 30 = 36/30 = 1.2, chi-square(1) gives p = 0.2733. With continuity correction: (6 - 1)^2 / 30 = 0.833, p = 0.3613 (close to the exact test, which is the point of the correction).
  5. Every version gives p much larger than 0.05.
Not statistically significant (exact two-sided p = 0.36) 
from math import comb, erfc, sqrt
n, b = 30, 18
p = 2 * sum(comb(n, k) for k in range(b, n + 1)) / 2**n
print(round(p, 4))                     # 0.3616  exact sign test
chi2 = (18 - 12)**2 / 30               # 1.2
print(round(erfc(sqrt(chi2 / 2)), 4))  # 0.2733  McNemar (no correction)
# scipy, if installed: scipy.stats.binomtest(18, 30, 0.5).pvalue -> 0.3616

How lopsided would it need to be?

With 30 disagreements, the smallest B-win count with two-sided p < 0.05 is 21 (p = 0.0428). 20 of 30 gives p = 0.0987. If B truly won 60% of disagreements, a 30-disagreement test would detect it only 17.7% of the time (its power). See the power section for how many questions you would need.

The wrong test: unpaired two-proportion z-test

Treating the results as two independent samples of 200 ignores that the same questions were used:

  • Pooled p = 318/400 = 0.795. SE = sqrt(0.795 x 0.205 x (1/200 + 1/200)) = 0.0404. z = 0.03/0.0404 = 0.743, p = 0.457.
  • Here it happens to reach the same verdict, but the reasoning is wrong. It treats question difficulty as noise. Paired tests remove that noise (both prompts saw the same hard questions), so they are usually more powerful. Many real comparisons are significant under McNemar but not under the unpaired test.
  • The paired normal approximation is z = (b - c)/sqrt(b + c) = 6/sqrt(30) = 1.095. Its square is McNemar's 1.2.

Options partly seen

"Not significant" does not mean "no difference". It means this data cannot distinguish them. The right next step is more eval questions, or a decision on other grounds (cost, latency).

Common traps

  • Using all 200 questions as the sample size in a paired test. Only n = b + c = 30 matters.
  • Using a one-sided p (0.18) when the question is "is there a difference".
  • Unpaired z-test or chi-square on the two accuracies when the items are shared.
  • Concluding "B is better, it is 3 points higher" from point estimates alone.

  • They cannot be compared Paired data is ideal for comparison.
  • B is significantly better p = 0.36, which is not significant.
  • The difference is not statistically significant (p about 0.36) Exact sign test on 18 vs 12.

Self-check

Why do concordant pairs carry no information about which prompt is better?

They contribute equally to both accuracies and cancel in the difference: diff = (b - c)/N.

Exact sign test formula?

p = 2 x sum over k from max(b,c) to n of C(n,k)/2^n, with n = b + c.

McNemar statistic with and without continuity correction?

(b - c)^2/(b + c), and (|b - c| - 1)^2/(b + c).

Confidence intervals: Wilson and bootstrap

Intuition

An accuracy of 81% on 200 questions is an estimate. The true accuracy on all possible questions could plausibly be anywhere from about 75% to 86%. Reporting that range stops people from celebrating noise.

Formulas

Standard error, Wald and Wilson intervals for a proportion
SE = sqrt( p(1 - p) / n ) Wald: p +/- z * SE (bad near 0 or 1, and for small n) Wilson: ( p + z^2/(2n) +/- z * sqrt( p(1-p)/n + z^2/(4n^2) ) ) / (1 + z^2/n)
p
observed proportion (k/n)
n
number of items
z
1.96 for 95%
Prompt B: 162/200
  1. SE at p = 0.8, n = 200: sqrt(0.16/200) = 0.0283, so a 95% half-width of about 5.5 points.
  2. Wald for 0.81: 0.7556 to 0.8644.
  3. Wilson for 162/200: 0.7500 to 0.8583. For 156/200: 0.7176 to 0.8318. The intervals overlap heavily.
  4. At 10/10, Wald gives the useless interval [1, 1]. Wilson gives 0.7225 to 1.
B: 81% (95% Wilson CI 75.0% to 85.8%)

Overlapping individual intervals do not by themselves prove "no difference", and non-overlapping is a conservative test. For paired data, compute an interval for the difference directly.

Bootstrap

Resample the 200 questions with replacement many times, recompute the metric each time, and take the 2.5th and 97.5th percentiles. For a paired comparison, resample question indices and keep each question's (A, B) outcome together. That preserves the pairing.

Paired bootstrap of B - A (10,000 resamples, seed 0)
  1. Build 200 pairs: 144 (1,1), 18 (0,1), 12 (1,0), 26 (0,0).
  2. Each resample: draw 200 pairs with replacement and compute mean(B - A).
  3. Percentile interval: -0.025 to 0.085. It contains 0, which agrees with the sign test.
95% CI for the difference: about -2.5 to +8.5 points 
import random
pairs = [(1,1)]*144 + [(0,1)]*18 + [(1,0)]*12 + [(0,0)]*26
rng, diffs = random.Random(0), []
for _ in range(10_000):
    s = [pairs[rng.randrange(200)] for _ in range(200)]
    diffs.append(sum(b - a for a, b in s) / 200)
diffs.sort()
print(diffs[249], diffs[9749])   # about -0.025 0.085 (exact values depend on the seed)

Bootstrap works for any metric (nDCG, F1, judge scores) without a formula. It is weak with very small n and for extreme statistics such as the max.

How this gets asked

Why prefer the Wilson interval over p +/- 1.96 SE for an accuracy of 98% on 50 items?

  • Wilson is always narrower Not always. It is better calibrated, not necessarily narrower.
  • Wald needs paired data Unrelated.
  • Wald coverage is poor near 0 or 1 and can exceed [0, 1]; Wilson stays inside and has better coverage Correct.
  • Wilson does not depend on n It does.

Near the boundaries, the normal approximation behind Wald breaks down.

Self-check

SE of an accuracy p on n items?

sqrt(p(1 - p)/n).

How do you bootstrap a paired comparison?

Resample item indices with replacement, keeping both systems' outcomes for each item together.

95% half-width for 80% accuracy on 200 items?

About 5.5 points.

Power, sample size and multiple comparisons

Intuition

Power is the chance your test detects a real difference of a given size. Small eval sets have low power, so real improvements look like "not significant". Before running an eval, decide what difference matters and size the set to detect it.

Multiple comparisons

Test 20 prompt variants against a baseline at alpha = 0.05, with none truly better: P(at least one "significant") = 1 - 0.95^20 = 0.64. Fixes: Bonferroni (use alpha/m, here 0.0025), Holm (step-down, less conservative), Benjamini-Hochberg (controls the false discovery rate). Or hold out a fresh test set and confirm the winner there.

How this gets asked

You test 20 independent prompt variants at alpha = 0.05 and none is truly better. Probability of at least one false positive? (2 decimals)

1 - 0.95^20 = 0.6415.

Self-check

Define statistical power.

The probability of rejecting H0 when a specified real effect exists (1 - beta).

Bonferroni threshold for 10 tests at 0.05?

0.005.

Why does pairing reduce the required sample size?

It removes variance from item difficulty. Only discordant items add noise.

LLM-as-judge and its biases

Intuition

An LLM judge is a fast, cheap, slightly biased annotator. Treat it like a new human rater: measure how often it agrees with humans, look for systematic biases, and design the protocol to cancel them.

BiasWhat happensMitigation
Position biasPrefers the first (or second) answer in pairwise comparisonsRun both orders. Count a win only if consistent, otherwise a tie.
Verbosity biasPrefers longer answersRubric that penalizes padding, length-controlled comparisons, a "concise" criterion
Self-preferenceRates its own model family's outputs higherJudge from a different family, or several judges
Style over substanceConfident tone and formatting winReference answers, criteria-specific scores, checks for factual claims
Score compressionEverything gets 7 to 8 out of 10Pairwise or binary pass/fail per criterion instead of 1 to 10 scales

Validate the judge: label 100 to 200 items by hand, then compute agreement (accuracy, Cohen's kappa) between the judge and humans before trusting it at scale. Re-validate when you change the judge model or prompt.

How this gets asked

A pairwise LLM judge picks the first-listed answer 70% of the time. Best fix?

  • Evaluate each pair in both orders and count only consistent wins This cancels position bias.
  • Raise the judge's temperature Adds noise without removing bias.
  • Always put the baseline second That systematically favors the baseline.
  • Ask for longer justifications Does not address order.

Swap augmentation is the standard fix for position bias.

Self-check

Three LLM-judge biases?

Position, verbosity, self-preference.

How do you validate a judge?

Compare with human labels on a sample and measure agreement (for example kappa).

Why prefer pass/fail per criterion over 1 to 10 scores?

Better consistency and less score compression. Easier to calibrate.

Golden sets, regression suites, contamination, online eval

  • Golden set: a curated, versioned set of inputs with expected outputs or rubrics, covering common cases, edge cases and known past failures. Keep it out of any training data.
  • Regression suite: run the golden set on every prompt, model or retrieval change in CI. Track metrics over time and block merges on significant regressions (using the paired tests above).
  • Contamination: test items leaked into training data (public benchmarks scraped into pretraining, or your eval set copied into a fine-tuning set). Symptoms: suspiciously high scores, verbatim completions. Defenses: private held-out sets, near-duplicate checks between train and test, fresh items.
  • Offline vs online: offline evals (fixed datasets) are fast and repeatable. Online evals (production traffic) measure real outcomes: user ratings, task completion, escalations. Offline gates releases, online confirms them.
  • A/B testing: randomize users (not requests, if experiences should stay consistent) into control and treatment. Pick one primary metric and its sample size in advance. Do not stop early when the p-value dips below 0.05 ("peeking" inflates false positives) unless you use a sequential testing method. Watch guardrail metrics (latency, cost, safety).
  • Component evals for RAG and agents: retrieval recall, faithfulness, tool-call accuracy, end-to-end task success. Each failure should map to a component.

How this gets asked

Which practices reduce the risk of fooling yourself with evals? Select all.

  • Deduplicate fine-tuning data against the eval set Prevents contamination.
  • Stop an A/B test as soon as p < 0.05 Peeking inflates false positives.
  • Use paired tests when both systems answer the same items Correct analysis and more power.
  • Tune prompts on the test set until it improves That overfits the test set. Use a dev set.

Separate dev and test sets, deduplicate, analyze correctly, and fix the stopping rules in advance.

Self-check

What is eval contamination?

Eval items (or near copies) present in training data, which inflates scores.

Why is peeking at an A/B test a problem?

Repeated significance checks raise the false-positive rate well above alpha.

Offline vs online evaluation in one line?

Offline: fixed datasets, repeatable, gates releases. Online: real traffic outcomes, confirms impact.

Interview questions: evaluation

Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What is a golden set?

A curated, versioned set of representative inputs with expected outputs or rubrics, used to evaluate and regression-test a system.

Basic What is an LLM-as-judge?

Using an LLM to grade outputs against a rubric or compare two outputs. It is fast and cheap, but must be validated against human labels and checked for biases.

Basic Name classic text-generation metrics and their limitations.

Exact match, token F1, BLEU, ROUGE and BERTScore. They measure surface or embedding overlap with references and correlate poorly with quality on open-ended answers that can be phrased many ways.

Medium Prompt B scores 81% and A 78% on the same 200 questions, with 30 disagreements (18 for B). Is B better?

Not significantly. Use a paired test: the exact sign test on the 30 discordant pairs gives p = 0.36. A 3-point gap with 30 disagreements is within chance.

Medium Why use a paired test instead of comparing two proportions?

Both systems answered the same items, so item difficulty is shared. Paired tests (McNemar, sign test) use only discordant items, which is correct and usually more powerful than the unpaired z-test.

Medium What biases do LLM judges have and how do you mitigate them?

Position bias (swap the order and keep only consistent wins), verbosity bias (rubrics penalizing padding), self-preference (a judge from a different model family), and score compression (use binary or pairwise criteria).

Medium How do you put a confidence interval on accuracy?

Wilson interval for a proportion, or bootstrap (resample items with replacement). For two systems on the same items, use a paired bootstrap of the difference.

Medium What is eval contamination?

Test items appearing in training data, which inflates scores. Defend with private held-out sets, near-duplicate checks between train and eval, and fresh items.

Advanced How many eval questions do you need to detect a 3-point improvement?

It depends on the discordance rate. With 15% discordant and a true 60/40 split of disagreements, about 194 discordant pairs are needed for 80% power, so about 1,300 questions. Unpaired designs need about 2,800 per arm.

Advanced What is the multiple comparisons problem in prompt experiments?

Testing many variants inflates false positives: 20 tests at alpha 0.05 gives a 64% chance of at least one false winner. Use Bonferroni, Holm or Benjamini-Hochberg corrections, or confirm on a fresh test set.

Advanced Offline vs online evaluation: how do they fit together?

Offline (golden sets, component metrics) gates releases quickly and repeatably. Online (A/B tests, user feedback, task success) measures real impact. Production failures feed back into the offline set.

Advanced How would you evaluate an agent?

Task success rate in simulated or sandboxed environments, tool-call accuracy, policy compliance, step and cost efficiency, and trajectory review. Plus regression suites and online containment and escalation metrics.
