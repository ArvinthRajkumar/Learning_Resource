Basics first: what fine-tuning is

Intuition

Pretraining gives a model general language skill. Fine-tuning continues training on a smaller, focused dataset so the model adopts a specific behavior: answer in your format, use your domain's style, follow your labeling rules. It is transfer learning: start from learned weights instead of random ones, so a few thousand examples go a long way.

The mechanism

  • Data: (input, desired output) pairs, rendered with the model's chat template.
  • Loss: next-token cross-entropy on the output tokens (part F1 covers cross-entropy).
  • What gets updated: all weights (full fine-tuning) or a small set of added weights (parameter-efficient fine-tuning, PEFT, such as LoRA).
  • Key hyperparameters: learning rate (much smaller than pretraining, for example 1e-5 to 2e-4 depending on full vs LoRA), epochs (1 to 3), batch size, max sequence length, LoRA rank and alpha.
  • Outputs: a new checkpoint, or a small adapter file loaded on top of the base model.

Common traps

  • Fine-tuning before trying prompting and RAG, or without an eval set to show it helped.
  • Too high a learning rate or too many epochs: the model memorizes and forgets general skills.
  • Training and inference chat templates that do not match.

How this gets asked

Which is the best reason to fine-tune rather than prompt?

  • To give the model this week's product prices Changing facts belong in RAG.
  • Because prompting is unscientific Prompting can be measured just as rigorously.
  • To get a consistent output style and format at scale, or a cheaper, smaller model with the same behavior Correct.
  • To fix a retrieval bug Fix retrieval.

Fine-tuning changes behavior. RAG supplies knowledge.

Self-check

What is transfer learning?

Starting from a model trained on a large general task and adapting it to a specific task with less data.

Typical number of epochs for LLM fine-tuning?

About 1 to 3. More risks overfitting.

Full fine-tuning vs PEFT?

Full updates all weights. PEFT trains a small number of added or selected parameters.

LoRA: low-rank adaptation

Intuition

Fine-tuning changes a weight matrix W into W + ΔW. The LoRA paper's bet is that the useful ΔW for a new task has low rank: it can be written as a tall thin matrix times a short wide one. Instead of learning 16.8 million numbers for a 4096 x 4096 update, you learn two thin matrices with 131 thousand numbers total. The original W never changes.

Analogy: instead of reprinting a 1,000-page manual, you ship a short errata sheet. Readers apply the errata on top. Later you can even print a new edition with the errata merged in.

The mechanism

The formulas

LoRA forward pass and parameter count
h = W x + (alpha / r) * B (A x) trainable params per module = r x (d_in + d_out) merged weight: W' = W + (alpha / r) * B A
W
frozen pretrained weight, d_out x d_in
A
r x d_in, trained (random init)
B
d_out x r, trained (zero init)
r
rank, e.g. 8, 16, 64
alpha
scaling hyperparameter. The update is scaled by alpha / r, so changing r does not require retuning the learning rate as much. (rsLoRA proposes alpha / sqrt(r) instead.)

Worked example: r = 16 on q_proj and v_proj of a 7B model

Llama 2 7B: hidden 4096, 32 layers, MHA so q_proj and v_proj are both 4096 x 4096
  1. One module: r x (d_in + d_out) = 16 x (4096 + 4096) = 16 x 8192 = 131,072.
  2. Two modules per layer (q and v): 2 x 131,072 = 262,144.
  3. 32 layers: 262,144 x 32 = 8,388,608, about 8.4M trainable parameters.
  4. As a fraction of 6.74B: about 0.124%.
  5. Scale: alpha / r = 32 / 16 = 2.
8,388,608 trainable params; scale = 2

Variations to practice: r = 8 halves it to 4,194,304. Llama-3-8B has GQA, so v_proj is 4096 to 1024: 16 x (4096 + 1024) = 81,920, and q+v over 32 layers gives 6,815,744. Targeting all seven linear modules of Llama 2 7B (q, k, v, o at 4096 x 4096; gate and up at 4096 x 11008; down at 11008 x 4096) at r = 16 gives 39,976,960.

What LoRA saves, and what it does not

Memory itemFull fine-tuneLoRA
Base weightsbf16 + fp32 master copybf16, frozen (same size, no master copy)
Gradientsfor all paramsonly A, B
Optimizer state (Adam m, v)for all paramsonly A, B
Activationsneeded for backpropstill needed: gradients must flow back through the frozen layers to reach earlier adapters

Full fine-tuning a 7B model with Adam in mixed precision needs about 16 bytes per parameter, so about 112 GB before activations. With LoRA the adapter state is 8.39M x 16 bytes, about 134 MB. The frozen bf16 base (14 GB) and activations dominate.

Merging and serving

  • After training, compute W' = W + (alpha/r) BA once. The merged model has the same shape as the base, so there is zero extra inference latency.
  • Or keep adapters separate and serve many of them on one base model (multi-LoRA serving, as in S-LoRA and vLLM's LoRA support). The small extra matmul per request is the price of per-request adapter swapping.

Common traps

  • "LoRA removes activation memory." No. It removes most gradient and optimizer memory. Activations stay. (Gradient checkpointing is the tool for activations.)
  • "Higher rank is always better." No. Returns diminish quickly. A higher rank adds parameters and overfitting risk, and the LoRA paper found small ranks competitive. Tune it like any hyperparameter.
  • "LoRA adds inference latency." Only if you leave it unmerged.
  • "The base model is updated slightly." No, it stays frozen. Only A and B receive gradients.
  • "Scale is alpha x r" or "r / alpha". It is alpha / r.

How this gets asked

LoRA with r = 16, alpha = 32, applied to the q and v projections. Select all that are true.

  • Adapters can be merged into the base weights for no extra inference latency W' = W + (alpha/r)BA has the original shape.
  • It removes activation memory during training Activations are still needed for backprop through the frozen layers.
  • The update is scaled by alpha / r = 2 32 / 16 = 2.
  • Only the A and B matrices are trained The base weights are frozen.
  • A higher rank is always better Returns diminish, and overfitting and cost grow.

LoRA saves gradient and optimizer memory, not activations, and rank is a hyperparameter to tune.

Trainable parameters for LoRA r = 16 on q_proj and v_proj (both 4096 x 4096) in each of 32 layers?

16 x (4096 + 4096) x 2 x 32 = 8,388,608.

Why is B initialized to zeros?

  • To make the adapter sparse B becomes dense once training starts.
  • So that BA = 0 and training starts exactly from the pretrained model Correct. The first forward pass equals the base model.
  • Because zeros quantize better This has nothing to do with initialization.
  • To reduce the rank Rank is fixed by the shapes.

If both A and B were random, the model would start perturbed away from the base. Zero B with random A gives a no-op start, while gradients still flow to B.

Self-check

Trainable params formula for one LoRA module?

r x (d_in + d_out).

Which memory does LoRA save during training?

Gradients and optimizer states (and the fp32 master copy) for the frozen weights. Not activations.

How do you get zero inference overhead?

Merge: W' = W + (alpha/r) BA.

QLoRA, PEFT and full fine-tuning

Intuition

LoRA froze the base weights. QLoRA adds a twist: since they are frozen anyway, store them in 4 bits. Train the small adapters in bf16 on top. A 7B base shrinks from 14 GB to about 3.5 GB, so fine-tuning fits on a single consumer or T4-class GPU.

The mechanism

  • NF4 (4-bit NormalFloat): a 4-bit data type whose 16 levels are placed for normally distributed weights, so precision lands where weights actually are.
  • Double quantization: the per-block scales are themselves quantized, saving roughly another 0.4 bits per parameter (per the QLoRA paper).
  • Paged optimizers: optimizer state can spill to CPU memory on spikes, avoiding out-of-memory crashes.
  • Forward and backward: 4-bit weights are dequantized to bf16 on the fly for each matmul. Gradients flow through them to the LoRA adapters, but the 4-bit weights get no updates.

Other PEFT methods: prefix or prompt tuning (learned virtual tokens), IA3 (learned scaling vectors), DoRA (splits each weight into magnitude and direction, applying LoRA to the direction). In practice LoRA and QLoRA dominate.

Common traps

  • "QLoRA trains the model in 4-bit." The adapters train in bf16. Only the frozen base is stored in 4-bit.
  • "Merge a QLoRA adapter into the 4-bit base." Merging into quantized weights loses precision. The usual path is to merge into a bf16 copy of the base, then re-quantize for serving if needed.

How this gets asked

What does QLoRA quantize to 4 bits?

  • The LoRA adapters Adapters are trained in 16-bit.
  • The gradients Gradients are 16-bit and exist only for the adapters.
  • The frozen base model weights Correct: NF4 storage, dequantized on the fly.
  • The activations Activations stay 16-bit.

QLoRA = 4-bit frozen base + bf16 LoRA adapters + paged optimizers + double quantization.

Self-check

Three ingredients of QLoRA besides LoRA itself?

NF4 data type, double quantization, paged optimizers.

Why is QLoRA slower per step than LoRA?

Weights must be dequantized from 4-bit to bf16 for every matmul in the forward and backward passes.

Roughly how big is a 7B base in 4-bit?

About 3.5 GB plus scales.

Prompting vs RAG vs fine-tuning

Intuition

Fine-tuning changes behavior (format, style, a narrow skill, latency and cost by distilling into a smaller model). RAG supplies knowledge at query time, especially knowledge that changes or must be cited. Prompting is the cheapest experiment and should come first.

NeedBest first toolWhy
Answers from your docs, which change weeklyRAGUpdate the index, not the weights. Citations come free.
Strict output format or house style, consistentlyPrompting, then fine-tuneFine-tuning bakes in behavior and shortens prompts.
Cut cost or latency of a working big-model pipelineFine-tune a smaller model (distillation)Same behavior at a fraction of the inference cost.
New facts the model must "know" without retrievalUsually RAG, not fine-tuningFine-tuning is unreliable for injecting facts and can raise hallucination rates.
Domain jargon, classification of your labelsFine-tune (if prompting plateaus)Many labeled examples teach the decision boundary.
Align tone and preferences (helpful, safe, concise)Preference optimization (DPO and similar)Learns from comparisons rather than gold answers.

Order of operations: prompt engineering, then add RAG for knowledge, then fine-tune for behavior or efficiency. Always build the eval set first, so you can tell whether each step helped.

How this gets asked

A support bot must answer from a policy manual updated weekly and quote the relevant section. Best approach?

  • Fine-tune weekly on the manual Expensive, slow to update, unreliable at fact recall, and no citations.
  • RAG over the manual with citations Fresh knowledge at query time, with sources to quote.
  • A longer system prompt with the whole manual and temperature 0 This can work if it fits, but it is costly per request and does not scale. RAG is the standard answer.
  • DPO on manual excerpts DPO aligns preferences. It does not inject a changing knowledge base.

Changing knowledge plus citations is the textbook RAG case.

Self-check

One sentence: when fine-tune, when RAG?

Fine-tune for behavior, format and efficiency. Use RAG for knowledge that changes or needs citations.

What should exist before any of these?

An eval set with a metric.

Why is fine-tuning a weak way to add facts?

Facts seen a few times are poorly memorized and can increase hallucination. Updates also need retraining.

DPO and preference optimization

Intuition

For many tasks it is easier to say which of two answers is better than to write the perfect answer. Preference data is triples (prompt, chosen, rejected). Classic RLHF first trains a reward model on these pairs, then runs RL (PPO) to maximize that reward. DPO showed the same objective can be optimized directly with a simple classification-style loss on the pairs. There is no reward model and no RL loop.

The mechanism

The DPO loss

Direct Preference Optimization (Rafailov et al., 2023)
L = - log sigmoid( beta * [ (log pi(y_w|x) - log pi_ref(y_w|x)) - (log pi(y_l|x) - log pi_ref(y_l|x)) ] )
pi
the policy being trained
pi_ref
frozen reference model (usually the SFT checkpoint)
y_w, y_l
chosen (winner) and rejected (loser) responses
beta
strength of staying close to the reference (like the KL coefficient). Typical 0.1.
log pi(y|x)
sum of token log-probs of the response

The quantity beta x (log pi - log pi_ref) acts as an implicit reward. The loss pushes the chosen response's implicit reward above the rejected one's. The reference keeps the model from drifting arbitrarily far just to separate the pair.

Worked example

beta = 0.1. Chosen: policy -12, ref -14. Rejected: policy -15, ref -13 (sequence log-probs)
  1. Chosen log-ratio: -12 - (-14) = +2. Rejected log-ratio: -15 - (-13) = -2.
  2. Margin: 2 - (-2) = 4. Times beta: 0.4.
  3. sigmoid(0.4) = 0.5987. Loss = -ln(0.5987) = 0.513.
  4. At initialization the policy equals the reference: margin 0, loss = -ln(0.5) = 0.693.
loss 0.513 (down from 0.693 at init)

Common traps

  • "DPO needs a reward model." No, that is the point of DPO. It still needs a frozen reference model.
  • "DPO is online RL." It is offline: a fixed preference dataset and no sampling during training.
  • "The reference model is updated." It stays frozen.
  • Large beta means staying closer to the reference, small beta allows more drift. People often invert this.

How this gets asked

DPO uses a frozen model and needs no separately trained model.

Reference (usually the SFT checkpoint), and reward. DPO's loss contains log pi_ref terms, and the reward model is implicit in the log-ratio.

You only have thumbs up and down on single responses (no pairs). Which method fits best without building pairs?

  • DPO DPO needs chosen and rejected for the same prompt.
  • ORPO ORPO also uses pairs.
  • Plain SFT on the thumbs-down responses That would teach the bad behavior.
  • KTO KTO is designed for unpaired desirable or undesirable labels.

KTO works on binary per-example feedback. You could also SFT on only the thumbs-up examples as a baseline.

-log sigmoid(beta x [(log pi(y_w) - log pi_ref(y_w)) - (log pi(y_l) - log pi_ref(y_l))]).

What is the DPO loss value when policy equals reference?

ln 2, about 0.693.

Which of DPO, ORPO, KTO, GRPO need no reference model?

ORPO (and SimPO). DPO, KTO and GRPO use one.

SFT data, loss masking and failure modes

Intuition

Supervised fine-tuning is next-token prediction on example conversations. The model copies what it sees, including mistakes, inconsistencies and formatting quirks. A few thousand clean, diverse, consistent examples usually beat a large noisy set.

The mechanism

  • Loss masking: compute loss only on the assistant's response tokens. Prompt and system tokens get label -100 (ignored by PyTorch's cross-entropy). Otherwise the model spends capacity learning to generate user prompts, and the long shared system prompt dominates the gradient.
  • Chat templates: train with exactly the template the model will see at inference (special tokens, role markers, end-of-turn token). A mismatch causes rambling, missing stop tokens or role confusion. In Hugging Face, tokenizer.apply_chat_template renders the model's own template.
  • EOS: make sure each training response ends with the end-of-turn token, or the model never learns to stop.
  • Packing: concatenating short examples into one sequence improves throughput. Use attention masking that prevents cross-example attention if your framework supports it.

How this gets asked

During SFT, why set the labels of prompt tokens to -100?

  • So the loss is computed only on the response, and the model learns to answer instead of learning to reproduce prompts Correct: -100 is ignored by cross-entropy.
  • To shorten the sequence The tokens are still in the input. Only the loss ignores them.
  • To freeze the embedding layer Unrelated.
  • To enable LoRA Unrelated.

The prompt is still attended to as context. It just contributes no gradient as a target.

Self-check

What is loss masking?

Excluding non-response tokens from the loss by setting their labels to the ignore index.

Two ways to reduce catastrophic forgetting?

Mix in general replay data. Use PEFT or a lower learning rate with fewer epochs.

Why must the training chat template match inference?

The model learns token patterns, including role markers and stop tokens. A different template at inference is out of distribution.

Interview questions: fine-tuning

Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What is fine-tuning?

Continuing training of a pretrained model on task-specific data so it adapts its behavior (format, style, domain), instead of training from scratch.

Basic What is LoRA in one sentence?

Freeze the pretrained weights and learn a low-rank update B x A (scaled by alpha/r) added to selected weight matrices, training only about 0.1 to 1% of the parameters.

Basic When should you fine-tune vs use RAG vs prompt?

Prompt first. Use RAG for knowledge that changes or needs citations. Fine-tune for consistent behavior or format, domain style, or cheaper and faster distilled models.

Basic What is SFT?

Supervised fine-tuning on (prompt, ideal response) pairs with next-token loss, usually computed only on the response tokens.

Medium Compute LoRA trainable parameters for r = 16 on q and v (4096 x 4096) over 32 layers.

Per module r(d_in + d_out) = 16 x 8192 = 131,072. Times 2 modules times 32 layers = 8,388,608.

Medium What memory does LoRA save and not save?

It saves gradients and optimizer states (and the fp32 master copy) for the frozen weights. It does not remove activation memory, because backprop still passes through the frozen layers.

Medium What is QLoRA?

LoRA on top of a frozen base stored in 4-bit NF4, with double quantization and paged optimizers. Adapters train in bf16. It lets 7B to 70B fine-tunes fit on far less GPU memory.

Medium Explain DPO and how it differs from RLHF with PPO.

DPO optimizes preferences directly with a logistic loss on the policy's log-probability ratios versus a frozen reference for chosen vs rejected responses. No reward model and no RL sampling loop. PPO-RLHF trains a reward model and runs online RL with a KL penalty.

Medium What is catastrophic forgetting and how do you mitigate it?

Losing general capabilities after narrow fine-tuning. Mitigate with PEFT or a lower learning rate, fewer epochs, mixing general replay data, and evaluating general benchmarks alongside the task.

Medium Why mask prompt tokens in the SFT loss?

So gradients come only from the response tokens. The model learns to answer rather than to reproduce prompts, and long shared system prompts do not dominate the loss.

Medium What is the role of alpha in LoRA?

The update is scaled by alpha/r, which keeps the effective update magnitude stable when changing rank. With r = 16 and alpha = 32 the scale is 2.

Advanced KTO, ORPO, GRPO: what problem does each address?

KTO learns from unpaired good/bad labels. ORPO folds preference alignment into SFT with an odds-ratio term and no reference model. GRPO is a PPO variant without a critic, using group-normalized rewards over several samples per prompt, popular for verifiable reasoning rewards.

Advanced How would you build a dataset for fine-tuning a support model?

Collect real conversations, clean and deduplicate them, remove PII, label or rewrite to the target style, balance intents, include refusals and edge cases, split by customer or time to avoid leakage, and hold out an eval set that mirrors production.

Advanced Can fine-tuning reliably inject new facts?

Not reliably. Facts seen few times are poorly memorized and fine-tuning on new knowledge can increase hallucination. Prefer RAG for facts, and fine-tune for behavior and format.
