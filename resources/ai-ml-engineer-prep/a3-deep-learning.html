Backpropagation by building it

What a neural network computes

A network is a composition of simple differentiable operations. To train it we need d loss / d parameter for every parameter. Reverse-mode automatic differentiation (backpropagation) computes all of them in one backward sweep, at about the cost of one forward pass.

  1. Forward pass: compute and record each operation's inputs and output.
  2. Backward pass: starting with d loss / d loss = 1, visit operations in reverse; each passes gradient x local derivative to its inputs, accumulating (summing) when a value is used more than once.

A complete engine and a trained network

Below is a tiny autograd engine (the idea behind PyTorch, minus tensors) followed by a 2-4-1 network trained on XOR, a problem no single linear layer can solve.

import math, random

class V:
    def __init__(self, data, parents=()):
        self.data, self.grad, self._parents, self._backward = data, 0.0, parents, lambda: None
    def __add__(self, o):
        o = o if isinstance(o, V) else V(o)
        out = V(self.data + o.data, (self, o))
        def bw():
            self.grad += out.grad
            o.grad += out.grad
        out._backward = bw
        return out
    def __mul__(self, o):
        o = o if isinstance(o, V) else V(o)
        out = V(self.data * o.data, (self, o))
        def bw():
            self.grad += o.data * out.grad
            o.grad += self.data * out.grad
        out._backward = bw
        return out
    __radd__ = __add__
    __rmul__ = __mul__
    def __neg__(self): return self * -1
    def __sub__(self, o): return self + (-o if isinstance(o, V) else V(-o))
    def tanh(self):
        t = math.tanh(self.data)
        out = V(t, (self,))
        def bw(): self.grad += (1 - t * t) * out.grad
        out._backward = bw
        return out
    def backward(self):
        order, seen = [], set()
        def visit(v):
            if v not in seen:
                seen.add(v)
                for p in v._parents: visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order): v._backward()

random.seed(1)
class Neuron:
    def __init__(self, n_in):
        self.w = [V(random.uniform(-1, 1)) for _ in range(n_in)]
        self.b = V(0.0)
    def __call__(self, x):
        return (sum((wi * xi for wi, xi in zip(self.w, x)), self.b)).tanh()
    def params(self): return self.w + [self.b]
class MLP:
    def __init__(self, sizes):
        self.layers = [[Neuron(sizes[i]) for _ in range(sizes[i + 1])] for i in range(len(sizes) - 1)]
    def __call__(self, x):
        for layer in self.layers:
            x = [n(x) for n in layer]
        return x[0]
    def params(self): return [p for layer in self.layers for n in layer for p in n.params()]

net = MLP([2, 4, 1])
X = [[0, 0], [0, 1], [1, 0], [1, 1]]
Y = [-1, 1, 1, -1]                         # XOR with targets in {-1, +1}
for epoch in range(301):
    loss = sum(((net(x) - y) * (net(x) - y) for x, y in zip(X, Y)), V(0.0))
    for p in net.params(): p.grad = 0.0
    loss.backward()
    for p in net.params(): p.data -= 0.05 * p.grad
    if epoch in (0, 100, 300):
        print("epoch %3d loss %.4f" % (epoch, loss.data))
print([round(net(x).data, 2) for x in X], "targets", Y)

epoch 100 loss 0.0862

The loss falls and the four outputs approach the XOR targets: a hidden layer with a non-linearity solves what a linear model cannot. Every framework works this way, with tensors instead of scalars and fused kernels instead of Python closures.

Key facts about backprop

  • Cost: backward costs about 2x forward; memory must store activations (hence activation checkpointing).
  • Accumulation: a value used twice gets gradient contributions summed. Forgetting += is a classic bug.
  • Zero the gradients each step (frameworks accumulate by default).
  • Gradient check: compare to finite differences (A2).
  • Vanishing and exploding gradients: products of many small or large factors.
# Vanishing gradients: the sigmoid's derivative is at most 0.25, so gradients shrink geometrically with depth.
for depth in (2, 5, 10, 20):
    print("depth %2d: gradient factor at most %.2e" % (depth, 0.25 ** depth))

How this gets asked

Why must gradients be accumulated (summed) in backprop?

  • To save memory No.
  • A value used in several places receives gradient contributions from each use Correct.
  • To normalise them No.
  • Because of tanh No.

The chain rule's total derivative sums over all paths.

Roughly how much more costly is the backward pass than the forward pass?

  • About the same A bit more.
  • About twice Correct.
  • 100 times No.
  • Free No.

The backward pass computes gradients for activations and weights, about 2x forward.

Initialisation and activations

Why initialisation matters

If weights are too small, signals shrink layer by layer to zero; if too large, they explode. Good initialisation keeps the variance of activations and gradients roughly constant across layers.

import math, random
random.seed(0)
def forward_std(scale_fn, layers=20, width=256):
    x = [random.gauss(0, 1) for _ in range(width)]
    for _ in range(layers):
        s = scale_fn(width)
        x = [math.tanh(sum(random.gauss(0, s) * xi for xi in x)) for _ in range(width)]
    m = sum(x) / len(x)
    return math.sqrt(sum((v - m) ** 2 for v in x) / len(x))
print("std 0.01          :", round(forward_std(lambda n: 0.01, width=64), 6))
print("std 1.0           :", round(forward_std(lambda n: 1.0, width=64), 3))
print("Xavier 1/sqrt(n)  :", round(forward_std(lambda n: 1 / math.sqrt(n), width=64), 3))

Output

std 0.01          : 0.0
std 1.0           : 0.971
Xavier 1/sqrt(n)  : 0.125

With a tiny scale the activations collapse to zero (std 0.00); with scale 1 the tanh units saturate near plus or minus 1 (std 0.97, gradients vanish there); the Xavier/Glorot scale 1 / sqrt(n) shrinks the signal only gradually (0.13 after 20 layers) and stays in the responsive range of tanh.

How this gets asked

He (Kaiming) initialisation uses variance 2 / n_in. It is designed for:

  • Sigmoid Xavier suits tanh and sigmoid.
  • ReLU networks Correct.
  • Embeddings only No.
  • Bias terms No.

ReLU zeroes half the activations, so the variance factor 2 compensates.

Self-check

Why not initialise all weights to zero?

Neurons in a layer would receive identical gradients and stay identical (symmetry), so they could not learn different features.

Normalisation and regularisation

Normalisation layers

Normalising activations stabilises and speeds up training.

LayerNormalises overUsed in
BatchNormThe batch, per featureCNNs; depends on batch statistics (train versus eval differ)

RMSNormFeatures, no mean subtractionModern LLMs (cheaper)

import math
def layernorm(x, eps=1e-5):
    m = sum(x) / len(x)
    v = sum((a - m) ** 2 for a in x) / len(x)
    return [(a - m) / math.sqrt(v + eps) for a in x]
def rmsnorm(x, eps=1e-5):
    r = math.sqrt(sum(a * a for a in x) / len(x) + eps)
    return [a / r for a in x]
x = [10.0, 12.0, 8.0, 14.0]
y = layernorm(x)
print("layernorm:", [round(v, 3) for v in y], "mean %.3f" % (sum(y) / len(y)))
print("rmsnorm  :", [round(v, 3) for v in rmsnorm(x)])

Output

layernorm: [-0.447, 0.447, -1.342, 1.342] mean 0.000
rmsnorm  : [0.891, 1.069, 0.713, 1.247]

Both then apply a learned scale (and, for LayerNorm, shift). Pre-norm (normalise before each sub-layer) trains more stably for deep transformers than post-norm.

Dropout and weight decay

Dropout randomly zeroes a fraction p of activations during training and rescales by 1 / (1 - p) (inverted dropout) so the expected activation is unchanged; at inference it is off. It prevents co-adaptation. Weight decay shrinks weights each step (decoupled in AdamW). Other regularisers: early stopping, data augmentation, label smoothing, stochastic depth, smaller models and more data.

import random
random.seed(2)
p = 0.5
acts = [1.0] * 10
mask_scaled = [a / (1 - p) if random.random() > p else 0.0 for a in acts]
print(mask_scaled, "mean %.2f (expected 1.0 on average)" % (sum(mask_scaled) / 10))
avg = sum(sum(a / (1 - p) if random.random() > p else 0.0 for a in acts) / 10 for _ in range(2000)) / 2000
print("average over many masks: %.3f" % avg)

How this gets asked

Why do transformers use LayerNorm instead of BatchNorm?

  • It is older No.
  • It normalises per example, independent of batch size and identical in training and inference Correct.
  • It has no parameters No.
  • It is faster on GPUs always No.

Batch statistics are unreliable for variable-length sequences and small batches.

Pre-norm versus post-norm?

Pre-norm normalises before each sub-layer, keeping a clean residual path and training deep transformers more stably.

Learning-rate schedules

import math
def schedule(step, total, warmup, peak=1.0, floor=0.1):
    if step < warmup:
        return peak * step / warmup                      # linear warm-up
    progress = (step - warmup) / max(1, total - warmup)
    return floor * peak + (peak - floor * peak) * 0.5 * (1 + math.cos(math.pi * progress))   # cosine decay
for s in (0, 50, 100, 500, 900, 1000):
    print("step %4d lr %.3f" % (s, schedule(s, 1000, 100)))

Output

step    0 lr 0.000
step   50 lr 0.500
step  100 lr 1.000
step  500 lr 0.628
step  900 lr 0.127
step 1000 lr 0.100

Batch size and learning rate interact: a common rule is to scale the learning rate with the square root (Adam) or linearly (SGD) of the batch size, with warm-up. Gradient clipping (norm 1.0) protects against spikes.

Self-check

Why warm up the learning rate?

Early gradients and Adam's second-moment estimates are unreliable, so large steps can destabilise training.

Convolutional and recurrent networks

Convolution

A convolution slides a small kernel over the input, computing a dot product at each position. Benefits: weight sharing (few parameters), locality, translation equivariance. Output size: (n + 2p - k) / s + 1 for input n, kernel k, padding p, stride s.

def conv2d(img, kernel):
    kh, kw = len(kernel), len(kernel[0])
    return [[sum(img[i + a][j + b] * kernel[a][b] for a in range(kh) for b in range(kw))
             for j in range(len(img[0]) - kw + 1)] for i in range(len(img) - kh + 1)]
img = [[0, 0, 0, 9, 9],
       [0, 0, 0, 9, 9],
       [0, 0, 0, 9, 9],
       [0, 0, 0, 9, 9]]
vertical_edge = [[-1, 1], [-1, 1]]
for row in conv2d(img, vertical_edge):
    print(row)
n, k, p, s = 32, 3, 1, 1
print("output size:", (n + 2 * p - k) // s + 1, " parameters for 3x3 kernel, 64 in, 128 out channels:", 3 * 3 * 64 * 128 + 128)

The kernel responds only where the intensity jumps (a vertical edge). Stacking layers builds from edges to textures to parts to objects (the receptive field grows). Pooling downsamples; ResNets add skip connections x + f(x) so very deep networks train (A8).

Recurrent networks

An RNN processes a sequence step by step, carrying a hidden state: h_t = tanh(W x_t + U h_(t-1) + b). Training uses backpropagation through time, which suffers vanishing and exploding gradients over long sequences. LSTM and GRU add gates (forget, input, output) and an additive cell state so gradients flow further. They are sequential (slow on GPUs) and were largely replaced by transformers, whose attention connects any two positions directly (F2).

import math
sig = lambda z: 1 / (1 + math.exp(-z))
def lstm_step(x, h, c, W):
    f = sig(W["f"][0] * x + W["f"][1] * h)       # forget gate
    i = sig(W["i"][0] * x + W["i"][1] * h)       # input gate
    g = math.tanh(W["g"][0] * x + W["g"][1] * h) # candidate
    o = sig(W["o"][0] * x + W["o"][1] * h)       # output gate
    c = f * c + i * g                            # additive cell update
    return o * math.tanh(c), c
W = {k: (0.5, 0.3) for k in "figo"}
h = c = 0.0
for x in (1.0, 0.0, 0.0, 0.0):
    h, c = lstm_step(x, h, c, W)
    print("h %.3f c %.3f" % (h, c))

Debugging and diagnosing training

A systematic checklist

  1. Overfit one small batch. If the loss will not go to about zero, there is a bug (shapes, labels, loss, learning rate).
  2. Check the initial loss. For K classes with a sensible init it should be ln K (e.g. 2.30 for 10 classes).
  3. Verify data: view samples and labels, check normalisation, confirm train and validation use the same preprocessing, no leakage.
  4. Track training and validation loss, gradient norm, update-to-weight ratio (about 1e-3), learning rate, and activation statistics.
  5. Change one thing at a time, with fixed seeds.

Key idea

A neural network is a differentiable program trained by gradient descent. Most failures come from scale: initialisation, learning rate, normalisation and data preprocessing. Make the pipeline overfit a tiny batch before scaling up.

How this gets asked

  • 2.30 Correct: ln 10.
  • 10 No.
  • 1 No.

A uniform prediction over K classes gives ln K.

The model cannot overfit a single small batch. What does that tell you?

  • It needs more data No.
  • There is a bug in the pipeline: shapes, labels, loss or learning rate Correct.
  • It is regularised well No.
  • Training is finished No.

Any reasonable network should memorise a handful of examples.

Interview questions: Deep learning

13 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic Explain backpropagation.

A forward pass computes the loss while storing intermediate values; a backward pass applies the chain rule from the loss to every parameter, accumulating gradients where values are reused.

Basic Why do we need non-linear activation functions?

Without them a stack of linear layers collapses to a single linear map and cannot model complex functions.

Basic What is overfitting and how do you reduce it?

Fitting noise: low training error but high validation error. Use more data, augmentation, dropout, weight decay, early stopping, smaller models.

Medium What causes vanishing and exploding gradients and how are they handled?

Products of many small or large factors through depth. Use ReLU-family activations, good initialisation (He, Xavier), normalisation, residual connections, gradient clipping and gated units (LSTM).

Medium BatchNorm versus LayerNorm?

BatchNorm normalises over the batch per feature and depends on batch statistics; LayerNorm normalises over the features of each example, suiting transformers and variable batch sizes.

Medium How does dropout work at training and test time?

It randomly zeroes activations with probability p during training, scaling the rest by 1/(1-p); at test time it is off, so the network acts like an ensemble average.

Medium Why is the learning rate the most important hyperparameter?

Too high diverges or oscillates, too low is slow or stuck. Use warm-up and decay schedules, and tune it first.

Medium What is weight initialisation and why does it matter?

Starting weights set the scale of activations and gradients. Xavier (tanh) and He (ReLU) scale variance by layer width to keep signals stable; all-zero init breaks symmetry.

Medium What do convolutions provide over fully connected layers?

Weight sharing, locality and translation equivariance, giving far fewer parameters and better generalisation for grid-like data.

Advanced Why do residual connections help?

They give gradients a direct path, so very deep networks train; each block learns a correction to the identity.

Advanced How would you debug a network that does not train?

Overfit a tiny batch, check the initial loss equals ln K, verify data and labels, check the learning rate and gradient norms, test with and without regularisation, and change one thing at a time.

Advanced AdamW versus Adam with L2 regularisation?

In Adam, L2 added to the gradient is scaled by the adaptive step, weakening regularisation. AdamW decouples weight decay from the gradient update, which generalises better.

Advanced Why did transformers replace RNNs?

Attention connects any two positions directly, avoiding long gradient paths, and processes sequences in parallel on GPUs, scaling to far more data.
