Part 06

Decoding and sampling

The model outputs a score (logit) for every token in the vocabulary. Decoding is the policy that turns those scores into a choice. Each knob reshapes or truncates one distribution. Compute it once by hand and the knobs stop being magic.

Feeds coding problem d~1.5 hours

Softmax, temperature and greedy

Intuition

Softmax turns arbitrary scores into probabilities: exponentiate (making everything positive and stretching differences), then divide by the total. Temperature divides the logits first. Low T exaggerates differences, so the top token dominates. High T shrinks them, flattening the distribution toward uniform. Greedy decoding always takes the top token, which is the T approaching 0 limit.

The formula

Softmax with temperature (stable form)
p_i = exp((z_i - max_j z_j) / T) / sum_k exp((z_k - max_j z_j) / T)
z_i
logit of token i
T
temperature > 0 (T = 0 is implemented as argmax)
max z
subtracted for numerical stability. It cancels in the ratio.

Worked example: logits [2, 1, 0]

  1. T = 1: exp values e^2 = 7.389, e^1 = 2.718, e^0 = 1. Sum = 11.107. p = [0.6652, 0.2447, 0.0900].
  2. T = 0.5: logits become [4, 2, 0]. p = [0.8668, 0.1173, 0.0159]. Sharper.
  3. T = 2: logits become [1, 0.5, 0]. p = [0.5065, 0.3072, 0.1863]. Flatter.
  4. Greedy: token 0 regardless of T. Temperature never changes the argmax, only how likely the alternatives are.
T rescales confidence; the ranking of tokens never changes

Common traps

  • "Temperature 0 makes outputs perfectly deterministic." Greedy is deterministic in principle, but batched GPU inference can produce tiny floating-point differences that flip near-ties. Providers generally do not guarantee bit-identical outputs.
  • "Higher temperature makes the model more creative and more accurate." More diverse, usually less accurate on factual tasks.
  • Computing exp(z) directly on large logits overflows. Subtract the max first.

How this gets asked

Logits [2, 1, 0], temperature 0.5. Probability of the first token? (4 decimals)

Divide by T: [4, 2, 0]. e^4 / (e^4 + e^2 + 1) = 54.598 / 62.987 = 0.8668.

Self-check

Why subtract the max logit?

To prevent overflow in exp. The result is unchanged because it cancels in numerator and denominator.

What does T approaching infinity give?

The uniform distribution over the vocabulary.

Does temperature change which token is most likely?

No. Dividing by a positive T preserves order.

Top-k, top-p (nucleus) and min-p

Intuition

Even after temperature, thousands of tokens keep tiny probabilities. Together they add up, and sampling one occasionally derails the text. Truncation methods cut off that tail, then renormalize what is left:

  • Top-k: keep a fixed number k of most likely tokens. Simple, but the same k is too many when the model is confident and too few when it is unsure.
  • Top-p: keep the smallest set whose total probability reaches p. Adapts to confidence: few tokens when peaked, many when flat.
  • Min-p: keep tokens with probability at least min_p x p_max. The cutoff scales with the top token's confidence (Nguyen et al., 2024). Supported in Hugging Face transformers, vLLM and llama.cpp.

Formulas

Truncation rules (then renormalize the kept set)
top-k: keep the k tokens with the largest p_i top-p: sort descending, keep tokens 1..m where m = min{ m : p_(1) + ... + p_(m) >= p } min-p: keep { i : p_i >= min_p * max_j p_j }

Worked examples

  1. Top-k = 2 on logits [2, 1, 0]: keep tokens 0 and 1. Renormalize e^2 and e^1: [0.7311, 0.2689, 0].
  2. Top-p = 0.75 on p = [0.5, 0.3, 0.15, 0.05]: the cumulative sum is 0.5 (short), then 0.8 (reaches 0.75). Keep 2: [0.625, 0.375].
  3. Top-p = 0.9: cumulative 0.5, 0.8, 0.95. Keep 3: divide by 0.95, giving [0.5263, 0.3158, 0.1579].
  4. Flat distribution (five tokens at 0.12, five at 0.08): top-p 0.75 keeps 7 tokens (0.6 + 0.08 + 0.08 = 0.76). Top-p adapts to uncertainty, while top-k = 2 would keep only 2.
  5. Min-p 0.2 on [0.5, 0.3, 0.15, 0.05]: threshold 0.1, so keep 3.

Order matters: many libraries apply temperature, then top-k, then top-p (Hugging Face's default processor order), but this varies by library and version. Implementations are in part 08.

Common traps

  • Forgetting to renormalize after truncation.
  • Top-p with "strictly greater than p" versus "at least p". Implementations differ at exact boundaries. The usual rule includes the token that crosses p.
  • Always keep at least one token (top-p with a tiny p).
  • top-k = 1 is greedy, whatever the temperature.

How this gets asked

Probabilities [0.5, 0.3, 0.15, 0.05], top-p = 0.75. After renormalization, the probability of the second token is:

  • 0.30 Not renormalized.
  • 0.375 Keep 2 (cumulative 0.8): 0.3 / 0.8.
  • 0.316 That is the top-p 0.9 answer.
  • 0.5 That is the first token before renormalizing.

The kept set is the first two tokens (0.5 + 0.3 = 0.8, at least 0.75). 0.3/0.8 = 0.375.

Why does top-p adapt better than top-k across contexts?

  • It is faster It needs a sort, so it is not faster.
  • It never truncates It does truncate.
  • The number of kept tokens grows when the model is uncertain and shrinks when it is confident Correct.
  • It removes the need for temperature They are complementary.

A fixed k ignores the shape of the distribution. A probability-mass cutoff follows it.

Self-check

Define the top-p kept set precisely.

The smallest prefix of tokens sorted by descending probability whose cumulative probability reaches p.

Min-p threshold formula?

min_p x p_max.

What must happen after any truncation?

Renormalize the kept probabilities to sum to 1.

Repetition penalties and logprobs

Penalties

Two families
Repetition penalty (CTRL style, Hugging Face): for tokens already generated, z' = z / r if z > 0, z' = z * r if z < 0 (r > 1 discourages) Frequency / presence (OpenAI style): z' = z - alpha_freq * count(token) - alpha_presence * [count(token) > 0]
  • r = 1.2 on logit 2.0 gives 1.667. On logit -1.0 it gives -1.2 (pushed further down).
  • Frequency 0.5 with count 3, plus presence 0.6, on logit 2.0: 2.0 - 1.5 - 0.6 = -0.1.
  • Penalties apply to tokens, so they also hit legitimately repeated tokens (names, code syntax, JSON keys). Use them lightly for structured output.

Logprobs

APIs can return the log-probability of each generated token (and often the top alternatives). log p = -0.1 means p = 0.905. A sequence's probability is exp(sum of logprobs). For [-0.1, -0.5, -2.0] that is exp(-2.6) = 0.0743. Perplexity = exp(-mean logprob) = exp(0.8667) = 2.379.

Uses: confidence scores for classification (the logprob of the label token), detecting low-confidence spans, calibration, comparing candidate answers, and building reward or verifier signals. Caveat: token probabilities are not calibrated truth probabilities, especially after RLHF.

How this gets asked

Token logprobs are [-0.1, -0.5, -2.0]. Perplexity? (3 decimals)

Mean = -0.8667. exp(0.8667) = 2.379.

Self-check

Why does the CTRL penalty multiply negative logits?

Dividing a negative logit by r > 1 would raise it toward 0, which encourages the token. Multiplying pushes it down.

Perplexity formula from logprobs?

exp(-(1/n) x sum of log p_i).

Frequency vs presence penalty?

Frequency scales with the count. Presence is a flat penalty once the token has appeared at all.

Beam search, and why it is not optimal

Intuition

Greedy decoding commits to the best token at each step and can walk into a dead end. Beam search keeps the B best partial sequences (the beam) at every step. It extends each of them by every token and keeps the best B of the results. It is a breadth-limited search. Anything that falls out of the top B is gone forever, even if it would have led to the best complete sequence.

The mechanism

The algorithm

Beam search (sum of log-scores)
beam = top_B { [v] : score = start[v] } repeat steps - 1 times: candidates = { s + [v] : s in beam, v in vocab }, score(s+[v]) = score(s) + trans[last(s)][v] beam = top_B(candidates) (ties: a deterministic rule, e.g. lexicographically smaller) return best of beam
B
beam width (B = 1 is greedy, B = all is exhaustive)
cost
O(steps x B x V log(B x V)) with a sort, O(steps x B x V) with a heap

Why beam search misses the global optimum

  • Pruning is based on prefix scores. A prefix that looks worse now can have much better continuations. Beam search cannot see the future.
  • Guaranteed optimal only if B is at least V^(steps-1) (nothing pruned), or if the scoring has special structure.
  • When scores depend only on the previous token (a first-order chain, like coding problem d), Viterbi dynamic programming finds the exact optimum in O(steps x V^2). LLMs condition on the whole prefix, so no such shortcut exists there.
  • For LLMs, a larger beam can even hurt open-ended text: higher-likelihood sequences tend to be short, generic or repetitive (the "beam search curse" and degeneration observations). Beam search shines in constrained tasks like translation and speech recognition.

Length normalization

Log-probs are at most 0, so every extra token lowers the total. Beam search with end-of-sequence tokens therefore prefers stopping early. Fix: compare finished hypotheses by score / length^alpha. Example: a 3-token hypothesis at -3.0 versus an 8-token one at -4.0. Raw scores prefer the short one. Normalized with alpha = 1: -1.0 versus -0.5, so the long one wins. GNMT's penalty is ((5 + |Y|)/6)^alpha. For |Y| = 8 and alpha = 0.6 that is 1.5903.

How this gets asked

Select all true statements about beam search.

  • It can miss the highest-scoring sequence because it prunes by prefix score Correct.
  • A wider beam always produces better text for open-ended chat Often blander or more repetitive. Likelihood is not quality.
  • Without length normalization it tends to favor shorter outputs Each token adds a negative log-prob.
  • Width 1 is the same as top-k sampling with k = 1 at temperature 1, so it is random Width 1 is greedy and deterministic.

Beam search is approximate maximum-likelihood search. Likelihood favors short, generic text unless normalized.

Self-check

When is beam search guaranteed to find the optimum?

When nothing is pruned (B at least V^(steps-1)). For first-order chains, use Viterbi instead.

What does length normalization fix?

The bias toward short sequences caused by summing negative log-probs.

Beam width 1 is equal to what?

Greedy decoding.

How this gets asked

You need the same JSON structure on every call for a data-extraction pipeline. Best decoding setup?

  • T = 1.2 with top-p 0.95 Too random for extraction.
  • Beam search width 10 Expensive and not structure-aware.
  • High repetition penalty Penalizes repeated JSON keys and syntax.
  • Temperature 0 (or low) with schema-constrained decoding Deterministic-leaning and structurally guaranteed.

Pick the most likely values and constrain the shape. Then measure accuracy with evals.

Self-check

Setting for self-consistency?

Moderate temperature with several samples, then majority vote.

Why can repetition penalties break JSON?

JSON legitimately repeats tokens (quotes, braces, keys), and penalties push them down.

Where does beam search still win?

Translation and ASR, where likelihood correlates with quality.

Interview questions: decoding

Try to answer aloud in under a minute, then reveal. Tags show the level. All questions are also in the interview bank.

Basic What does temperature do?

It divides logits before the softmax. Lower T sharpens the distribution (more deterministic), higher T flattens it (more diverse). T = 0 is treated as greedy. It never changes which token is most likely.

Basic Greedy decoding vs sampling?

Greedy takes the argmax each step (deterministic, can be repetitive). Sampling draws from the distribution (diverse), usually with temperature, top-k or top-p.

Basic What is top-p (nucleus) sampling?

Keep the smallest set of most-probable tokens whose cumulative probability reaches p, renormalize, then sample. It adapts the candidate count to the model's confidence.

Medium Top-k vs top-p: which adapts better and why?

Top-p, because the number of kept tokens grows when the distribution is flat and shrinks when it is peaked. Top-k keeps a fixed count regardless.

Medium What is beam search and why is it not guaranteed optimal?

It keeps the best B partial sequences at each step and extends them all. Pruning by prefix score can discard prefixes whose continuations would score best, so it can miss the global optimum.

Medium Why do beam search outputs favor short sequences, and how is it fixed?

Summing negative log-probs penalizes every extra token. Length normalization (score / length^alpha, or the GNMT penalty) corrects it.

Medium What are logprobs useful for?

Confidence estimation, classification scores, detecting low-confidence spans, comparing candidate answers, and computing perplexity. They are not calibrated truth probabilities.

Medium What is min-p sampling?

Keep tokens with probability at least min_p x p_max, then renormalize. The cutoff scales with the top token's confidence.

Advanced Why might temperature 0 still give non-deterministic outputs?

Floating-point non-associativity in batched GPU kernels (different batch compositions or kernel choices) can flip near-ties in the argmax. Providers generally do not guarantee bit-identical outputs.

Advanced When would you use Viterbi instead of beam search?

When scores factor over adjacent tokens (a first-order Markov chain, like HMMs or CRFs), Viterbi dynamic programming finds the exact best sequence in O(T x V^2). LLMs condition on full prefixes, so beam or sampling is used there.

Advanced How do repetition, frequency and presence penalties differ?

The CTRL-style repetition penalty divides positive logits (multiplies negative ones) of seen tokens by r. Frequency penalty subtracts proportional to the count. Presence penalty subtracts a flat amount once a token has appeared.
