Part A16

Interpretability, fairness, privacy and robustness: responsible machine learning

A model that is accurate but opaque, biased, leaky or brittle is a liability. This part covers the four properties interviewers and regulators ask about, with small experiments that make each one measurable instead of rhetorical.

MediumAdvanced~5 hours

Why responsibility is an engineering topic

Real systems decide loans, jobs, medical priorities and what billions of people see. Failures are concrete: a hiring model that penalises women, a face model that fails on darker skin, a recommender that amplifies harm, a model that memorises and leaks personal data, a classifier flipped by a sticker on a stop sign. The tools below turn vague worries into tests you can run and thresholds you can monitor. Regulation (EU AI Act, GDPR, sector rules, the NIST AI Risk Management Framework) increasingly requires them.

Interpretability: understanding predictions

LevelQuestionMethods
Intrinsically interpretable modelsCan a person read the model?Linear and logistic regression, small decision trees, rule lists, generalised additive models (GAMs), scoring cards
Global post-hocWhich features matter overall?Permutation importance, partial dependence, surrogate models
Local post-hocWhy this prediction?LIME, SHAP, counterfactual explanations, saliency maps

First rule: if a simple model gets nearly the accuracy, use it and skip the explanation machinery.

Permutation importance

Shuffle one feature's values and measure how much the score drops. A large drop means the model relies on it. It is model-agnostic, uses held-out data, and can mislead when features are correlated (shuffling one leaves its twin to compensate, hiding importance).

import random
random.seed(1)
def make(n):
    rows = []
    for _ in range(n):
        a, b, noise = random.gauss(0, 1), random.gauss(0, 1), random.gauss(0, 1)
        y = 1 if 2.0 * a + 0.5 * b + random.gauss(0, 0.5) > 0 else 0                # feature a matters most, b a little, noise not at all
        rows.append(([a, b, noise], y))
    return rows
train, test = make(2000), make(1000)
w, bias = [0.0, 0.0, 0.0], 0.0
import math
for _ in range(60):                                                                  # logistic regression by gradient descent
    gw, gb = [0.0] * 3, 0.0
    for x, y in train:
        p = 1 / (1 + math.exp(-(sum(wi * xi for wi, xi in zip(w, x)) + bias))); e = p - y
        gw = [g + e * xi for g, xi in zip(gw, x)]; gb += e
    w = [wi - 0.5 * g / len(train) for wi, g in zip(w, gw)]; bias -= 0.5 * gb / len(train)
def accuracy(rows): return sum(((sum(wi * xi for wi, xi in zip(w, x)) + bias) > 0) == (y == 1) for x, y in rows) / len(rows)
base = accuracy(test)
print("learned weights:", [round(v, 2) for v in w], "| test accuracy:", round(base, 3))
for j, name in enumerate(["a", "b", "noise"]):
    drops = []
    for _ in range(10):
        col = [x[j] for x, _ in test]; random.shuffle(col)
        shuffled = [([*x[:j], col[i], *x[j + 1:]], y) for i, (x, y) in enumerate(test)]
        drops.append(base - accuracy(shuffled))
    print(f"permuting {name:>5}: accuracy drops by {sum(drops) / len(drops):.3f}")

Output

learned weights: [2.99, 0.74, 0.0] | test accuracy: 0.918
permuting     a: accuracy drops by 0.403
permuting     b: accuracy drops by 0.045
permuting noise: accuracy drops by 0.000

Partial dependence

Vary one feature over a grid, hold the others at their observed values, and average the predictions: the average effect of that feature on the output. Plot one line per instance (ICE curves) to see heterogeneity that the average hides. Like permutation importance it assumes feature independence.

Local surrogates (LIME) and exact Shapley values (SHAP)

LIME perturbs the input near one example and fits a small interpretable model to the black box's responses in that neighbourhood. Shapley values come from cooperative game theory: the contribution of feature i is its average marginal contribution over all orders in which features could be added. They are the unique attribution satisfying efficiency (contributions sum to prediction minus baseline), symmetry, dummy and additivity. Exact computation is 2^n subsets, so SHAP uses tricks (TreeSHAP for trees, sampling or kernel approximations for others).

from itertools import combinations
from math import factorial
def model(x1, x2, x3): return 3 * x1 + 2 * x2 * x3 + 1                                # a model with an interaction between x2 and x3
instance, baseline = (1.0, 2.0, 3.0), (0.0, 0.0, 0.0)
def value(subset):                                                                    # features outside the subset take baseline values
    return model(*[instance[i] if i in subset else baseline[i] for i in range(3)])
n = 3; shap = []
for i in range(n):
    total = 0.0; others = [j for j in range(n) if j != i]
    for k in range(n):
        for S in combinations(others, k):
            weight = factorial(k) * factorial(n - k - 1) / factorial(n)
            total += weight * (value(set(S) | {i}) - value(set(S)))
    shap.append(total)
print("Shapley values:", [round(v, 2) for v in shap])
print("they sum to prediction minus baseline:", round(sum(shap), 2), "=", model(*instance) - model(*baseline))
print("x2 and x3 each receive half of the interaction term 2*x2*x3 = 12:", shap[1], shap[2])

Output

Shapley values: [3.0, 6.0, 6.0]
they sum to prediction minus baseline: 15.0 = 15.0
x2 and x3 each receive half of the interaction term 2*x2*x3 = 12: 6.0 6.0

Counterfactual explanations

"Your loan was declined; if your income were 5,000 higher it would be approved." Find the smallest change to the input that flips the decision; make it actionable (do not suggest changing age or immutable attributes) and plausible. This is the form of explanation most useful to the person affected.

Pitfalls

  • Explanation is not causation: attributions describe the model, not the world.
  • Saliency maps for images can be unreliable (sanity checks show some are insensitive to model weights).
  • Faithfulness versus plausibility: an explanation that looks reasonable may not reflect what the model used. For language models, written chain-of-thought can be unfaithful to the real computation.
  • Explanations can be gamed or used to launder bad models; validate with experts and ablation tests.

How this gets asked

What does a large accuracy drop after permuting a feature indicate?

  • The feature is irrelevant The opposite.
  • The model relies on that feature Correct.
  • The data leaked Not necessarily.
  • The feature is correlated with nothing No.

But correlated features can hide each other's importance.

What property do Shapley value attributions satisfy?

  • They are always positive No.
  • They sum to the prediction minus the baseline (efficiency) Correct.
  • They are causal No.
  • They are unique per model No.

Together with symmetry, dummy and additivity they are the unique fair attribution.

Why can an explanation be misleading?

  • Explanations are always accurate No.
  • It describes the model's behaviour, not causality in the world, and may look plausible without being faithful Correct.
  • It is too slow No.
  • It uses too much memory No.

Validate explanations with ablation tests and experts.

Self-check

Global versus local explanations?

Global methods describe overall feature influence; local methods explain one prediction (LIME, SHAP, counterfactuals).

Fairness: defining and measuring

Fairness has no single definition. Common group fairness criteria, for a protected attribute A (such as gender), a label Y and a prediction Y_hat:

CriterionRequiresIntuition
Demographic (statistical) parityP(Y_hat = 1 | A = a) equal for all groupsEqual selection rates
Equal opportunityEqual true positive rate across groupsQualified people are accepted equally often
Equalised oddsEqual true and false positive ratesEqual error rates of both kinds
Predictive parity / calibrationP(Y = 1 | score) equal across groupsA score means the same for everyone
Individual fairnessSimilar individuals receive similar outcomesNeeds a similarity metric
Counterfactual fairnessOutcome unchanged if the attribute were different (causally)Needs a causal model

Impossibility results: when base rates differ between groups, a non-perfect classifier cannot satisfy calibration and equalised odds at the same time (Kleinberg et al., Chouldechova). So fairness is a policy choice about which error matters, made with stakeholders, not a number to maximise blindly.

import random
random.seed(2)
def applicants(n):
    rows = []
    for _ in range(n):
        g = random.choice("AB")
        skill = random.gauss(0, 1) + (0.0 if g == "A" else -0.5)                       # historical disadvantage lowers B's measured score
        qualified = skill + random.gauss(0, 0.7) > 0.3 if g == "A" else skill + 0.5 + random.gauss(0, 0.7) > 0.3     # same true qualification rule
        rows.append((g, skill, qualified))
    return rows
data = applicants(20000)
def report(threshold_for):
    out = {}
    for g in "AB":
        grp = [(s, q) for gg, s, q in data if gg == g]
        pred = [(s > threshold_for[g], q) for s, q in grp]
        sel = sum(p for p, _ in pred) / len(pred)
        tpr = sum(p and q for p, q in pred) / max(1, sum(q for _, q in pred))
        fpr = sum(p and not q for p, q in pred) / max(1, sum(not q for _, q in pred))
        out[g] = (sel, tpr, fpr)
    return out
for name, th in [("one threshold (0.3)", {"A": 0.3, "B": 0.3}), ("group-specific thresholds", {"A": 0.3, "B": -0.2})]:
    r = report(th)
    print(f"{name:>26}: " + " | ".join(f"group {g}: selected {r[g][0]:.2f}, TPR {r[g][1]:.2f}, FPR {r[g][2]:.2f}" for g in "AB"))

Output

       one threshold (0.3): group A: selected 0.38, TPR 0.74, FPR 0.14 | group B: selected 0.21, TPR 0.48, FPR 0.03
 group-specific thresholds: group A: selected 0.38, TPR 0.74, FPR 0.14 | group B: selected 0.38, TPR 0.74, FPR 0.13

With one threshold the lower-scored group gets lower selection and true positive rates (the score is a biased measurement of ability); adjusting thresholds closes the gap but changes other metrics: a trade-off to be decided and documented, with legal advice, since using protected attributes for decisions can itself be unlawful in some contexts.

Where bias enters and how to mitigate

StageSourceMitigation
Problem framingTarget proxy (arrests instead of crime, cost instead of need)Choose the label deliberately
DataSampling bias, historical bias, label bias, missing groupsCollect representative data, audit labels, document
FeaturesProxies for protected attributes (zip code), measurement differencesReview features; test for proxy leakage
TrainingOptimising average accuracy hides minority errorsReweighting, fairness constraints, adversarial debiasing
Post-processingOne threshold for allGroup thresholds, calibrated outputs (within legal limits)
DeploymentFeedback loops, different populationsMonitor metrics per group, appeals process

Always evaluate by slices (group, region, device, language); report the worst group, not only the average; and include human oversight and contestability for consequential decisions.

How this gets asked

What is demographic parity?

  • Equal accuracy No.
  • Equal positive prediction (selection) rates across groups Correct.
  • Equal feature values No.
  • Equal group sizes No.

It ignores whether the groups have different base rates.

Why can't a classifier usually satisfy calibration and equalised odds at once when base rates differ?

  • Computation limits No.
  • It is a mathematical impossibility for imperfect classifiers, so the choice is a policy decision Correct.
  • Bad code No.
  • Small datasets No.

Kleinberg and Chouldechova showed the incompatibility.

Self-check

Name three group fairness criteria.

Demographic parity, equal opportunity (equal true positive rates) and equalised odds.

Privacy

Models can memorise training data (language models emit rare strings; attacks recover training examples or tell if a record was in the training set: membership inference). Protections:

  • Data minimisation, access control, retention limits, encryption, de-identification (remove direct identifiers). Beware that "anonymised" data can be re-identified by linking quasi-identifiers (zip, birth date, gender identify most people).
  • k-anonymity: every combination of quasi-identifiers appears at least k times.
  • Differential privacy (DP): a mechanism is epsilon-DP if adding or removing any one person changes the probability of any output by at most a factor e^epsilon. Smaller epsilon means stronger privacy and noisier answers. The Laplace mechanism adds noise with scale sensitivity / epsilon to a query.
  • DP-SGD: clip each example's gradient and add Gaussian noise during training, with a privacy accountant tracking the budget.
  • Federated learning: train on devices and send only updates (still needs DP and secure aggregation).
  • Synthetic data and secure computation (homomorphic encryption, trusted hardware) in specific settings.
import random, math
random.seed(3)
ages = [random.randint(18, 80) for _ in range(1000)]
true_count = sum(a > 60 for a in ages)                              # a counting query: sensitivity 1 (one person changes it by at most 1)
def laplace(scale):                                                 # Laplace noise as the difference of two exponentials
    return random.expovariate(1 / scale) - random.expovariate(1 / scale)
def private_count(epsilon): return true_count + laplace(1 / epsilon)
print("true count of people over 60:", true_count)
for eps in (0.1, 1.0, 10.0):
    answers = [private_count(eps) for _ in range(2000)]
    err = sum(abs(a - true_count) for a in answers) / len(answers)
    print(f"epsilon {eps:>4}: typical absolute error {err:6.2f} (theory: 1/epsilon = {1 / eps:5.1f})")

Output

true count of people over 60: 322
epsilon  0.1: typical absolute error  10.03 (theory: 1/epsilon =  10.0)
epsilon  1.0: typical absolute error   1.02 (theory: 1/epsilon =   1.0)
epsilon 10.0: typical absolute error   0.10 (theory: 1/epsilon =   0.1)

How this gets asked

A counting query has sensitivity 1. With epsilon = 0.5, what is the Laplace noise scale?

Scale = sensitivity / epsilon = 1 / 0.5 = 2.

What does a smaller epsilon mean in differential privacy?

  • Weaker privacy, more accuracy Opposite.
  • Stronger privacy and more noise Correct.
  • No noise No.
  • Faster queries No.

It is a privacy budget.

Self-check

What is membership inference?

An attack that determines whether a specific record was in a model's training set, exploiting differences in model behaviour on seen and unseen data.

Robustness and adversarial examples

Small, carefully chosen perturbations can flip a model's prediction while looking identical to people. For a differentiable model the fast gradient sign method (FGSM) moves the input by epsilon in the direction that increases the loss: x_adv = x + epsilon x sign(grad_x loss).

import random, math
random.seed(4)
dim = 100
w_true = [random.gauss(0, 1) for _ in range(dim)]
def sample():
    y = random.choice([-1, 1]); x = [y * 0.2 * wi + random.gauss(0, 1) for wi in w_true]; return x, y         # many small weak signals
train = [sample() for _ in range(2000)]
w = [0.0] * dim
for _ in range(40):
    grad = [0.0] * dim
    for x, y in train:
        z = y * sum(wi * xi for wi, xi in zip(w, x)); s = -y / (1 + math.exp(z))
        grad = [g + s * xi for g, xi in zip(grad, x)]
    w = [wi - 0.1 * g / len(train) for wi, g in zip(w, grad)]
test = [sample() for _ in range(1000)]
acc = lambda data: sum((sum(wi * xi for wi, xi in zip(w, x)) > 0) == (y == 1) for x, y in data) / len(data)
def attack(x, y, eps): return [xi - eps * y * (1 if wi > 0 else -1) for xi, wi in zip(x, w)]              # step against the true class along sign(w)
print("clean accuracy:", round(acc(test), 3))
for eps in (0.05, 0.1, 0.2, 0.4):
    print(f"perturbation of size {eps} per coordinate -> accuracy {acc([(attack(x, y, eps), y) for x, y in test]):.3f}")

Output

clean accuracy: 0.963
perturbation of size 0.05 per coordinate -> accuracy 0.926
perturbation of size 0.1 per coordinate -> accuracy 0.853
perturbation of size 0.2 per coordinate -> accuracy 0.595
perturbation of size 0.4 per coordinate -> accuracy 0.078

A tiny change per coordinate is enough to wreck accuracy because the effect adds up across 100 dimensions: high-dimensional models are inherently fragile. Defences: adversarial training (train on attacked examples), input preprocessing, certified robustness bounds, ensembles, and detection. For language models the analogues are prompt injection and jailbreaks (A6); treat model output as untrusted and constrain actions. Other robustness concerns: distribution shift (covariate, label, concept), spurious correlations (a model that recognises cows by grass), data poisoning and backdoors, and model extraction through the API.

How this gets asked

What does FGSM do?

  • Trains faster No.
  • Perturbs the input in the direction of the sign of the loss gradient to cause misclassification Correct.
  • Compresses images No.
  • Measures fairness No.

Tiny per-coordinate changes add up in high dimensions.

Self-check

Name two defences against adversarial examples.

Adversarial training and certified or randomised smoothing defences (also input preprocessing and ensembles).

Governance and documentation

  • Model cards record intended use, training data, evaluation by slice, limitations and ethical considerations; datasheets for datasets record how data was collected and its biases.
  • Risk assessment before launch: who is affected, what can go wrong, severity, reversibility; classify by risk tier (the EU AI Act bans some uses, regulates "high-risk" ones and imposes transparency duties on others).
  • Human oversight: human-in-the-loop for high-stakes decisions, with the ability to override, and appeals.
  • Monitoring in production: performance, drift, fairness metrics per group, incident reporting, and a rollback plan (A7).
  • Red teaming and external audits; transparency to users when they interact with AI or when content is AI-generated; provenance (watermarks, content credentials).
  • Reproducibility: version data, code and configuration; keep decision logs.

Key idea

Prefer simple models when they suffice; explain complex ones with permutation importance, Shapley values and counterfactuals while knowing their limits; choose fairness criteria deliberately, measure them per group and accept that they trade off; protect privacy with minimisation and differential privacy; test robustness against adversaries and shift; and document, monitor and keep humans in the loop.

Interview questions: Responsible AI

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic Why prefer an interpretable model when possible?

Simple models can be audited, debugged and trusted more easily, and often perform nearly as well on tabular data.

Basic What is permutation importance?

The drop in a held-out metric when one feature's values are shuffled, showing reliance on that feature; it can mislead with correlated features.

Medium Explain Shapley values for feature attribution.

Each feature's average marginal contribution over all orders of adding features; they sum to the prediction minus the baseline and are computed exactly for small models or approximated (TreeSHAP, sampling).

Medium What is a counterfactual explanation?

The smallest feasible change to the input that would change the decision, such as 'approved if income were 5,000 higher', ideally actionable and plausible.

Medium Define demographic parity, equal opportunity and equalised odds.

Equal selection rates across groups; equal true positive rates; equal true and false positive rates.

Medium Why can't all fairness criteria hold at once?

When base rates differ, calibration and equalised odds are mutually incompatible for imperfect classifiers, so choices reflect policy and context.

Medium Where does bias enter an ML system?

In problem framing and labels, sampling and historical data, proxy features, optimisation of average metrics, thresholds, and deployment feedback loops.

Medium What is differential privacy?

A guarantee that any one person's data changes the probability of any output by at most a factor e^epsilon, achieved by adding calibrated noise.

Medium What is membership inference?

An attack that decides whether a record was in the training data by exploiting model confidence differences, a privacy risk for overfit models.

Advanced What is an adversarial example and how does FGSM make one?

An input with a small, targeted perturbation that changes the prediction; FGSM adds epsilon times the sign of the loss gradient with respect to the input.

Advanced How do you defend against adversarial attacks?

Adversarial training, certified or randomised-smoothing defences, input validation, ensembles and monitoring, plus treating model outputs as untrusted in downstream systems.

Advanced What belongs in a model card?

Intended use and limits, training data, metrics by slice, ethical considerations, risks and maintenance contacts.

Advanced How do you test for proxy discrimination?

Check whether non-protected features predict the protected attribute, evaluate outcomes and error rates by group, and use counterfactual tests or feature ablations.

Advanced What does DP-SGD do?

It clips each example's gradient and adds Gaussian noise during training, with accounting that tracks the privacy budget spent.
