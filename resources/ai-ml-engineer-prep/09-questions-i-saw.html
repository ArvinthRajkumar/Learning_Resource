1. KV cache size

A model has 32 layers, 8 KV heads, head dimension 128 and an fp16 KV cache. You run a batch of 4 sequences of 8,192 tokens each. How much memory does the KV cache need?

  • 16 GiB Uses 32 heads instead of the 8 KV heads (4x too big).
  • 1 GiB One sequence only. The batch is 4.
  • 32 GiB 32 heads and 4-byte elements: two mistakes.
  • 4 GiB 2 x 32 x 8 x 128 x 8192 x 4 x 2 = 2^32 bytes = 4 GiB.

128 KiB per token (2 x 32 x 8 x 128 x 2 bytes) times 32,768 tokens = 4 GiB exactly (4.295 GB).

Python check
kv = 2 * 32 * 8 * 128 * 8192 * 4 * 2
print(kv, kv / 1024**3)   # 4294967296 4.0

2. Speculative decoding

Which statement about speculative decoding is correct?

  • Each rejected draft token costs a full extra target forward pass The target scores all drafted positions in one pass. The replacement token comes from that same pass.
  • The output follows the same distribution as sampling from the target model alone Correct. Rejection sampling (accept with min(1, p/q), resample from max(0, p - q)) is exactly distribution-preserving.
  • It only speeds things up at temperature 0 The acceptance rule works for any sampling distribution. Acceptance is often higher at low temperature, but not exclusively.
  • Output quality is capped by the draft model The target decides every emitted token. The draft only affects speed.

Speculative decoding is lossless with respect to the target distribution. The speedup depends on the acceptance rate, the draft's cost and k: E[tokens per target pass] = (1 - a^(k+1))/(1 - a).

3. RAG: high recall, low accuracy

Your RAG system has recall@20 = 0.93 but answer accuracy = 0.61, and wrong answers quote the wrong chunk. What is the best next change?

  • Add a cross-encoder reranker and pass only the top 3 to 5 chunks Retrieval already finds the chunk. Precision at the top and less distraction fix the generation stage.
  • Raise the temperature Randomness does not help pick the right evidence. It usually lowers factual accuracy.
  • Retrieve 50 chunks instead of 20 Recall is already 0.93. More chunks mean more distractors, more cost and worse lost-in-the-middle effects.
  • Use an embedding model with bigger dimensions Targets first-stage recall, which is not the failing stage, and forces a full re-embed.

Diagnose by stage: high recall@k plus low accuracy points past retrieval to ranking or generation. A reranker scores (question, chunk) jointly, and trimming to the top few removes look-alike distractors.

Learn it: Diagnose a RAG system by stage

4. New embedding model, same dimension

Your provider releases a new 1,536-dimension embedding model (the same dimension as your current one). What should you do with the existing index?

  • Nothing, the dimensions match Same shape, different meaning: each model has its own vector space.
  • Embed only new documents with the new model Mixes two incompatible spaces in one index. Query-to-old-doc similarities become meaningless.
  • Re-embed the entire corpus with the new model Correct. Queries must use the new model too. Do it blue/green: dual-write, backfill, evaluate, switch reads.
  • Normalize the old vectors Normalization changes length, not direction in a foreign space.

Vectors are only comparable within the model that produced them, even at equal dimension.

5. Prompt order for prefix caching

A prompt contains: a system prompt plus tool definitions (never change), a 20k-token product manual (updated weekly) and the user's question. With longest-repeated-prefix caching, which order maximizes cache hits?

  • System + tools, then manual, then user question Static, then semi-static, then dynamic. The shared prefix covers about 22k tokens.
  • User question, then system + tools, then manual The first tokens change on every request, so nothing is reusable.
  • Manual, then system + tools, then user question Works within a week, but the manual's weekly change invalidates the never-changing system and tools part behind it.
  • System + tools, then user question, then manual The question in the middle blocks reuse of the 20k-token manual.

KV at position i depends on all earlier tokens, so only an identical prefix can be reused. Put content in order of how rarely it changes. These option wordings are reconstructed. The rule decides any variant: the most stable content goes first.

Python check
static, manual, question = 2000, 20000, 100   # illustrative token counts
print((static + manual) / (static + manual + question))   # 0.9955 of the prompt is cacheable

6. Why 4-bit weight quantization speeds up decoding

Why does 4-bit weight-only quantization (AWQ, GPTQ) speed up single-user decoding?

  • Fewer layers run per token Every layer still runs. Only the storage format of the weights changes.
  • Decoding is memory-bandwidth bound, so reading about 4x fewer weight bytes per token is the win Correct. At batch 1 each weight byte supports about 1 FLOP, far below the GPU's ridge point (about 150 to 300 FLOP/byte).
  • Attention becomes linear The attention algorithm is unchanged by the weight format.
  • Matmuls run in int4 Weights are dequantized to fp16/bf16 in registers (W4A16). The arithmetic is still 16-bit.

Decode time per token is roughly weight bytes / bandwidth. An 8B model on an H100 (~3.35 TB/s, approximate vendor figure): 4.78 ms per token in bf16 versus 1.23 ms at about 4.125 bits per weight.

Python check
bw = 3.35e12                       # H100 SXM HBM bandwidth, approximate
print(16e9 / bw * 1e3)             # 4.78 ms/token, bf16 8B
print(8e9 * 4.125 / 8 / bw * 1e3)  # 1.23 ms/token, int4 + group scales
print(16 / 4.125)                  # 3.88x fewer bytes

Learn it: Roofline and quantization

7. What raises throughput for many concurrent requests

Which techniques raise throughput for many concurrent requests? Select all that apply.

  • Raise max_new_tokens for every request Requests occupy slots and KV memory longer, so fewer fit and useful throughput drops.
  • Continuous batching Refills batch slots every step, so there are no idle slots behind long requests.
  • PagedAttention Block-allocated KV cache: almost no fragmentation, more concurrent sequences.
  • Prefix caching of a shared system prompt Skips repeated prefill and stores shared KV blocks once.
  • Disabling the KV cache Forces recomputation of all previous tokens at every step. Far slower.

Throughput comes from keeping the batch full (continuous batching) and fitting more sequences in memory (PagedAttention, prefix sharing, quantized KV).

Learn it: Throughput techniques

8. Grammar-constrained decoding

You use grammar-constrained decoding against a JSON schema. Which statements are true? Select all.

  • It removes the need for an eval set Structure is guaranteed, correctness is not. You still measure accuracy.
  • A short reasoning field placed before the answer field can improve accuracy Generation is left to right, so the answer tokens can condition on the reasoning tokens.
  • An overly strict enum can force a wrong value If the truth is not among the options, the mask forces one of them anyway. Add an unknown option.
  • Field values are guaranteed correct Only syntax and schema shape are guaranteed.
  • The output always parses as schema-valid JSON That is the guarantee (assuming generation is not cut off by the token limit).

Constrained decoding masks illegal tokens at each step. It controls form, not truth.

9. LoRA r = 16, alpha = 32 on q and v

LoRA with r = 16 and alpha = 32 is applied to the q and v projections. Which statements are true? Select all.

  • The adapter can be merged into the base weights for no extra inference latency W' = W + (alpha/r) BA has the original shape.
  • It removes activation memory Activations are still needed to backpropagate through the frozen layers. LoRA saves gradient and optimizer memory.
  • The scale is alpha / r = 2 32 / 16 = 2.
  • Only the A and B matrices are trained The base weights are frozen.
  • Higher rank is always better Returns diminish, and overfitting risk and cost grow. Rank is a hyperparameter.

For a 4096 x 4096 projection: 16 x (4096 + 4096) = 131,072 trainable parameters per module. q + v over 32 layers gives 8,388,608.

Python check
r, alpha, d, layers = 16, 32, 4096, 32
print(alpha / r)                  # 2.0
print(r * (d + d) * 2 * layers)   # 8388608 trainable params (q and v)

Learn it: LoRA

10. Prompt A vs Prompt B: is 3 points real?

On the same 200 questions, Prompt A gets 156 right (78%) and Prompt B gets 162 right (81%). They disagree on 30 questions: B is right on 18, A on 12. What is the right conclusion?

  • A is better A scored lower, and there is no evidence for A.
  • They cannot be compared Shared questions make a paired comparison ideal. It is just not conclusive here.
  • B is significantly better Exact sign test: p = 0.36, far above 0.05.
  • The difference is not statistically significant (p about 0.36) Exact two-sided binomial test on the 30 discordant pairs gives 0.3616. McNemar with continuity correction gives 0.361.

Only the 30 disagreements carry information: the 144 both-right and 26 both-wrong cancel out of the difference. Under 'no difference', each disagreement is a fair coin, and 18 or more heads (or 12 or fewer) out of 30 happens 36% of the time. The unpaired z-test (p = 0.457) is the wrong tool because it ignores the pairing. With 30 disagreements you would need at least 21 to 9 for p < 0.05.

Python check
from math import comb, erfc, sqrt
p = 2 * sum(comb(30, k) for k in range(18, 31)) / 2**30
print(round(p, 4))                              # 0.3616  exact sign test
print(round(erfc(sqrt(((18-12)**2/30) / 2)), 4))  # 0.2733  McNemar, no correction
print(round(erfc(sqrt(((6-1)**2/30) / 2)), 4))    # 0.3613  McNemar, continuity corrected

Learn it: Paired tests

11. Tamil costs about 3x the tokens

The same message uses about 3x more tokens in Tamil than in English with a byte-level BPE tokenizer. Why?

  • The model translates Tamil to English internally There is no hidden translation step. Tokens are counted on the input as given.
  • Tokenizers count characters They segment bytes into learned subword units.
  • The provider adds a surcharge for non-English text Billing is per token. The token count is genuinely higher.
  • Tamil characters are 3 bytes each in UTF-8, and BPE merges were learned mostly from English Correct: 3x more starting symbols and few learned merges for Tamil byte sequences.

Byte-level BPE starts from UTF-8 bytes and only compresses patterns frequent in its training data. Exact token counts depend on the tokenizer. Byte counts are exact.

Python check
word = "வணக்கம்"
print(len(word), len(word.encode("utf-8")))   # 7 code points, 21 bytes
print(all(len(chr(c).encode()) == 3 for c in range(0x0B80, 0x0C00)))  # True: the whole Tamil block

12. DPO blanks

DPO uses a frozen model, and needs no separately trained model.

Reference (usually the SFT checkpoint) and reward. The loss is -log sigmoid(beta x [(log pi(y_w) - log pi_ref(y_w)) - (log pi(y_l) - log pi_ref(y_l))]). The reward is implicit in the log-ratios.

14. RRF formula

Reciprocal Rank Fusion: score = sum over ranked lists of 1 / (k + ), with k conventionally .

The document's 1-based rank in each list, and k = 60 (Cormack et al., 2009).

Python check
bm25, dense = ["D3", "D1", "D7"], ["D1", "D9", "D3"]
score = {}
for lst in (bm25, dense):
    for rank, d in enumerate(lst, start=1):
        score[d] = score.get(d, 0) + 1 / (60 + rank)
print(sorted(score, key=lambda d: -score[d]))   # ['D1', 'D3', 'D9', 'D7']

15. Name the metric

The ranking metric that discounts gain by log2(1 + position) and normalizes by the ideal ordering is .

nDCG: DCG@k = sum of gain_i / log2(i + 1), divided by the DCG of the ideal ordering of all judged documents.

Python check
import math
dcg  = 3/math.log2(2) + 2/math.log2(4) + 1/math.log2(6)                 # ranked: rel 3, 0, 2, 0, 1

17. The refund that timed out

An agent's create_refund tool call times out after the refund was actually created. What is the safest design?

  • An idempotency key generated once per logical refund and reused on every retry Retries become safe: the server sees the same key and returns the original refund instead of creating a second one.
  • A 5-minute timeout and no retries The ambiguity remains (timeouts still happen), real failures are never recovered, and users wait minutes.
  • Exponential backoff alone Backoff decides when to retry, not whether a retry duplicates the refund.
  • Let the LLM decide whether to retry The model cannot observe whether the refund happened. Money handling must be deterministic.

At-least-once delivery (retries) plus idempotent processing (server-side dedup by key, enforced atomically) gives an exactly-once effect. Generate the key in code, persist it with the agent state, never let the model invent it.

Learn it: Idempotency
