Part A13

Time series: forecasting, seasonality, stationarity and anomaly detection

Time series break the assumption behind most of machine learning: that examples are independent. Today depends on yesterday. This part shows how to describe, forecast and monitor such data, and how to evaluate forecasts without fooling yourself.

MediumAdvanced~5 hours

What makes time series different

Observations are ordered and dependent. Consequences:

  • Never shuffle the data for splitting. Training must use the past and testing the future; otherwise information leaks backward in time (look-ahead bias).
  • Features include lags, rolling statistics and calendar effects (hour, weekday, holiday).
  • Structure to look for: trend (long-run direction), seasonality (repeating pattern with a known period), cycles (irregular longer swings), noise, and level shifts or outliers.
  • Frequency and gaps matter: resample to a regular grid, decide how to fill missing values (forward-fill, interpolate, leave as missing) and keep time zones consistent.

Typical tasks: forecasting (demand, traffic, load, revenue), anomaly detection (outages, fraud, sensor faults), classification of sequences, nowcasting and causal impact estimation.

How this gets asked

Why must time series not be randomly shuffled for train-test splits?

  • It is slower No.
  • The future would leak into training, giving unrealistically good scores Correct.
  • Shuffling changes the mean No.
  • Time series have no labels No.

Always train on the past and test on the future.

Decomposition: trend, season, remainder

A series is often modelled as y = trend + seasonal + remainder (additive) or y = trend x seasonal x remainder (multiplicative; use when seasonal swings grow with the level, or take logs to make it additive). A simple decomposition: estimate the trend with a centred moving average over one period, average the detrended values for each position in the cycle to get the seasonal profile, and what is left is the remainder.

import math, random
random.seed(1)
period, n = 7, 70
series = [50 + 0.5 * t + 10 * math.sin(2 * math.pi * (t % period) / period) + random.gauss(0, 1.5) for t in range(n)]    # trend + weekly season + noise
def moving_average(x, w):                                              # centred moving average for odd w
    h = w // 2
    return [sum(x[i - h:i + h + 1]) / w if h <= i < len(x) - h else None for i in range(len(x))]
trend = moving_average(series, period)
detrended = [s - t if t is not None else None for s, t in zip(series, trend)]
seasonal = [sum(d for i, d in enumerate(detrended) if d is not None and i % period == k) / sum(1 for i, d in enumerate(detrended) if d is not None and i % period == k) for k in range(period)]
mean_seasonal = sum(seasonal) / period
seasonal = [s - mean_seasonal for s in seasonal]                       # centre the seasonal profile at zero
true_profile = [10 * math.sin(2 * math.pi * k / period) for k in range(period)]
print("estimated seasonal profile:", [round(s, 1) for s in seasonal])
print("true seasonal profile     :", [round(s, 1) for s in true_profile])
rem = [d - seasonal[i % period] for i, d in enumerate(detrended) if d is not None]
print("remainder std (should be about the noise level 1.5):", round((sum(r * r for r in rem) / len(rem)) ** 0.5, 2))

Output

estimated seasonal profile: [-0.8, 8.2, 9.9, 4.3, -4.5, -9.3, -7.8]
true seasonal profile     : [0.0, 7.8, 9.7, 4.3, -4.3, -9.7, -7.8]
remainder std (should be about the noise level 1.5): 1.26

import random, math
random.seed(2)
period, n = 7, 120
y = [100 + 0.3 * t + 12 * math.sin(2 * math.pi * (t % period) / period) + random.gauss(0, 2) for t in range(n)]
train, test = y[:100], y[100:]
def mae(a, b): return sum(abs(p - q) for p, q in zip(a, b)) / len(a)
naive = [train[-1]] * len(test)
seasonal_naive = [train[len(train) - period + (i % period)] for i in range(len(test))]
def ses(x, alpha):
    level = x[0]
    for v in x[1:]: level = alpha * v + (1 - alpha) * level
    return level
ses_fc = [ses(train, 0.3)] * len(test)
def holt_winters(x, period, alpha=0.3, beta=0.05, gamma=0.3, horizon=20):
    level, trend = sum(x[:period]) / period, (sum(x[period:2 * period]) - sum(x[:period])) / period ** 2
    season = [x[i] - level for i in range(period)]
    for t in range(period, len(x)):
        last_level = level
        level = alpha * (x[t] - season[t % period]) + (1 - alpha) * (level + trend)
        trend = beta * (level - last_level) + (1 - beta) * trend
        season[t % period] = gamma * (x[t] - level) + (1 - gamma) * season[t % period]
    return [level + (h + 1) * trend + season[(len(x) + h) % period] for h in range(horizon)]
hw = holt_winters(train, period, horizon=len(test))
for name, fc in [("naive", naive), ("seasonal naive", seasonal_naive), ("simple exp. smoothing", ses_fc), ("Holt-Winters", hw)]:
    print(f"{name:>22}: MAE {mae(test, fc):6.2f}")

Autocorrelation and stationarity

The autocorrelation function (ACF) at lag k is the correlation between the series and itself shifted by k. Peaks at lag 7 reveal a weekly pattern; slow decay reveals trend or a unit root; the partial ACF isolates the direct effect of each lag.

A series is (weakly) stationary when its mean, variance and autocorrelation do not change over time. Many classic models (ARMA) assume stationarity, so transform first: difference (y_t - y_(t-1)) to remove trend, seasonal difference (y_t - y_(t-m)) to remove seasonality, take logs to stabilise variance. A random walk is non-stationary but its differences are stationary noise; the Augmented Dickey-Fuller test checks for a unit root.

import random, math
random.seed(3)
def acf(x, max_lag):
    m = sum(x) / len(x); var = sum((v - m) ** 2 for v in x)
    return [sum((x[i] - m) * (x[i + k] - m) for i in range(len(x) - k)) / var for k in range(max_lag + 1)]
n = 400
white = [random.gauss(0, 1) for _ in range(n)]
walk = [0.0]
for _ in range(n - 1): walk.append(walk[-1] + random.gauss(0, 1))
weekly = [math.sin(2 * math.pi * t / 7) + random.gauss(0, 0.3) for t in range(n)]
diff = [walk[i] - walk[i - 1] for i in range(1, n)]
for name, s in [("white noise", white), ("random walk", walk), ("weekly season", weekly), ("differenced walk", diff)]:
    a = acf(s, 8)
    print(f"{name:>17}: ACF lags 1..8 =", [round(v, 2) for v in a[1:]])

Output

      white noise: ACF lags 1..8 = [-0.06, 0.05, 0.0, 0.05, -0.05, 0.02, -0.02, -0.04]
      random walk: ACF lags 1..8 = [0.99, 0.98, 0.98, 0.97, 0.96, 0.96, 0.95, 0.95]
    weekly season: ACF lags 1..8 = [0.5, -0.18, -0.73, -0.75, -0.18, 0.51, 0.83, 0.52]
 differenced walk: ACF lags 1..8 = [0.03, 0.02, -0.01, -0.04, -0.04, 0.01, -0.04, -0.04]

White noise has near-zero ACF; the random walk's ACF decays very slowly (non-stationary) but its first difference looks like white noise; the weekly series peaks at lag 7.

Autoregressive models from scratch

An AR(p) model predicts the next value from the previous p: y_t = c + phi_1 y_(t-1) + ... + phi_p y_(t-p) + noise. Fit by least squares on lag features (plain linear regression). ARIMA(p, d, q) adds d differences and q moving-average error terms; SARIMA adds seasonal terms.

import random
random.seed(4)
TRUE_PHI = (0.6, -0.3)
y = [0.0, 0.0]
for _ in range(1500): y.append(TRUE_PHI[0] * y[-1] + TRUE_PHI[1] * y[-2] + random.gauss(0, 1))
def solve(A, b):                                               # Gaussian elimination for the normal equations
    n = len(b); M = [row[:] + [b[i]] for i, row in enumerate(A)]
    for i in range(n):
        p = max(range(i, n), key=lambda r: abs(M[r][i])); M[i], M[p] = M[p], M[i]
        for r in range(i + 1, n):
            f = M[r][i] / M[i][i]
            for c in range(i, n + 1): M[r][c] -= f * M[i][c]
    x = [0.0] * n
    for i in reversed(range(n)): x[i] = (M[i][n] - sum(M[i][j] * x[j] for j in range(i + 1, n))) / M[i][i]
    return x
def fit_ar(series, p):
    X = [[1.0] + [series[t - k] for k in range(1, p + 1)] for t in range(p, len(series))]
    target = [series[t] for t in range(p, len(series))]
    XtX = [[sum(X[r][i] * X[r][j] for r in range(len(X))) for j in range(p + 1)] for i in range(p + 1)]
    Xty = [sum(X[r][i] * target[r] for r in range(len(X))) for i in range(p + 1)]
    return solve(XtX, Xty)
coef = fit_ar(y, 2)
print("true phi:", TRUE_PHI, "| estimated phi:", [round(c, 2) for c in coef[1:]], "| intercept:", round(coef[0], 2))
def forecast(series, coef, steps):
    out, hist = [], series[:]
    for _ in range(steps):
        nxt = coef[0] + sum(coef[k] * hist[-k] for k in range(1, len(coef))); out.append(nxt); hist.append(nxt)
    return out
print("multi-step forecasts decay toward the mean:", [round(v, 2) for v in forecast(y, coef, 6)])

Output

true phi: (0.6, -0.3) | estimated phi: [0.58, -0.25] | intercept: 0.01
multi-step forecasts decay toward the mean: [0.95, 0.03, -0.21, -0.12, -0.0, 0.04]

Forecasts several steps ahead feed on their own predictions, so uncertainty widens with the horizon and point forecasts regress toward the mean; report prediction intervals (from the model's noise or by quantile regression) not just a line.

Machine learning on time series

Turn forecasting into supervised learning with lag features and rolling statistics, plus calendar and external features (price, promotions, weather), then use a tree ensemble or a linear model. Care points:

  • Build features using only past information at prediction time (shift before rolling; features known in the future, such as holidays, are allowed).
  • Direct strategy (a model per horizon) versus recursive (one-step model fed its own forecasts, errors compound).
  • Many series: one global model across series (with series id or statistics as features) often beats one model per series.
  • Intermittent demand (many zeros) needs specialised methods (Croston) or probabilistic models.
  • Hierarchies (store, region, country) need reconciliation so forecasts add up.
import random, math
random.seed(5)
n = 300
x = [20 + 0.05 * t + 6 * math.sin(2 * math.pi * t / 24) + random.gauss(0, 1) for t in range(n)]      # hourly-like with a 24-step cycle
def features(series, t):                                       # only information available before time t
    window = series[max(0, t - 24):t]
    return [series[t - 1], series[t - 24], sum(window) / len(window), t % 24]
rows = [(features(x, t), x[t]) for t in range(48, n)]
split = int(len(rows) * 0.8)
train, test = rows[:split], rows[split:]
def knn_predict(train, f, k=5):
    near = sorted(train, key=lambda r: sum((a - b) ** 2 for a, b in zip(r[0], f)))[:k]
    return sum(r[1] for r in near) / k
pred = [knn_predict(train, f) for f, _ in test]
mae = lambda a, b: sum(abs(p - q) for p, q in zip(a, b)) / len(a)
seasonal_naive = [f[1] for f, _ in test]                       # feature 1 is the value 24 steps ago
print(f"nearest-neighbour regression on lag features MAE {mae([t for _, t in test], pred):.2f} | seasonal naive MAE {mae([t for _, t in test], seasonal_naive):.2f}")

Output

nearest-neighbour regression on lag features MAE 1.52 | seasonal naive MAE 1.51

Self-check

Direct versus recursive multi-step forecasting?

Direct trains a model per horizon; recursive repeats a one-step model feeding back its forecasts, which compounds error.

Evaluation: backtesting honestly

A single train-test split can be lucky. Use rolling-origin (walk-forward) evaluation: train on data up to time T, forecast the next h steps, score, move the origin forward, repeat, and average. Use an expanding window (all history) or a sliding window (recent history only, adapts faster) and keep the gap between training end and test start equal to your real deployment delay.

import random, math
random.seed(6)
period, n = 7, 160
y = [100 + 0.2 * t + 10 * math.sin(2 * math.pi * (t % period) / period) + random.gauss(0, 2) for t in range(n)]
def seasonal_naive(train, h): return [train[len(train) - period + (i % period)] for i in range(h)]
def mean_forecast(train, h): return [sum(train[-28:]) / 28] * h
def walk_forward(model, start=80, horizon=7, step=7):
    errors = []
    for origin in range(start, n - horizon + 1, step):
        fc = model(y[:origin], horizon)
        errors += [abs(a - b) for a, b in zip(y[origin:origin + horizon], fc)]
    return sum(errors) / len(errors)
naive_errors = [abs(y[t] - y[t - 1]) for t in range(1, n)]
naive_mae = sum(naive_errors) / len(naive_errors)
for name, model in [("seasonal naive", seasonal_naive), ("trailing mean", mean_forecast)]:
    m = walk_forward(model)
    print(f"{name:>15}: walk-forward MAE {m:5.2f} | MASE vs one-step naive {m / naive_mae:4.2f}")

Output

 seasonal naive: walk-forward MAE  2.56 | MASE vs one-step naive 0.44
  trailing mean: walk-forward MAE  6.69 | MASE vs one-step naive 1.14

Report the metric per horizon (error grows with lead time), per segment (volume tier, region) and as a business cost (stock-outs versus overstock are not symmetric). Beware leakage from future-looking normalisation and from tuning hyperparameters on the test period.

Anomaly detection

Define what "anomalous" means for the use: point anomalies (a spike), contextual anomalies (normal value at the wrong time: 3 am traffic at noon levels), and collective anomalies (a sequence is odd). Approaches:

ApproachIdea
Thresholds / control chartsAlert beyond mean ± 3 sigma (use robust statistics)
Residual-basedForecast with a good model, flag large residuals relative to their spread
Seasonal-aware baselinesCompare with the same hour last week
Robust z-score (MAD)Median and median absolute deviation resist the outliers themselves
Change-point detectionCUSUM, Bayesian online change point detection for level shifts
Isolation forest, one-class modelsUnsupervised outlier scores on feature windows
AutoencodersHigh reconstruction error means unusual
SupervisedWhen labelled incidents exist

Practical concerns: alert fatigue (tune for precision, set a minimum duration), seasonality (a naive threshold fires every evening), drift (baselines must adapt), and explanations (which metric and by how much).

import random, math, statistics
random.seed(7)
period, n = 24, 24 * 14
y = [50 + 20 * math.sin(2 * math.pi * (t % period) / period) + random.gauss(0, 2) for t in range(n)]
injected = {200: +40, 250: -35, 300: +30}                    # three spikes
for t, d in injected.items(): y[t] += d
naive_flags = [t for t in range(n) if abs(y[t] - statistics.mean(y)) > 3 * statistics.pstdev(y)]
def seasonal_flags(y, period, history_days=7, threshold=5):
    profile = [statistics.median(y[d * period + h] for d in range(history_days)) for h in range(period)]       # typical value for each hour of day
    resid = [y[t] - profile[t % period] for t in range(len(y))]
    med = statistics.median(resid); mad = statistics.median(abs(r - med) for r in resid)                        # robust spread of the residuals
    scale = 1.4826 * mad
    return [t for t, r in enumerate(resid) if abs(r - med) / scale > threshold]
flags = seasonal_flags(y, period)
print("injected anomalies:", sorted(injected))
print("global 3-sigma threshold flags:", naive_flags, "(misses anomalies hidden inside the daily swing)")
print("seasonal robust z-score flags :", flags)

Output

injected anomalies: [200, 250, 300]
global 3-sigma threshold flags: [200] (misses anomalies hidden inside the daily swing)
seasonal robust z-score flags : [200, 250, 300]

Self-check

Why does a global 3-sigma threshold fail on seasonal data?

Normal seasonal peaks and troughs look extreme or hide real anomalies; compare with the same time in previous cycles.

Putting it into production

  • Monitor forecast error continuously; retrain on a schedule or when error drifts; keep a fallback (seasonal naive) when the model fails or data is late.
  • Data quality: late-arriving data, backfills and revisions change history; store as-of versions so backtests use what was known at the time.
  • Business rules: round to whole units, enforce minimums and maximums, handle new items (cold start) with hierarchical or similar-item forecasts.
  • Uncertainty drives decisions (safety stock uses the upper quantile), so deliver quantiles, not only means.
  • Cost: simple models on millions of series are cheaper and often as accurate as deep ones; compare on the metric that matters.
Key idea

Respect time: split by time, build features from the past only, beat the naive and seasonal-naive baselines, choose transformations to reach stationarity, evaluate with walk-forward backtests and scale-free metrics, report prediction intervals, and use seasonal-aware, robust methods for anomaly detection.

Interview questions: Time series

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic Why can't you shuffle time series data for train-test splits?

The future would leak into training, giving unrealistically good results. Split by time and evaluate on later data.

Basic What are the components of a time series?

Trend, seasonality, cycles and noise (remainder), combined additively or multiplicatively.

Medium What is stationarity and how do you achieve it?

Constant mean, variance and autocorrelation over time. Difference to remove trend, seasonally difference to remove seasonality and take logs to stabilise variance.

Medium What baselines should a forecast beat?

Naive (last value) and seasonal naive (value one season ago); a complex model that cannot beat them is not worth deploying.

Medium Explain exponential smoothing.

A weighted average of past observations with geometrically decaying weights: level = alpha x observation + (1 - alpha) x previous level; Holt and Holt-Winters add trend and seasonality.

Medium What is ARIMA(p, d, q)?

Autoregression on p lags, d differences to achieve stationarity and a moving average of q past errors; SARIMA adds seasonal terms.

Medium What does the ACF show?

Correlation of the series with lagged copies of itself: peaks reveal seasonality and slow decay indicates non-stationarity; the PACF shows direct lag effects.

Medium Explain walk-forward validation.

Train on data up to an origin, forecast the next horizon, score, then move the origin forward and repeat, averaging errors, which mimics real deployment.

Medium Why is MAPE problematic?

It explodes or is undefined near zero actuals and penalises over-forecasts and under-forecasts asymmetrically; MASE or MAE are safer.

Advanced How do you use gradient boosting for forecasting?

Create lag, rolling and calendar features using only past information, train a global model across series, and forecast directly per horizon or recursively.

Advanced Direct versus recursive multi-step forecasting?

Direct trains one model per horizon; recursive reuses a one-step model feeding back forecasts, which compounds errors but is simpler.

Advanced How would you detect anomalies in seasonal data?

Compare against a seasonal baseline (same time in previous cycles) or a forecast, using robust statistics such as MAD on the residuals, then tune thresholds and minimum duration to limit false alerts.

Advanced What is a prediction interval and why report it?

A range expected to contain the future value with stated probability; decisions such as safety stock depend on the upper quantile, not the mean.

Advanced How do you forecast intermittent demand?

Specialised methods such as Croston or probabilistic count models, evaluated with quantile or inventory-based metrics rather than MAPE.
