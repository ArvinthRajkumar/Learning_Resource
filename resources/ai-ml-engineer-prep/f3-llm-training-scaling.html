LLM training and scaling

How a model goes from random weights to a helpful assistant, how much compute that takes (you can estimate it in one line), how training is split across thousands of GPUs, and how models are evaluated.

Medium~2 hours

The LLM training pipeline

Intuition

Pretraining is reading the internet: the model learns language, facts and reasoning patterns by predicting the next token trillions of times. The result (a base model) is a brilliant autocomplete that does not follow instructions. Post-training teaches it to be an assistant: first by imitation (SFT on example conversations), then by preference (RLHF, DPO and related methods), increasingly with reinforcement learning on verifiable tasks.

  • Data curation: web crawl (for example Common Crawl), code, books, papers. Language and quality filtering (classifier-based), deduplication (exact and MinHash near-duplicates), PII and toxicity filtering, and decontamination against benchmarks. Data quality and mixture matter as much as size.
  • Base vs instruct: a base model continues text ("Q: What is the capital of France? Q: What is..."). An instruct model answers. Base models are better starting points for some fine-tunes. Instruct models are what you put behind a chat UI.
  • Distillation: train a small "student" on the outputs or probability distributions of a large "teacher". It is how many strong small models are produced.
  • Synthetic data: model-generated training examples, filtered by verifiers or other models. Widely used for SFT and reasoning data. It risks errors propagating and diversity collapsing.

How this gets asked

A base model answers "Write a haiku about rain" by continuing with more instructions. Why?

  • It is too small Size is not the issue.
  • It was only pretrained to continue text; instruction following comes from post-training (SFT, preference tuning) Correct.
  • Its temperature is too high That does not cause this behavior.
  • The tokenizer is broken No.

Web text often contains lists of instructions, so continuing them is a likely completion.

Self-check

Name the stages from raw data to a chat model.

Data curation, pretraining, SFT, preference optimization or RL, then evaluation and safety.

What is knowledge distillation?

Training a smaller student to imitate a larger teacher's outputs or distributions.

Why deduplicate pretraining data?

It reduces memorization, saves compute, improves quality, and prevents benchmark contamination.

The pretraining objective and teacher forcing

Intuition

Give the model a sequence and ask it to predict every next token at once. Thanks to the causal mask, position t only sees tokens 1..t. One forward pass over a 4,096-token sequence produces 4,096 predictions and 4,096 loss terms. During training the model is always fed the true previous tokens (teacher forcing), not its own guesses. That parallelism is why transformers train so efficiently.

Language modeling loss
L = -(1/T) sum_{t=1}^{T} log p_theta(x_t | x_1 ... x_{t-1}) perplexity = exp(L)
x_t
token at position t
T
tokens in the batch
  • A loss of 2.0 nats gives perplexity 7.39. A perplexity of 10 corresponds to a loss of 2.3026 nats.
  • Lower loss on held-out text tracks better downstream ability, though not perfectly.
  • Exposure bias: training always conditions on gold prefixes, while generation conditions on the model's own outputs. Errors can compound.
  • Context length is set during pretraining (often extended in a later phase). Attention cost grows as n^2, so long-context training is expensive.

How this gets asked

Validation loss is 2.0 nats per token. Perplexity? (3 decimals)

e^2 = 7.389.

Self-check

What is teacher forcing?

Feeding the ground-truth previous tokens during training, rather than the model's own predictions.

How many predictions does one training sequence of 4,096 tokens give?

About 4,096 (one per position), all in a single forward pass.

What is exposure bias?

The mismatch between training on gold prefixes and generating from the model's own outputs.

Scaling laws and compute math (6ND)

Intuition

Loss falls smoothly and predictably (as a power law) as you scale parameters, data and compute. Given a fixed compute budget, there is an optimal split between a bigger model and more tokens. The Chinchilla paper (Hoffmann et al., 2022) found earlier models were undertrained: compute-optimal training uses roughly 20 tokens per parameter.

Compute estimates (dense transformers)
training FLOPs C ~ 6 * N * D (2 forward + 4 backward per param per token) inference FLOPs ~ 2 * N per token time = C / (num_GPUs * peak_FLOPs * MFU)
N
parameters
D
training tokens
MFU
model FLOPs utilization, often 30 to 50% in practice
How much compute did a 7B model on 2T tokens take?
  1. C = 6 x 6.74e9 x 2e12 = 8.09e22 FLOPs.
  2. One A100 at 312 TFLOPS (dense bf16) and 40% MFU does 1.25e14 FLOP/s.
  3. 8.09e22 / 1.25e14 = 6.5e8 GPU-seconds, about 180,000 A100-hours.
  4. Sanity check: Meta's Llama 2 paper reports 184,320 A100-hours for the 7B model, consistent with about 40% utilization.
~180k A100-hours (about 7,500 GPU-days)
  • Chinchilla itself: 70B parameters on 1.4T tokens (20 per parameter). GPT-3 (175B on 300B tokens, 1.7 per parameter) was undertrained by that standard.
  • Overtraining small models is deliberate: inference cost scales with N, so training a small model far past compute-optimal makes it cheaper to serve. Meta reported Llama 3 8B was trained on over 15T tokens, about 1,875 tokens per parameter.
  • Inference FLOPs per token for 6.74B: 2N = 13.5 GFLOP. Decode is still memory bound, as part 01 explains.
  • Emergent abilities: some benchmarks jump sharply with scale. Part of this is an artifact of discontinuous metrics like exact match. Smooth metrics often show steady improvement.
  • Test-time compute: reasoning models spend more tokens thinking (long chains of thought, sampling and verifying) to trade inference compute for accuracy. This is a second scaling axis.

How this gets asked

Under Chinchilla-style compute-optimal scaling, about how many training tokens suit a 10B-parameter model?

  • 10B 1 token per parameter is badly undertrained.
  • 50B 5 per parameter.
  • 200B 20 tokens per parameter.
  • 10T 1,000 per parameter: far past compute-optimal (though sometimes chosen to cut inference cost).

About 20 tokens per parameter is the compute-optimal rule of thumb. Production models often train much longer to be cheaper at inference.

Training compute for a dense transformer is about x N x D FLOPs.

6: about 2 FLOPs per parameter per token forward and about 4 backward.

Self-check

Where does the 6 in 6ND come from?

A forward pass is about 2 FLOPs per parameter per token (multiply + add). The backward pass is about twice that.

Why train small models on far more than 20 tokens per parameter?

It costs more training compute but gives a smaller model of the same quality, which is cheaper to serve.

What is MFU?

Model FLOPs utilization: the achieved useful FLOP/s divided by the hardware peak.

Distributed training and mixed precision

Intuition

A 70B model's training state does not fit on one GPU, and one GPU would take centuries anyway. So you split the data (each GPU sees different examples), the model (each GPU holds part of each layer, or a range of layers), and the training state (sharding optimizer states, gradients and weights). Real systems combine all of them ("3D parallelism").

  2. ZeRO-1 (shard only the 12 bytes of fp32 master weights and Adam moments): 2 + 2 + 12/8 = 5.5 bytes per parameter, about 38.5 GB per GPU.

Mixed precision and memory tricks

  • bf16 has the same exponent range as fp32 (8 exponent bits) with fewer mantissa bits, so no loss scaling is needed. fp16 has a narrower range and needs loss scaling to avoid gradient underflow. bf16 is the default on A100 and H100.
  • An fp32 master copy of the weights keeps small updates from being rounded away.
  • Activation (gradient) checkpointing: store only some activations and recompute the rest during backward. It trades about 30% more compute for much less memory.
  • Gradient accumulation: sum gradients over several micro-batches before one optimizer step, to emulate a larger batch.
  • fp8 training (on H100-class GPUs) is used in some recent large runs, with careful scaling.

How this gets asked

Why is bf16 usually preferred over fp16 for training?

  • bf16 has fp32's exponent range, so gradients rarely overflow or underflow and no loss scaling is needed Correct.
  • bf16 has more mantissa precision than fp16 It has less (7 bits vs 10).
  • bf16 uses half the memory of fp16 Both are 2 bytes.
  • fp16 is not supported by GPUs It is.

Range matters more than precision for training stability.

Which ZeRO stage also shards the model parameters themselves?

  • Stage 1 Optimizer states only.
  • Stage 2 Adds gradients.
  • Stage 3 (equivalent in spirit to FSDP full sharding) Correct.
  • None Stage 3 does.

Stage 1: optimizer states. Stage 2: plus gradients. Stage 3: plus parameters.

Self-check

Tensor vs pipeline parallelism?

Tensor splits each layer's matrices (communication every layer). Pipeline splits layers into stages (activations passed along, with bubbles).

What does activation checkpointing trade?

Extra compute (recomputation) for lower activation memory.

What is gradient accumulation?

Summing gradients across micro-batches before one update, to simulate a large batch with limited memory.

With n = 10 samples and c = 3 correct: pass@1 = 1 - 7/10 = 0.3. pass@5 = 1 - C(7,5)/C(10,5) = 1 - 21/252 = 0.9167. More attempts raise the chance that at least one is right.

Benchmarks saturate and leak into training data (contamination). Public scores are a weak proxy for your task. Build task-specific evals (part 04).

Hallucination

  • What: fluent, confident output that is false or unsupported by the source.
  • Why: the model is trained to produce likely text, not to verify truth. Gaps in knowledge, rare facts, and pressure to always answer (an "I don't know" was rarely rewarded) all contribute.
  • Mitigations: retrieval grounding with citations (RAG), allowing and rewarding abstention, lower temperature for factual tasks, verification steps or tools, constrained outputs, and evals that measure faithfulness.

How this gets asked

A model generated n = 10 code samples for a problem and 3 pass the tests. Unbiased pass@5? (4 decimals)

1 - C(7,5)/C(10,5) = 1 - 21/252 = 0.9167.

Self-check

Why are public benchmarks weak evidence for your product?

Contamination, saturation, and a mismatch with your task distribution.

How does Chatbot Arena rank models?

Crowdsourced pairwise human votes, fitted with an Elo or Bradley-Terry model.

Two hallucination mitigations?

RAG with citations, and allowing abstention (plus verification and evals).

Interview questions: LLM training and scaling

Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic What are the stages of training a chat LLM?

Pretraining on large text (next-token prediction) gives a base model. SFT on instruction/response demonstrations, then preference optimization (RLHF or DPO) and possibly RL on verifiable tasks, give a helpful, aligned assistant.

Basic What is the difference between a base model and an instruct model?

A base model continues text. An instruct (chat) model has been post-trained to follow instructions, use a chat template and refuse unsafe requests.

Basic What is perplexity?

exp of the average negative log-likelihood per token. Lower is better. It is the effective number of equally likely choices the model is uncertain between.

Basic What is teacher forcing?

During training the model is fed the true previous tokens instead of its own predictions, so all positions can be trained in parallel in one forward pass.

Medium Estimate the training FLOPs for a 7B model trained on 2T tokens.

C is about 6ND = 6 x 7e9 x 2e12, about 8.4e22 FLOPs (8.1e22 with the exact 6.74B). At about 125 TFLOP/s effective per A100 (40% MFU) that is roughly 180k GPU-hours.

Medium What did the Chinchilla paper find?

For a fixed compute budget, models should be trained on about 20 tokens per parameter. Many earlier models were too big and undertrained. Example: Chinchilla, 70B on 1.4T tokens.

Medium Why would anyone train a small model on far more tokens than compute-optimal?

Inference cost scales with model size. Overtraining a small model reaches the same quality at lower serving cost (Llama 3 8B used over 15T tokens), trading extra training compute for cheaper inference.

Medium Data parallelism vs tensor parallelism vs pipeline parallelism?

Data: split batches, all-reduce gradients. Tensor: split matrices within layers, with communication every layer (needs NVLink). Pipeline: split layers into stages, with micro-batches to reduce bubbles. Large runs combine all three.

Medium What are ZeRO stages 1, 2 and 3?

Sharding of the training state across data-parallel ranks. Stage 1 shards optimizer states, stage 2 adds gradients, stage 3 adds parameters (similar to FSDP full sharding). Memory per GPU drops roughly linearly with the number of GPUs.

Medium Why bf16 over fp16 for training?

bf16 keeps fp32's 8-bit exponent (same dynamic range), so gradients rarely underflow and loss scaling is unnecessary. fp16 has more mantissa but a narrow range, so it needs loss scaling.

Medium What is knowledge distillation?

Training a smaller student model to match a larger teacher's outputs (soft probabilities or generated responses). It transfers capability at lower inference cost.

Medium How is pass@k computed for code models?

Generate n samples per problem with c passing. The unbiased estimate is 1 - C(n-c, k)/C(n, k). With n = 10 and c = 3: pass@1 = 0.3, pass@5 is about 0.917.

Advanced What causes hallucinations, and how do you reduce them in a product?

Models are trained to produce plausible text, not verified truth. Gaps in knowledge and pressure to always answer cause fabrication. Reduce it with retrieval grounding and citations, abstention options, lower temperature, verification tools, constrained outputs, and faithfulness evals.

Advanced What is test-time compute scaling?

Improving accuracy by spending more inference compute per query: long chains of thought (reasoning models), self-consistency sampling, search with verifiers. It complements training-time scaling.

Advanced What is activation checkpointing and when do you use it?

Store only some activations in the forward pass and recompute the rest during backward. It cuts activation memory greatly at about one extra forward pass of compute. Use it when activations limit batch size or sequence length.

Advanced How would you detect benchmark contamination in a model?

Check n-gram or embedding overlap between benchmark items and training data, test on rephrased or freshly written items, compare performance on pre- vs post-cutoff items, and look for verbatim completion of test items.
