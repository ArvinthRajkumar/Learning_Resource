Machine learning foundations

The vocabulary every interviewer assumes: what "learning" means, how to split data honestly, why models overfit, what a loss and a gradient are, and how to measure a classifier without fooling yourself. LLM questions build on all of it.

What machine learning is: the landscape

Intuition

Normal programming: you write the rules, the computer applies them. Machine learning: you show the computer examples, and it finds the rules (the parameters of a model) that best explain them. A model is a function with adjustable knobs. Training turns the knobs to make its outputs match the data.

The mechanism: kinds of learning

TypeDataGoalExamples
Supervisedinputs x with labels ylearn x to yspam detection (classification), house prices (regression)
Unsupervisedinputs onlyfind structureclustering (k-means), dimensionality reduction (PCA), anomaly detection
Self-supervisedraw data. Labels are created from the data itself.predict a hidden part of the inputLLM pretraining: predict the next token. BERT: predict masked tokens.
Reinforcement learningactions and rewards from an environmentmaximize long-term rewardgame playing, RLHF for LLM alignment
Semi-superviseda few labels, many unlabeled examplesuse bothpseudo-labeling
  • Classification predicts a category (spam or not). Regression predicts a number (price).
  • Features are the inputs (x). Label or target is the answer (y). Parameters are learned (weights). Hyperparameters are chosen by you (learning rate, depth, k).
  • Generalization is the real goal: doing well on data the model has never seen, not memorizing the training set.
  • Discriminative models learn P(y | x) (logistic regression, classifiers). Generative models learn P(x) or P(x, y) and can sample new data (LLMs, diffusion models).

Common traps

  • "LLM pretraining is unsupervised." The more precise term is self-supervised: there IS a target (the next token), it just comes from the text itself.
  • Confusing parameters (learned) with hyperparameters (set before training).
  • "Logistic regression is regression." It is a classification model. The name comes from regressing the log-odds.

How this gets asked

Next-token prediction on raw web text is best described as:

  • Supervised learning with human labels No human labels are involved.
  • Reinforcement learning No environment or reward.
  • Self-supervised learning Correct: the target (the next token) comes from the data itself.
  • Clustering No grouping objective.

Self-supervised learning creates labels from structure in the data. It is technically supervised training on automatically made labels.

Self-check

Parameter vs hyperparameter?

Parameters are learned from data (weights). Hyperparameters are set before training (learning rate, number of layers, k).

Classification vs regression?

A discrete category vs a continuous number.

Discriminative vs generative?

Discriminative models P(y | x). Generative models the data distribution P(x) or P(x, y) and can sample new examples.

Train, validation, test, cross-validation and leakage

Intuition

If a student sees the exam questions while studying, a perfect score proves nothing. The test set is the exam. It must stay unseen until the very end. The validation set is the practice exam you use to choose between study strategies (hyperparameters). Use it too often and you start overfitting to it as well.

The mechanism

  • k-fold CV: split into k folds, train k times, each time validating on a different fold, and average the scores. More reliable estimates with small data, at k times the cost. With 5 folds, each model trains on 4/5 = 80% of the data.
  • Stratified splits keep class proportions equal in every split (important for imbalanced data).
  • Group splits: all rows from the same user, patient or document go in the same split. Otherwise the model memorizes the entity and scores look inflated.
  • Time series: split by time (train on the past, test on the future). A random split leaks the future.

Data leakage

Leakage is any information in training that would not be available at prediction time, or test information sneaking into training. Classic examples:

  • Fitting a scaler or imputer on the full dataset before splitting. Fit preprocessing on train only, then apply it to val and test.
  • A feature that is a proxy for the label ("refund_issued" when predicting "will complain").
  • Duplicates or near-duplicates across train and test. For LLMs this is benchmark contamination.

Distribution shift

Production data drifts away from training data. Covariate shift: P(x) changes (new user demographics). Label or prior shift: P(y) changes (fraud rate rises). Concept drift: P(y | x) changes (what counts as spam evolves). Monitor input statistics and model metrics, and retrain on fresh data.

How this gets asked

You standardize features using the mean and std of the whole dataset, then split into train and test. What is wrong?

  • Nothing, standardization does not use labels It still uses test-set statistics.
  • Test statistics leak into training; fit the scaler on the training split only Correct.
  • You should min-max scale instead The scaling method is not the problem.
  • Standardization causes overfitting Not by itself.

Any statistic used for preprocessing must be computed on training data only. Pipelines (for example scikit-learn's Pipeline) enforce this inside cross-validation.

Self-check

Why keep a test set separate from the validation set?

Repeatedly choosing models by validation score overfits to the validation set. The test set gives one unbiased final estimate.

How should you split time-series data?

By time: train on earlier data, validate and test on later data.

Name two leakage examples.

Preprocessing fit on all data. Duplicate entities (or near-duplicates) across splits. Also: features unavailable at prediction time.

Bias, variance, overfitting and regularization

Intuition

A model that is too simple (a straight line through a curve) misses the pattern everywhere. That is high bias, or underfitting. A model that is too flexible (a wiggly curve through every noisy point) memorizes noise. That is high variance, or overfitting. It looks great on training data and fails on new data. The goal is the sweet spot.

The mechanism

Bias-variance decomposition (squared error)
E[(y - f_hat(x))^2] = Bias[f_hat(x)]^2 + Var[f_hat(x)] + sigma^2
Bias
error from wrong assumptions: average prediction vs truth
Var
how much predictions change with a different training sample
sigma^2
irreducible noise in the labels

Diagnosis and fixes

SymptomDiagnosisFixes
Train error high, val error highunderfitting (bias)bigger model, better features, train longer, less regularization
Train error low, val error much higheroverfitting (variance)more data, augmentation, regularization (L2, dropout), early stopping, smaller model
Both low, production baddistribution shift or leakagecheck splits, monitor drift, use fresh test data

Regularization

Penalized loss
L2 (ridge, weight decay): loss + lambda * sum w_i^2 shrinks all weights smoothly L1 (lasso): loss + lambda * sum |w_i| drives some weights to exactly 0 (feature selection)
  • Dropout: randomly zero activations during training (for example p = 0.1), so the network cannot rely on any single unit. It is disabled at inference.
  • Early stopping: stop when validation loss stops improving.
  • Data augmentation: more varied training data (crops, paraphrases).
  • Weight decay in AdamW is decoupled from the gradient update. That is the "W". It is the standard for training transformers.
  • Modern note: very large networks can show "double descent", where test error falls again past the interpolation point. The classic U-curve is a guide, not a law.

How this gets asked

Training accuracy 99%, validation accuracy 71%. Which action is LEAST likely to help?

  • Collect more training data This reduces variance.
  • Add dropout or L2 regularization This reduces variance.
  • Early stopping This reduces variance.
  • Increase model size and train longer Correct choice: it increases variance and makes the overfitting worse.

A big train-val gap means overfitting. More capacity and more epochs go in the wrong direction.

Which regularizer tends to produce sparse weights (many exactly zero)?

  • L1 Correct: the absolute-value penalty has a corner at 0.
  • L2 L2 shrinks weights but rarely to exactly 0.
  • Dropout Dropout zeros activations temporarily, not weights.
  • Batch normalization Not a sparsity method.

L1's constant-magnitude gradient pushes small weights all the way to 0. L2's gradient shrinks in proportion to the weight.

Self-check

Write the bias-variance decomposition.

Expected squared error = bias^2 + variance + irreducible noise.

L1 vs L2 effect?

L1 gives sparse weights (feature selection). L2 shrinks all weights smoothly.

Is dropout active at inference?

No. It is a training-time regularizer.

Loss functions: MSE, MAE, cross-entropy

Intuition

A loss is a single number that says how wrong the model is. Training means "make this number small". The loss you choose decides which mistakes matter most. Cross-entropy punishes confident wrong answers brutally, which is exactly what you want for classification and for LLMs.

Common losses
MSE = (1/n) sum (y_i - y_hat_i)^2 regression; big errors dominate MAE = (1/n) sum |y_i - y_hat_i| regression; robust to outliers BCE = -(1/n) sum [ y log p + (1 - y) log(1 - p) ] binary classification CE = -(1/n) sum log p(correct class) multi-class, and LLM next-token loss perplexity = exp(CE) LLM loss in "effective choices" units
p
predicted probability (after sigmoid or softmax)
log
natural log in most frameworks (the loss is in nats)

Worked examples

  1. Regression: y = [3, 5, 2], predictions [2.5, 5, 4]. Errors 0.5, 0, 2. MSE = (0.25 + 0 + 4)/3 = 1.4167. MAE = (0.5 + 0 + 2)/3 = 0.8333. RMSE = 1.1902. The single big error dominates MSE.
  2. Cross-entropy, correct class probability 0.8: -ln 0.8 = 0.2231. At 0.5: 0.6931. At 0.01: 4.6052. Confident and wrong is about 20x worse than mildly unsure.
  3. BCE with true label 0 and predicted p = 0.9: -ln(1 - 0.9) = 2.3026.
  4. LLM loss of 2.0 nats per token means perplexity e^2 = 7.389: on average the model is as unsure as choosing among about 7.4 tokens.

Why cross-entropy? Minimizing cross-entropy is maximum likelihood estimation: it makes the observed data as probable as possible under the model. With a softmax output, its gradient with respect to the logits is simply (p - y), which is clean and well scaled. MSE with a sigmoid gives a non-convex loss and vanishing gradients when the model is confidently wrong.

How this gets asked

A classifier assigns probability 0.8 to the correct class. What is its cross-entropy loss on that example (natural log, 4 decimals)?

-ln(0.8) = 0.2231.

Your regression data has a few huge outliers that are measurement errors. Which loss is more robust?

  • MSE Squaring makes outliers dominate.
  • MAE (or Huber) Correct: linear penalty for large errors.
  • Cross-entropy For classification.
  • Hinge loss For SVM classification.

Huber loss is quadratic near 0 and linear for large errors, a common compromise.

Self-check

Relationship between cross-entropy and perplexity?

Perplexity = exp(mean cross-entropy in nats).

Gradient of softmax + cross-entropy with respect to the logits?

p - y (predicted probabilities minus the one-hot label).

Why not use MSE for classification?

With a sigmoid it is non-convex and gives tiny gradients when confidently wrong. Cross-entropy is the maximum-likelihood loss.

Gradient descent, SGD, Adam and learning rates

Intuition

You are on a foggy hill and want the valley. Feel the slope under your feet (the gradient) and step downhill. Step size is the learning rate: too small and you crawl, too large and you overshoot and bounce up the other side. Backpropagation is just the chain rule, used to compute that slope for every weight at once.

The mechanism

Update rules
GD / SGD: w = w - lr * g g = gradient of the loss (full batch / mini-batch) Momentum: v = beta v + g; w = w - lr * v Adam: m = b1 m + (1-b1) g; v = b2 v + (1-b2) g^2 m_hat = m / (1 - b1^t); v_hat = v / (1 - b2^t) w = w - lr * m_hat / (sqrt(v_hat) + eps) (AdamW: also w -= lr * wd * w)
lr
learning rate
b1, b2
typically 0.9 and 0.999 (LLM training often uses b2 = 0.95)
t
step number (bias correction)

Worked example

Minimize (w - 3)^2 from w = 0
  1. lr = 0.1: gradient at 0 is -6, so w = 0 + 0.6 = 0.6. Next 1.08, then 1.464. It converges toward 3.
  2. lr = 1.1: w goes to 6.6, then -1.32, then 8.184. Each step overshoots more, so it diverges.
  3. Adam's first step: thanks to bias correction, the step size is about lr regardless of the gradient's scale. With g = 0.5 and lr = 0.001, the step is 0.001. Adam normalizes per-parameter step sizes.

Practical vocabulary

  • Batch vs mini-batch vs stochastic: the gradient comes from all data, a batch (for example 32 to 4M tokens), or one example. Mini-batch noise helps escape sharp minima, and batches use GPUs efficiently.
  • Epoch: one pass over the training data. LLM pretraining is usually about one epoch over a huge corpus. Fine-tuning runs 1 to 3 epochs.
  • Learning-rate schedules: warmup (start small, ramp up, which stabilizes early training), then cosine or linear decay.
  • Gradient clipping: cap the gradient norm (for example 1.0) to prevent loss spikes.
  • Vanishing and exploding gradients: in deep nets, repeated multiplication shrinks or blows up gradients. Fixes: residual connections, normalization layers, careful initialization, ReLU-family activations.
  • Backpropagation: forward pass computes outputs and caches activations. The backward pass applies the chain rule from the loss back to every weight. That is why training must store activations (memory) and costs about 2x the forward FLOPs.

How this gets asked

Training loss oscillates wildly and sometimes becomes NaN early in training. Most likely first fix?

  • Train for more epochs This does not fix instability.
  • Increase the learning rate Worse.
  • Lower the learning rate, add warmup or gradient clipping Correct.
  • Remove the validation set Unrelated.

Divergence usually means steps are too large for the loss curvature. Check for bad data (NaN or inf inputs) too.

Self-check

What do Adam's m and v track?

Exponential moving averages of the gradient (first moment) and the squared gradient (second moment).

Why warmup?

Early gradients and Adam's statistics are unreliable. Small initial steps avoid divergence.

Why does training need more memory than inference?

It stores activations for backprop, plus gradients and optimizer states.

Classification metrics: precision, recall, F1, ROC-AUC

Intuition

Accuracy hides everything when classes are imbalanced. With 6% positives, a model that always says "negative" scores 94%. Precision asks "when I flag something, am I right?". Recall asks "of everything I should have flagged, how much did I catch?". You trade one for the other by moving the decision threshold.

The mechanism

Definitions
precision = TP / (TP + FP) recall (sensitivity, TPR) = TP / (TP + FN) specificity = TN / (TN + FP) FPR = FP / (FP + TN) = 1 - specificity F1 = 2 P R / (P + R) F_beta = (1 + b^2) P R / (b^2 P + R) (b > 1 favors recall) ROC-AUC = P(score(random positive) > score(random negative))
TP 40, FP 10, FN 20, TN 930
  1. Precision 40/50 = 0.80. Recall 40/60 = 0.6667. F1 = 2(0.8)(0.6667)/(1.4667) = 0.7273. F2 = 0.6897 (it weights recall, which is the weaker one).
  2. Accuracy 970/1000 = 0.97, but "always negative" already gets 0.94. Accuracy is nearly useless here.
  3. Specificity 930/940 = 0.9894. FPR = 0.0106.
  4. AUC example: positive scores [0.9, 0.8, 0.4], negative [0.7, 0.3, 0.2, 0.1]. Of 12 positive-negative pairs, positives win 11 (0.4 loses to 0.7). AUC = 11/12 = 0.9167.

Thresholds, curves, calibration

  • Most classifiers output a score. The threshold (default 0.5) sets the precision-recall tradeoff. Choose it by business cost: missed fraud vs annoyed customers.
  • ROC curve: TPR vs FPR across thresholds. AUC is threshold-free and insensitive to class balance. That can look optimistic under heavy imbalance.
  • PR curve and PR-AUC (average precision): more informative when positives are rare.
  • Calibration: does a score of 0.8 mean right 80% of the time? Check with a reliability diagram. Fix with Platt scaling or isotonic regression.
  • Multi-class: macro averaging (mean over classes, every class equal) vs micro averaging (pool all decisions, frequent classes dominate) vs weighted.
  • Imbalance remedies: class weights, resampling (over- or under-sampling, SMOTE), threshold tuning, and the right metric.

How this gets asked

Precision 0.8 and recall 2/3. F1? (4 decimals)

2 x 0.8 x 0.6667 / (0.8 + 0.6667) = 0.7273.

A cancer screening model must miss as few true cases as possible. Which metric do you prioritize?

  • Precision That minimizes false alarms, not misses.
  • Recall Correct: misses are false negatives.
  • Accuracy Misleading with rare positives.
  • Specificity That is about true negatives.

High recall at an acceptable precision. Lower the threshold and confirm positives with a second test.

Self-check

Define precision and recall in words.

Precision: of the predicted positives, the fraction that are right. Recall: of the actual positives, the fraction found.

What does AUC = 0.5 mean?

Random ranking: a positive outranks a negative only half the time.

Macro vs micro F1?

Macro averages per-class F1 equally. Micro pools all predictions, so frequent classes dominate.

How this gets asked

Which ensemble method mainly reduces variance by averaging independently trained models?

  • Bagging (for example random forest) Correct.
  • Boosting Sequential, and mainly reduces bias.
  • Stacking only Combines models with a meta-learner. Not the textbook answer here.
  • PCA Not an ensemble.

Averaging decorrelated models cancels their individual errors.

Self-check

Gini for a 50/50 node?

1 - (0.25 + 0.25) = 0.5, the maximum for two classes.

What does PCA find?

Orthogonal directions of maximum variance (top eigenvectors of the covariance matrix).

Best default for tabular data?

Gradient-boosted trees, with logistic or linear regression as the baseline.

Features: scaling, encoding, missing values

  • Scaling: standardization z = (x - mean)/std (x = 70, mean 50, std 10 gives z = 2), or min-max to [0, 1]. Needed for distance-based models (kNN, k-means, SVM) and helps gradient descent. Trees do not need it.
  • Categorical encoding: one-hot for low cardinality. Target or frequency encoding, or learned embeddings, for high cardinality (watch for target leakage: compute it out-of-fold).
  • Missing values: drop, impute (mean, median, model-based), and add a "was missing" indicator, since missingness itself can be informative.
  • Text: bag of words or TF-IDF (classic), dense embeddings (modern). Embeddings are the bridge to everything in part 03.
  • Curse of dimensionality: in high dimensions, points become far apart and distances concentrate, so nearest-neighbor contrast drops. Dimensionality reduction and good representations help.

How this gets asked

Which model is LEAST affected by unscaled features (income in dollars next to age in years)?

  • k-nearest neighbors Distances are dominated by income.
  • k-means Same problem.
  • Decision tree Correct: splits are thresholds on one feature at a time.
  • SVM with an RBF kernel Distance based.

Tree splits are invariant to monotonic rescaling of a feature.

Self-check

Standardize x = 70 with mean 50 and std 10.

z = 2.

Why add a missing-indicator feature?

The fact that a value is missing can carry signal that imputation would erase.

When is one-hot encoding a bad idea?

Very high cardinality (thousands of IDs). Use embeddings or target encoding computed out-of-fold.

Interview questions: ML foundations

Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic What is the difference between supervised, unsupervised and self-supervised learning?

Supervised learns from labeled pairs (x, y). Unsupervised finds structure without labels (clustering, PCA). Self-supervised creates labels from the data itself, like predicting the next token, which is how LLMs are pretrained.

Basic What is overfitting and how do you detect it?

The model fits noise in the training data and generalizes poorly. Detect it by a large gap between training and validation performance, or validation loss rising while training loss keeps falling.

Basic Why do we need separate train, validation and test sets?

Train fits parameters, validation picks hyperparameters and models, and test gives one unbiased final estimate. Tuning on the test set makes its score optimistic.

Basic Explain precision and recall with an example.

In spam filtering, precision is the share of emails flagged as spam that really are spam, and recall is the share of all spam that got flagged. Raising the threshold usually raises precision and lowers recall.

Basic Why is accuracy misleading on imbalanced data?

With 1% positives, predicting all negative gives 99% accuracy while catching nothing. Use precision, recall, F1, PR-AUC or cost-weighted metrics.

Basic What does a learning rate do, and what happens if it is too high or too low?

It scales each gradient step. Too high overshoots and can diverge (loss spikes or NaN). Too low converges slowly or gets stuck.

Basic What is the difference between a parameter and a hyperparameter?

Parameters (weights) are learned during training. Hyperparameters (learning rate, depth, batch size, k) are set before or around training and tuned on validation data.

Basic What is cross-entropy loss and why is it used for classification?

The negative log probability assigned to the correct class. Minimizing it is maximum likelihood, it punishes confident mistakes heavily, and with softmax its gradient is simply p - y.

Medium Explain the bias-variance tradeoff.

Expected error splits into bias squared (wrong assumptions, underfitting), variance (sensitivity to the training sample, overfitting) and irreducible noise. More capacity lowers bias but raises variance. Regularization and more data manage the balance.

Medium L1 vs L2 regularization: what is the difference in effect?

L1 adds lambda times the sum of |w| and drives some weights to exactly zero (sparse, feature selection). L2 adds lambda times the sum of w squared and shrinks all weights smoothly. AdamW applies decoupled L2-style weight decay.

Medium What is data leakage? Give two examples.

Information at training time that would not be available at prediction time, or test data influencing training. Examples: fitting a scaler on the full dataset before splitting, and duplicate users or documents across train and test.

Medium How does k-fold cross-validation work and when would you use it?

Split the data into k folds, train k times holding out a different fold each time, and average the scores. Use it when data is small, to get a more reliable estimate. Use group or time-based folds when rows are related.

Medium What does ROC-AUC measure? When would you prefer PR-AUC?

AUC is the probability a random positive scores higher than a random negative, so it is threshold-free. With rare positives, ROC can look optimistic because the FPR denominator is huge. PR-AUC focuses on positive-class performance.

Medium Explain gradient descent vs SGD vs Adam.

GD uses the full-data gradient. SGD or mini-batch uses noisy batch gradients (cheaper, can escape sharp minima). Adam keeps moving averages of the gradient and squared gradient, giving per-parameter adaptive step sizes with bias correction.

Medium What is the vanishing gradient problem and how is it addressed?

Gradients shrink exponentially through many layers with saturating activations, so early layers stop learning. Fixes: ReLU-family activations, residual connections, normalization layers, careful initialization.

Medium Bagging vs boosting?

Bagging trains models independently on bootstrap samples and averages them, which reduces variance (random forest). Boosting trains models sequentially, each fixing the previous errors, which reduces bias (XGBoost, LightGBM).

Medium How would you handle a heavily imbalanced classification dataset?

Use the right metric (PR-AUC, recall at fixed precision), class weights or resampling, threshold tuning for the business cost, stratified splits, and possibly anomaly-detection framing. Collect more positives if possible.

Advanced What is calibration and how do you fix a poorly calibrated classifier?

A model is calibrated if events predicted at 0.8 happen about 80% of the time. Check with reliability diagrams or ECE. Fix with Platt scaling (logistic on scores), isotonic regression or temperature scaling, fitted on held-out data.

Advanced Explain double descent.

As model capacity grows past the point where it exactly fits the training data, test error can fall again after the classic U-shaped rise. Large overparameterized networks generalize well despite interpolating, so the classic tradeoff curve is incomplete.

Advanced Covariate shift vs concept drift: how would you detect and handle each?

Covariate shift: P(x) changes. Detect it with input distribution tests or embedding drift, and reweight or retrain. Concept drift: P(y|x) changes. Detect it via degrading labeled metrics or delayed feedback, and retrain on recent labels or use online updates.
