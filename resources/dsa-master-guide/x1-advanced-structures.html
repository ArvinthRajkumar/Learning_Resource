Advanced data structures: Fenwick tree, segment tree, sparse table, AVL, LFU and more

The core modules cover arrays, hashing, heaps and trees. These structures answer harder questions fast: range sums with updates, range minimums, ordered sets, caches with eviction rules. Every implementation here is checked against a slow, obviously-correct version on random data.

Range queries: choosing the structure

The problem family

Given an array, answer many range queries (sum, minimum, maximum, count) and possibly updates. The right structure depends on whether the array changes.

Prefix sums (the baseline)

prefix[i] = a[0] + ... + a[i-1]; the sum over [l, r) is prefix[r] - prefix[l]. The same idea in 2D uses inclusion-exclusion.

import random
random.seed(0)
a = [random.randint(-9, 9) for _ in range(20)]
prefix = [0]
for x in a:
    prefix.append(prefix[-1] + x)
def range_sum(l, r): return prefix[r] - prefix[l]
assert all(range_sum(l, r) == sum(a[l:r]) for l in range(21) for r in range(l, 21))
print("prefix sums verified on all", 21 * 22 // 2, "ranges")

Output

prefix sums verified on all 231 ranges

Min is idempotent, so two overlapping blocks cover any range.

Prefix sums for static data, Fenwick for sums with point updates, segment tree for any associative operation and lazy range updates.

Fenwick tree (binary indexed tree)

Idea

Store partial sums so that both prefix sums and point updates take O(log n) using a clever index trick: the lowest set bit of an index, i & -i, tells how many elements that cell covers. To update position i, walk up with i += i & -i; to query a prefix, walk down with i -= i & -i.

import random
random.seed(1)

class Fenwick:
    def __init__(self, n):
        self.n, self.t = n, [0] * (n + 1)
    def add(self, i, delta):              # 1-based index
        while i <= self.n:
            self.t[i] += delta
            i += i & -i
    def prefix(self, i):                  # sum of a[1..i]
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i
        return s
    def range_sum(self, l, r):            # inclusive, 1-based
        return self.prefix(r) - self.prefix(l - 1)

n = 50
a = [0] * (n + 1)
f = Fenwick(n)
for _ in range(2000):
    if random.random() < 0.5:
        i, d = random.randint(1, n), random.randint(-5, 5)
        a[i] += d; f.add(i, d)
    else:
        l = random.randint(1, n); r = random.randint(l, n)
        assert f.range_sum(l, r) == sum(a[l:r + 1])
print("2000 random operations match brute force")
print("lowest set bits:", [(i, i & -i) for i in (1, 2, 3, 4, 6, 8, 12)])

Output

2000 random operations match brute force
lowest set bits: [(1, 1), (2, 2), (3, 1), (4, 4), (6, 2), (8, 8), (12, 4)]

Uses: counting inversions (add 1 at each value as you scan), order statistics (find the k-th smallest via binary descent), 2D Fenwick for matrices, offline range counting. A Fenwick tree is shorter and faster than a segment tree but supports only invertible operations (sum, xor), not min or max.

How this gets asked

In a Fenwick tree, what is i & -i for i = 12?

12 is 1100 in binary; the lowest set bit is 100 = 4.

Why can a Fenwick tree not directly support range minimum?

  • It is too slow No.
  • Its prefix subtraction trick needs an invertible operation, and min has no inverse Correct.
  • It needs a power-of-two size No.
  • It stores no values No.

Range sum is prefix(r) - prefix(l - 1); min cannot be subtracted.

Segment tree

Structure

A binary tree where each node stores the answer (sum, min, max, gcd) for a segment of the array. A query decomposes the range into O(log n) whole nodes; a point update recomputes O(log n) ancestors. The iterative bottom-up version below uses an array of size 2n.

import random
random.seed(2)

class SegTree:
    """Iterative segment tree for any associative operation with an identity element."""
    def __init__(self, data, op, identity):
        self.n, self.op, self.id = len(data), op, identity
        self.t = [identity] * self.n + list(data)
        for i in range(self.n - 1, 0, -1):
            self.t[i] = op(self.t[2 * i], self.t[2 * i + 1])
    def update(self, i, v):
        i += self.n
        self.t[i] = v
        while i > 1:
            i //= 2
            self.t[i] = self.op(self.t[2 * i], self.t[2 * i + 1])
    def query(self, l, r):               # half-open [l, r)
        res_l, res_r = self.id, self.id
        l += self.n; r += self.n
        while l < r:
            if l & 1:
                res_l = self.op(res_l, self.t[l]); l += 1
            if r & 1:
                r -= 1; res_r = self.op(self.t[r], res_r)
            l //= 2; r //= 2
        return self.op(res_l, res_r)

data = [random.randint(-50, 50) for _ in range(37)]
mn = SegTree(data, min, float("inf"))
sm = SegTree(data, lambda x, y: x + y, 0)
for _ in range(3000):
    if random.random() < 0.4:
        i, v = random.randrange(37), random.randint(-50, 50)
        data[i] = v; mn.update(i, v); sm.update(i, v)
    else:
        l = random.randrange(37); r = random.randint(l + 1, 37)
        assert mn.query(l, r) == min(data[l:r]) and sm.query(l, r) == sum(data[l:r])
print("min and sum segment trees match brute force on 3000 operations")

Lazy propagation: range updates

To add a value to a whole range, updating every leaf costs O(n). Lazy propagation stores a pending update at a node and pushes it down only when a query or update needs the children. Below, range add and range sum in O(log n).

import random
random.seed(3)

class LazySum:
    def __init__(self, n):
        self.n = n
        self.sum = [0] * (4 * n)
        self.lazy = [0] * (4 * n)
    def _push(self, node, lo, hi):
        if self.lazy[node]:
            mid = (lo + hi) // 2
            for child, clo, chi in ((2 * node, lo, mid), (2 * node + 1, mid + 1, hi)):
                self.sum[child] += self.lazy[node] * (chi - clo + 1)
                self.lazy[child] += self.lazy[node]
            self.lazy[node] = 0
    def add(self, l, r, v, node=1, lo=0, hi=None):
        hi = self.n - 1 if hi is None else hi
        if r < lo or hi < l: return
        if l <= lo and hi <= r:
            self.sum[node] += v * (hi - lo + 1)
            self.lazy[node] += v
            return
        self._push(node, lo, hi)
        mid = (lo + hi) // 2
        self.add(l, r, v, 2 * node, lo, mid)
        self.add(l, r, v, 2 * node + 1, mid + 1, hi)
        self.sum[node] = self.sum[2 * node] + self.sum[2 * node + 1]
    def query(self, l, r, node=1, lo=0, hi=None):
        hi = self.n - 1 if hi is None else hi
        if r < lo or hi < l: return 0
        if l <= lo and hi <= r: return self.sum[node]
        self._push(node, lo, hi)
        mid = (lo + hi) // 2
        return self.query(l, r, 2 * node, lo, mid) + self.query(l, r, 2 * node + 1, mid + 1, hi)

n = 40
arr = [0] * n
t = LazySum(n)
for _ in range(2000):
    l = random.randrange(n); r = random.randint(l, n - 1)
    if random.random() < 0.5:
        v = random.randint(-4, 4)
        for i in range(l, r + 1): arr[i] += v
        t.add(l, r, v)
    else:
        assert t.query(l, r) == sum(arr[l:r + 1])
print("lazy segment tree matches brute force")

Sparse table

For a static array and an idempotent operation (min, max, gcd, where overlapping is harmless), precompute table[k][i] = min(a[i .. i + 2^k - 1]). A query on [l, r] uses two overlapping power-of-two blocks, so it is O(1) after O(n log n) preprocessing.

import random
random.seed(4)
a = [random.randint(0, 99) for _ in range(40)]
n = len(a)
LOG = [0] * (n + 1)
for i in range(2, n + 1):
    LOG[i] = LOG[i // 2] + 1
table = [a[:]]
k = 1
while (1 << k) <= n:
    prev = table[-1]
    table.append([min(prev[i], prev[i + (1 << (k - 1))]) for i in range(n - (1 << k) + 1)])
    k += 1
def rmq(l, r):                              # inclusive
    k = LOG[r - l + 1]
    return min(table[k][l], table[k][r - (1 << k) + 1])
assert all(rmq(l, r) == min(a[l:r + 1]) for l in range(n) for r in range(l, n))
print("sparse table verified on all", n * (n + 1) // 2, "ranges; levels:", len(table))

Output

sparse table verified on all 820 ranges; levels: 6

It also yields the lowest common ancestor of a tree (via an Euler tour and range minimum) in O(1) per query.

Balanced search trees: AVL

An ordinary binary search tree degrades to a list on sorted input. A self-balancing tree keeps height O(log n). An AVL tree requires every node's two subtree heights to differ by at most 1, restoring balance with rotations after inserts and deletes.

ImbalanceFix
Left-leftRotate right at the node
Right-rightRotate left at the node
Left-rightRotate left at the child, then right at the node
Right-leftRotate right at the child, then left at the node
 
import random
random.seed(5)

class Node:
    def __init__(self, key):
        self.key, self.left, self.right, self.h = key, None, None, 1
h = lambda n: n.h if n else 0
def upd(n): n.h = 1 + max(h(n.left), h(n.right))
def balance(n): return h(n.left) - h(n.right)
def rot_right(y):
    x = y.left; y.left, x.right = x.right, y
    upd(y); upd(x); return x
def rot_left(x):
    y = x.right; x.right, y.left = y.left, x
    upd(x); upd(y); return y
def insert(n, key):
    if not n: return Node(key)
    if key < n.key: n.left = insert(n.left, key)
    elif key > n.key: n.right = insert(n.right, key)
    else: return n
    upd(n)
    b = balance(n)
    if b > 1 and key < n.left.key: return rot_right(n)
    if b < -1 and key > n.right.key: return rot_left(n)
    if b > 1: n.left = rot_left(n.left); return rot_right(n)
    if b < -1: n.right = rot_right(n.right); return rot_left(n)
    return n
def inorder(n): return inorder(n.left) + [n.key] + inorder(n.right) if n else []
def valid(n):
    return True if not n else abs(balance(n)) <= 1 and valid(n.left) and valid(n.right)

root = None
for k in range(1, 1025):                    # sorted insertion: the worst case for a plain BST
    root = insert(root, k)
print("height after inserting 1..1024 in order:", root.h, "(a plain BST would be 1024)")
root2 = None
keys = random.sample(range(10000), 500)
for k in keys: root2 = insert(root2, k)
print("random keys sorted correctly:", inorder(root2) == sorted(keys), "| balanced everywhere:", valid(root2), "| height", root2.h)

Output

height after inserting 1..1024 in order: 11 (a plain BST would be 1024)
random keys sorted correctly: True | balanced everywhere: True | height 11

Height is at most 1.44 log2(n). Red-black trees relax the rule (height at most 2 log2 n) for cheaper updates; they back std::map in C++ and Java's TreeMap. B-trees store many keys per node to minimise disk reads and underlie databases (SD4). Python has no built-in balanced tree: use bisect on a sorted list (O(n) insert but fast in practice) or the sortedcontainers package.

How this gets asked

After inserting a key into the left subtree of the left child makes a node's balance factor +2, the fix is:

  • Rotate left That fixes right-right.
  • Rotate right at that node Correct.
  • Do nothing The tree stays unbalanced.
  • Delete the node No.

Left-left imbalance needs a single right rotation.

Self-check

AVL versus red-black tree?

AVL is stricter (faster lookups, more rotations on updates); red-black allows a looser balance for cheaper updates.

Caches: LRU and LFU in O(1)

LRU

Hash map plus doubly linked list, as in M10 and SD7; OrderedDict implements it directly.

LFU

Least frequently used evicts the key with the lowest access count (ties broken by least recently used). The O(1) design keeps a map from key to (value, count) and a map from count to an ordered set of keys, plus the current minimum count.

from collections import defaultdict, OrderedDict

class LFU:
    def __init__(self, capacity):
        self.cap, self.min_count = capacity, 0
        self.kv = {}                                        # key -> (value, count)
        self.buckets = defaultdict(OrderedDict)             # count -> ordered keys (oldest first)
    def _touch(self, key):
        value, c = self.kv[key]
        del self.buckets[c][key]
        if not self.buckets[c]:
            del self.buckets[c]
            if self.min_count == c:
                self.min_count += 1
        self.kv[key] = (value, c + 1)
        self.buckets[c + 1][key] = None
    def get(self, key):
        if key not in self.kv: return -1
        self._touch(key)
        return self.kv[key][0]
    def put(self, key, value):
        if self.cap == 0: return
        if key in self.kv:
            self.kv[key] = (value, self.kv[key][1])
            self._touch(key)
            return
        if len(self.kv) >= self.cap:
            victim, _ = self.buckets[self.min_count].popitem(last=False)
            if not self.buckets[self.min_count]:
                del self.buckets[self.min_count]
            del self.kv[victim]
        self.kv[key] = (value, 1)
        self.buckets[1][key] = None
        self.min_count = 1

c = LFU(2)
c.put(1, 1); c.put(2, 2)
print(c.get(1))        # 1, key 1 now used twice
c.put(3, 3)            # evicts key 2 (least frequently used)
print(c.get(2), c.get(3))
c.put(4, 4)            # keys 1 and 3 both have count 2, so the less recently used key 1 is evicted
print(c.get(1), c.get(3), c.get(4))

Output

1
-1 3
-1 3 4

How this gets asked

What makes the LFU design O(1)?

  • Sorting by frequency each time O(n log n).
  • A map from count to an ordered set of keys, plus tracking the minimum count Correct.
  • A heap of frequencies O(log n).
  • A linked list scan O(n).

Every operation moves a key between adjacent count buckets.

Self-check

LRU versus LFU?

LRU evicts the least recently used; LFU evicts the least frequently used, breaking ties by recency.

Probabilistic and specialised structures

Skip list

Layered linked lists: the bottom list holds all keys in order; each higher layer is a random sample (each element promoted with probability 1/2), acting as express lanes. Search, insert and delete are O(log n) expected, with simpler code than balanced trees and easy concurrency. Used in Redis sorted sets and LevelDB memtables.

Bloom filter and count-min sketch

Bloom filter (membership with no false negatives) and count-min sketch (approximate counts) trade accuracy for tiny memory (SD12).

Monotonic deque

Keeps candidates in decreasing order so the maximum of a sliding window is at the front in amortised O(1).

from collections import deque
import random
random.seed(6)
def sliding_max(a, k):
    dq, out = deque(), []                      # dq holds indices with decreasing values
    for i, x in enumerate(a):
        while dq and a[dq[-1]] <= x: dq.pop()
        dq.append(i)
        if dq[0] <= i - k: dq.popleft()
        if i >= k - 1: out.append(a[dq[0]])
    return out
a = [random.randint(0, 50) for _ in range(30)]
assert sliding_max(a, 5) == [max(a[i:i + 5]) for i in range(len(a) - 4)]
print("sliding window maximum verified; example:", sliding_max([1, 3, -1, -3, 5, 3, 6, 7], 3))

Output

sliding window maximum verified; example: [3, 3, 5, 5, 6, 7]

Key idea

Pick the structure from three facts: does the data change, which operation (invertible sum versus min or max), and what is queried (point, prefix, range). Always test against a brute-force implementation on random inputs.

Interview questions: Advanced data structures

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic What problem does a Fenwick tree (BIT) solve?

Point updates and prefix-sum queries in O(log n) with O(n) memory and a very small constant, using lowbit (i & -i) to jump between nodes.

Basic When would you choose a segment tree over a Fenwick tree?

When the operation is not invertible (min, max, gcd) or you need range updates with lazy propagation. A Fenwick tree needs an invertible operation for range queries.

Basic What is a sparse table and what are its limits?

A table of answers for ranges of length 2^k, built in O(n log n), giving O(1) queries for idempotent operations like min and max. It does not support updates.

Medium Explain lazy propagation.

Store pending updates on internal nodes and push them to children only when a later operation needs to descend, so range updates and range queries both stay O(log n).

Medium How do AVL trees stay balanced?

Each node's subtree heights differ by at most one; insertions and deletions fix violations with single or double rotations, giving O(log n) operations.

Medium How do you implement an LFU cache in O(1)?

A hash map from key to node plus a map from frequency to an ordered list of keys, with a tracked minimum frequency that is updated on every access and eviction.

Medium What is a monotonic deque used for?

Sliding window maximum or minimum in O(n): keep indexes whose values are monotonic, pop dominated elements from the back and expired ones from the front.

Medium Compare a hash table with a balanced BST.

Hash tables give O(1) average lookups but no ordering. Balanced BSTs give O(log n) with ordered traversal, predecessor/successor and range queries.

Advanced How do you answer 'number of elements less than x in a range' with updates?

Offline with a Fenwick tree and coordinate compression, a merge sort tree, a persistent segment tree, or sqrt decomposition depending on constraints.

Advanced What is a persistent data structure?

One that preserves earlier versions after updates, usually by path copying so each update adds O(log n) new nodes while old roots remain valid.

Advanced Why do skip lists appear in practice?

They give expected O(log n) ordered operations with simple code and good concurrency properties; Redis sorted sets use them.

Advanced What is amortised O(1) for union-find and what makes it so fast?

With union by rank (or size) and path compression, any sequence of m operations costs O(m alpha(n)), where alpha is the inverse Ackermann function, below 5 for practical n.

Advanced What is a B-tree and why do databases use it?

A balanced multiway tree with large nodes sized to disk pages; the high fan-out keeps the tree very shallow, minimising disk reads.

Advanced How does a bloom filter work and what are its error properties?

k hash functions set bits in a bit array; a query reports present only if all k bits are set. It has false positives but no false negatives and cannot delete (without counting variants).
