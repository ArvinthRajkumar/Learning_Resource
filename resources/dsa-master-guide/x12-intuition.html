Part X12

Data structures and algorithms explained simply: intuition, analogies and pattern recognition

Before the code and the proofs comes the picture in your head. This page gives one for each idea in the guide, names the beginner mistake attached to it, and finishes with a table that maps problem wording to the technique that usually works.

BasicMedium~4 hours

Why intuition first

Interview problems are disguised versions of a few dozen ideas. If you can say each idea in a sentence and draw it, you will recognise it when the wording changes. For each topic below: the picture, why it exists, the trap.

Memory and linear structures

Array

Picture: a row of numbered lockers, all the same size, side by side. If you know the locker number you open it instantly (O(1)), but squeezing a new locker into the middle means sliding everyone along (O(n)). Trap: forgetting that inserting or deleting near the front is slow, and that "dynamic arrays" (Python lists) occasionally copy everything when they grow (cheap on average).

Linked list

Picture: a treasure hunt where each clue tells you where the next clue is. You can splice a new clue in anywhere quickly if you are already standing there (O(1)), but to reach the 500th clue you must follow 499 hints (O(n)). Trap: losing the rest of the list by overwriting a pointer before saving it; forgetting to handle the head and empty list.

Stack

Picture: a pile of plates: you only touch the top one. Last in, first out (LIFO). Browsers use it for the Back button; recursion uses one for pending calls; matching brackets pops the most recent opener.

Queue

Picture: a line at the bank: first in, first out (FIFO). Breadth-first search is a line of "to visit" nodes; task schedulers and print jobs queue work. A deque is a line you can join or leave at either end.

Monotonic stack

Picture: a queue of people where anyone shorter than the new arrival, standing in front of them, leaves because they can never be the "next taller" answer. It finds the next greater element for everyone in one pass.

def next_greater(nums):
    ans, stack = [-1] * len(nums), []                       # stack holds indexes still waiting for a taller element
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x: ans[stack.pop()] = x
        stack.append(i)
    return ans
print(next_greater([2, 1, 2, 4, 3]), "(each element is pushed and popped once, so O(n))")

Output

[4, 2, 4, -1, -1] (each element is pushed and popped once, so O(n))

How this gets asked

Which structure matches 'last in, first out'?

  • Queue FIFO.
  • Stack Correct.
  • Heap Priority.
  • Hash table Lookup.

Think of a pile of plates.

What does a monotonic stack find in one pass?

  • The median No.
  • The next greater (or smaller) element for every position Correct.
  • The shortest path No.
  • Duplicates No.

Each element is pushed and popped once.

Self-check

Array versus linked list in one line each?

Arrays give O(1) indexing but costly middle inserts; linked lists give cheap splicing but O(n) access.

Hashing and searching

Hash table

Picture: a coat check. You hand over a coat and get a numbered ticket; the number is computed from the coat so you can walk straight to the right hook instead of searching every hook. Two coats may get the same number (a collision), so each hook holds a short list. Why fast: the ticket computation does not depend on how many coats are stored (O(1) on average). Trap: assuming order, using mutable keys (a list cannot be a key because its ticket would change), or relying on average-case speed when someone can craft collisions.

import zlib
words = ["apple", "banana", "cherry", "date", "elderberry", "fig", "grape"]
buckets = {}
for w in words: buckets.setdefault(zlib.crc32(w.encode()) % 4, []).append(w)         # 7 words, 4 hooks: collisions are normal
print("words per hook:", sorted(len(v) for v in buckets.values()), "| lookup still checks only one hook")

Output

words per hook: [1, 1, 2, 3] | lookup still checks only one hook

Binary search

Picture: guessing a number between 1 and 1000 with "higher or lower" hints: always guess the middle, and each answer halves the remaining range. Ten guesses suffice (log2 1000 ≈ 10). It needs order. Trap: off-by-one errors with lo, hi and mid; infinite loops from lo = mid instead of mid + 1.

import math
n = 1_000_000
print("worst-case guesses for 1,000,000 sorted items:", math.ceil(math.log2(n)), "versus up to", n, "for a linear scan")

Output

worst-case guesses for 1,000,000 sorted items: 20 versus up to 1000000 for a linear scan

How this gets asked

Why is a hash table lookup O(1) on average?

  • It sorts the data No.
  • The key's hash gives the location directly, regardless of how many items are stored Correct.
  • It uses binary search No.
  • It uses a heap No.

Collisions are resolved within a short bucket.

Self-check

What is a collision and how is it handled?

Two keys map to the same slot; handle it with chaining (a list per slot) or open addressing (probe for another slot).

Trees and heaps

Tree

Picture: a family tree or a folder structure: one root, each node has children, and there is exactly one route between any two nodes. Recursion matches it perfectly: "solve for the left subtree, solve for the right, combine".

Binary search tree

Picture: a "higher or lower" game turned into a data structure: everything smaller hangs left, larger hangs right, so a search discards half the remaining tree at each step if the tree is balanced. Trap: inserting sorted data into a plain BST builds a chain (a linked list in disguise); balanced variants (AVL, red-black) prevent it.

Heap (priority queue)

Picture: a tournament bracket where the winner (the smallest or largest) always sits at the top; removing the winner re-runs a short chain of matches to find the next one. It is not fully sorted, only the top is guaranteed, which is why it is cheap: O(log n) to insert or remove. Use it for: "the k largest", scheduling by priority, merging sorted streams, Dijkstra's shortest paths.

import heapq
data = [9, 4, 7, 1, 8, 2, 6]
print("3 smallest:", heapq.nsmallest(3, data))
heap = list(data)
heapq.heapify(heap)                                            # O(n): only the top is guaranteed to be the smallest
print("internal heap array (not sorted):", heap, "| top is the minimum:", heap[0])
print("popping repeatedly yields sorted order:", [heapq.heappop(heap) for _ in range(len(heap))])

Output

3 smallest: [1, 2, 4]
internal heap array (not sorted): [1, 4, 2, 9, 8, 7, 6] | top is the minimum: 1
popping repeatedly yields sorted order: [1, 2, 4, 6, 7, 8, 9]

Trie

Picture: a phone's predictive text: a tree of letters where every path from the root spells a prefix, so every word starting with "ca" hangs below the same two nodes.

How this gets asked

What does a heap guarantee?

  • Fully sorted order Only the top is guaranteed.
  • The minimum (or maximum) is at the top, with O(log n) insert and remove Correct.
  • Fast arbitrary lookup No.
  • Unique keys No.

That makes it ideal for priority queues.

Graphs

Graph

Picture: a map of cities (nodes) and roads (edges). Social networks, web links, dependencies and maps are all graphs.

BFS versus DFS

Picture: dropping a stone in a pond. BFS is the ripple spreading outward ring by ring: it finds the fewest hops first. DFS is a mouse in a maze that follows one corridor to the end, then backtracks: good for exploring everything, finding cycles and ordering dependencies.

from collections import deque
graph = {"A": ["B", "C"], "B": ["D"], "C": ["D", "E"], "D": ["F"], "E": ["F"], "F": []}
def bfs_levels(start):
    seen, q, out = {start}, deque([start]), []
    while q:
        u = q.popleft(); out.append(u)
        for v in graph[u]:
            if v not in seen: seen.add(v); q.append(v)
    return out
def dfs_order(u, seen=None):
    seen = seen if seen is not None else set(); seen.add(u); out = [u]
    for v in graph[u]:
        if v not in seen: out += dfs_order(v, seen)
    return out
print("BFS (ring by ring):", bfs_levels("A"), "| DFS (deep first):", dfs_order("A"))

Output

BFS (ring by ring): ['A', 'B', 'C', 'D', 'E', 'F'] | DFS (deep first): ['A', 'B', 'D', 'F', 'C', 'E']

Shortest paths

Picture: Dijkstra is a rumour spreading at speeds proportional to road length: the closest towns hear first, and the first time you hear about a town is the shortest route (this fails with negative roads). A\* adds a compass: it explores promising directions first.

Topological sort

Picture: getting dressed: socks before shoes, underwear before trousers. An ordering that respects every "must come before" arrow, possible only if there is no cycle (nobody waiting on each other in a circle).

Union-find

Picture: friend groups at a party. "Are these two in the same group?" and "merge these groups" are both near-instant because every group has a leader and you follow leaders up to the top (and shorten the chain as you go).

How this gets asked

Which search finds the fewest edges from the start in an unweighted graph?

  • DFS Not shortest.
  • BFS Correct.
  • Binary search No.
  • Quick sort No.

BFS explores in rings of increasing distance.

Self-check

BFS or DFS for cycle detection and for shortest hops?

DFS (with colours) for cycles in directed graphs, BFS for fewest edges.

Sorting

Picture: sorting a deck of cards. Insertion sort is how you sort a hand: pick up one card at a time and slide it into place. Merge sort splits the deck in half, sorts each pile and merges them, always O(n log n). Quick sort picks a pivot card and sorts into "smaller" and "larger" piles, usually very fast. Counting sort skips comparing entirely by counting how many of each value there are (fine for small ranges). Why n log n: sorting n items needs log2(n!) comparisons, about n log n, because each comparison gives at most one bit of information.

Recursion and its relatives

Recursion

Picture: Russian nesting dolls, or looking up a word whose definition uses another word you must look up first. To solve a problem, solve a smaller copy and use its answer, with a base case so it eventually stops. Trap: no base case, or not shrinking the problem, causing infinite recursion (Python stops at about 1000 levels).

Dynamic programming (DP)

Picture: climbing stairs and remembering how many ways there are to reach each step so you never recompute it. If a recursive solution keeps solving the same small problems, write down each answer once (memoisation), or fill a table from small to large. Two questions: what is the state? (what do I need to know to continue) and how do states relate? (the recurrence).

from functools import lru_cache
calls = 0
def fib_slow(n):
    global calls; calls += 1
    return n if n < 2 else fib_slow(n - 1) + fib_slow(n - 2)
@lru_cache(None)
def fib_fast(n): return n if n < 2 else fib_fast(n - 1) + fib_fast(n - 2)
result = fib_slow(25); fast = fib_fast(25)
print("fib(25) =", result, "| equal:", result == fast, "| took", calls, "calls without memory; with memory only", fib_fast.cache_info().misses, "distinct problems are solved")

Output

fib(25) = 75025 | equal: True | took 242785 calls without memory; with memory only 26 distinct problems are solved

Greedy

Picture: making change with the fewest coins by always taking the largest coin that fits. Quick and simple, but it only works when a local best choice never ruins the global best, which you must prove (or find a counterexample; greedy fails for coins of 1, 3, 4 making 6).

def greedy_coins(amount, coins):
    out = []
    for c in sorted(coins, reverse=True):
        while amount >= c: amount -= c; out.append(c)
    return out
print("coins 1,5,10,25 for 63:", greedy_coins(63, [1, 5, 10, 25]), "| greedy fails for coins 1,3,4 and amount 6:", greedy_coins(6, [1, 3, 4]), "uses 3 coins, but 3 + 3 uses only 2")

Output

coins 1,5,10,25 for 63: [25, 25, 10, 1, 1, 1] | greedy fails for coins 1,3,4 and amount 6: [4, 1, 1] uses 3 coins, but 3 + 3 uses only 2

Backtracking

Picture: solving a maze by trying a path and, at a dead end, stepping back to the last junction to try another. Choose, explore, un-choose. Pruning (not walking into obviously dead corridors) is what makes it practical (N-queens, Sudoku, subsets, permutations).

Divide and conquer

Picture: to count the votes in a huge room, split the room in two, let each half count, then add. Merge sort and quick sort are the standard examples.

How this gets asked

What makes dynamic programming faster than plain recursion on overlapping subproblems?

  • It uses more threads No.
  • Each subproblem is solved once and its answer reused Correct.
  • It avoids loops No.
  • It sorts first No.

Memoisation or a table.

Greedy for coins 1, 3, 4 and amount 6 gives 4 + 1 + 1. What does that show?

  • Greedy always works No.
  • A locally best choice can miss the global best (3 + 3 uses fewer coins), so greedy needs proof Correct.
  • Coins are broken No.
  • DP is slower No.

DP would find the optimum.

Self-check

What are the two questions of DP?

What is the state, and how does a state relate to smaller states?

Complexity: the speed limit

Picture: how the work grows when the input doubles. Constant: no change. Logarithmic: one extra step (binary search). Linear: doubles (reading a list). n log n: slightly more than doubles (good sorting). Quadratic: quadruples (comparing every pair). Exponential: explodes (trying every subset).

Space counts memory: recursion depth, extra arrays, hash tables. A solution that is fast but uses 100 GB is not a solution.

Self-check

How large n can an O(n^2) solution handle?

About 5,000 within a second at roughly 10^8 simple operations per second.

Key idea

Learn the picture before the code: arrays are lockers, lists are treasure hunts, stacks are plates, queues are lines, hash tables are coat checks, trees are family trees, heaps are tournaments, graphs are maps, DP is remembering, greedy is the best next step, backtracking is a maze. Then match the problem's wording to the pattern table and check the complexity budget.

How this gets asked

A problem asks for 'the k largest elements from a stream'. Which tool?

  • Sorting the whole stream each time Wasteful.
  • A min-heap of size k Correct.
  • A stack No.
  • Union-find No.

Keep only the k best seen so far.

Interview questions: Intuition guide

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic Explain an array and a linked list with analogies.

An array is a row of numbered lockers with instant access but costly insertion in the middle; a linked list is a treasure hunt where each clue points to the next, cheap to splice but slow to reach the n-th item.

Basic Explain a stack and a queue.

A stack is a pile of plates (last in, first out); a queue is a line at a bank (first in, first out).

Basic Explain a hash table simply.

A coat check: a computed ticket number tells you which hook to use, so lookup does not scan everything; collisions share a hook.

Basic Explain binary search with a game.

Guess a number from 1 to 1000 with higher or lower hints: always guess the middle, halving the range each time, so about 10 guesses suffice.

Medium Explain BFS versus DFS with a picture.

BFS is ripples in a pond finding the fewest hops; DFS is a mouse following one corridor to the end before backtracking.

Medium Explain a heap with an analogy.

A tournament bracket where the winner sits on top; removing the winner replays a short chain of matches, so insert and remove are O(log n) while only the top is ordered.

Medium Explain dynamic programming simply.

Remember answers to small subproblems so you never solve the same one twice, either by memoising recursion or by filling a table from small to large.

Medium When does greedy fail?

When a locally best choice can prevent a better global result, as in coins 1, 3, 4 for amount 6 where 4 + 1 + 1 is worse than 3 + 3. Greedy needs a proof.

Medium Explain backtracking.

Choose an option, explore, and undo the choice if it leads nowhere, like retreating to the last junction in a maze; pruning avoids hopeless branches.

Medium Explain union-find with an analogy.

Friend groups at a party where each group has a leader: finding a person's group follows leaders upward, and merging groups links leaders, with path compression keeping chains short.

Medium Explain Dijkstra's idea.

A rumour spreading proportionally to road lengths: the first time a town hears it gives the shortest distance, provided no road has negative length.

Advanced How do you decide the complexity you need from the constraints?

About 10^8 simple operations per second: n up to 20 allows 2^n, up to 500 allows n^3, up to 5,000 allows n^2, up to 10^6 needs n log n or n, and up to 10^9 needs log n or a formula.

Advanced How do you recognise a DP problem?

Counting or optimising with overlapping subproblems and optimal substructure, where a recursive brute force repeats the same states.

Advanced What question separates stack-based from queue-based problems?

Stacks handle most-recent-first problems like matching brackets, undo and next-greater; queues handle in-order or level-by-level problems like BFS and scheduling.
