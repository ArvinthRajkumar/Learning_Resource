Part X3

Advanced dynamic programming: knapsacks, bitmasks, intervals, trees and optimisation

Module 16 introduced dynamic programming. This part gives a repeatable way to design it and covers the families that decide hard interview and contest problems. Every recurrence is verified against an exhaustive search on small inputs.

Advanced~6 hours

A method for designing DP

The five questions

  1. State: what is the smallest set of numbers that describes a subproblem? (dp[i], dp[i][j], dp[mask])
  2. Meaning: say in words what the value stores ("the best score using the first i items with capacity c").
  3. Transition: how does a state's answer come from smaller states? (the recurrence)
  4. Base cases and order: which states are known, and in what order can you fill the rest (so dependencies are ready)?
  5. Answer and cost: which state holds the final answer; time = number of states x work per state; can space be compressed?

Top-down or bottom-up

Top-down (memoised recursion) writes the recurrence directly and computes only needed states; bottom-up (tabulation) fills a table in order, avoids recursion limits and allows space optimisation. Python's functools.lru_cache makes top-down trivial for prototypes; convert to a loop when depth or speed matter.

from functools import lru_cache
import itertools, random
random.seed(0)

def coin_change_dp(coins, target):                    # minimum coins, bottom-up
    INF = float("inf")
    dp = [0] + [INF] * target
    for amount in range(1, target + 1):
        for c in coins:
            if c <= amount and dp[amount - c] + 1 < dp[amount]:
                dp[amount] = dp[amount - c] + 1
    return dp[target] if dp[target] != INF else -1

def coin_change_brute(coins, target):
    best = [float("inf")]
    def go(rem, used):
        if rem == 0: best[0] = min(best[0], used); return
        for c in coins:
            if c <= rem and used + 1 < best[0]: go(rem - c, used + 1)
    go(target, 0)
    return best[0] if best[0] != float("inf") else -1

for _ in range(60):
    coins = random.sample(range(1, 9), random.randint(1, 4))
    t = random.randint(0, 18)
    assert coin_change_dp(coins, t) == coin_change_brute(coins, t)
print("coin change DP matches brute force; example:", coin_change_dp([1, 5, 6, 9], 11))

Output

coin change DP matches brute force; example: 2

The example shows why greedy fails: for coins 1, 5, 6, 9 and target 11, greedy takes 9 + 1 + 1 (3 coins) but the optimum is 5 + 6 (2 coins). DP explores all combinations implicitly.

Knapsack family

0/1 knapsack

Each item has weight w and value v and can be used once; maximise value within capacity W. State dp[c] = best value with capacity c. Iterate items in the outer loop and capacities downwards so an item is not reused.

import itertools, random
random.seed(1)
def knapsack(items, W):
    dp = [0] * (W + 1)
    for w, v in items:
        for c in range(W, w - 1, -1):               # downwards: each item used at most once
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[W]
def brute(items, W):
    best = 0
    for mask in range(1 << len(items)):
        w = sum(items[i][0] for i in range(len(items)) if mask >> i & 1)
        if w <= W: best = max(best, sum(items[i][1] for i in range(len(items)) if mask >> i & 1))
    return best
for _ in range(80):
    items = [(random.randint(1, 8), random.randint(1, 20)) for _ in range(random.randint(1, 9))]
    W = random.randint(0, 20)
    assert knapsack(items, W) == brute(items, W)
print("0/1 knapsack verified against 2^n enumeration")

Output

def can_partition(nums):                 # subset sum: split into two equal-sum halves?
    total = sum(nums)
    if total % 2: return False
    target, reach = total // 2, {0}
    for x in nums:
        reach |= {r + x for r in reach if r + x <= target}
    return target in reach
def ways_combinations(coins, target):    # unordered: coins outer, amount inner
    dp = [1] + [0] * target
    for c in coins:
        for a in range(c, target + 1): dp[a] += dp[a - c]
    return dp[target]
def ways_permutations(coins, target):    # ordered: amount outer, coins inner
    dp = [1] + [0] * target
    for a in range(1, target + 1):
        for c in coins:
            if c <= a: dp[a] += dp[a - c]
    return dp[target]
print(can_partition([1, 5, 11, 5]), can_partition([1, 2, 3, 5]))
print("combinations:", ways_combinations([1, 2, 5], 5), "| ordered sequences:", ways_permutations([1, 2, 5], 5))

How this gets asked

In 0/1 knapsack with a 1D array, why iterate capacity downwards?

  • To use less memory Not the reason.
  • So each item is used at most once: smaller capacities have not yet been updated by the current item Correct.
  • To sort items No.
  • It is faster No.

Iterating upwards would reuse an item multiple times (unbounded knapsack).

Coins {1, 2, 5}, amount 5. How many ordered sequences sum to 5? (the count from the amount-outer loop)

Compositions of 5 using 1, 2, 5: 9. Combinations (unordered) are 4.

Sequences and strings

Longest increasing subsequence in O(n log n)

The simple DP is O(n^2). The patience sorting method keeps tails[k] = the smallest possible last element of an increasing subsequence of length k + 1; binary search finds where each new number goes.

import bisect, random
random.seed(2)
def lis_fast(a):
    tails = []
    for x in a:
        i = bisect.bisect_left(tails, x)
        if i == len(tails): tails.append(x)
        else: tails[i] = x
    return len(tails)
def lis_slow(a):
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i]: dp[i] = max(dp[i], dp[j] + 1)
    return max(dp, default=0)
for _ in range(200):
    a = [random.randint(0, 20) for _ in range(random.randint(0, 15))]
    assert lis_fast(a) == lis_slow(a)
print("O(n log n) LIS matches the O(n^2) DP; example:", lis_fast([10, 9, 2, 5, 3, 7, 101, 18]))

Output

O(n log n) LIS matches the O(n^2) DP; example: 4

Note: tails is not the subsequence itself, only its length is meaningful (reconstruct with parent pointers).

Edit distance and LCS

dp[i][j] = minimum operations to turn the first i characters of a into the first j of b; transitions: insert, delete, replace (or match for free).

from functools import lru_cache
def edit_distance(a, b):
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            cur[j] = min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (a[i - 1] != b[j - 1]))
        prev = cur
    return prev[-1]
def lcs(a, b):
    @lru_cache(None)
    def go(i, j):
        if i == len(a) or j == len(b): return 0
        if a[i] == b[j]: return 1 + go(i + 1, j + 1)
        return max(go(i + 1, j), go(i, j + 1))
    return go(0, 0)
print(edit_distance("kitten", "sitting"), edit_distance("", "abc"), lcs("ABCBDAB", "BDCABA"))

Output

3 3 4

Both are O(nm) time; keeping only two rows reduces space to O(m) (as above).

Maximum subarray product, decode ways, house robber

Track the minimum and maximum ending here (a negative flips them); for decode ways use dp[i] = dp[i-1] (valid single digit) + dp[i-2] (valid two digits); house robber is dp[i] = max(dp[i-1], dp[i-2] + a[i]).

  • The smallest possible last element of an increasing subsequence of length k + 1 Correct.
  • The index of the max No.
  • A count No.

Binary search places each element in tails.

How do you speed up LIS?

Maintain the smallest tail per length and binary search each element, giving O(n log n).

Interval DP

State dp[l][r] for the best answer on the **substring or subarray from l to r**, combining two smaller intervals by trying a split point k. Typical: matrix chain multiplication, burst balloons, palindromic partitioning, optimal BST. Fill by increasing interval length. Complexity O(n^3) for O(n^2) states and O(n) splits.

import random, itertools
random.seed(3)
def matrix_chain(dims):                          # dims of matrices: A_i is dims[i-1] x dims[i]
    n = len(dims) - 1
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            dp[l][r] = min(dp[l][k] + dp[k + 1][r] + dims[l] * dims[k + 1] * dims[r + 1] for k in range(l, r))
    return dp[0][n - 1]
def brute(dims):
    def go(l, r):
        if l == r: return 0
        return min(go(l, k) + go(k + 1, r) + dims[l] * dims[k + 1] * dims[r + 1] for k in range(l, r))
    return go(0, len(dims) - 2)
for _ in range(30):
    dims = [random.randint(1, 9) for _ in range(random.randint(2, 7))]
    assert matrix_chain(dims) == brute(dims)
print("matrix chain verified; classic example [40, 20, 30, 10, 30] ->", matrix_chain([40, 20, 30, 10, 30]))

def burst_balloons(nums):
    a = [1] + nums + [1]; n = len(a)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n):
        for l in range(n - length):
            r = l + length
            dp[l][r] = max(dp[l][k] + a[l] * a[k] * a[r] + dp[k][r] for k in range(l + 1, r))
    return dp[0][n - 1]
print("burst balloons [3, 1, 5, 8] ->", burst_balloons([3, 1, 5, 8]))

Bitmask DP

When the state is which items of a small set (up to about 20) have been used, encode it as an integer mask. 2^n states times O(n) work gives O(2^n n), far better than n!.

Travelling salesman (Held-Karp)

dp[mask][last] = shortest route visiting exactly the set mask, ending at last.

import itertools, random
random.seed(4)
def tsp(dist):
    n = len(dist)
    INF = float("inf")
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0                                      # start at city 0
    for mask in range(1 << n):
        for last in range(n):
            if dp[mask][last] == INF or not (mask >> last & 1): continue
            for nxt in range(n):
                if not (mask >> nxt & 1):
                    nm = mask | (1 << nxt)
                    dp[nm][nxt] = min(dp[nm][nxt], dp[mask][last] + dist[last][nxt])
    full = (1 << n) - 1
    return min(dp[full][last] + dist[last][0] for last in range(1, n))
def tsp_brute(dist):
    n = len(dist)
    return min(sum(dist[a][b] for a, b in zip((0,) + p, p + (0,))) for p in itertools.permutations(range(1, n)))
for _ in range(20):
    n = random.randint(3, 7)
    d = [[0 if i == j else random.randint(1, 20) for j in range(n)] for i in range(n)]
    assert tsp(d) == tsp_brute(d)
print("Held-Karp matches brute force over all permutations: O(2^n n^2) vs O(n!)")

Output

Held-Karp matches brute force over all permutations: O(2^n n^2) vs O(n!)

DP on trees and digit DP

Tree DP

Compute a value per vertex from its children using a post-order DFS. Example, maximum independent set (no two chosen vertices adjacent): for each vertex keep take and skip.

import random, itertools
random.seed(5)
def mis_tree(n, parent):
    kids = [[] for _ in range(n)]
    for v in range(1, n): kids[parent[v]].append(v)
    take, skip = [0] * n, [0] * n
    for v in range(n - 1, -1, -1):                    # parents have smaller index, so this is post-order
        take[v] = 1 + sum(skip[c] for c in kids[v])
        skip[v] = sum(max(take[c], skip[c]) for c in kids[v])
    return max(take[0], skip[0])
def brute(n, parent):
    edges = [(v, parent[v]) for v in range(1, n)]
    best = 0
    for mask in range(1 << n):
        if all(not (mask >> a & 1 and mask >> b & 1) for a, b in edges):
            best = max(best, bin(mask).count("1"))
    return best
for _ in range(60):
    n = random.randint(1, 11)
    parent = [0] + [random.randrange(v) for v in range(1, n)]
    assert mis_tree(n, parent) == brute(n, parent)
print("tree DP (take or skip) verified against subset enumeration")

Output

tree DP (take or skip) verified against subset enumeration

Other tree DPs: diameter (longest path through each vertex), rerooting (compute the answer for every root in O(n)), tree knapsack, counting paths with a property, lowest common ancestor via binary lifting.

Digit DP

Count numbers in [0, N] with a property of their digits (no two adjacent equal digits, digit sum equals s, avoiding a digit). State: position, tight bound flag, plus whatever the property needs. Handles N up to 10^18.

from functools import lru_cache
def count_no_digit_7(N):
    digits = list(map(int, str(N)))
    @lru_cache(None)
    def go(pos, tight):
        if pos == len(digits): return 1
        total = 0
        for d in range(0, (digits[pos] if tight else 9) + 1):
            if d == 7: continue
            total += go(pos + 1, tight and d == digits[pos])
        return total
    return go(0, True)
brute = lambda N: sum(1 for x in range(N + 1) if "7" not in str(x))
assert all(count_no_digit_7(N) == brute(N) for N in (0, 6, 7, 70, 99, 100, 777, 1234))
print("digit DP verified; count up to 10^18:", count_no_digit_7(10 ** 18))

Output

        bits |= bits << x
    return bool(bits >> target & 1)

When not to use DP

  • Greedy is enough and faster when the greedy-choice property holds (interval scheduling, Huffman, fractional knapsack); prove it, or test against DP.
  • The state space is too large (n up to 10^5 with an O(n^2) DP): look for structure (monotonicity, convexity, data structures) or a different model.
  • A graph shortest path or flow formulation is more natural.
  • NP-hard problems (general knapsack with huge capacity, TSP) need exponential or approximate algorithms; DP is pseudo-polynomial (knapsack is O(nW), not polynomial in the input length).

A debugging routine for DP

  1. Write the brute force first (even exponential) and compare on tiny random inputs, as in every example above.
  2. Print the table for a small case and check it by hand.
  3. Check base cases and loop direction (upwards or downwards, increasing length).
  4. Check off-by-one between 0-based items and 1-based capacities.
Key idea

State, meaning, transition, order, answer. Write the meaning of each state in a sentence; most DP bugs are a state that does not mean what the code assumes. Always validate against brute force on small cases.

Interview questions: Advanced DP

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic How do you recognise a DP problem?

Overlapping subproblems and optimal substructure: a recursive solution that recomputes the same states, where the best answer builds from best answers to smaller states.

Basic Top-down versus bottom-up DP?

Top-down memoises recursion and computes only needed states; bottom-up fills a table in dependency order, avoiding recursion depth and enabling space optimisation.

Basic Solve 0/1 knapsack and give its complexity.

dp[w] = max(dp[w], dp[w - wt] + val), iterating w downward for 0/1. O(nW) time, O(W) space; it is pseudo-polynomial.

Medium Why iterate capacity downward in 0/1 knapsack but upward for unbounded?

Downward prevents reusing an item within the same pass; upward intentionally allows reusing the same item.

Medium Longest increasing subsequence in O(n log n)?

Keep tails[k], the smallest tail of an increasing subsequence of length k + 1, and binary search each element's position.

Medium Define edit distance DP.

dp[i][j] is the cost to convert the first i characters to the first j: equal characters copy dp[i-1][j-1]; otherwise 1 + min(insert, delete, replace).

Medium How do you reconstruct the answer, not only its value?

Store the choice (parent pointer) at each state, or walk backwards through the table checking which transition produced the value.

Medium Interval DP: describe the pattern.

dp[l][r] combines dp over split points k in [l, r), iterating by increasing length. Examples: matrix chain, burst balloons, optimal BST.

Advanced When do you use bitmask DP?

When n is small (about 20) and the state is the subset of items used, as in TSP in O(2^n n^2), assignment problems and partitioning.

Advanced Explain digit DP.

Count numbers up to N with a property by processing digits left to right with state (position, tight, extra info like sum or last digit), memoising when not tight.

Advanced What is the knapsack optimisation for large weights but small values?

Swap the dimensions: dp[value] = minimum weight, giving O(n sum of values), the basis of the FPTAS.

Advanced How do convex hull trick and divide-and-conquer optimisation speed up DP?

When transitions are lines or satisfy monotone optimal split points, you can reduce O(n^2) transitions to O(n log n) or O(n).

Advanced Tree DP: how is it structured?

Compute states for children first (post-order) and combine them, e.g. maximum independent set with dp[v][taken] or rerooting to get answers for every root.

Advanced Why is the coin change count different from the minimum coins DP?

Counting combinations loops over coins outside and amounts inside (order ignored); counting sequences swaps the loops. Minimum uses min instead of sum.
