Start from scratch: why this module exists

Arrays are the oldest and most common data structure: a numbered row of boxes in memory. Nearly every other structure is built on top of one. Array fundamentals and basic operations

Essential Topic 3.1

Simple definition

An array (a Python list) is an ordered collection of items stored one after another and accessed by an index that starts at 0.

Why it matters

Arrays are the default container for input data. Most problems are about scanning, modifying or searching one.

Real-world analogy

A row of numbered lockers: you can open locker 7 instantly, but inserting a new locker in the middle means shifting all the lockers after it.

From scratch: why this idea exists and how you could invent it

You need to store many values of the same kind: marks of 60 students, daily temperatures, prices. Separate variables (m1, m2, ... m60) are impossible to loop over. You want ONE name for the whole group and a number to pick a member. That is an array.

How can the machine find the 5th item instantly? Store items one after another in memory in equal-sized slots. The address of item i is start + i x slot_size, a single multiplication and addition. That is why indexing is O(1), and why indexes start at 0 (the first item is at offset 0).

But this layout has a cost. To insert in the middle, every later item must slide over to keep the slots contiguous: O(n). To append, you need free space after the last item. If there is none, the whole array is copied to a bigger block. Python lists over-allocate extra capacity, so most appends are cheap and an occasional resize is amortised away.

Python lists hold references (pointers) to objects, not the objects themselves, so one list can hold numbers, strings and other lists. This is flexible but uses more memory than arrays in C. The array module and NumPy store raw numbers compactly when you need speed.

Almost every other structure you will meet (stacks, queues, heaps, hash tables, matrices) is built on arrays. Understanding the strengths and weaknesses of the array tells you why those structures were invented: to fix its weak spots (slow insert, slow search).

Step-by-step walkthrough

  2. Search for a value with "x in nums": O(n).

  4. Maximum: keep the largest seen so far. Second largest: keep two variables (see the problem library).
  5. Negative indices count from the end: nums[-1] is the last element.
  6. Slicing nums[a:b] creates a NEW list (O(b - a) time and space).

Deep dive in simple words

A Python list is a 'dynamic array'. The items sit next to each other in memory, so jumping to index i is one step (O(1)). Appending at the end is usually one step too. The expensive moves are at the front or middle: inserting or deleting there makes every later item shift one place, which costs O(n).

Indexing: the first item is index 0, the last is index n - 1 (or -1). Slicing nums[a:b] gives items from a up to but NOT including b. nums[::-1] reverses a copy. nums[::2] takes every second item. Slicing never raises an index error even when it goes past the end, but nums[i] does.

In-place means 'change the same list without making another big one'. In-place work needs O(1) extra space and usually uses pointers: one pointer reads and another writes (move zeroes, remove duplicates) or two pointers swap from the ends (reverse).

Looping safely: do not add or remove items from a list while a for loop is walking over it. The loop's position gets confused and items are skipped. Instead loop over a copy (for x in nums[:]) or build a new list.

Two-dimensional lists are lists of lists. Make them with [[0] * cols for _ in range(rows)]. The tempting shortcut [[0] * cols] * rows is a trap: it repeats the SAME inner list rows times, so changing one row changes all.

Under the hood: what really happens inside Python

  • CPython's list is a dynamic array of pointers. When it is full, it grows to about 1.125x its size (plus a little), so appends are amortised O(1). Removing from the end is O(1); removing from the front shifts everything and is O(n).
  • Slicing a[i:j] allocates a new list and copies j - i pointers, so it is O(j - i). a[:] is a shallow copy: the new list shares the same element objects.
  • Negative indexes are translated as len(a) + i, so a[-1] is the last element. An out-of-range single index raises IndexError, but out-of-range slice bounds are silently clipped.

  • enumerate(nums) gives (index, value) pairs; zip(a, b) walks two lists together.

Python implementation

def reverse_in_place(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        a[lo], a[hi] = a[hi], a[lo]   # swap ends
        lo += 1
        hi -= 1
    return a

Why? and Why not?

Why do list indexes start at 0?

The index is the distance from the first element. The first element is 0 steps away, so its offset is 0. It also makes address arithmetic simple.

Why is inserting in the middle slow?

Items sit side by side, so everything after the insertion point must move one place to make room: O(n).

Why not use a list as a queue?

pop(0) shifts every remaining element: O(n). Use collections.deque for O(1) at both ends.

Why does b = a not copy a list?

Assignment copies the reference (the label), not the object. Both names point at the same list. Use a[:] or list(a) to copy.

Why is append fast even though the list occasionally resizes?

Python allocates extra spare room, so most appends just use a free slot. The rare resize cost is spread over many appends (amortised O(1)).

Frequency counting, duplicates, missing numbers and rotation

Essential Topic 3.2

Simple definition

Many array problems become easy when you count how often each value appears, or use mathematical tricks (sum formulas, XOR) and the reversal trick for rotation.

Why it matters

Counting avoids nested loops. Instead of comparing every pair you look values up in a dictionary.

Real-world analogy

A ballot box: rather than comparing ballots against each other, you make one tally sheet and add a mark per ballot.

From scratch: why this idea exists and how you could invent it

A teacher asks: which marks appear more than once? Without a tool you would compare every mark with every other mark (n^2). The better human method is a tally sheet: go down the list once and put a stroke next to each mark. That tally sheet is a frequency map, and it shows the idea that most array problems hide: do not compare everything with everything; remember what you have seen.

A dictionary is the computer version of a tally sheet because looking up a key is O(1) on average. A list indexed by value does the same when values are small integers. Counting costs one pass; answering questions from the map costs one more.

Missing number: we know the SET of numbers that should be there. Instead of searching, use arithmetic: the full set sums to n(n+1)/2, so the shortfall is the missing number. When data has structure (a range, pairs), maths replaces searching and memory.

Rotation: moving every element k places looks like it needs a second array. The reversal trick shows in-place thinking: reversing the whole array flips the order and reversing each part fixes the inner order, with no extra memory. Many array puzzles are solved by combining a few reversals or swaps.

Merging two sorted lists introduced the two-pointer scan: because both lists are already ordered, the next smallest item is always one of the two fronts, so one pass is enough. Remember this: sorted input changes the best algorithm.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Frequency map: freq[x] = freq.get(x, 0) + 1 for every x. Duplicates are the keys with count > 1.
  2. Missing number in 0..n: expected sum n(n+1)/2 minus actual sum.
  3. Rotation by k: reduce k %= n, then reverse the whole list, reverse the first k, reverse the rest.
  4. Merging two sorted lists: two pointers, always take the smaller front.
  5. Sorting first can simplify problems: duplicates become adjacent.

Deep dive in simple words

Whenever a problem says 'how many times', 'which item appears twice', or 'is there a duplicate', your brain should say 'frequency map'. A frequency map is a dictionary where the key is the item and the value is how many times it appeared. You build it in one pass, then answer almost any counting question by reading it.

Counting without a dictionary: if values are small and known (like letters a-z or numbers 0-100) use a plain list as the counter, where the index is the value. counts[x] += 1. This is faster and shows you understand the idea behind counting sort.

Maths tricks save memory. For numbers 0 to n with one missing, the sum of 0..n is n(n+1)/2, so missing = expected - actual. For 'every number appears twice except one', XOR cancels pairs because x ^ x = 0. Both run in O(n) time and O(1) space.

Rotation by k: after k %= n, the last k items move to the front. The reversal trick does it in place: reverse the whole list, then reverse the first k items, then reverse the rest. Think of it as turning a sentence around and then fixing each part.

Merging two sorted lists is the heart of merge sort. Keep one pointer in each list, always take the smaller front item, and when one list ends copy what is left of the other. Linear time, no sorting needed.

Under the hood: what really happens inside Python

  • A Python dict stores keys in a hash table: hash(key) picks a slot, collisions are resolved by probing. Lookup is O(1) average. Counter is a dict subclass specialised for counting.
  • XOR works bit by bit: each bit of the result is 1 only if the bits differ. Because x ^ x = 0 and XOR is commutative and associative, any number appearing twice cancels out, no matter the order.
  • Sum-based tricks rely on exact integer arithmetic. In Python big integers prevent overflow, which is a benefit over C/Java where n(n+1)/2 can overflow 32-bit ints.

Python tips and shortcuts for this topic

  • collections.Counter(nums) builds the frequency map; .most_common(k) returns the k most frequent.
  • d.get(x, 0) returns 0 if x is missing, so d[x] = d.get(x, 0) + 1 never crashes.
  • defaultdict(int) or defaultdict(list) creates missing keys automatically.
  • set(nums) removes duplicates; len(set(nums)) < len(nums) means duplicates exist.
  • Rotation in one line: nums[-k:] + nums[:-k] (after k %= n).

Python implementation

def find_duplicates(nums):
    freq = {}
    for x in nums:
        freq[x] = freq.get(x, 0) + 1    # count occurrences
    return [k for k, v in freq.items() if v > 1]

Build it step by step: from the simplest idea to the best

Every stage is runnable and was checked against its stated result.

Stage 1 - search for every number

For each value 0..n check whether it is in the list. 'in list' is O(n), so total O(n^2).

def missing_number(nums):
    for v in range(len(nums) + 1):
        if v not in nums:
            return v

Check: missing_number([3, 0, 1]) returns 2

Stage 2 - use a set

Membership in a set is O(1), giving O(n) time with O(n) memory.

def missing_number(nums):
    s = set(nums)
    for v in range(len(nums) + 1):
        if v not in s:
            return v

Check: missing_number([3, 0, 1]) returns 2

Stage 3 - use arithmetic

The numbers 0..n always add up to n(n+1)/2. The shortfall is the missing value: O(n) time, O(1) memory.

def missing_number(nums):
    n = len(nums)
    return n * (n + 1) // 2 - sum(nums)

Check: missing_number([3, 0, 1]) returns 2

Stage 4 - use XOR

XOR cancels equal numbers, so XOR of all indices and values leaves the missing number. Same cost as stage 3 but cannot overflow in languages with fixed-size integers.

def missing_number(nums):
    x = len(nums)
    for i, v in enumerate(nums):
        x ^= i ^ v
    return x

Check: missing_number([3, 0, 1]) returns 2

Why? and Why not?

Why use a dictionary to count instead of count() in a loop?

list.count(x) scans the whole list, so calling it for every element is O(n^2). One dictionary pass is O(n).

Why does XOR find the single number?

XOR cancels equal numbers (x ^ x = 0) and does not care about order, so only the unpaired value survives.

Why not just sort to find duplicates?

Sorting works (equal items become neighbours) but costs O(n log n). A set or Counter is O(n).

Why take k %= n before rotating?

Rotating by n returns the original list, so only the remainder matters. It also prevents index errors for large k.

Why is the sum formula safe in Python but risky elsewhere?

Python integers do not overflow. In C/Java n(n+1)/2 can exceed 32-bit limits, so XOR is safer there.

Prefix sums and Kadane's algorithm

Essential Topic 3.3

Simple definition

A prefix sum array stores running totals so any range sum is a subtraction. Kadane's algorithm finds the best contiguous subarray sum by deciding at every element whether to extend the current subarray or restart.

Why it matters

Range-sum queries and "maximum sum subarray" appear constantly. Prefix sums turn O(n) per query into O(1); Kadane turns O(n^2) into O(n).

Real-world analogy

Prefix sums are the odometer of a car: distance between two towns is the difference of two readings. Kadane is a gambler who quits a losing streak and starts over.

From scratch: why this idea exists and how you could invent it

Suppose a shop owner asks 100,000 times: 'how much did we sell between day l and day r?'. Adding the range each time is slow. The natural improvement: keep a running total after each day. Then the sales between two days is the difference of two running totals. That is a prefix sum, discovered by exactly this reasoning: precompute once, answer cheaply many times.

The pattern behind it is more general: when a computation repeats on overlapping pieces, store partial results. This is the same instinct as dynamic programming and caching.

Kadane's problem: the best stretch of days for profit when some days lose money. Every candidate stretch ends somewhere. For a stretch that ends at day i, the best one either starts at day i alone or extends the best stretch that ended at i-1. That two-way decision is the whole algorithm. It works because the best stretch ending at i only depends on the best stretch ending at i-1, which is the DP idea of optimal substructure.

Why not just try all stretches? There are about n^2/2 of them, and summing each costs more. Kadane compresses this to one pass because it throws away prefixes that can only hurt (negative running sums).

Prefix sums plus a dictionary: if a stretch from i+1 to j sums to k then prefix[j] - prefix[i] = k, so prefix[i] = prefix[j] - k. Looking up how many earlier prefixes equal that value counts every valid stretch ending at j in O(1).

Visual explanation (interactive)

Step-by-step walkthrough

  1. prefix[0] = 0 and prefix[i] = nums[0] + ... + nums[i-1]. Sum of l..r (inclusive) = prefix[r+1] - prefix[l].
  2. Kadane: cur = best sum of a subarray ending HERE. cur = max(x, cur + x). best = max(best, cur).
  3. If cur + x < x then the old running sum was negative - dropping it improves the result.
  4. Dry run on [-2, 1, -3, 4, -1, 2]: cur = -2, 1, -2, 4, 3, 5; best ends at 5 (subarray [4, -1, 2]).
  5. Watch the animation: the highlighted window is the best subarray found so far.

Deep dive in simple words

A prefix sum array stores running totals. If nums = [2, 4, 1, 3] then prefix = [0, 2, 6, 7, 10]. To get the sum of a range, subtract two prefix values. Why does it work? prefix[r+1] is 'everything up to r' and prefix[l] is 'everything before l'. The difference is exactly the part in between.

Build it once in O(n), then answer every range question in O(1). If you have 100,000 questions on a list of 100,000 numbers, brute force is 10^10 steps while prefix sums take about 2 x 10^5.

Kadane's algorithm asks at every position: 'is it better to extend the subarray I was building, or start fresh here?'. If the running sum has become negative it can only hurt the future, so throw it away. That one decision per element is the whole algorithm.

Prefix sums plus a dictionary solve 'count subarrays with sum k': if prefix[j] - prefix[i] = k then prefix[i] = prefix[j] - k. While scanning, keep a dictionary of how many times each prefix has appeared and look up prefix - k. It works even with negative numbers, where sliding window fails.

Related idea: a difference array does range UPDATES fast. Instead of adding v to each cell in [l, r], add v at l and subtract v at r + 1. A prefix sum at the end rebuilds the final array.

Under the hood: what really happens inside Python

  • Prefix sums trade O(n) extra memory for O(1) queries. They work for any invertible operation (sum, XOR, count). They do NOT work for max/min because you cannot 'subtract' a max.
  • Kadane runs with two variables, so space is O(1), and each element is touched once, giving O(n). The same pass can also track the start and end indices of the best subarray.

Python implementation

def kadane(nums):
    cur = best = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)    # extend or restart
        best = max(best, cur)
    return best
Prefix sums in two lines

Stage 1 - try every subarray and add it up

Three nested loops: O(n^3). Clear but hopeless for large input.

def max_subarray(nums):
    best = nums[0]
    for i in range(len(nums)):
        for j in range(i, len(nums)):
            best = max(best, sum(nums[i:j + 1]))
    return best

Check: max_subarray([-2, 1, -3, 4, -1, 2]) returns 5

Stage 2 - keep a running sum

Extending a subarray by one element only adds that element, so the innermost sum is unnecessary: O(n^2).

def max_subarray(nums):
    best = nums[0]
    for i in range(len(nums)):
        total = 0
        for j in range(i, len(nums)):
            total += nums[j]
            best = max(best, total)
    return best

Check: max_subarray([-2, 1, -3, 4, -1, 2]) returns 5

Stage 3 - Kadane: decide at every element

The best subarray ending here either extends the previous one or starts fresh. One pass, O(n), O(1) space.

def max_subarray(nums):
    cur = best = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best

Check: max_subarray([-2, 1, -3, 4, -1, 2]) returns 5

Time and space complexity

One pass: O(n) time, O(1) space. Building prefix sums: O(n) time and space, then O(1) per query.

Common mistakes and edge cases

  • Initialising best = 0 breaks all-negative arrays.
  • Off-by-one in prefix[r+1] - prefix[l].
  • Using sliding window for arrays with negatives.

How to recognise problems that use this technique

  • "Maximum/minimum sum of a contiguous subarray" -> Kadane.
  • "Sum of range" repeated many times -> prefix sums.
  • "Count subarrays with sum k" -> prefix sums + hash map.

Why? and Why not?

Why does the prefix array start with 0?

So that sum(l..r) = prefix[r+1] - prefix[l] also works when l = 0 without a special case.

Why does Kadane restart when the running sum is negative?

A negative running sum can only lower any future subarray total, so the best choice is to start fresh at the current element.

Why not use sliding window for max subarray with negatives?

Windows assume that shrinking changes the sum in a known direction. Negative numbers break that assumption.

Why use prefix sums instead of recalculating each query?

Q queries on n items cost O(Qn) recalculating but only O(n + Q) with prefix sums.

Why initialise best with nums[0] and not 0?

If all numbers are negative the true answer is negative. Starting at 0 would wrongly return 0 (an empty subarray).

How this gets asked

For nums = [-3, -1, -2] what does Kadane return?

  • 0
  • -1
  • -3
  • -6

All numbers are negative, so the best subarray is the single largest element, -1.

Given prefix array P with P[0]=0, the sum of nums[2..4] is:

  • P[4] - P[2]
  • P[5] - P[2]
  • P[5] - P[1]
  • P[4] - P[1]

Sum(l..r) = P[r+1] - P[l].

Interview questions: Arrays and Lists

55 questions: try to answer aloud in under a minute, then reveal. All questions from every module are also in the interview bank.

Basic Conceptual How do you reverse a list in Python? Give two ways.
nums.reverse()        # in place, O(1) extra space
rev = nums[::-1]      # new reversed list, O(n) extra space

You can also write the two-pointer swap loop yourself.

Basic Conceptual Why is inserting at the front of a list slow?

Every existing element has to move one position to the right to make room, so it takes O(n). If you need fast inserts at both ends, use collections.deque.

Basic Conceptual How do you find the second largest element in one pass?

Keep two variables first and second. For each x: if x > first then second = first and first = x; elif first > x > second then second = x. Return second (or -1 if it never changed). O(n) time, O(1) space.

Basic Conceptual How do you remove duplicates from a sorted list in place?

Use a write pointer w starting at 1. For each element after the first, if it differs from nums[w-1], copy it to nums[w] and increase w. The first w items are the unique values.

Basic Conceptual What is the difference between a shallow copy and a deep copy?

A shallow copy (a[:] or list(a)) creates a new outer list but the inner objects are shared. For a list of lists, changing an inner list changes both copies. A deep copy (copy.deepcopy) copies everything recursively.

Basic Conceptual Why is array indexing O(1)?

Elements sit in contiguous memory in equal-sized slots, so the address of element i is base + i x size, computed in one step. In Python the slots hold pointers.

Basic Conceptual How do you find duplicates in a list in O(n)?

Count with a dictionary or Counter, then collect keys whose count is above 1. Or use a seen set and record an item when it is already in the set.

Basic Conceptual How do you find the missing number from 0..n in O(n) time and O(1) space?

expected = n * (n + 1) // 2 and the answer is expected - sum(nums). XOR of all indices and values also works.

Basic Conceptual How would you rotate an array by k in place?

Do k %= n, reverse the whole array, reverse the first k elements, reverse the remaining n - k elements. O(n) time, O(1) space.

Basic Conceptual How do you find the element that appears once when all others appear twice?

XOR all the numbers. Equal numbers cancel (x ^ x = 0) and 0 ^ y = y, so only the single number remains.

Basic Conceptual What is the Boyer-Moore voting algorithm?

It finds an element appearing more than n/2 times in O(1) space. Keep a candidate and a count. Same number: count + 1, different number: count - 1, when count is 0 pick a new candidate. The true majority cannot be fully cancelled out.

Basic Conceptual Why does XOR find the single number?

x ^ x = 0 and x ^ 0 = x, and XOR is order-independent, so every pair cancels and only the single number remains.

Basic Conceptual Explain Kadane's algorithm.

Scan once with cur = best sum of a subarray that ends at the current element. cur = max(x, cur + x) (extend or restart), best = max(best, cur). Time O(n), space O(1). Start best at nums[0] so all-negative arrays work.

Basic Conceptual How do prefix sums speed up range queries?

Precompute prefix[i] once in O(n). Then sum(l..r) = prefix[r+1] - prefix[l] in O(1) instead of looping each time.

Basic Conceptual How do you count subarrays with sum exactly k, even with negative numbers?

Keep a running prefix sum and a dictionary of prefix frequencies starting with {0: 1}. For each element add count[prefix - k] to the answer, then record the current prefix. O(n) time.

Basic Conceptual Why does sliding window fail when the array has negative numbers?

Window logic relies on 'adding an element increases the sum, removing decreases it'. With negatives that is not true, so you cannot decide whether to shrink or grow. Use prefix sums + hash map instead.

Basic Conceptual What do you return if the array is all negative in the maximum subarray problem?

The largest single element (the least negative). That is why best must start at nums[0], not 0.

Basic Conceptual Why do prefix sums fail for 'range maximum'?

Subtraction undoes addition but nothing undoes max. Use a sparse table or segment tree for range max.

Medium Coding Reverse an array in place and explain complexity.
def reverse(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        a[lo], a[hi] = a[hi], a[lo]
        lo += 1
        hi -= 1

O(n) time, O(1) extra space.

Medium Real-world Why do image libraries use arrays instead of linked lists?

Pixel access by coordinates must be O(1) and processing scans memory sequentially, which is fast for contiguous data thanks to CPU caching.

Medium Why / Why not Why do list indexes start at 0?

The index is the distance from the first element. The first element is 0 steps away, so its offset is 0. It also makes address arithmetic simple.

Medium Why / Why not Why is inserting in the middle slow?

Items sit side by side, so everything after the insertion point must move one place to make room: O(n).

Medium Why / Why not Why not use a list as a queue?

pop(0) shifts every remaining element: O(n). Use collections.deque for O(1) at both ends.

Medium Why / Why not Why does b = a not copy a list?

Assignment copies the reference (the label), not the object. Both names point at the same list. Use a[:] or list(a) to copy.

Medium Why / Why not Why is append fast even though the list occasionally resizes?

Python allocates extra spare room, so most appends just use a free slot. The rare resize cost is spread over many appends (amortised O(1)).

Medium Why / Why not Why use enumerate instead of range(len(nums))?

enumerate gives index and value together, is clearer, and avoids indexing mistakes. Use range(len(...)) only when you really need to change items by index.

def is_sorted(a):

O(n) time, stops at the first violation.

Medium Tricky output What does Counter('aab') - Counter('abb') produce?

Counter({'a': 1}). Subtraction keeps only positive counts: a has 2 - 1 = 1; b has 1 - 2 < 0 and is dropped.

Medium Real-world How would you find duplicate user IDs in a file with 10 million lines that does not fit memory?

Hash partition the IDs into many smaller files (same ID always lands in the same file) and check duplicates per file with a set, or use external sorting.

Medium Why / Why not Why use a dictionary to count instead of count() in a loop?

list.count(x) scans the whole list, so calling it for every element is O(n^2). One dictionary pass is O(n).

Medium Why / Why not Why does XOR find the single number?

XOR cancels equal numbers (x ^ x = 0) and does not care about order, so only the unpaired value survives.

Medium Why / Why not Why not just sort to find duplicates?

Sorting works (equal items become neighbours) but costs O(n log n). A set or Counter is O(n).

Medium Why / Why not Why take k %= n before rotating?

Rotating by n returns the original list, so only the remainder matters. It also prevents index errors for large k.

Medium Why / Why not Why is the sum formula safe in Python but risky elsewhere?

Python integers do not overflow. In C/Java n(n+1)/2 can exceed 32-bit limits, so XOR is safer there.

Medium Why / Why not Why not use a list of size max(nums) as a counter for any data?

If values are huge (10^9) the list needs gigabytes. Use a dictionary when the value range is large or unknown.

Medium Coding Return the element that appears exactly once when all others appear three times.

Count bits: for each bit position sum the bits across all numbers modulo 3; the remaining bits form the answer. O(32 n) time, O(1) space. A Counter is simpler (O(n) space).

Medium Tricky output What does Counter([1, 1, 2]).most_common(1) return?

[(1, 2)]: the most common element and its count.

Medium Coding Return the start and end index of the maximum subarray.
def max_sub_idx(a):
    best, cur, s, bs, be = a[0], a[0], 0, 0, 0
    for i in range(1, len(a)):
        if a[i] > cur + a[i]:
            cur, s = a[i], i
        else:
            cur += a[i]
        if cur > best:
            best, bs, be = cur, s, i
    return bs, be, best

Medium Coding Count subarrays with sum equal to k using prefix sums.
def count(nums, k):
    seen, pre, ans = {0: 1}, 0, 0
    for x in nums:
        pre += x
        ans += seen.get(pre - k, 0)
        seen[pre] = seen.get(pre, 0) + 1
    return ans

Reader/writer pointers: copy non-matching items to the write index and return that index as the new length.

Answer = max(Kadane max, total sum - Kadane min). If all numbers are negative the wrap case must be ignored (return the Kadane max).
