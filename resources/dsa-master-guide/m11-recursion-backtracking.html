Module 11

Recursion & Backtracking

Think recursively, then add "choose / explore / un-choose" to generate every possibility. Topics in this module: Recursion and the call stack; backtracking: subsets, permutations and combinations; n-queens and pruning.

Essential3 topics14 problems55 interview questions

Start from scratch: why this module exists

Recursion expresses a problem in terms of smaller copies of itself. Backtracking adds an undo step so you can explore every combination of choices systematically, abandoning dead ends early.

These two ideas underpin trees, graphs, divide and conquer and dynamic programming, so a firm grasp here pays off in every later module.

Who needs it: Game and puzzle solvers, compilers and parsers, constraint and scheduling software, and interviewers.

Before you start: Modules 1-2.

After this module you can

  • Write recursive functions with correct base cases.
  • Analyse recursion by drawing call trees.
  • Generate subsets, permutations and combinations.
  • Solve N-Queens with pruning.

Common pitfalls: Missing base cases, forgetting to undo choices, storing the path instead of a copy, huge recursion depth.

Typical interview questions here: Factorial/Fibonacci, power function, subsets, permutations, combination sum, generate parentheses, N-Queens, word search, sudoku.

Recursion and the call stack

Essential Topic 11.1

Simple definition

Recursion solves a problem by solving smaller copies of the same problem. Each call gets its own frame on the call stack holding its own variables; frames are removed as calls return.

Why it matters

Trees, graphs, divide-and-conquer and backtracking are naturally recursive. You also need to know when recursion is too slow.

Real-world analogy

Nested Russian dolls: opening a doll reveals a smaller doll until you reach the tiniest one (base case); then you close them in reverse order.

From scratch: why this idea exists and how you could invent it

Why does recursion exist? Because some problems are defined in terms of themselves. A folder contains files and folders. A sentence contains phrases that contain phrases. The factorial of 5 is 5 times the factorial of 4. If the definition is self-referential, the code that mirrors the definition is a function that calls itself.

To avoid infinite loops the definition needs an anchor, a case simple enough to answer directly (0! = 1, an empty folder, a leaf node). This is exactly the structure of a proof by mathematical induction: prove the base, then prove 'if true for smaller, true for this'. If you trust the smaller call, you only reason about one level at a time, which keeps your head from exploding.

The recursion tree explains cost. Draw each call as a node with its recursive calls as children. Total work is the sum of work at all nodes. Naive Fibonacci's tree is huge because fib(3) appears many times. Memoisation compresses the tree into a DAG where each distinct call appears once.

Recursion isn't free: each call uses a stack frame (time to create it, memory to keep it). In Python this also means a depth limit. Learn both ways of solving problems and choose deliberately.

Step-by-step walkthrough

  1. Three questions: (1) What is the base case? (2) How do I shrink the problem? (3) How do I combine the sub-result?
  2. fib(n) = fib(n-1) + fib(n-2) with fib(0)=0, fib(1)=1. Each call spawns two more -> the recursion TREE grows exponentially: O(2^n) calls.
  3. The same sub-problems (fib(2), fib(3)...) are recomputed many times. Memoisation caches results and reduces the cost to O(n) (Module 16).
  4. Python limits recursion depth to about 1000 (sys.setrecursionlimit can raise it). Deep recursion (like 10^5) should be converted to a loop.
  5. Use the visualiser: it shows the call stack grow and shrink, and counts the number of calls.

Deep dive in simple words

Recursion means defining a solution using smaller copies of itself. To write one, ask three questions: What is the simplest case I can answer without recursion (base case)? How do I make the problem smaller? How do I combine the answer of the smaller problem into mine?

Look at fib(4). It calls fib(3) and fib(2); fib(3) calls fib(2) and fib(1)... The picture is a tree. The same sub-problems (like fib(2)) appear again and again. That is why plain recursive Fibonacci is O(2^n). Remember the answers (memoisation) and it becomes O(n).

Recursion uses the call stack. Each call stores its own variables. Deep recursion uses lots of memory and Python limits it (about 1000). Prefer loops for simple counting and use recursion when the problem is naturally nested: trees, graphs, divide and conquer.

Tail recursion (the recursive call is the last action) can be turned into a loop easily. Python does not optimise it for you.

Debugging tip: print the arguments at the start of the function with indentation based on depth, or draw the recursion tree by hand for a tiny input.

Under the hood: what really happens inside Python

  • CPython frames are heap-allocated objects; each Python-level call costs on the order of a microsecond and the default recursion limit of 1000 protects the C stack.
  • functools.lru_cache wraps the function and stores results in a dict keyed by arguments, which is why arguments must be hashable (use tuples not lists).
  • Mutual recursion and tail calls also appear, but CPython has no tail-call optimisation.

Stage 1 - plain recursion

Mirrors the definition but recomputes the same values: O(2^n).

def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

Check: fib(20) returns 6765

Stage 2 - add a notebook (memoisation)

Cache every answer the first time. Each n is computed once: O(n).

def fib(n, memo=None):
    memo = {} if memo is None else memo
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]

Check: fib(20) returns 6765

Stage 3 - loop with two variables

No recursion limit and O(1) space.

def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

Why does naive Fibonacci take exponential time?

It recomputes the same subproblems over and over (fib(3) many times).

Each distinct n is computed once, reducing the work to O(n).

To protect the interpreter from running out of memory in endless recursion.

Both solve the base case and then show that solving the smaller case lets you solve the bigger one.

Some problems (trees, backtracking) are far clearer recursively.

Backtracking: subsets, permutations and combinations

Essential Topic 11.2

Simple definition

Backtracking builds a solution one choice at a time. After exploring a choice, it undoes it ("un-choose") and tries the next option - like exploring a maze and walking back at dead ends.

Why it matters

It generates all subsets, permutations, combinations and solves constraint puzzles (N-Queens, Sudoku) while pruning impossible branches early.

Real-world analogy

Choosing an outfit: pick a shirt, then trousers; if you do not like the result, put the trousers back and try different ones.

From scratch: why this idea exists and how you could invent it

Some problems ask for ALL arrangements or ALL choices: every subset, every ordering, every valid way. There is no clever formula; you must generate them. How do you generate systematically without missing or repeating any? Make one decision at a time and explore both consequences.

Picture standing at a maze junction. You choose a corridor and walk. At a dead end you walk back to the junction and try the next corridor. 'Walking back' is the undo step. Backtracking is a depth-first search of the tree of all possible choices, where each node is a partial solution.

Why undo instead of copying the state each time? Copying is O(n) per step. Undoing is O(1) per step because you reverse only the last change (append then pop). That is why backtracking uses one shared list and push/pop.

Pruning is where backtracking beats brute force. If a partial solution already breaks a rule (sum too big, queen attacked), abandon the whole subtree. Large parts of the search space vanish without being visited.

Counting what you will generate (2^n, n!, Catalan numbers) tells you the largest n that is feasible. That is why constraints like n <= 10 or n <= 15 hint at backtracking.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Template: record answer if complete -> for each option: choose (append) -> recurse -> un-choose (pop).
  2. Subsets: at each call the current path is a valid subset. Loop i from start; recurse with i + 1 so each element is used at most once and order does not repeat.
  3. Permutations: use a used array; recurse with no start index; base case when len(path) == n.
  4. Combination sum: recurse with the same index i to allow reuse; prune when remaining < 0.
  5. Sizes: subsets 2^n, permutations n!, combinations C(n, k). That is why backtracking only works for small n.
  6. Always store a COPY of the path: res.append(path[:]).
  7. The visualiser walks through the decision tree for subsets.

Deep dive in simple words

Backtracking is recursion for making a sequence of choices. At each step: choose an option, explore everything that follows from it, then UN-choose (undo) it and try the next option. Undoing is the 'back' in backtracking; it restores the state like walking back to a junction in a maze.

Use one shared list called path. Append the choice, recurse, then pop. Because you reuse the same list, never store the path itself in your results; store a copy (path[:]), otherwise later changes change your stored answer.

Subsets: at every call the current path is already a valid subset, so record it. Then try each later item (use a start index so you never choose items out of order and never repeat a subset). Permutations: choose any item not yet used; the answer is complete when the path has n items.

Combinations (choose k items) stop when the path length is k. Combination sum allows reuse: recurse with the same index. Prune early: if the remaining target is negative, stop; if a sorted candidate is already bigger than the target, break.

Duplicates: sort the input and skip an item that equals the previous item at the same level. This avoids generating the same subset twice.

Remember the size of the answer: subsets 2^n, permutations n!, so this technique is only for small n (about 20 for subsets, about 10 for permutations).

Under the hood: what really happens inside Python

  • The recursion tree for subsets has 2^n leaves and depth n; permutations have n! leaves. Cost per leaf is O(n) to copy the path.
  • Sorting the input and skipping equal neighbours (i > start and a[i] == a[i-1]) deduplicates results at a level without a set.
  • Pruning with sorted input: if candidates[i] > remaining, every later candidate is also too big, so break instead of continue.

Python implementation

def gen_subsets(nums, start, path, res):
    res.append(path[:])                     # every path is a subset
    for i in range(start, len(nums)):
        path.append(nums[i])                # choose
        gen_subsets(nums, i + 1, path, res) # explore
        path.pop()                          # un-choose

def subsets(nums):
    res = []
    gen_subsets(nums, 0, [], res)
    return res

Build it step by step: from the simplest idea to the best

Every stage is runnable and was checked against its stated result.

Stage 1 - build subsets by doubling

Start with [[]]. For each item copy every existing subset and add the item. Simple and iterative.

def subsets(nums):
    res = [[]]
    for x in nums:
        res += [s + [x] for s in res]
    return res

Check: len(subsets([1, 2, 3])) returns 8

Stage 2 - backtracking

Choose, explore, un-choose. This is the template that also handles pruning (combination sum, N-Queens).

def subsets(nums):
    res, path = [], []
    def go(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            go(i + 1)
            path.pop()
    go(0)
    return res

Check: len(subsets([1, 2, 3])) returns 8

Stage 3 - bitmasks

Every number from 0 to 2^n - 1 is a subset. Short, but no pruning is possible.

def subsets(nums):
    n = len(nums)
    return [[nums[i] for i in range(n) if m >> i & 1] for m in range(1 << n)]

Check: len(subsets([1, 2, 3])) returns 8

Why? and Why not?

Why undo (pop) after each recursive call?

The shared path must return to its previous state before the next option is tried.

Why store path[:] and not path?

path keeps changing; a copy freezes the current answer.

Why use a start index in subsets?

It ensures each subset is built in increasing order so none is generated twice.

Why prune?

Cutting branches that cannot succeed avoids exploring huge parts of the search space.

Why sort the input for duplicate handling?

Equal values become adjacent, so a simple 'skip if equal to the previous' rule removes duplicate subsets.

N-Queens and pruning

Important Topic 11.3

Simple definition

N-Queens asks you to place n queens on an n x n board so none attack each other. Backtracking places one queen per row and abandons a placement as soon as it conflicts.

Why it matters

It is the standard example of pruning: rejecting partial solutions early shrinks an enormous search space.

Real-world analogy

Seating guests who dislike each other: seat them one at a time and if the next guest has no valid seat, move the previous guest.

From scratch: why this idea exists and how you could invent it

N-Queens is the classic 'place things so none conflict'. A naive plan tries every placement of n queens on n^2 squares: astronomically many. Insight one: two queens can never share a row, so put exactly one per row and only choose columns. That alone reduces n^2-choose-n to n^n.

Insight two: check conflicts as you place. If a queen conflicts with an earlier one, do not continue; undo and try another column. Whole subtrees disappear. For n = 8 the full space has millions of branches but only about 2,000 board states are ever visited.

Insight three: make conflict checks O(1). A queen at (r, c) attacks column c, the diagonal where r - c is constant and the anti-diagonal where r + c is constant. Three sets give instant checks.

N-Queens teaches the full pattern of constraint satisfaction: choose, check, recurse, undo. Sudoku, graph colouring and scheduling are the same shape with different constraints.

Visual explanation (interactive)

Step-by-step walkthrough

  1. One queen per row, so we only decide the column for each row.
  2. Queens conflict if they share a column or a diagonal. Diagonals: row - col is constant on one direction, row + col on the other.
  3. Keep three sets (cols, diag1, diag2) so each safety test is O(1).
  4. Try each column; if safe, mark it, recurse to the next row, then unmark.
  5. For n = 4 there are exactly two solutions. The visualiser shows queens being placed and removed.

Deep dive in simple words

N-Queens: place n queens on an n x n chessboard so none can capture another. Queens attack along rows, columns and both diagonals. Because there must be exactly one queen per row, we place one queen per row and only decide the column.

Checking attacks fast: keep three sets: used columns, used 'down-left' diagonals (row - col is the same along one) and used 'down-right' diagonals (row + col is the same along the other). Checking a square is three O(1) set lookups.

The search: for row 0 try every column; if safe, place and recurse to the next row. If no column works in some row, return and move the previous queen. When we pass the last row, we found a solution.

Pruning is why it works: without pruning there are n^n placements; with pruning the search tree is tiny for small n (for n = 8 there are 92 solutions).

Other 'place things without conflicts' problems (Sudoku, graph colouring, word search) use exactly the same skeleton.

Under the hood: what really happens inside Python

  • The number of solutions for n = 1..8 is 1, 0, 0, 2, 10, 4, 40, 92. Search nodes visited are far fewer than n^n thanks to pruning.
  • Using bit masks for columns and diagonals makes it much faster in practice (an integer holds the occupied columns), but sets are clearer for interviews.

Python implementation

def n_queens(n):
    cols, d1, d2 = set(), set(), set()
    count = 0
    def place(row):
        nonlocal count
        if row == n:
            count += 1
            return
        for c in range(n):
            if c in cols or row - c in d1 or row + c in d2:
                continue                       # pruned: attacked
            cols.add(c); d1.add(row - c); d2.add(row + c)
            place(row + 1)
            cols.remove(c); d1.remove(row - c); d2.remove(row + c)
    place(0)
    return count

Roughly O(n!) with heavy pruning in practice; O(n) space.

  • Forgetting to remove diagonals when backtracking.

Basic Conceptual What are the parts of a recursive function?

A base case that stops the recursion, a recursive case that calls the function with a smaller input, and (usually) a way to combine the results.

Basic Conceptual Why is naive recursive Fibonacci slow?

It recomputes the same values exponentially many times (O(2^n)). Memoisation reduces it to O(n).

Basic Conceptual Recursion vs iteration - which is better?

Iteration is usually faster and uses O(1) stack. Recursion is clearer for trees, graphs and backtracking. Python has a recursion limit, so deep inputs need loops.

Basic Conceptual What is memoisation?

Caching results of function calls by their arguments so repeated calls return instantly.

Basic Conceptual What is a base case and what happens if it is missing or unreachable?

It is the case answered without recursion. If missing, the recursion never stops and Python raises RecursionError.

Basic Conceptual Explain backtracking.

Build a solution step by step. At each step choose, recurse, then undo the choice. Prune branches that cannot lead to a valid answer.

Basic Conceptual Generate all subsets of a list.
def subsets(nums):
    res, path = [], []
    def go(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            go(i + 1)
            path.pop()
    go(0)
    return res
Basic Conceptual Why must you copy the path before storing it?

path is a single list that keeps changing. If you store the list itself, all stored answers end up pointing to the same final (empty) list.

Basic Conceptual How do you avoid duplicate subsets when the input has duplicates?

Sort the input and skip nums[i] if i > start and nums[i] == nums[i - 1].

Basic Conceptual Time complexity of generating all permutations?

O(n x n!). There are n! permutations and each takes O(n) to copy.

Basic Conceptual What is pruning?

Stopping a branch early when it cannot possibly produce a valid solution (for example the remaining sum is already negative).

Basic Conceptual What is the time complexity of generating all subsets?

O(n x 2^n): there are 2^n subsets and copying each takes up to O(n).

Basic Conceptual Explain the N-Queens algorithm.

Place queens row by row. For each row try each column; skip squares attacked via column or diagonal (checked with sets); place, recurse, remove (backtrack). Count or collect solutions when all rows are filled.

Basic Conceptual How do you check diagonals in constant time?

Cells on the same '/' diagonal share row + col, cells on the same '\' diagonal share row - col. Keep sets of those values.

Basic Conceptual How many solutions does 8-Queens have?

92 (12 if you count rotations and reflections as the same).

Basic Conceptual What is the time complexity?

Roughly O(n!) in the worst case, far smaller in practice due to pruning.

Basic Conceptual How do you detect diagonal conflicts in O(1)?

Cells on the same diagonal share r - c and on the other diagonal share r + c; keep sets of used values.

def combine(n, k):
    res, path = [], []
    def go(start):
        if len(path) == k:
            res.append(path[:])
            return
        for i in range(start, n + 1):
