Part X8

Advanced tree techniques: LCA, binary lifting, Euler tours, diameter, rerooting and treaps

Tree problems at interview level go beyond traversal: find the common ancestor of two nodes, sum a subtree after updates, answer distances, or compute something for every possible root. This part gives the standard toolkit with the reasoning and tested code.

Advanced~5 hours

Trees as data: rooted, parents and depths

A tree with n nodes has n - 1 edges and exactly one path between any two nodes. Most techniques begin by rooting the tree and computing, for every node, its parent, depth and subtree size in one DFS (use an explicit stack for deep trees in Python).

import random
random.seed(1)
def random_tree(n):
    return [(random.randrange(i), i) for i in range(1, n)]            # edge (parent, child); node 0 is the root
def build(n, edges):
    adj = [[] for _ in range(n)]
    for a, b in edges: adj[a].append(b); adj[b].append(a)
    return adj
def dfs_info(n, adj, root=0):
    parent, depth, order, size = [-1] * n, [0] * n, [], [1] * n
    stack = [root]
    while stack:                                                       # iterative preorder
        u = stack.pop(); order.append(u)
        for v in adj[u]:
            if v != parent[u]: parent[v], depth[v] = u, depth[u] + 1; stack.append(v)
    for u in reversed(order):                                          # children before parents
        if parent[u] >= 0: size[parent[u]] += size[u]
    return parent, depth, order, size
n = 12; edges = random_tree(n); adj = build(n, edges)
parent, depth, order, size = dfs_info(n, adj)
print("parent:", parent); print("depth :", depth); print("subtree sizes:", size, "| root size is n:", size[0] == n)

Output

parent: [-1, 0, 0, 1, 0, 3, 3, 3, 6, 3, 1, 7]
depth : [0, 1, 1, 2, 1, 3, 3, 3, 4, 3, 2, 4]
subtree sizes: [12, 9, 1, 7, 1, 1, 2, 2, 1, 1, 1, 1] | root size is n: True

Lowest common ancestor (LCA)

The LCA of u and v is the deepest node that is an ancestor of both. Distance between them is depth[u] + depth[v] - 2 depth[lca]. Three common methods:

Walk up with depthsnoneO(h)Simple; fine for balanced or small trees
Binary liftingO(n log n)O(log n)Easy to code; also gives k-th ancestor

Binary lifting

Store up[k][v], the 2^k-th ancestor of v. Lift the deeper node to the same depth by jumping with the bits of the depth difference, then lift both together from the largest jump down while their ancestors differ.

import random
random.seed(2)
LOG = 5
def preprocess(n, parent):
    up = [[0] * n for _ in range(LOG)]
    for v in range(n): up[0][v] = parent[v] if parent[v] >= 0 else v          # the root is its own ancestor
    for k in range(1, LOG):
        for v in range(n): up[k][v] = up[k - 1][up[k - 1][v]]
    return up
def lca(u, v, depth, up):
    if depth[u] < depth[v]: u, v = v, u
    diff = depth[u] - depth[v]
    for k in range(LOG):
        if diff >> k & 1: u = up[k][u]
    if u == v: return u
    for k in reversed(range(LOG)):
        if up[k][u] != up[k][v]: u, v = up[k][u], up[k][v]
    return up[0][u]
def lca_naive(u, v, parent, depth):
    while depth[u] > depth[v]: u = parent[u]
    while depth[v] > depth[u]: v = parent[v]
    while u != v: u, v = parent[u], parent[v]
    return u
def kth_ancestor(v, k, up):
    for i in range(LOG):
        if k >> i & 1: v = up[i][v]
    return v
n = 30
parent = [-1] + [random.randrange(i) for i in range(1, n)]
depth = [0] * n
for v in range(1, n): depth[v] = depth[parent[v]] + 1
up = preprocess(n, parent)
for _ in range(500):
    u, v = random.randrange(n), random.randrange(n)
    assert lca(u, v, depth, up) == lca_naive(u, v, parent, depth)
print("binary lifting LCA matches the naive walk on 500 random queries")
deep = max(range(n), key=lambda v: depth[v])
print("deepest node", deep, "at depth", depth[deep], "| its 2nd ancestor:", kth_ancestor(deep, 2, up), "equals walking up twice:", parent[parent[deep]] if depth[deep] >= 2 else None)

Output

binary lifting LCA matches the naive walk on 500 random queries
deepest node 15 at depth 5 | its 2nd ancestor: 9 equals walking up twice: 9

The same table answers "k-th ancestor", "is u an ancestor of v" (compare after lifting) and path queries when combined with extra tables (max edge on the path, using mx[k][v] alongside up).

Euler tour: turning subtrees into ranges

Record the time you enter and exit each node in a DFS: tin[v], tout[v]. A node u is an ancestor of v exactly when tin[u] <= tin[v] < tout[u]. Crucially, the **subtree of v is the contiguous range** [tin[v], tout[v]) in DFS order. So "sum over a subtree" becomes "sum over a range", and a Fenwick tree (X1) handles point updates with range queries in O(log n).

import random
random.seed(3)
n = 40
parent = [-1] + [random.randrange(i) for i in range(1, n)]
children = [[] for _ in range(n)]
for v in range(1, n): children[parent[v]].append(v)
tin, tout, timer = [0] * n, [0] * n, 0
stack = [(0, 0)]
while stack:                                                           # iterative DFS with enter/exit events
    v, state = stack.pop()
    if state == 0:
        tin[v] = timer; timer += 1
        stack.append((v, 1))
        for c in children[v]: stack.append((c, 0))
    else:
        tout[v] = timer
class Fenwick:
    def __init__(self, n): self.t = [0] * (n + 1)
    def add(self, i, d):
        i += 1
        while i < len(self.t): self.t[i] += d; i += i & -i
    def prefix(self, i):                                               # sum of [0, i)
        s = 0
        while i > 0: s += self.t[i]; i -= i & -i
        return s
values = [random.randint(1, 9) for _ in range(n)]
fw = Fenwick(n)
for v in range(n): fw.add(tin[v], values[v])
def subtree_sum(v): return fw.prefix(tout[v]) - fw.prefix(tin[v])
def subtree_sum_naive(v):
    return values[v] + sum(subtree_sum_naive(c) for c in children[v])
for _ in range(100):
    v = random.randrange(n); assert subtree_sum(v) == subtree_sum_naive(v)
for _ in range(100):                                                   # point updates, then re-check
    v, d = random.randrange(n), random.randint(-5, 5)
    values[v] += d; fw.add(tin[v], d)
    w = random.randrange(n); assert subtree_sum(w) == subtree_sum_naive(w)
print("subtree sums with point updates verified against recursion; root subtree sum:", subtree_sum(0), "=", sum(values))

Output

subtree sums with point updates verified against recursion; root subtree sum: 186 = 186

For path queries with updates (sum from root to v), use the same tour: adding d to node u adds d to every node in u's subtree's root-path sums, a range update, point query (Fenwick on a difference array).

Diameter, centres and farthest nodes

The diameter is the longest path in a tree. Classic two-pass method: BFS from any node to find the farthest node a; BFS from a to find the farthest node b; the distance a to b is the diameter. This works because the farthest node from any start is always an end of some diameter (for unweighted or non-negative weighted trees). The centre is the middle node (or two nodes) of the diameter path; rooting there minimises the height.

import random, itertools
from collections import deque
random.seed(4)
def bfs(adj, src):
    dist = {src: 0}; q = deque([src])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist: dist[v] = dist[u] + 1; q.append(v)
    return dist
def diameter(adj):
    d0 = bfs(adj, 0); a = max(d0, key=d0.get)
    da = bfs(adj, a); b = max(da, key=da.get)
    return da[b], a, b
for _ in range(200):
    n = random.randint(2, 12)
    adj = [[] for _ in range(n)]
    for i in range(1, n):
        p = random.randrange(i); adj[p].append(i); adj[i].append(p)
    best = max(bfs(adj, s)[t] for s in range(n) for t in range(n))
    assert diameter(adj)[0] == best
print("two-pass diameter matches the brute-force maximum over all pairs on 200 random trees")
path_adj = [[1], [0, 2], [1, 3], [2, 4], [3]]
print("diameter of a path of 5 nodes:", diameter(path_adj)[0])

Output

two-pass diameter matches the brute-force maximum over all pairs on 200 random trees
diameter of a path of 5 nodes: 4

Rerooting: answers for every root in O(n)

Some problems ask, for every node as the root, a quantity such as the sum of distances to all other nodes. Recomputing from scratch costs O(n^2). Rerooting computes it once for the root (a down pass), then derives each child's answer from its parent's (an up pass).

For the sum of distances: let down[v] be the sum of distances from v to nodes in its subtree and size[v] the subtree size. Then ans[root] = down[root], and moving the root from p to a child c brings the size[c] nodes of c's subtree one step closer and the other n - size[c] nodes one step farther: ans[c] = ans[p] - size[c] + (n - size[c]).

import random
from collections import deque
random.seed(5)
def sum_distances_all_roots(n, adj):
    parent, order = [-1] * n, []
    stack = [0]
    while stack:
        u = stack.pop(); order.append(u)
        for v in adj[u]:
            if v != parent[u]: parent[v] = u; stack.append(v)
    size, down = [1] * n, [0] * n
    for u in reversed(order):                                           # down pass
        p = parent[u]
        if p >= 0: size[p] += size[u]; down[p] += down[u] + size[u]
    ans = [0] * n; ans[0] = down[0]
    for u in order[1:]:                                                 # up pass: parents are processed first
        ans[u] = ans[parent[u]] - size[u] + (n - size[u])
    return ans
def brute(n, adj):
    out = []
    for s in range(n):
        dist = {s: 0}; q = deque([s])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if v not in dist: dist[v] = dist[u] + 1; q.append(v)
        out.append(sum(dist.values()))
    return out
for _ in range(200):
    n = random.randint(1, 15)
    adj = [[] for _ in range(n)]
    for i in range(1, n):
        p = random.randrange(i); adj[p].append(i); adj[i].append(p)
    assert sum_distances_all_roots(n, adj) == brute(n, adj)
print("rerooting matches brute force on 200 random trees; star with 4 leaves:", sum_distances_all_roots(5, [[1, 2, 3, 4], [0], [0], [0], [0]]))

Output

rerooting matches brute force on 200 random trees; star with 4 leaves: [4, 7, 7, 7, 7]

The same two-pass pattern solves: the root minimising height, the number of nodes within distance k of each node (with more bookkeeping), tree DP "for every root" such as maximum independent set weight (X3).

Heavy-light decomposition (HLD) in outline

Query "max (or sum) on the path between u and v" with point or range updates. HLD splits the tree into heavy paths: each node's heavy child is the child with the largest subtree. Any root-to-node path crosses at most O(log n) light edges, so it consists of O(log n) heavy-path segments. Lay out each heavy path contiguously in an array (DFS order visiting the heavy child first) and run a segment tree or Fenwick tree over it; a path query becomes O(log n) range queries, O(log^2 n) total.

Use it when a problem has both path queries and updates and binary lifting (static) is not enough. The implementation is long; knowing when it applies and the O(log^2 n) bound is what interviews usually check.

How this gets asked

Why does a root-to-node path cross only O(log n) light edges in heavy-light decomposition?

  • Light edges are rare Not the reason.
  • Each light edge at least doubles the subtree size you move into, so there can be only log n of them Correct.
  • Heavy edges are free No.
  • Trees are shallow No.

Going up a light edge, the parent's subtree is at least twice the child's.

Balanced trees and treaps

A treap stores (key, priority): it is a binary search tree by key and a heap by priority. Giving each node a random priority makes the tree balanced in expectation (expected height O(log n)), with simple code based on split and merge. It supports order statistics, range operations and implicit-key sequences (insert, delete, reverse a range).

import random
random.seed(6)
class Node:
    __slots__ = ("key", "pri", "left", "right", "size")
    def __init__(self, key): self.key, self.pri, self.left, self.right, self.size = key, random.random(), None, None, 1
def sz(t): return t.size if t else 0
def upd(t): t.size = 1 + sz(t.left) + sz(t.right)
def split(t, key):                                                # (keys < key, keys >= key)
    if not t: return None, None
    if t.key < key:
        a, b = split(t.right, key); t.right = a; upd(t); return t, b
    a, b = split(t.left, key); t.left = b; upd(t); return a, t
def merge(a, b):                                                  # all keys of a < all keys of b
    if not a or not b: return a or b
    if a.pri > b.pri: a.right = merge(a.right, b); upd(a); return a
    b.left = merge(a, b.left); upd(b); return b
def insert(t, key):
    a, b = split(t, key); return merge(merge(a, Node(key)), b)
def erase(t, key):
    a, b = split(t, key); _, c = split(b, key + 1); return merge(a, c)
def kth(t, k):                                                    # k-th smallest, 0-indexed
    while t:
        if k < sz(t.left): t = t.left
        elif k == sz(t.left): return t.key
        else: k -= sz(t.left) + 1; t = t.right
def height(t): return 0 if not t else 1 + max(height(t.left), height(t.right))
root, shadow = None, []
for _ in range(2000):
    x = random.randrange(10_000)
    if x in shadow: continue
    shadow.append(x); root = insert(root, x)
for x in random.sample(shadow, 500):
    root = erase(root, x); shadow.remove(x)
shadow.sort()
assert all(kth(root, i) == shadow[i] for i in range(0, len(shadow), 17))
print(f"{sz(root)} keys after random inserts and deletes; order statistics verified; height {height(root)} (a balanced tree would be about {len(shadow).bit_length()}, a chain would be {len(shadow)})")

Output

1286 keys after random inserts and deletes; order statistics verified; height 25 (a balanced tree would be about 11, a chain would be 1286)

Self-check

What do split and merge do?

Split partitions a treap by key into two treaps; merge joins two treaps whose keys are ordered, choosing the root by priority.

Choosing a technique

QuestionTool
Common ancestor, distance between nodes, k-th ancestorBinary lifting (or Euler tour + RMQ)
Subtree sum or update, "is u in v's subtree"Euler tour ranges + Fenwick
Path query with updatesHeavy-light decomposition + segment tree
Longest path, tree centreTwo BFS passes
Answer for every possible rootRerooting DP
Dynamic ordered set with order statisticsTreap, AVL, or a skip list
Offline many queries on a static treeTarjan offline LCA, or sort and sweep
Key idea

Root the tree and precompute parents, depths and DFS order once. Then LCA is binary lifting, subtrees are contiguous ranges of the Euler tour, paths are a few heavy-chain ranges, "every root" is rerooting, and random priorities give balance for free. Always test against a simple recursive version on small random trees.

Interview questions: Advanced trees

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic How do you compute depth, parent and subtree size for every node?

One DFS from the root (iterative for deep trees) records parent and depth; subtree sizes accumulate from children to parents in reverse visit order.

Basic What is the lowest common ancestor?

The deepest node that is an ancestor of both given nodes. The tree distance between u and v is depth[u] + depth[v] - 2 depth[lca].

Medium Explain binary lifting.

Precompute up[k][v], the 2^k-th ancestor of v. For LCA, lift the deeper node to equal depth using the bits of the difference, then lift both while their 2^k ancestors differ, and return the parent. O(n log n) preprocessing, O(log n) per query.

Medium How does an Euler tour turn subtree queries into range queries?

Record entry and exit times in DFS. A subtree occupies the contiguous range [tin, tout), so subtree sums with point updates use a Fenwick tree in O(log n).

Medium How do you test whether u is an ancestor of v?

tin[u] <= tin[v] < tout[u] using entry and exit times.

Medium How do you find the diameter of a tree?

BFS from any node to the farthest node a, then BFS from a; the farthest distance is the diameter. It works for non-negative edge weights.

Medium What is a tree centre?

The middle node (or two nodes) of a diameter path; rooting there minimises the height.

Advanced Explain rerooting dynamic programming.

Compute answers for the root in a bottom-up pass, then derive each child's answer from its parent's in a top-down pass, solving 'for every root' queries in O(n), such as the sum of distances.

Advanced Give the rerooting recurrence for the sum of distances.

ans[child] = ans[parent] - size[child] + (n - size[child]): nodes in the child's subtree get one closer and all others one farther.

Advanced What is heavy-light decomposition and its complexity?

It splits the tree into heavy chains by choosing the largest-subtree child at each node. A path crosses O(log n) light edges, so path queries with a segment tree cost O(log^2 n).

Advanced Why does a path touch only O(log n) light edges?

Each light edge leads to a subtree at most half the size of its parent's, so the subtree size at least doubles going up, limiting light edges to log n.

Advanced What is a treap and why is it balanced?

A BST by key and a heap by random priority. The random priorities make its shape equal to a random-insertion BST, giving expected O(log n) height with simple split and merge operations.

Advanced How would you support 'k-th smallest' in a dynamic set?

A balanced BST or treap with subtree sizes (order-statistic tree), or a Fenwick tree over compressed values with binary descent.

Advanced What is the offline Tarjan LCA algorithm?

A DFS using union-find that answers all LCA queries in near-linear time when they are known in advance.
