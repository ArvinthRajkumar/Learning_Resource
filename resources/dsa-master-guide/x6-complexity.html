Complexity theory: amortised analysis, recurrences, NP-completeness and lower bounds

Big-O is about growth, not speed: it ignores constants and lower terms, and says nothing for small inputs. "Best/worst/average case" describes which input you analyse; O, Omega, Theta describe which bound you give. Typical ordering: 1 < log n < sqrt n < n < n log n < n^2 < n^3 < 2^n < n! .

Amortised analysis

Amortised cost is the average cost per operation over a worst-case sequence, with no probability involved. Three methods: aggregate (total cost / number of operations), accounting (charge credits) and potential (a potential function Phi; amortised cost = actual + change in Phi).

Dynamic array doubling

Appending costs 1 normally and k when copying k elements into a double-size array. Over n appends the copies total 1 + 2 + 4 + ... < 2n, so the amortised cost is O(1).

def total_copy_cost(n, factor=2):
    cap, size, cost = 1, 0, 0
    for _ in range(n):
        if size == cap:
            cost += size            # copy all elements
            cap = max(cap + 1, int(cap * factor))
        size += 1
        cost += 1                   # the append itself
    return cost
for n in [10**3, 10**4, 10**5]:
    print(f"n = {n:>6}: total cost / n = {total_copy_cost(n) / n:.2f} (doubling) vs {total_copy_cost(n, 1.0) / n:.1f} (grow by +1)")

Output

n =  10000: total cost / n = 2.64 (doubling) vs 5000.5 (grow by +1)

Growing by a constant instead of a factor gives O(n) amortised cost per append, which is why geometric growth is essential.

Other classic examples

  • Binary counter increment: each bit flips at most once per 2^i increments, total O(n) flips for n increments.
  • Two-stack queue: each element moves between stacks at most once.
  • Union-find with union by rank and path compression: inverse-Ackermann amortised.
  • Monotonic stack / sliding window: each element is pushed and popped once.
  • Splay trees, **Fibonacci heap decrease-key**: proved with potentials.
def counter_flips(n):
    bits, flips = [0] * 40, 0
    for _ in range(n):
        i = 0
        while bits[i] == 1:
            bits[i] = 0; flips += 1; i += 1
        bits[i] = 1; flips += 1
    return flips
for n in [100, 1000, 10**5]:

Self-check

Amortised versus average case?

Amortised is the worst-case average over a sequence of operations with no randomness; average case assumes a probability distribution over inputs.

Recurrences and the Master theorem

Divide-and-conquer gives T(n) = a T(n / b) + f(n): a subproblems of size n/b and f(n) work to split and combine. Compare f(n) with n^(log_b a):

import math
from functools import lru_cache
@lru_cache(None)
def T(n):  # merge sort comparisons-like recurrence
    return 0 if n <= 1 else T(n // 2) + T(n - n // 2) + n
@lru_cache(None)
def K(n):  # Karatsuba-like: 3 subproblems of half size plus linear work
    return 1 if n <= 1 else 3 * K(n // 2) + n
for n in [2**10, 2**14, 2**18]:
    print(f"n = 2^{int(math.log2(n)):>2}: T/(n log n) = {T(n) / (n * math.log2(n)):.3f} | K/n^1.585 = {K(n) / n ** math.log2(3):.3f}")

Output

n = 2^14: T/(n log n) = 1.000 | K/n^1.585 = 2.993

Both ratios stay roughly constant as n grows, confirming Theta(n log n) and Theta(n^1.585). When the Master theorem does not apply (unequal splits, such as T(n) = T(n/3) + T(2n/3) + n), draw the recursion tree or use Akra-Bazzi.

P, NP, NP-hard and NP-complete

  • P: decision problems solvable in polynomial time (shortest path, sorting, matching, linear programming).
  • NP: problems whose "yes" answers can be verified in polynomial time given a certificate (a subset, a colouring, a path). P is contained in NP.
  • NP-hard: at least as hard as every problem in NP (everything in NP reduces to it). Need not be in NP (e.g. halting problem).
  • NP-complete: in NP and NP-hard. The hardest problems in NP.
  • Whether P = NP is open. If any NP-complete problem has a polynomial algorithm, all of NP does.

Reductions

To show problem B is NP-hard, reduce a known NP-hard A to it: transform any instance of A into an instance of B in polynomial time, preserving the answer. Chain: SAT, 3-SAT, Clique, Independent Set, Vertex Cover, Hamiltonian Cycle, TSP (decision), Subset Sum, Partition, Knapsack (decision), Graph Colouring (k >= 3).

Subset sum and knapsack are pseudo-polynomial (O(nW)): polynomial in the value of W but exponential in its bit-length, so they are NP-hard yet DP solves them for small W.

from itertools import combinations
# Verification is cheap, search is expensive: Subset Sum
def verify(nums, subset, target):  # O(n)
    return sum(subset) == target and all(x in nums for x in subset)
def search(nums, target):  # O(2^n)
    for r in range(len(nums) + 1):
        for c in combinations(nums, r):
            if sum(c) == target: return c
nums = [3, 34, 4, 12, 5, 2]
sol = search(nums, 9)
print("certificate:", sol, "| verified in linear time:", verify(nums, sol, 9))

Output

certificate: (4, 5) | verified in linear time: True

Coping with hardness

  1. Exact exponential with pruning: backtracking, branch and bound, DP over subsets (O(2^n n) for TSP, X3).
  2. Approximation with a guarantee: vertex cover by taking both endpoints of a maximal matching is within factor 2; metric TSP within 1.5 (Christofides).
  3. Heuristics: greedy, local search, simulated annealing, genetic algorithms.
  4. Special cases: trees, small treewidth, small parameters (fixed-parameter tractable).
  5. Pseudo-polynomial DP when the numbers are small.
import random, itertools
random.seed(4)
def vc_two_approx(edges):
    cover, used = set(), set()
    for u, v in edges:
        if u not in used and v not in used:
            cover |= {u, v}; used |= {u, v}
    return cover
def vc_opt(n, edges):
    for k in range(n + 1):
        for c in itertools.combinations(range(n), k):
            s = set(c)
            if all(u in s or v in s for u, v in edges): return k
worst = 0
for _ in range(200):
    n = 8
    edges = [(i, j) for i in range(n) for j in range(i + 1, n) if random.random() < 0.3]
    if not edges: continue
    approx = len(vc_two_approx(edges)); opt = vc_opt(n, edges)
    assert approx <= 2 * opt
    worst = max(worst, approx / opt)
print("2-approximation never exceeded factor 2; worst observed ratio:", round(worst, 2))

Output

2-approximation never exceeded factor 2; worst observed ratio: 2.0

Self-check

What does a reduction prove?

That B is at least as hard as A: an algorithm for B would solve A after a polynomial-time transformation.

What is pseudo-polynomial time?

Polynomial in the numeric value of the input (like knapsack capacity W) but exponential in its bit length.

Lower bounds

Comparison sorting needs Omega(n log n) comparisons. A decision tree distinguishing all n! orderings has at least n! leaves, so height at least log2(n!), which is Theta(n log n) by Stirling. Counting, radix and bucket sort beat it by not using only comparisons.

import math, itertools
for n in [4, 8, 16, 64]:
    print(f"n = {n:>3}: ceil(log2(n!)) = {math.ceil(math.log2(math.factorial(n))):>4} comparisons needed at minimum | n log2 n = {n * math.log2(n):.0f}")
def mergesort_compares(a):
    cnt = [0]
    def ms(x):
        if len(x) <= 1: return x
        L, R = ms(x[:len(x)//2]), ms(x[len(x)//2:])
        out, i, j = [], 0, 0
        while i < len(L) and j < len(R):
            cnt[0] += 1
            if L[i] <= R[j]: out.append(L[i]); i += 1
            else: out.append(R[j]); j += 1
        return out + L[i:] + R[j:]
    ms(a); return cnt[0]
worst = max(mergesort_compares(list(p)) for p in itertools.permutations(range(8)))
print("merge sort worst case on 8 items:", worst, "vs information-theoretic minimum", math.ceil(math.log2(math.factorial(8))))

Other lower bounds worth knowing: searching a sorted array is Omega(log n) (comparisons); finding the maximum needs n - 1 comparisons; element distinctness needs Omega(n log n) in the comparison model; any algorithm that must read every input item is Omega(n).

Why can radix sort beat n log n?

Space complexity and recursion cost

  • Recursion depth counts as space: DFS is O(h) on trees, up to O(n) on a path; merge sort uses O(n) auxiliary; quicksort O(log n) expected stack.
  • In-place means O(1) extra space (ignoring the stack). Python's default recursion limit (1000) makes deep recursion a practical limit; convert to an explicit stack.
  • Time-space trade-offs: memoisation, hash sets, precomputation tables, and rolling arrays in DP.
Key idea

State complexity with the input variable defined (n, m, V, E, W), say which case, count recursion stack, and use amortised bounds for data structure operations. For hard problems, name the class, the nearest tractable relative, and a realistic strategy.

Interview questions: Complexity theory

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic Difference between O, Omega and Theta?

Upper bound, lower bound, and tight bound. They are independent of best/worst/average case.

Basic What is the complexity of nested loops where the inner runs i times?

Sum of i from 1 to n is n(n + 1)/2, which is Theta(n^2).

Basic What is amortised analysis?

Averaging the cost over a worst-case sequence of operations, e.g. dynamic array append is O(1) amortised although a resize costs O(n).

Medium State the Master theorem.

For T(n) = aT(n/b) + f(n): compare f with n^(log_b a). If f is polynomially smaller the answer is n^(log_b a); if equal, n^(log_b a) log n; if polynomially larger (with regularity), f(n).

Medium Why do comparison sorts need Omega(n log n)?

A decision tree with n! leaves has height at least log2(n!), which is Theta(n log n).

Medium What is the difference between P and NP?

P can be solved in polynomial time; NP can be verified in polynomial time given a certificate. P is a subset of NP; whether they are equal is open.

Medium What does NP-complete mean?

A problem in NP to which every problem in NP reduces in polynomial time.

Medium Name some NP-complete problems.

SAT, 3-SAT, clique, vertex cover, Hamiltonian cycle, subset sum, graph colouring, travelling salesman (decision).

Advanced What is pseudo-polynomial time?

Polynomial in the numeric value of the input rather than its bit length, like knapsack DP O(nW). The problem remains weakly NP-hard.

Advanced How do you prove a problem is NP-hard?

Reduce a known NP-hard problem to it in polynomial time, so a fast algorithm for the new problem would solve the known one.

Advanced What strategies exist for NP-hard problems in practice?

Exact search with pruning, DP over small parameters, approximation algorithms with guarantees, heuristics and local search, and exploiting special structure.

Advanced Give an approximation algorithm and its guarantee.

Vertex cover: take both endpoints of each edge in a maximal matching, giving at most twice the optimum.

Advanced Why is the 2-SAT problem in P but 3-SAT NP-complete?

2-SAT reduces to reachability in an implication graph, solved by SCCs in linear time; no such structure exists for three-literal clauses.

Advanced What is the time complexity of recursive Fibonacci and how do you improve it?

Exponential, about 1.618^n. Memoisation or iteration makes it O(n), matrix exponentiation O(log n).
