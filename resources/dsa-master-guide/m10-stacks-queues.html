Stacks & Queues

LIFO and FIFO containers, plus the monotonic stack trick that solves "next greater" style problems. Topics in this module: Stack (LIFO); queue, deque, circular queue and priority queue; balanced parentheses and monotonic stacks.

Essential3 topics13 problems55 interview questions

Start from scratch: why this module exists

Stacks and queues restrict access to make behaviour predictable: last-in-first-out (undo, nesting) and first-in-first-out (waiting lines). The restriction is a feature: fewer operations, no way to misuse them, and a direct match to many real processes.

Monotonic stacks and deques extend the idea to solve 'next greater' and sliding-window problems in linear time.

Who needs it: Compilers (parsing), operating systems (scheduling), browsers (history), message systems (queues) and interviewers.

  • Use monotonic stacks and deques.
  • Choose between stack, queue, deque and priority queue.

Common pitfalls: Using list.pop(0) as a queue, popping an empty stack, storing values instead of indices in monotonic stacks.

Stack (LIFO)

Essential Topic 10.1

Simple definition

A stack is a collection where the last item added is the first removed (Last In, First Out). The operations are push (add on top), pop (remove top) and peek (look at top).

Why it matters

Stacks track "what is still open or pending": brackets, undo history, function calls, expression evaluation.

Real-world analogy

A pile of plates: you can only add or remove from the top.

From scratch: why this idea exists and how you could invent it

Think about how you read a maths expression like (2 + (3 * 4)). When you hit the first '(' you must remember that something is still open. When you hit the next '(' you remember another. When you hit ')' you close the most recently opened one. The 'most recent unfinished thing' is always the one to resolve first. That is Last In, First Out.

A stack is the minimal data structure for that behaviour: you may only touch the top. Restricting the operations is a feature: with only push, pop and peek (all O(1)) there is nothing to get wrong, and the discipline matches many real problems (undo, nested calls, matching).

Your own program uses a stack all the time: the call stack. When function A calls B, A pauses and B runs on top; when B returns, control comes back to A. Recursion is a stack in disguise, and DFS can be written with an explicit stack instead of recursion.

In Python you never need a special class: a list with append and pop is a stack. This is why many Python solutions are only a few lines.

When you see 'matching', 'nested', 'undo', 'most recent', 'reverse order' or 'evaluate an expression', think stack first.

Deep dive in simple words

A stack is a pile where you can only touch the top. Last in, first out. Real-life examples: undo in an editor, the back button of a browser, a stack of plates. Python programs themselves use a stack of function calls.

In Python the list is a perfect stack: append(x) pushes, pop() removes and returns the top, stack[-1] peeks. All three are O(1). Never use pop(0); that is a queue operation and costs O(n).

The pattern: 'match the most recent unfinished thing'. Brackets are the classic: when you see a closer, the opener it matches is the most recent unmatched opener, which is the top of the stack. Same idea for HTML tags, nested functions and undo history.

Expression evaluation: in postfix (reverse Polish) notation like '2 3 + 4 *', numbers are pushed and an operator pops the top two numbers, applies the operation and pushes the result. Careful: the first number popped is the RIGHT operand.

Depth-first search is also stack-based: a recursion uses the call stack, and an iterative DFS uses your own list as a stack.

Under the hood: what really happens inside Python

  • Python's list.append and list.pop() work at the end of a dynamic array: amortised O(1) each. list.pop(0) would shift the whole array: O(n).
  • The call stack is a stack of frame objects. The recursion limit protects the interpreter from unbounded growth.

Python implementation

class Stack:
    def __init__(self):
        self.items = []

    def push(self, x):
        self.items.append(x)

    def pop(self):
        if not self.items:
            raise IndexError("pop from empty stack")
        return self.items.pop()

    def peek(self):
        return self.items[-1] if self.items else None

    def is_empty(self):
        return not self.items

    def size(self):
        return len(self.items)

Queue, deque, circular queue and priority queue

Essential Topic 10.2

Simple definition

A queue is First In, First Out: items are added at the back (enqueue) and removed from the front (dequeue). A deque allows O(1) operations at both ends. A priority queue always gives the smallest (or largest) item first.

Why it matters

Queues model waiting lines and BFS. Deques power sliding-window tricks. Priority queues power schedulers, Dijkstra and top-K problems.

Real-world analogy

A ticket counter: the person who arrived first is served first. A hospital emergency room is a priority queue: the most urgent patient goes first.

From scratch: why this idea exists and how you could invent it

People wait in line: the first person to arrive is served first. That fairness rule (First In, First Out) is the queue. Operating systems schedule tasks this way, printers print jobs this way and BFS explores a graph this way.

Why can't a Python list be a good queue? Removing the first element forces every other element to shift left: O(n) each time. A deque (double-ended queue) is built so both ends are O(1). That is why the standard answer is collections.deque.

A circular queue fixes a classic array problem: if you dequeue from the front of a fixed array, the freed slots at the front are wasted. Wrapping the indexes with modulo reuses them, so a fixed-size buffer behaves like an endless queue. Keyboard buffers and audio streams use this.

Sometimes order of arrival is not what matters; priority is. An emergency room treats the most urgent patient first. A priority queue returns the most important item first. The heap makes this efficient: O(log n) to insert and remove instead of O(n) to scan.

Three structures, three question types: 'serve in arrival order' (queue), 'access both ends' (deque), 'serve the best next' (priority queue).

Visual explanation (interactive)

Step-by-step walkthrough

  1. Do NOT use list.pop(0) for queues: it is O(n). Use collections.deque: append(x) to enqueue, popleft() to dequeue, both O(1).
  2. Circular queue: a fixed-size array with front and rear indices that wrap around using % capacity so freed slots are reused.
  3. Deque: appendleft, append, popleft, pop - all O(1).
  4. Priority queue: heapq.heappush(h, x) and heapq.heappop(h) are O(log n); h[0] is the minimum. For a max-heap, push negative values.
  5. Try enqueue and dequeue in the live demo.

Deep dive in simple words

A queue is a line: first in, first out. Add at the back (enqueue), remove from the front (dequeue). BFS, task scheduling and 'process in order of arrival' all use queues. In Python use collections.deque, because popping from the left of a list is O(n).

A deque (double-ended queue) can add and remove at BOTH ends in O(1). It also works as a stack. It is the tool behind the sliding window maximum trick: keep a deque of indices in decreasing value order.

A circular queue stores items in a fixed array and uses front/size with modulo to wrap around, reusing freed slots. It is often asked in theory and design questions. Track size separately to tell 'full' from 'empty'.

A priority queue gives the item with the highest priority first, not the oldest. Python's heapq implements a min-heap: heappush and heappop are O(log n), and heap[0] peeks at the smallest in O(1). For a max-heap push negative numbers. For custom priorities push tuples (priority, item).

How to choose: plain order of arrival -> deque. Need smallest/largest repeatedly -> heap. Need both ends -> deque. Need random access -> list.

Under the hood: what really happens inside Python

  • deque is a doubly linked list of fixed-size blocks, which makes append/popleft O(1) and memory use efficient. Indexing in the middle is O(n).
  • heapq maintains a binary heap in a plain list: parent at (i-1)//2, children at 2i+1, 2i+2; push sifts up, pop sifts down in O(log n).
  • Circular queue: next free slot is (front + size) % capacity; full when size == capacity; empty when size == 0.

Python implementation

from collections import deque
import heapq

class CircularQueue:
    def __init__(self, capacity):
        self.data = [None] * capacity
        self.front = self.size = 0
        self.cap = capacity

    def enqueue(self, x):
        if self.size == self.cap:
            return False                       # full
        self.data[(self.front + self.size) % self.cap] = x
        self.size += 1
        return True

    def dequeue(self):
        if self.size == 0:
            return None
        x = self.data[self.front]
        self.front = (self.front + 1) % self.cap    # wrap around
        self.size -= 1
        return x

Balanced parentheses and monotonic stacks

Essential Topic 10.3

Simple definition

A monotonic stack keeps its elements in increasing or decreasing order. When a new element breaks the order you pop until it fits - each pop resolves a pending question, such as "what is the next greater element?".

Why it matters

Next greater element, daily temperatures, stock span and largest rectangle all fall in O(n) with this idea, versus O(n^2) brute force.

Real-world analogy

People in a queue at a photo shoot: a taller person steps in and everyone shorter in front of them becomes "hidden" - they are resolved and removed.

From scratch: why this idea exists and how you could invent it

Next greater element: for each number find the first bigger number to its right. The obvious method scans right from each element: O(n^2) in bad cases. Observe the waste: if you are looking for something bigger than a, and a bigger b to the right is found, then b also answers every smaller element sitting between them that has not yet found its answer.

So keep a 'waiting room' of elements that have not found their answer. When a new number arrives, it answers every waiting element smaller than it. The waiting elements are always in decreasing order from bottom to top, because a larger number arriving would have cleared the smaller ones. Decreasing order is why it is called monotonic.

Each element enters the waiting room once and leaves once, so total work is O(n). This 'amortised' argument is the key analytic idea: the while loop in the code does not multiply, it is bounded by the number of pushes.

Once you see the template you can adapt it: next smaller (flip the comparison), previous greater (scan from the other side), stock span, daily temperatures (store index differences), and largest rectangle in a histogram (when a lower bar arrives, the popped bar's rectangle ends here).

Visual explanation (interactive)

Step-by-step walkthrough

  1. Balanced brackets: push openers, match closers; the stack must be empty at the end.
  2. Next greater: keep a stack of INDICES whose answer is unknown (their values decrease). For a new x, while stack top value < x, pop it and set its answer to x. Then push the new index.
  3. Every index is pushed once and popped once -> O(n).
  4. Example [4, 5, 2, 25]: 4 waits; 5 > 4 resolves 4; 2 waits; 25 resolves 2 and 5; 25 never resolved -> -1.
  5. Use both visualisers: bracket matching and next greater.

Deep dive in simple words

A monotonic stack keeps its items in sorted order (always increasing or always decreasing). When a new item breaks the order you pop items until the order is restored. Each pop is when an item 'finds its answer'.

Next greater element: keep a stack of positions that are still waiting for a bigger number to the right. When a bigger number arrives, it answers every smaller waiting position on top of the stack. Then it joins the stack itself. The leftover positions at the end have no greater element.

Why O(n)? Every position is pushed once and popped at most once. The inner while loop looks scary but the total pops cannot exceed the total pushes.

Daily temperatures, stock span, next smaller element, trapping rain water and largest rectangle in a histogram are all variations. The difference is what you store (value or index) and which comparison you use (< or >).

Tip: store INDICES, not values. You can always get the value with nums[index], and indices let you compute distances.

Under the hood: what really happens inside Python

  • Storing indices instead of values lets you compute distances and read values via a[idx]. Using strict or non-strict comparison decides how equal values behave.
  • Adding a sentinel (like a 0 height at the end) flushes everything left on the stack at the end of the scan so no special cleanup is needed.

Python implementation

def is_balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

def next_greater(nums):
    res = [-1] * len(nums)
    stack = []                     # indices with unresolved answers
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x
        stack.append(i)
    return res

Interview questions: Stacks & Queues

Basic Conceptual What is a stack? Give uses.

A LIFO collection with push, pop and peek in O(1). Uses: undo/redo, bracket matching, expression evaluation, DFS, function call stack, browser history.

Basic Conceptual How do you check balanced brackets?
def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    st = []
    for ch in s:
        if ch in pairs:
            if not st or st.pop() != pairs[ch]:
                return False
        else:
            st.append(ch)
    return not st
Basic Conceptual How would you implement a queue using two stacks?

Push onto an 'inbox' stack. When you need to pop, if the 'outbox' is empty move everything from inbox to outbox (reversing the order) and pop from outbox. Amortised O(1) per operation.

Basic Conceptual How do you get the minimum of a stack in O(1)?

Store (value, min so far) pairs, or keep a second stack of minimums.

Basic Conceptual What happens if you pop an empty list?

IndexError. Check 'if stack:' before popping.

Basic Conceptual Why is the call stack a stack?

Functions finish in the reverse order that they started: the most recently called function must finish first.

Basic Conceptual Why should you not use list.pop(0) as a queue?

It shifts every remaining element, costing O(n). collections.deque.popleft() is O(1).

Basic Conceptual What is a deque?

A double-ended queue with O(1) append and pop at both ends.

Basic Conceptual What is a priority queue and how is it implemented in Python?

A queue that always returns the smallest (or highest priority) item first. Python's heapq module (binary min-heap): push and pop are O(log n).

Basic Conceptual How do you make a max-heap with heapq?

Store negative values (or use negated priorities) and negate again after popping.

Basic Conceptual How does a circular queue work?

A fixed-size array with a front index and a size. Position of the next free slot is (front + size) % capacity; dequeue moves front = (front + 1) % capacity.

Basic Conceptual Implement a queue with a list of two stacks.

See the 'Queue Using Two Stacks' problem in the library.

Basic Conceptual What is the difference between a queue and a priority queue?

A queue serves by arrival order; a priority queue serves by priority regardless of arrival order.

Basic Conceptual What is a monotonic stack?

A stack whose elements are kept in increasing or decreasing order by popping elements that violate the order when a new element arrives.

Basic Conceptual Solve Next Greater Element in O(n).

Scan left to right with a stack of indices waiting for a greater value. For each x pop while nums[stack[-1]] < x and set their answer to x; then push the current index.

Basic Conceptual Why is it O(n) and not O(n^2)?

Each element is pushed once and popped at most once, so total work is at most 2n.

Basic Conceptual How would you do daily temperatures?

Same as next greater element but store index differences: answer[j] = i - j.

Basic Conceptual What is the largest rectangle in a histogram approach?

Keep a stack of increasing bar heights. When a smaller bar arrives, pop taller bars and compute area = height x width where width reaches back to the previous stack element.

Basic Conceptual Why is the algorithm O(n) even with a while loop inside the for loop?

Each index is pushed once and popped at most once, so total pops are bounded by n.

Medium Real-world Why do web servers use a queue between request handling and heavy work?

It absorbs bursts: requests are enqueued quickly and workers process them at their own pace, preventing overload and enabling retries.

Medium Why / Why not Why is deque better than list for queues?

popleft is O(1) while list.pop(0) shifts all items.

Medium Why / Why not Why use a circular queue?

It reuses freed array slots by wrapping indexes, giving a fixed-size queue without wasted space.

Medium Why / Why not Why a priority queue instead of sorting repeatedly?

A heap gives the next best item in O(log n) after each insert, while re-sorting costs O(n log n).

Medium Why / Why not Why does heapq give a min-heap only?

That is how the library is written; negate values to simulate a max-heap.

Medium Why / Why not Why track size in a circular queue?

front == rear is ambiguous (empty or full); a size counter removes the ambiguity.

Medium Why / Why not Why not always use a heap when order matters?

If you only need arrival order, a deque is simpler and O(1).

Medium Coding Compute the stock span for each day (number of consecutive days up to and including today with price <= today).
def spans(p):
    st, res = [], []
    for i, x in enumerate(p):
        while st and p[st[-1]] <= x:
            st.pop()
        res.append(i + 1 if not st else i - st[-1])
        st.append(i)
    return res
