Part X9

Problem-solving techniques: sqrt decomposition, Mo's algorithm, divide and conquer, meet in the middle, bit tricks and randomisation

Beyond data structures there are techniques: reorganise the work into blocks, answer queries in a smart order, split the problem in half, or let randomness do the balancing. Each technique here is explained by the problem shape it fits, then shown in working, brute-force-checked code.

Sqrt decomposition

Split an array of n items into blocks of size B about sqrt(n). Store a summary per block. A range query combines whole blocks from summaries and the partial ends item by item: about n/B + 2B = O(sqrt n). Updates change an item and its block summary. It is slower than a segment tree but handles operations where merging two summaries is hard.

import math, random
random.seed(1)
class SqrtArray:
    def __init__(self, a):
        self.a, self.B = a[:], max(1, int(math.sqrt(len(a))))
        self.sums = [sum(a[i:i + self.B]) for i in range(0, len(a), self.B)]
    def update(self, i, v):
        self.sums[i // self.B] += v - self.a[i]; self.a[i] = v
    def query(self, l, r):                                    # inclusive range sum
        total, B = 0, self.B
        while l <= r and l % B != 0: total += self.a[l]; l += 1          # left partial block
        while l + B - 1 <= r: total += self.sums[l // B]; l += B          # whole blocks
        while l <= r: total += self.a[l]; l += 1                          # right partial block
        return total
a = [random.randint(-9, 9) for _ in range(500)]
sa = SqrtArray(a)
for _ in range(2000):
    if random.random() < 0.3:
        i, v = random.randrange(500), random.randint(-9, 9); sa.update(i, v); a[i] = v
    else:
        l = random.randrange(500); r = random.randrange(l, 500); assert sa.query(l, r) == sum(a[l:r + 1])
print(f"sqrt decomposition (block size {sa.B}) matches brute force on 2000 mixed operations")

Output

sqrt decomposition (block size 22) matches brute force on 2000 mixed operations

A strong use: mode of a range or count of distinct values, where you keep per-block frequency tables; and "rebuild every sqrt(q) updates" patterns where a batch of recent changes is checked separately from a static preprocessed structure.

How this gets asked

What is the typical per-query cost of sqrt decomposition?

  • O(1) No.
  • O(sqrt n) Correct.
  • O(log n) That is a segment tree.
  • O(n) No.

Whole blocks plus two partial ends.

Self-check

When prefer sqrt decomposition over a segment tree?

When the combine operation is hard to define on summaries, or when simplicity matters more than log versus sqrt speed.

Mo's algorithm (offline range queries)

Suppose you must answer q queries "how many distinct values are in a[l..r]?" and you can move a window [L, R] by adding or removing one end element in O(1). Mo's algorithm sorts the queries to keep window moves small: group queries by block of l (size about n / sqrt(q)), and within a block sort by r (alternating direction). Total pointer movement is O((n + q) sqrt n) instead of O(n q).

import math, random
random.seed(2)
def mo_distinct(a, queries):
    n = len(a); B = max(1, int(n / math.sqrt(max(1, len(queries)))))
    order = sorted(range(len(queries)), key=lambda i: (queries[i][0] // B, queries[i][1] if (queries[i][0] // B) % 2 == 0 else -queries[i][1]))
    count, distinct, L, R, ans, moves = {}, 0, 0, -1, [0] * len(queries), 0
    def add(i):
        nonlocal distinct
        count[a[i]] = count.get(a[i], 0) + 1
        if count[a[i]] == 1: distinct += 1
    def remove(i):
        nonlocal distinct
        count[a[i]] -= 1
        if count[a[i]] == 0: distinct -= 1
    for qi in order:
        l, r = queries[qi]
        while L > l: L -= 1; add(L); moves += 1
        while R < r: R += 1; add(R); moves += 1
        while L < l: remove(L); L += 1; moves += 1
        while R > r: remove(R); R -= 1; moves += 1
        ans[qi] = distinct
    return ans, moves
n, q = 2000, 2000
a = [random.randint(0, 50) for _ in range(n)]
queries = []
for _ in range(q):
    l = random.randrange(n); queries.append((l, random.randrange(l, n)))
ans, moves = mo_distinct(a, queries)
for i in random.sample(range(q), 200): assert ans[i] == len(set(a[queries[i][0]:queries[i][1] + 1]))
naive_work = sum(r - l + 1 for l, r in queries)
print(f"Mo's answers verified | window moves {moves:,} versus {naive_work:,} element visits for the naive approach")

Output

Mo's answers verified | window moves 75,558 versus 1,008,297 element visits for the naive approach

Requirements: queries are known in advance (offline), updates are absent (or use the time-dimension variant), and an element can be added and removed cheaply. Typical tasks: distinct count, frequency-based statistics, counting pairs with a property.

How this gets asked

What does Mo's algorithm require?

  • Online queries It is offline.
  • Offline queries and a window where adding or removing one element is cheap Correct.
  • A sorted array No.
  • Updates between queries Not the basic form.

Sort queries by (block of l, r) to minimise pointer movement.

Self-check

How are queries ordered in Mo's algorithm?

By the block of the left endpoint, then by the right endpoint (often alternating direction).

Divide and conquer

Split the input in half, solve each half, combine across the split. The combine step is where the work is. Complexity follows the recurrence T(n) = 2T(n/2) + f(n) (X6): with f(n) = O(n) you get O(n log n).

Counting inversions with merge sort

An inversion is a pair i < j with a[i] > a[j]. While merging two sorted halves, every time an element of the right half is placed before remaining elements of the left half, it forms inversions with all of them.

import random, itertools
random.seed(3)
def count_inversions(a):
    if len(a) <= 1: return a, 0
    mid = len(a) // 2
    left, x = count_inversions(a[:mid]); right, y = count_inversions(a[mid:])
    merged, i, j, cross = [], 0, 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]: merged.append(left[i]); i += 1
        else: merged.append(right[j]); j += 1; cross += len(left) - i          # right[j] precedes all remaining left elements
    merged += left[i:] + right[j:]
    return merged, x + y + cross
for _ in range(300):
    a = [random.randint(0, 9) for _ in range(random.randint(0, 12))]
    assert count_inversions(a)[1] == sum(1 for i, j in itertools.combinations(range(len(a)), 2) if a[i] > a[j])
print("inversion counting verified | reversed list of 6 has", count_inversions([6, 5, 4, 3, 2, 1])[1], "inversions (15 = 6 choose 2)")

Output

inversion counting verified | reversed list of 6 has 15 inversions (15 = 6 choose 2)

Maximum subarray by divide and conquer

The best subarray is in the left half, the right half, or crosses the middle (best suffix of the left plus best prefix of the right). Kadane's linear scan is simpler, but the divide-and-conquer form generalises to problems where a streaming scan does not (segment-tree style merges).

import random
random.seed(4)
def max_sub(a, lo, hi):
    if lo == hi: return a[lo]
    mid = (lo + hi) // 2
    best_left, best_right = max_sub(a, lo, mid), max_sub(a, mid + 1, hi)
    s, left_best = 0, float("-inf")
    for i in range(mid, lo - 1, -1): s += a[i]; left_best = max(left_best, s)
    s, right_best = 0, float("-inf")
    for i in range(mid + 1, hi + 1): s += a[i]; right_best = max(right_best, s)
    return max(best_left, best_right, left_best + right_best)
for _ in range(300):
    a = [random.randint(-6, 6) for _ in range(random.randint(1, 12))]
    brute = max(sum(a[i:j]) for i in range(len(a)) for j in range(i + 1, len(a) + 1))
    assert max_sub(a, 0, len(a) - 1) == brute
print("divide-and-conquer maximum subarray verified")

Output

divide-and-conquer maximum subarray verified

Binary search on the answer

When "can we achieve value x?" is a monotone yes/no question (feasible for all x >= x0), binary search for the smallest feasible x using a greedy or simple check. Works for "minimise the maximum" and "maximise the minimum" problems.

import random
random.seed(5)
def min_largest_sum(nums, k):
    """Split nums into k contiguous parts to minimise the largest part sum."""
    def feasible(limit):
        parts, cur = 1, 0
        for x in nums:
            if x > limit: return False
            if cur + x > limit: parts += 1; cur = x
            else: cur += x
        return parts <= k
    lo, hi = max(nums), sum(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid): hi = mid
        else: lo = mid + 1
    return lo
def brute(nums, k):
    from itertools import combinations
    n, best = len(nums), float("inf")
    for cuts in combinations(range(1, n), k - 1):
        bounds = (0,) + cuts + (n,)
        best = min(best, max(sum(nums[bounds[i]:bounds[i + 1]]) for i in range(k)))
    return best
for _ in range(300):
    nums = [random.randint(1, 9) for _ in range(random.randint(1, 8))]; k = random.randint(1, len(nums))
    assert min_largest_sum(nums, k) == brute(nums, k)
print("binary search on the answer verified | [7,2,5,10,8] into 2 parts:", min_largest_sum([7, 2, 5, 10, 8], 2))

Output

binary search on the answer verified | [7,2,5,10,8] into 2 parts: 18

Meet in the middle

If brute force over n items costs 2^n, split the items into two halves of n/2, enumerate each half's subsets (2^(n/2) each), and combine with sorting plus two pointers or a hash lookup. For n = 40, 2^40 (about 10^12) becomes 2 x 2^20 (about 2 x 10^6).

import random, itertools, bisect
random.seed(6)
def subset_sums(items):
    sums = [0]
    for x in items: sums += [s + x for s in sums]
    return sums
def closest_subset_sum(items, target):
    half = len(items) // 2
    A, B = subset_sums(items[:half]), sorted(subset_sums(items[half:]))
    best = None
    for a in A:
        j = bisect.bisect_left(B, target - a)
        for k in (j - 1, j):                                          # neighbours of the ideal partner
            if 0 <= k < len(B):
                cand = a + B[k]
                if best is None or abs(cand - target) < abs(best - target): best = cand
    return best
for _ in range(200):
    items = [random.randint(-20, 40) for _ in range(random.randint(1, 12))]; target = random.randint(-30, 100)
    brute = min((sum(c) for r in range(len(items) + 1) for c in itertools.combinations(items, r)), key=lambda s: (abs(s - target), s))
    assert abs(closest_subset_sum(items, target) - target) == abs(brute - target)
big = [random.randint(1, 10**6) for _ in range(30)]
print("meet in the middle verified | 30 items solved with", 2 ** 15 * 2, "enumerated sums instead of", 2 ** 30, "| closest sum to 7,000,000:", closest_subset_sum(big, 7_000_000))

Output

meet in the middle verified | 30 items solved with 65536 enumerated sums instead of 1073741824 | closest sum to 7,000,000: 7000000

Bit manipulation and masks

Integers are arrays of bits; masks represent subsets of up to about 20 to 30 elements.

import random
random.seed(7)
def all_subsets_of(mask):
    sub, out = mask, []
    while True:
        out.append(sub)
        if sub == 0: break
        sub = (sub - 1) & mask
    return out
mask = 0b10110
subs = all_subsets_of(mask)
print("submasks of", bin(mask), ":", [bin(s) for s in sorted(subs)], "| count 2^popcount:", len(subs) == 2 ** mask.bit_count())
nums = [4, 1, 2, 1, 2, 7, 4]
single = 0
for x in nums: single ^= x
print("the element appearing once (XOR of everything):", single)
def single_numbers_two(nums):                                         # two unique numbers among pairs
    xor = 0
    for x in nums: xor ^= x
    low = xor & -xor                                                  # a bit where the two unique numbers differ
    a = b = 0
    for x in nums:
        if x & low: a ^= x
        else: b ^= x
    return sorted((a, b))
print("two unique numbers:", single_numbers_two([1, 2, 1, 3, 2, 5]))
def xor_range(prefix, l, r): return prefix[r + 1] ^ prefix[l]
arr = [random.randint(0, 255) for _ in range(50)]
prefix = [0]
for x in arr: prefix.append(prefix[-1] ^ x)
l, r = 7, 31
direct = 0
for x in arr[l:r + 1]: direct ^= x
print("range XOR via prefix XOR equals direct:", xor_range(prefix, l, r) == direct)
print("Gray code sequence of 3 bits:", [i ^ (i >> 1) for i in range(8)], "(each differs from the previous by one bit)")

Randomised algorithms

Randomness gives simple algorithms with good expected performance and defeats adversarial inputs.

import random
random.seed(8)
def reservoir(stream, k):
    res = []
    for i, x in enumerate(stream):
        if i < k: res.append(x)
        else:
            j = random.randint(0, i)                                  # keep x with probability k / (i + 1)
            if j < k: res[j] = x
    return res
counts = {x: 0 for x in range(10)}
for _ in range(20000):
    for x in reservoir(range(10), 3): counts[x] += 1
print("reservoir sampling selects each of 10 items about 6000 times (3/10 of 20000):", sorted(counts.values())[0] > 5700 and sorted(counts.values())[-1] < 6300)
def freivalds(A, B, C, rounds=10):
    n = len(A)
    for _ in range(rounds):
        r = [random.randint(0, 1) for _ in range(n)]
        Br = [sum(B[i][j] * r[j] for j in range(n)) for i in range(n)]
        ABr = [sum(A[i][j] * Br[j] for j in range(n)) for i in range(n)]
        Cr = [sum(C[i][j] * r[j] for j in range(n)) for i in range(n)]
        if ABr != Cr: return False
    return True
A = [[1, 2], [3, 4]]; B = [[0, 1], [1, 0]]; C_good = [[2, 1], [4, 3]]; C_bad = [[2, 1], [4, 4]]
print("Freivalds accepts the correct product:", freivalds(A, B, C_good), "| rejects a wrong one:", not freivalds(A, B, C_bad))
inside = sum(random.random() ** 2 + random.random() ** 2 <= 1 for _ in range(200_000))
print("Monte Carlo estimate of pi:", round(4 * inside / 200_000, 2))

Two pointers and sliding windows revisited

Two-pointer methods are amortised linear because each pointer only moves forward. Typical forms:

  • Opposite ends on a sorted array (pair sum, container with most water, 3Sum with an outer loop).
  • Fast and slow (cycle detection, middle of a list).
  • Sliding window with a condition maintained incrementally; expand the right edge, shrink the left while the window is invalid.
  • At most k trick: exactly(k) = atMost(k) - atMost(k - 1) for counting subarrays.
import random
random.seed(9)
def at_most_k_distinct(a, k):
    count, left, total = {}, 0, 0
    for right, x in enumerate(a):
        count[x] = count.get(x, 0) + 1
        while len(count) > k:
            count[a[left]] -= 1
            if count[a[left]] == 0: del count[a[left]]
            left += 1
        total += right - left + 1                                     # all subarrays ending at right
    return total
def exactly_k_distinct(a, k): return at_most_k_distinct(a, k) - at_most_k_distinct(a, k - 1)
for _ in range(300):
    a = [random.randint(1, 4) for _ in range(random.randint(0, 12))]; k = random.randint(1, 3)
    brute = sum(1 for i in range(len(a)) for j in range(i + 1, len(a) + 1) if len(set(a[i:j])) == k)
    assert exactly_k_distinct(a, k) == brute
print("subarrays with exactly k distinct values verified | [1,2,1,2,3] with k=2:", exactly_k_distinct([1, 2, 1, 2, 3], 2))

Key idea

Look at the constraint sizes and the query pattern to pick the technique: blocks for awkward merges, Mo's order for offline add/remove queries, halves for divide and conquer or meet in the middle, a binary search when feasibility is monotone, masks for small subsets, and randomness for balance. Always keep a brute-force checker next to the clever code.

Interview questions: Problem-solving techniques

15 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic When do you binary search on the answer?

When feasibility is monotone: if value x works then every larger (or smaller) value works, and a simple greedy check decides feasibility.

Basic Give three problems solved by binary search on the answer.

Minimum eating speed, shipping capacity within D days, and split array largest sum (also aggressive cows, painter's partition).

Medium Explain sqrt decomposition.

Split the array into blocks of about sqrt(n) with a summary each; queries combine whole-block summaries and partial ends in O(sqrt n), and updates fix a block summary.

Medium What is Mo's algorithm and its complexity?

An offline method that sorts range queries by block of l then r, moving a window with O(1) add and remove, giving O((n + q) sqrt n) total pointer moves.

Medium How does divide and conquer count inversions?

Merge sort; when merging, each time an element from the right half is placed before the remaining left elements it forms that many inversions. O(n log n).

Medium What is meet in the middle and when is it used?

Split a 2^n search into two halves of 2^(n/2), enumerate both, and combine by sorting and binary search or hashing. It suits n around 30 to 40, such as subset sum and 4-sum variants.

Medium How do you iterate all submasks of a mask?

sub = (sub - 1) & mask, starting from mask until sub becomes 0, visiting 2^popcount submasks.

Medium How does XOR find the single non-duplicated element?

XOR of all elements cancels pairs (a ^ a = 0, a ^ 0 = a), leaving the unique value.

Medium Exactly k distinct in a subarray count: how?

atMost(k) - atMost(k - 1) with a sliding window and frequency map, O(n).

Advanced How do you find two unique numbers when all others appear twice?

XOR everything to get a ^ b, isolate a differing bit with x & -x, partition numbers by that bit and XOR each group.

Advanced What is reservoir sampling?

A one-pass method to sample k items uniformly from a stream of unknown length: keep the first k, then replace a random slot with probability k/(i+1) for item i.

Advanced Monte Carlo versus Las Vegas algorithms?

Monte Carlo has bounded running time but may be wrong with small probability; Las Vegas is always correct with random running time, such as randomised quicksort.

Advanced What is Freivalds' algorithm?

It verifies a matrix product A x B = C in O(n^2) with high probability by testing on random 0/1 vectors.

Advanced Why randomise the pivot in quicksort or quickselect?

It makes the expected running time O(n log n) or O(n) regardless of input order, defeating adversarial worst cases.

Advanced How do you choose between a segment tree, sqrt decomposition and Mo's algorithm?

Segment tree for associative operations with updates, sqrt decomposition for awkward merges with updates, Mo's for offline queries with cheap add and remove and no updates.
