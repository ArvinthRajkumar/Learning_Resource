String basics: indexing, slicing, immutability and palindromes

Essential Topic 4.1

Simple definition

A string is an immutable (cannot be changed in place) sequence of characters. You can read characters by index and take pieces by slicing.

Why it matters

Strings appear in a big share of beginner questions: reversing, palindromes, counting vowels, formatting.

Real-world analogy

A string is like a printed ticket: you can read any character, but to change it you must print a whole new ticket.

From scratch: why this idea exists and how you could invent it

Text is everywhere: names, messages, DNA, logs, code. A computer must store text as numbers, so each character gets a code (ASCII, later Unicode). A string is therefore a sequence of character codes, and almost every string problem is an array problem with characters instead of numbers.

Why are Python strings immutable? Immutability lets Python safely share strings, use them as dictionary keys and cache their hash. Sharing and hashing are major performance wins for a language where strings are used constantly. The cost is that you cannot edit one in place.

Why do we care about palindromes and reversal? They are the simplest tests of two ends moving toward each other, which is the seed of the two-pointer technique. Once you can check a palindrome, you can solve harder problems: longest palindromic substring, palindrome partitioning, rotation checks.

Slicing is a shorthand for 'take positions a up to (not including) b'. The 'not including' rule makes lengths easy: s[a:b] has b - a characters, and s[:k] + s[k:] always rebuilds s.

Strings in real systems: validation (is this an email?), searching logs, parsing commands, compression, DNA matching. The techniques in this module scale from a homework exercise to a search engine.

Step-by-step walkthrough

  1. s[0] is the first character, s[-1] the last, s[a:b] the characters from a up to (not including) b, s[::-1] the reversed string.
  2. s[0] = "x" raises TypeError: strings are immutable. Build a new string or convert to a list, change it, and join it back.
  3. Concatenating in a loop (s += ch) can be O(n^2); collect pieces in a list and "".join(parts).
  4. Palindrome check with two pointers: compare s[lo] and s[hi], then move inwards. Watch it in the animation.
  5. Useful methods: lower(), upper(), isalpha(), isdigit(), isalnum(), split(), strip(), replace(), find(), count().

Deep dive in simple words

A string is a read-only list of characters. You can look at any character with s[i], cut a piece with s[a:b], and loop over it, but you cannot change a character in place. When you 'change' a string you really make a new one. This is why building a big string with += in a loop is slow, and why we collect pieces and join them.

Useful checks: s.isdigit(), s.isalpha(), s.isalnum(), s.islower(), s.isupper(), s.isspace(). Useful changes (they return new strings): s.lower(), s.upper(), s.strip(), s.replace('a', 'b'), s.split(), ' '.join(list). Use s.find(x) to get the first index (or -1) and s.count(x) to count non-overlapping matches.

Palindrome means 'reads the same both ways'. Easiest: s == s[::-1]. With two pointers you compare s[lo] and s[hi] and move inward, using O(1) extra space. For a 'clean' palindrome (ignore spaces, punctuation and case), skip non-alphanumeric characters or build a cleaned string first.

ASCII and characters: ord('a') = 97 and chr(97) = 'a'. The letter's position in the alphabet is ord(ch) - ord('a'). This is how you turn letters into list indexes for counting.

Common beginner traps: off-by-one in slices (s[1:3] has 2 characters), confusing 'abc' < 'abd' alphabetical comparison with length, forgetting to handle upper and lower case, and forgetting that split() with no argument removes extra spaces but split(' ') does not.

Under the hood: what really happens inside Python

  • A Python str stores characters as Unicode code points in a compact internal form (1, 2 or 4 bytes per character depending on the widest character). len(s) is O(1); s[i] is O(1); s + t creates a new string O(len(s)+len(t)).
  • CPython sometimes optimises s += x when s has no other references, but you must not rely on it. ''.join(parts) computes the final size once and copies each piece once: O(total).
  • Strings are interned for small identifiers, which is why 'is' can sometimes seem to work on strings. Never use 'is' to compare text; use ==.

  • Count vowels: sum(ch in 'aeiou' for ch in s.lower()).

Python implementation

def is_palindrome(s):
    lo, hi = 0, len(s) - 1
    while lo < hi:
        if s[lo] != s[hi]:      # mismatch -> not a palindrome
            return False
        lo += 1
        hi -= 1
    return True

Why? and Why not?

Why are Python strings immutable?

Immutability lets Python share strings safely, cache their hashes and use them as dictionary keys, which makes common operations fast.

Why not build strings with += in a loop?

Each += can copy the whole string, making n appends O(n^2). Append to a list and ''.join() once.

Why is slicing end-exclusive?

It makes lengths simple (s[a:b] has b - a characters) and lets s[:k] + s[k:] rebuild s with no overlap.

Why use two pointers for palindromes?

It uses O(1) extra space and can stop at the first mismatch, instead of building a reversed copy.

Why lower-case before comparing?

'A' and 'a' are different characters. Normalising case makes comparisons match what humans mean.

Character frequencies, anagrams and duplicates

Essential Topic 4.2

Simple definition

A character frequency map counts how many times each character appears. Two strings are anagrams if they have identical frequency maps.

Why it matters

Anagrams, first non-repeating character, duplicate detection and "most common character" are all one idea: count, then inspect.

Real-world analogy

Scrabble tiles: two words are anagrams if they use exactly the same tiles.

From scratch: why this idea exists and how you could invent it

Two words are anagrams when you can rearrange the letters of one to make the other. How would a person check 'listen' and 'silent'? They would lay out letter tiles for both and see if the piles match. The computer equivalent of 'piles' is a frequency count, and 'the piles match' is dictionary equality.

Sorting both words also works because sorting puts the tiles in a canonical order: if two words are anagrams their sorted forms are identical. This idea, a canonical form, is the root of grouping problems: map every member of a group to one representative.

Why the 26-slot list? When the alphabet is small and known, a direct-address table (index = letter number) beats a hash table: no hashing, no collisions, constant memory. It is the same principle as counting sort.

First-unique-character shows a general technique: two passes. Pass one gathers global information (counts). Pass two uses it to decide in the original order. Many problems need 'know everything first, then decide'.

Step-by-step walkthrough

  2. Anagram check: counts from s are decremented by t; any missing or negative count means not an anagram.
  3. For lowercase letters you can use a list of 26 ints: counts[ord(ch) - ord("a")] += 1.
  4. collections.Counter(s) does the counting in one call and supports == comparison.

Deep dive in simple words

Two strings are anagrams when they use the exact same letters the same number of times, just in a different order. 'listen' and 'silent' are anagrams. The two tests: sort both and compare (O(n log n)), or count letters in both and compare the counts (O(n)). Counting is better for long strings.

The same counting idea answers many questions: 'first letter that appears once' (count first, then scan the string again in order), 'most frequent letter' (find the key with the biggest count), 'are two words made of the same letters' and 'can word A be built from the letters of B' (ransom note).

A 26-slot list is the classic counter for lowercase letters. counts[ord(ch) - ord('a')] += 1. Comparing two such lists with == is a tiny O(26) step, and it helps with sliding windows over strings, where you add one letter and remove one letter at a time.

Group anagrams: all anagrams share one 'signature', for example the letters in sorted order. 'eat', 'tea' and 'ate' all become 'aet'. Use the signature as a dictionary key and collect words under it.

Be careful with the details: are uppercase and lowercase the same? Do spaces count? Are only letters allowed? Ask or check the statement and handle it at the start with s.lower() or filtering.

Under the hood: what really happens inside Python

  • Counter is a dict subclass: Counter(s) loops over s once, incrementing counts in a hash table. Comparing two Counters compares their dictionaries.
  • ord('a') = 97. Subtracting ord('a') maps letters a-z to 0-25, so counts[ord(ch) - 97] indexes a 26-slot list.
  • Sorting a string makes a list of characters: sorted('eat') = ['a', 'e', 't']. ''.join(...) turns it back to a string, which is hashable and can be a dict key.

  • Counter subtraction: Counter(a) - Counter(b) keeps only positive differences. An empty result means a is covered by b.
  • ''.join(sorted(word)) gives a signature; tuple(sorted(word)) also works as a key.
  • string.ascii_lowercase is 'abcdefghijklmnopqrstuvwxyz'.

Python implementation

def is_anagram(s, t):
    if len(s) != len(t):
        return False
    counts = {}
    for ch in s:
        counts[ch] = counts.get(ch, 0) + 1
    for ch in t:
        if counts.get(ch, 0) == 0:     # t has an extra / missing letter
            return False
        counts[ch] -= 1
    return True

def is_anagram(a, b):
    if len(a) != len(b):
        return False
    c = [0] * 26
    for x, y in zip(a, b):

        c[ord(y) - 97] -= 1
    return not any(c)

Pattern matching and basic string hashing

Important Topic 4.3

Simple definition

Pattern matching finds every place a short pattern occurs inside a longer text. String hashing turns a string into a number so two strings can be compared in O(1).

Why it matters

Naive search can be slow (O(n*m)). Rolling hashes and KMP bring it down to about O(n + m).

Real-world analogy

Rolling hash is a sliding fingerprint: when the window moves one letter, you update the fingerprint instead of re-reading the whole window.

From scratch: why this idea exists and how you could invent it

You press Ctrl+F and your editor finds a word in a million-character document in a blink. How? The simplest idea is to try every starting position and compare letter by letter. For most real text this is fast because mismatches happen early, but for adversarial text (aaaa...a vs aaa...b) it re-reads the same letters again and again: O(n x m).

Two famous ideas fix the waste. KMP notices that when a mismatch happens after matching several letters, those matched letters are information: the pattern itself tells you how far you can safely resume. Precompute that information once (the LPS table), and the text pointer never moves back.

Rabin-Karp takes a different road: convert strings to numbers (hashes) so comparing a window to the pattern is one number comparison. The trick that makes it fast is the rolling hash: sliding the window changes the number by removing one letter's contribution and adding another's in O(1). Because two different strings can share a hash, you verify candidates.

Why learn both? KMP gives a guaranteed O(n + m) with no randomness. Rabin-Karp generalises to searching many patterns at once and to 2D patterns, and its hashing idea shows up in duplicate detection and plagiarism tools.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Naive: for every start i compare text[i:i+m] with the pattern. Worst case O(n*m).
  2. Rolling hash (Rabin-Karp): hash(window) = sum(code(ch) * base^k) mod M. Sliding by one removes the leftmost character and adds the next one in O(1).
  3. If hashes match, verify by direct comparison (hashes can collide).
  4. KMP avoids rechecking by remembering the longest prefix that is also a suffix - see the KMP visualiser in Module 18.
  5. Python shortcuts: text.find(pat), pat in text, text.count(pat) (non-overlapping).

Deep dive in simple words

Pattern matching asks: 'where does the small string appear inside the big string?'. The naive way slides the pattern along the text one place at a time and compares letter by letter. In the worst case (text 'aaaaaaaa', pattern 'aaab') it re-reads a lot, costing O(n x m).

Hashing trick (Rabin-Karp): turn a window of the text into a single number (a 'fingerprint'). Comparing two numbers is one step. When the window slides by one letter, you update the number in O(1): remove the left letter's contribution, shift, and add the new letter. If the fingerprints match you double-check the real letters, because two different strings can sometimes have the same number (a collision).

KMP (Knuth-Morris-Pratt) avoids re-reading by remembering how much of the pattern already matched. It prepares a small table (LPS) that says: 'if I fail here, I can restart from this position of the pattern instead of from zero'. The text pointer never moves backwards, so the total work is O(n + m).

In interviews and tests, for plain 'does it contain', just use Python: pat in text, text.find(pat) and text.count(pat). Write KMP only when the question explicitly asks for an algorithm or needs all overlapping matches efficiently.

Related simple tricks: a string is a rotation of another if it appears inside s + s; a string has a repeated pattern if s in (s + s)[1:-1].

Under the hood: what really happens inside Python

  • Rolling hash formula: h = (c0 x B^(m-1) + c1 x B^(m-2) + ... + c(m-1)) mod M. To slide: h = ((h - c_out x B^(m-1)) x B + c_in) mod M. The modulus keeps numbers small; a large prime reduces collisions.
  • KMP's table fills in O(m) because k only increases by one per character and every fallback decreases it, so total fallbacks cannot exceed total increases (amortised).
  • Python's str.find uses a tuned two-way/Boyer-Moore-Horspool style algorithm in C, so it is usually the fastest option in real code.

CompareExplanation
Naive vs KMP vs Rabin-Karp vs built-inNaive: simple, O(nm) worst. KMP: O(n+m) guaranteed. Rabin-Karp: O(n+m) average, good for many patterns. Built-in find: use it in practice.

Python tips and shortcuts for this topic

  • text.find(pat, start) returns the next match index or -1.
  • Overlapping matches: loop with find and start = idx + 1 (count() would skip overlaps).
  • re.finditer(pattern, text) is the tool for regular expressions.
  • pow(base, m - 1, mod) is handy when rolling hashes need a big power modulo a number.

Python implementation

def rabin_karp(text, pat, base=256, mod=1_000_003):
    n, m = len(text), len(pat)
    if m > n:
        return []
    high = pow(base, m - 1, mod)           # weight of the leftmost char
    hp = ht = 0
    for i in range(m):
        hp = (hp * base + ord(pat[i])) % mod
        ht = (ht * base + ord(text[i])) % mod
    res = []
    for i in range(n - m + 1):
        if hp == ht and text[i:i + m] == pat:   # verify to rule out collisions
            res.append(i)
        if i < n - m:                           # roll the window one step
            ht = ((ht - ord(text[i]) * high) * base + ord(text[i + m])) % mod
    return res

Dry run (variable values at every step)

Trace the code by hand on a tiny input and write down every variable after each line.

Time and space complexity

Average O(n + m); worst case O(n*m) if many collisions. Space O(1).

Common mistakes and edge cases

  • Not verifying after a hash match.
  • Negative modulo results in other languages (Python % is safe).
  • Assuming count() finds overlapping matches (it does not).

How to recognise problems that use this technique

  • "find all occurrences", "substring search", "repeated pattern" -> KMP / hashing.

Why? and Why not?

Why not always use KMP?

Python's built-in find is highly tuned and simpler. KMP matters when asked to implement it, or when you need guaranteed linear time or the LPS table.

Why verify after a hash match in Rabin-Karp?

Different strings can have the same hash (a collision). Verification keeps the answer correct.

Why does KMP never move the text pointer backwards?

The LPS table already tells how much of the pattern is still matched, so no text needs to be re-read.

Why use a large prime modulus in rolling hashes?

Large primes spread hash values evenly and make collisions rare.

Why is naive search usually fine in practice?

Mismatches typically occur early, so the average cost is near O(n). Only adversarial inputs make it quadratic.

How this gets asked

Why must you verify a substring after a hash match?

  • Python requires it
  • To avoid overflow

Collisions are possible, so a match is only a candidate.

  • O(m)

You may compare up to m characters at each of n start positions.

Basic Conceptual Are strings mutable in Python? What does that mean for your code?

No, they are immutable. You cannot write s[0] = 'x'. To change text, build a new string, or convert to a list (list(s)), edit it and join it back with ''.join(list).

Basic Conceptual How do you check if a string is a palindrome ignoring case and punctuation?

Use two pointers. Skip characters where not ch.isalnum(), compare lower-case versions, and move inward. O(n) time, O(1) space.

Basic Conceptual What is the difference between split() and split(' ')?

split() splits on any amount of whitespace and drops empty pieces. split(' ') splits on every single space, so 'a b' (two spaces) gives ['a', '', 'b'].

O(n) time and O(n) space because it creates a new reversed string.

Strings are immutable, so each += may copy the whole string, giving O(n^2) total. Append to a list and join once.

Check lengths first. Then compare Counter(s) == Counter(t) (O(n)) or sorted(s) == sorted(t) (O(n log n)).

Basic Conceptual Why use a 26-element list instead of a dictionary for lowercase letters?

It uses fixed small memory and is a little faster since indexing a list is quicker than hashing. Both are O(n) overall.

Basic Conceptual What is the time complexity of checking anagrams with sorting vs counting?

Sorting: O(n log n). Counting: O(n) time and O(k) space where k is the alphabet size.

Basic Conceptual What is a canonical form and why is it useful?

A single standard representation for all equivalent items (sorted letters for anagrams). It lets you test equality by one comparison or use it as a hash key.

Basic Conceptual What is the naive pattern-matching time complexity and when is it bad?

O(n x m). It is bad on inputs with many partial matches, like text 'aaaa...a' and pattern 'aaa...ab'.

Basic Conceptual What is the idea behind KMP?

Precompute the LPS table: for each prefix of the pattern, the length of the longest proper prefix that is also a suffix. After a mismatch you use it to jump the pattern pointer back to the right place without moving the text pointer back. O(n + m) total.

Basic Conceptual What is a hash collision in Rabin-Karp and how do you handle it?

Two different strings can have the same hash number. When hashes match, compare the real characters to confirm.

Basic Conceptual How can you check if one string is a rotation of another?

Same length and s2 in s1 + s1. For example 'erbottlewat' is inside 'waterbottlewaterbottle'.

Basic Conceptual What does the LPS array of 'abab' look like?

[0, 0, 1, 2]. At index 3 the prefix 'ab' equals the suffix 'ab', so the value is 2.

Basic Conceptual What is a hash collision and why does Rabin-Karp still work?

Two different strings share a hash. Rabin-Karp verifies equal-hash candidates with a direct comparison, so correctness is kept; collisions only cost time.

Basic Conceptual What is a proper prefix?

A prefix that is not the whole string. The LPS table only considers proper prefixes.

Medium Coding Check if a string is a palindrome ignoring case and non-alphanumerics, in O(1) extra space.
def is_pal(s):
    lo, hi = 0, len(s) - 1
    while lo < hi:
        if not s[lo].isalnum():
            lo += 1
        elif not s[hi].isalnum():
            hi -= 1
        elif s[lo].lower() != s[hi].lower():
            return False
        else:
            lo += 1
            hi -= 1
    return True
