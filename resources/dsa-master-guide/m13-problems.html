Last Stone Weight

Easy Max-heap simulation LC 1046

Repeatedly smash the two heaviest stones: equal stones vanish, otherwise the difference stays. Return the weight of the last stone (0 if none).

This is a well-known public interview classic (LeetCode-style problem #1046). The guide does not claim any company asked it.

Python solution (try first)

import heapq

def last_stone_weight(stones):
    heap = [-s for s in stones]
    heapq.heapify(heap)
    while len(heap) > 1:
        a = -heapq.heappop(heap)       # heaviest
        b = -heapq.heappop(heap)       # second heaviest
        if a != b:
            heapq.heappush(heap, -(a - b))
    return -heap[0] if heap else 0

Complexity: Time O(n log n); Space O(n).

Edge cases to test

  • Single stone
  • All stones cancel out -> 0

Kth Largest Element

Medium Min-heap of size k LC 215

Return the k-th largest element (counting duplicates) in an unsorted list.

This is a well-known public interview classic (LeetCode-style problem #215). The guide does not claim any company asked it.

FieldDetail
DSA conceptMin-heap of size k (Heaps & Priority Queues)
Input formatList nums, integer k.
Output formatInteger.
Constraints1 <= k <= len <= 10^5

Sample input

[3,2,1,5,6,4], k=2

Sample output

5

Explanation: Sorted descending: 6, 5, 4... so the 2nd is 5.

Stuck? Reveal hints one at a time

Hint 1

If the heap grows beyond k, pop the smallest.

Recommended approach (spoiler)

Sorting is O(n log n). Keep a min-heap holding the k largest seen so far; its root is the k-th largest. Each push/pop costs O(log k).

Python solution (try first)

import heapq

def kth_largest(nums, k):
    heap = []                        # min-heap with the k largest values
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)      # drop the smallest
    return heap[0]

Complexity: Time O(n log k); Space O(k).

Edge cases to test

  • k = 1 (maximum)
  • k = n (minimum)
  • Duplicates

Top K Frequent Elements

Medium Heap + hash map LC 347 must-do

Return the k most frequent elements. Order the answer by frequency (descending), ties by smaller value.

This is a well-known public interview classic (LeetCode-style problem #347, also on widely shared must-practise lists such as Blind 75). The guide does not claim any company asked it.

FieldDetail
DSA conceptHeap + hash map (Heaps & Priority Queues)
Input formatList nums, integer k.
Output formatList of k values.
Constraintslen <= 10^5

Sample input

[1,1,1,2,2,3], k=2

Sample output

[1, 2]

Explanation: 1 appears 3 times, 2 appears twice.

Stuck? Reveal hints one at a time

Hint 1

heapq.nsmallest(k, items, key=...) is a compact tool.

Recommended approach (spoiler)

Count with Counter, then heapq.nsmallest/nlargest with a key (or a heap of (-freq, value)).

Python solution (try first)

import heapq
from collections import Counter

def top_k_frequent(nums, k):
    freq = Counter(nums)
    return heapq.nsmallest(k, freq, key=lambda x: (-freq[x], x))

Complexity: Time O(n log k); Space O(n).

Edge cases to test

  • k equals number of distinct values
  • Ties

K Closest Points to Origin

Medium Heap with a key LC 973

Return the k points closest to (0, 0) (use squared distance), nearest first.

Sample input

Sample output

Stuck? Reveal hints one at a time

Hint 1

Smaller squared distance means closer.

Recommended approach (spoiler)

def k_closest(points, k):

Reorganize String

Medium Max-heap (greedy) LC 767

Rearrange the letters so no two adjacent characters are the same. Return any valid arrangement or "".

This is a well-known public interview classic (LeetCode-style problem #767). The guide does not claim any company asked it.

Why interviewers ask this: Combines counting with a heap and checks whether you reason about when an arrangement is impossible.

FieldDetail
DSA conceptMax-heap (greedy) (Heaps & Priority Queues)
Input formatString s.
Output formatString.
Constraintslen <= 500

Sample input

"aab"

Sample output

"aba"

Explanation: Place the most frequent letter first, alternating.

Stuck? Reveal hints one at a time

Hint 1

Impossible if one letter appears more than (n + 1) // 2 times.

Recommended approach (spoiler)

Always place the most frequent remaining letter that is different from the previous one. A max-heap of counts does this; hold back the letter just used for one step.

Python solution (try first)

import heapq
from collections import Counter

def reorganize_string(s):
    heap = [(-c, ch) for ch, c in Counter(s).items()]
    heapq.heapify(heap)
    out, prev = [], (0, "")
    while heap:
        c, ch = heapq.heappop(heap)
        out.append(ch)
        if prev[0] < 0:
            heapq.heappush(heap, prev)      # the held-back letter returns
        prev = (c + 1, ch)
    res = "".join(out)
    return res if len(res) == len(s) else ""

Complexity: Time O(n log k); Space O(k).

Edge cases to test

  • Impossible input
  • Single letter

Kth Smallest Element in a Sorted Matrix

Medium Min-heap merge LC 378

Each row and each column of an n x n matrix is sorted ascending. Return the k-th smallest element.

This is a well-known public interview classic (LeetCode-style problem #378). The guide does not claim any company asked it.

Why interviewers ask this: Shows if you can use a heap (or binary search on values) on a sorted matrix instead of flattening it.

FieldDetail
DSA conceptMin-heap merge (Heaps & Priority Queues)
Input formatMatrix and k.
Output formatInteger.
Constraintsn <= 300

Sample input

[[1,5,9],[10,11,13],[12,13,15]], k=8

Sample output

13

Explanation: Sorted order: 1,5,9,10,11,12,13,13,15.

Stuck? Reveal hints one at a time

Hint 1

Heap entries: (value, row, col).

Recommended approach (spoiler)

Treat each row as a sorted list and merge with a heap: start with the first element of each row, pop k times, pushing the next element of the popped row.

Python solution (try first)

import heapq

def kth_smallest_matrix(matrix, k):
    heap = [(row[0], r, 0) for r, row in enumerate(matrix)]
    heapq.heapify(heap)
    for _ in range(k):
        val, r, c = heapq.heappop(heap)
        if c + 1 < len(matrix[r]):
            heapq.heappush(heap, (matrix[r][c + 1], r, c + 1))
    return val

Complexity: Time O(k log n); Space O(n).

Edge cases to test

  • k = 1
  • k = n*n

Meeting Rooms II

Medium Sort + min-heap of end times LC 253

Given meeting intervals [start, end], return the minimum number of rooms needed.

This is a well-known public interview classic (LeetCode-style problem #253). The guide does not claim any company asked it.

Why interviewers ask this: The classic interval + heap question (meeting rooms).

FieldDetail
DSA conceptSort + min-heap of end times (Heaps & Priority Queues)
Input formatList of intervals.
Output formatInteger.
Constraintslen <= 10^4

Sample input

[[0,30],[5,10],[15,20]]

Sample output

2

Explanation: [0,30] overlaps both others.

Stuck? Reveal hints one at a time

Hint 1

The heap size is the number of rooms.

Recommended approach (spoiler)

Sort by start. Keep a min-heap of the end times of rooms in use. If the earliest ending room is free before the next meeting starts, reuse it; otherwise add a room.

Python solution (try first)

import heapq

def meeting_rooms_ii(intervals):
    rooms = []                              # end times of rooms in use
    for start, end in sorted(intervals):
        if rooms and rooms[0] <= start:
            heapq.heapreplace(rooms, end)   # reuse the room that frees first
        else:
            heapq.heappush(rooms, end)
    return len(rooms)

Complexity: Time O(n log n); Space O(n).

Edge cases to test

  • No meetings
  • Back-to-back meetings

Task Scheduler

Medium Greedy counting / heap LC 621

Tasks are letters. Identical tasks must be at least n intervals apart. Return the minimum number of intervals (idle slots allowed) to finish all tasks.

This is a well-known public interview classic (LeetCode-style problem #621). The guide does not claim any company asked it.

Why interviewers ask this: A scheduling puzzle that checks greedy thinking with counts (or a heap).

FieldDetail
DSA conceptGreedy counting / heap (Heaps & Priority Queues)
Input formatTasks and n.
Output formatInteger.
Constraintslen <= 10^4

Sample input

["A","A","A","B","B","B"], n=2

Sample output

8

Explanation: A B idle A B idle A B.

Stuck? Reveal hints one at a time

Hint 1

Count how many tasks have the maximum frequency.

Recommended approach (spoiler)

The most frequent task decides the frame: (max_count - 1) blocks of size n + 1 plus the number of tasks that share the maximum count. The answer is the larger of that and the total number of tasks.

Python solution (try first)

from collections import Counter

def task_scheduler(tasks, n):
    counts = Counter(tasks).values()
    most = max(counts)
    with_most = sum(1 for c in counts if c == most)
    return max(len(tasks), (most - 1) * (n + 1) + with_most)

Complexity: Time O(n); Space O(1).

Edge cases to test

  • n = 0
  • Many different tasks

Ugly Number II

Medium Min-heap / three pointers LC 264

Ugly numbers have only prime factors 2, 3 and 5 (1 counts). Return the n-th ugly number.

This is a well-known public interview classic (LeetCode-style problem #264). The guide does not claim any company asked it.

Why interviewers ask this: A heap (or three-pointer) generation problem: build numbers in increasing order.

FieldDetail
DSA conceptMin-heap / three pointers (Heaps & Priority Queues)
Input formatInteger n.
Output formatInteger.
Constraintsn <= 1690

Sample input

10

Sample output

12

Explanation: Sequence: 1,2,3,4,5,6,8,9,10,12.

Stuck? Reveal hints one at a time

Hint 1

Advance all pointers that equal the minimum to avoid duplicates.

Recommended approach (spoiler)

Keep three pointers i2, i3, i5 into the list of ugly numbers; the next ugly number is the minimum of 2 x u[i2], 3 x u[i3], 5 x u[i5]; advance every pointer that produced it.

Python solution (try first)

def ugly_number_ii(n):
    ugly = [1]
    i2 = i3 = i5 = 0
    while len(ugly) < n:
        nxt = min(ugly[i2] * 2, ugly[i3] * 3, ugly[i5] * 5)
        ugly.append(nxt)
        if nxt == ugly[i2] * 2: i2 += 1
        if nxt == ugly[i3] * 3: i3 += 1
        if nxt == ugly[i5] * 5: i5 += 1
    return ugly[-1]

Complexity: Time O(n); Space O(n).

Edge cases to test

  • n = 1

Merge K Sorted Lists

Hard Heap merge LC 23 must-do

Merge k sorted lists into one sorted list.

This is a well-known public interview classic (LeetCode-style problem #23, also on widely shared must-practise lists such as Blind 75). The guide does not claim any company asked it.

FieldDetail
DSA conceptHeap merge (Heaps & Priority Queues)
Input formatList of sorted lists.
Output formatOne sorted list.
Constraintstotal elements <= 10^4

Sample input

[[1,4,5],[1,3,4],[2,6]]

Sample output

[1,1,2,3,4,4,5,6]

Explanation: Always take the smallest front element.

Stuck? Reveal hints one at a time

Hint 1

Tuples compare element by element, so the heap orders by value first.

Recommended approach (spoiler)

Put the first element of every list in a min-heap as (value, list_index, element_index). Pop the smallest, append, and push the next element from the same list.

Python solution (try first)

import heapq

def merge_k_sorted(lists):
    heap = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(heap)
    out = []
    while heap:
        val, i, j = heapq.heappop(heap)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][j + 1], i, j + 1))
    return out

Complexity: Time O(N log k) for N total elements; Space O(k).

Edge cases to test

  • Empty lists inside the input
  • k = 1

Median of a Data Stream

Hard Two heaps LC 295 must-do

After each number arrives, report the median of all numbers so far.

This is a well-known public interview classic (LeetCode-style problem #295, also on widely shared must-practise lists such as Blind 75). The guide does not claim any company asked it.

FieldDetail
DSA conceptTwo heaps (Heaps & Priority Queues)
Input formatList of numbers arriving in order.
Output formatList of medians.
Constraintslen <= 10^5

Sample input

[5,15,1,3]

Sample output

[5, 10.0, 5, 4.0]

Explanation: After [5,15] median is 10; after [1,5,15] is 5; after [1,3,5,15] is 4.

Stuck? Reveal hints one at a time

Hint 1

Push to low, move low's max to high, then rebalance.

Recommended approach (spoiler)

Keep a max-heap low for the smaller half and a min-heap high for the bigger half, balanced so sizes differ by at most one. The median is the top of the bigger heap or the mean of both tops.

Python solution (try first)

import heapq

def running_median(nums):
    low, high, out = [], [], []     # low: max-heap (negated), high: min-heap
    for x in nums:
        heapq.heappush(low, -x)
        heapq.heappush(high, -heapq.heappop(low))   # keep halves ordered
        if len(high) > len(low):
            heapq.heappush(low, -heapq.heappop(high))
        if len(low) > len(high):
            out.append(-low[0])
        else:
            out.append((-low[0] + high[0]) / 2)
    return out

Complexity: Time O(n log n); Space O(n).

Edge cases to test

  • Single number
  • Equal numbers
