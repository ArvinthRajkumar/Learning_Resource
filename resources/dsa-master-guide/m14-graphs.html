Graph terminology and representations

Important Topic 14.1

Simple definition

A graph is a set of vertices (nodes) connected by edges. Edges can be directed (one-way) or undirected, and weighted (with a cost) or unweighted.

Why it matters

Maps, social networks, dependencies and grids are graphs. Choosing a good representation makes algorithms efficient.

Real-world analogy

Cities (vertices) connected by roads (edges). One-way streets are directed edges; distance on a road is the weight.

From scratch: why this idea exists and how you could invent it

Lists and trees cannot describe a road network: cities connect in all directions, roads form loops, and there is no 'top'. Social networks, the web, circuits, flight routes and course prerequisites share this structure: things and relationships between them. A graph is simply the model for 'things connected to things'.

Choosing a representation is the first design decision. An adjacency list stores for each thing only the things it is connected to. Most real graphs are sparse (a person knows hundreds of people, not billions), so lists use memory proportional to the actual connections: O(V + E). A matrix stores a yes/no for every possible pair, O(V^2): wasteful for sparse data but instant for 'is a connected to b?'.

Direction and weight change what algorithms apply. Undirected: friendships. Directed: followers, dependencies. Weighted: distances, costs, times. Problems say 'shortest path', 'is it connected', 'can everything be ordered', 'cheapest network', and each phrase maps to a standard algorithm.

Grids are graphs in disguise: no one stores the edges because neighbours can be computed. Recognising a grid as a graph is what lets you apply BFS/DFS to mazes, islands, flood fill and puzzle boards.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Adjacency list: graph[u] = list of neighbours. Space O(V + E). Best for sparse graphs and most coding problems.
  2. Adjacency matrix: matrix[u][v] = 1 (or weight). Space O(V^2); checking an edge is O(1).
  3. Undirected edge (a, b): add b to graph[a] AND a to graph[b]. Directed: only graph[a].append(b).
  4. Degree = number of edges at a vertex (in-degree and out-degree for directed).
  5. A grid is an implicit graph: each cell connects to up to 4 neighbours (directions list [(1,0),(-1,0),(0,1),(0,-1)]).
  6. Important vs advanced for coding rounds: BFS/DFS, connected components, grid traversal and cycle detection are essential; topological sort and Dijkstra important; MST (Kruskal/Prim), Bellman-Ford, Floyd-Warshall advanced.

Deep dive in simple words

A graph is dots (vertices or nodes) joined by lines (edges). It models anything connected: cities and roads, people and friendships, courses and prerequisites, web pages and links. A tree is a graph with no cycles and exactly one path between nodes.

Kinds of edges: undirected (a two-way street), directed (a one-way street), weighted (the road has a length or cost). A path is a sequence of connected nodes, a cycle is a path that returns to its start, and a graph is connected if you can reach every node from any other.

How to store it: an adjacency list maps each node to a list of its neighbours. Space O(V + E) and best for most problems. An adjacency matrix is a V x V table where cell [a][b] says whether the edge exists. Space O(V^2), checking an edge is O(1). Use the matrix only for small dense graphs.

Reading input: edges often come as pairs (a, b). Build the adjacency list in one loop. For an undirected graph add b to graph[a] AND a to graph[b]. Watch out for 1-indexed nodes (use n + 1 slots).

A grid is a hidden graph: every cell is a node and its neighbours are up, down, left and right. You do not build a list; you just loop over four direction pairs and check bounds.

Under the hood: what really happens inside Python

  • In Python a defaultdict(list) maps node to neighbours; nodes can be any hashable value (strings, tuples). Lists indexed by integers are faster when nodes are 0..n-1.
  • Edge counts: undirected simple graph has up to V(V-1)/2 edges; directed up to V(V-1). A tree has V - 1 edges. Dense vs sparse decides list vs matrix.
  • Parallel edges and self loops matter for cycle detection and path counting; read the statement.

Python implementation

from collections import defaultdict

def build_graph(n, edges, directed=False):
    graph = defaultdict(list)
    for a, b in edges:
        graph[a].append(b)
        if not directed:
            graph[b].append(a)     # undirected: edge both ways
    return graph

def build_matrix(n, edges):
    m = [[0] * n for _ in range(n)]
    for a, b in edges:
        m[a][b] = m[b][a] = 1
    return m

Why? and Why not?

Why adjacency lists for most problems?

Real graphs are sparse; lists use O(V + E) memory and iterate neighbours quickly.

Why not always use a matrix?

It needs V^2 memory, which is huge for big sparse graphs.

Why add an edge in both directions for undirected graphs?

Either endpoint must be able to reach the other.

Cells are nodes and neighbouring cells are edges, so graph algorithms apply without building lists.

Why does direction matter?

A directed edge a -> b allows travel only one way, which changes reachability and cycles.

Breadth-first search and depth-first search

Essential Topic 14.2

Simple definition

BFS explores a graph level by level using a queue; DFS goes as deep as possible along one path before backtracking, using recursion or a stack.

Why it matters

Almost every graph, grid and tree problem starts from one of these traversals. BFS finds shortest paths in unweighted graphs.

Real-world analogy

BFS: ripples spreading from a stone dropped in a pond. DFS: exploring a maze by following one corridor to its end before backing up.

From scratch: why this idea exists and how you could invent it

How do you explore a maze or a network without getting lost or looping forever? You need a systematic order and a way to remember where you have been. Two natural orders exist: ripple outwards (everything one step away, then two steps away) and dive deep (follow one corridor to its end, then back up).

Ripple outwards is BFS. The 'waiting list' of things to explore must serve the oldest discovery first: a queue. Because you explore all nodes at distance d before any at distance d + 1, the first time you reach a node you have found a shortest route, a property that makes BFS the tool for fewest steps in unweighted graphs and grids.

Dive deep is DFS. The 'waiting list' must serve the newest discovery first: a stack (or recursion). DFS naturally tracks the current path, which is why it solves cycle detection, ordering, connected components and backtracking.

The visited set is the memory. Without it, a cycle traps you forever. Marking on enqueue (BFS) guarantees each node enters the queue once.

Both are the same algorithm with a different data structure for the waiting list. This is a deep and useful insight: change the container, change the behaviour.

Visual explanation (interactive)

Step-by-step walkthrough

  1. BFS: put the start in a queue and mark it visited. Repeat: pop a node, process it, add every unvisited neighbour (mark visited when you ENQUEUE).
  2. DFS: visit a node, then recursively visit each unvisited neighbour. An explicit stack gives the iterative version.
  3. Both run in O(V + E) because each vertex and each edge is handled a constant number of times.
  4. BFS gives shortest distance (fewest edges) from the start; DFS gives a different traversal order and is natural for connectivity, cycle detection and backtracking.
  5. The visited set prevents infinite loops in cyclic graphs.
  6. Run both in the visualiser on the sample graph and compare the order, queue and stack.

Deep dive in simple words

BFS (breadth-first search) explores a graph in waves: first the start, then everything one edge away, then two edges away, and so on. It uses a queue. Because it reaches nodes in order of distance, the first time BFS reaches a node it has found the shortest path (in number of edges).

DFS (depth-first search) follows one path as far as it can, then backs up and tries another. It uses recursion (the call stack) or an explicit stack. It is great for 'can I reach it', connected components, cycle detection, topological ordering and backtracking in graphs.

The visited set is essential. Without it a graph with a cycle makes you loop forever. In BFS mark a node visited when you ADD it to the queue, not when you remove it; otherwise the same node can be added many times.

Both run in O(V + E): every node is processed once and every edge is looked at once (twice for undirected). Space O(V) for the visited set and queue/stack.

Choosing: shortest path or fewest steps in an unweighted graph/grid: BFS. Exploring everything, detecting cycles, counting components, generating paths: DFS (or BFS, either works).

Under the hood: what really happens inside Python

  • BFS stores at most the frontier (width) in the queue, DFS recursion stores the current path (depth). On a long thin graph BFS uses little memory and DFS a lot; on a wide shallow graph it is the opposite.
  • BFS parents form the shortest-path tree: record parent[v] = u when discovering v to reconstruct a path by walking back from the target.
  • Recursive DFS on 10^5 nodes can exceed Python's recursion limit; use an iterative version with an explicit stack.

Python implementation

from collections import deque

def bfs(graph, start):
    visited, order = {start}, []
    q = deque([start])
    while q:
        node = q.popleft()
        order.append(node)
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)        # mark on enqueue
                q.append(nb)
    return order

def dfs(graph, node, visited=None, order=None):
    visited = set() if visited is None else visited
    order = [] if order is None else order
    visited.add(node)
    order.append(node)
    for nb in graph[node]:
        if nb not in visited:
            dfs(graph, nb, visited, order)
    return order

Why? and Why not?

Why does BFS find shortest paths?

It visits nodes in order of distance, so the first visit to a node uses the fewest edges.

Why mark visited when enqueuing?

Otherwise the same node can be queued many times before it is processed.

Why use DFS for cycle detection?

DFS follows a path and can notice when it returns to a node on the current path.

Why can DFS be risky in Python?

Deep recursion can exceed the recursion limit. Use an explicit stack.

Why not use BFS for weighted shortest paths?

BFS counts edges, not weights. Use Dijkstra for non-negative weights.

Grid traversal, connected components and cycle detection

Essential Topic 14.3

Simple definition

A grid can be treated as a graph where each cell is a node connected to its up/down/left/right neighbours. A connected component is a maximal group of nodes reachable from each other.

Why it matters

Number of islands, flood fill, rotting oranges, shortest path in a maze and "is there a cycle" all reuse BFS/DFS.

Real-world analogy

Painting a region on a map: start at one square and keep painting adjacent squares of the same colour.

From scratch: why this idea exists and how you could invent it

A photo editor's paint-bucket tool fills a region of similar colour. A map app counts islands in a satellite image. A game finds how far an enemy is through a maze. All of these look like different applications, but all are the same question on a grid: which cells are connected to this one?

A grid is a graph whose edges are implied by position. You do not build it; you generate neighbours on demand using direction pairs and boundary checks. This removes memory overhead and makes code short.

Flood fill for regions: start at a cell and spread to neighbours satisfying a rule. Counting components: repeat for every cell not yet claimed. Shortest path: spread in waves (BFS) and record distances. Multi-source: start with several cells at once.

Cycle detection differs by graph type: in undirected graphs a cycle exists when you meet a visited node that is not your parent; in directed graphs you must detect a node that is currently on the active path (three colours), or use topological sort failing to include all nodes.

Bipartite checking (two-colouring) uses BFS and tells you whether a graph has an odd cycle, which also answers 'can these items be split into two non-conflicting groups?'.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Neighbour directions: for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)). Always check bounds 0 <= r < rows and 0 <= c < cols.
  2. Counting islands: scan every cell; at an unvisited land cell, count++ and flood-fill (DFS/BFS) to mark the whole island.
  3. Shortest path in a maze: BFS with (row, col, distance) in the queue.
  4. Cycle in an undirected graph: DFS that reaches an already visited node which is not the parent, OR union-find: an edge joining two nodes with the same root closes a cycle.
  5. Cycle in a directed graph: DFS with three states (unvisited, in progress, done) or Kahn's topological sort (not all nodes processed).
  6. Edit the grid in the visualiser (# = wall, . = open, S = start, E = end) and see BFS find the shortest path.

Deep dive in simple words

Grid problems are graph problems in disguise. A cell (r, c) has neighbours (r+1, c), (r-1, c), (r, c+1), (r, c-1). Before visiting a neighbour always check it is inside the grid and not blocked or already visited.

Counting islands: scan every cell. When you find land that is not yet visited, add 1 to the answer and flood-fill (DFS or BFS) the whole island so you never count it again. The same flood fill is used for 'paint bucket', 'size of the largest region' and 'surrounded regions'.

Shortest path in a maze: BFS from the start; the first time you reach the exit, the distance is the shortest number of moves. Multi-source BFS (rotting oranges): put ALL starting cells in the queue at once; each BFS level is one time step.

Cycle detection differs: undirected graphs use 'visited neighbour that is not my parent' or Union-Find; directed graphs use DFS with three colours (not visited, in progress, done) or Kahn's algorithm (not all nodes get processed).

Bipartite check: BFS colouring with two colours; if two neighbours get the same colour there is an odd cycle and the graph is not bipartite.

Under the hood: what really happens inside Python

  • Visited can be a set of coordinate tuples or the grid itself (mutate cells to a marker) to save memory. Copy the grid first if you must preserve it.
  • Multi-source BFS works by putting every source into the initial queue; the first wave is distance 0 for all sources simultaneously.
  • 8-direction movement just adds four diagonal pairs to the direction list.

Python implementation

def region_size(grid, r, c, seen=None):
    seen = set() if seen is None else seen
    rows, cols = len(grid), len(grid[0])
    if not (0 <= r < rows and 0 <= c < cols):   # out of bounds
        return 0
    if grid[r][c] != "1" or (r, c) in seen:
        return 0
    seen.add((r, c))
    size = 1
    for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        size += region_size(grid, r + dr, c + dc, seen)
    return size

Why mark cells visited?

Without it, the search revisits cells forever in connected regions.

They all rot neighbours simultaneously; one wave per minute models that exactly.

It merges components as land is added without re-scanning the grid.

Why use BFS rather than DFS for the shortest maze path?

BFS's first arrival at the exit is guaranteed to be shortest.

Topological sort, Dijkstra and minimum spanning trees

Important Topic 14.4

Simple definition

Topological sort orders the tasks of a directed acyclic graph (DAG) so every dependency comes first. Dijkstra finds the shortest paths from one source in a graph with non-negative weights. A minimum spanning tree (MST) connects all nodes with the smallest total edge weight.

Why it matters

Course schedules, build orders, route planning and network design use these. For a beginner coding round, topological sort and Dijkstra are "important"; MST is "advanced".

Real-world analogy

Topological sort: getting dressed - socks before shoes. Dijkstra: GPS finding the fastest route. MST: laying the cheapest cable that still connects all towns.

From scratch: why this idea exists and how you could invent it

Three different questions arise on graphs. (1) In what order can I do tasks if some must come before others? (2) What is the cheapest route from A to everywhere? (3) How do I connect everything as cheaply as possible? Each has a classic algorithm.

Ordering: if A must come before B, draw A -> B. A valid order exists only if there is no cycle (A before B before A is impossible). Kahn's idea: tasks with no prerequisites can go first; remove them and repeat. If at some point every remaining task has an unfinished prerequisite, there is a cycle.

Cheapest route: BFS counts edges, but roads have different lengths. Dijkstra's key insight: if you always settle the unsettled node with the smallest known distance, that distance is final, because any other route to it would have to pass through a node that is at least as far (when no edge is negative). A heap gives that node quickly.

Connecting everything cheaply (minimum spanning tree): Kruskal's greedy idea is to add the cheapest edge that does not create a cycle. Union-Find answers 'does this edge create a cycle?' in near O(1).

Why is this in 'Important' and not 'Essential'? Because many entry-level tests focus on BFS/DFS and grids; these three algorithms appear in stronger rounds, but the ideas (greedy choice, heaps, Union-Find) deepen skills you use elsewhere.

Step-by-step walkthrough

  1. Kahn's topological sort: compute in-degrees; queue all nodes with in-degree 0; pop one, append to the order, decrement its neighbours' in-degrees and queue those that reach 0. If the order has fewer than V nodes there is a cycle.
  2. Dijkstra: dist[source] = 0. Use a min-heap of (distance, node). Pop the closest, skip if already finalised, relax each edge (u -> v, weight w): if dist[u] + w < dist[v], update and push.
  3. Dijkstra fails with negative edges (use Bellman-Ford). Complexity O(E log V).
  4. Kruskal MST: sort edges by weight, add an edge if it joins two different components (Union-Find). Prim grows one tree using a heap. Both O(E log V).
  5. Which to learn first: BFS/DFS -> components/cycle -> topological sort -> Dijkstra -> MST/union-find. Floyd-Warshall, Bellman-Ford, Tarjan are rarely needed in entry-level rounds.
  6. Step through Kahn's algorithm and Dijkstra in the visualisers.

Deep dive in simple words

Topological sort puts the nodes of a directed graph without cycles into a line so that every edge points forward. Example: courses with prerequisites. Kahn's algorithm: count each node's in-degree (number of incoming edges), repeatedly take nodes with in-degree 0, add them to the order and reduce their neighbours' in-degrees. If you cannot process all nodes, there is a cycle.

Dijkstra finds the cheapest path from one start node to all others when edge weights are not negative. Keep the best known distance for each node. Use a min-heap to always take the nearest unfinished node; its distance is now final. 'Relax' its edges: if going through it gives a shorter route to a neighbour, update that neighbour and push it onto the heap.

Why not negative weights? Dijkstra assumes once a node is taken its distance cannot get better. A negative edge could break that. Use Bellman-Ford for negative edges (rare in entry-level tests).

Minimum spanning tree (MST): connect all nodes using the cheapest set of edges with no cycles. Kruskal: sort the edges by weight and add an edge if it joins two different groups (Union-Find). Prim: grow one tree using a heap. These are 'advanced' for beginner rounds.

Priority guide: BFS/DFS, components and grids matter most; learn topological sort and Dijkstra next; MST, Bellman-Ford, Floyd-Warshall and strongly connected components are advanced extras.

Under the hood: what really happens inside Python

  • Dijkstra uses lazy deletion: the heap may contain outdated entries for a node; skip an entry when its distance is greater than the stored best. Complexity O((V + E) log V).
  • Dijkstra's correctness requires non-negative weights. With negative edges use Bellman-Ford (O(VE)); with negative cycles shortest paths are undefined.
  • Kruskal: sorting dominates, O(E log E). Prim: heap-based, O(E log V).

Python tips and shortcuts for this topic

  • heapq with tuples: heappush(h, (dist, node)); d, u = heappop(h).
  • dist = [float('inf')] * n; dist[src] = 0.
  • Skip stale heap entries: if d > dist[u]: continue.
  • indegree = [0] * n; q = deque(i for i in range(n) if indegree[i] == 0).

Python implementation

from collections import deque
import heapq

def topo_sort(n, edges):
    graph = [[] for _ in range(n)]
    indeg = [0] * n
    for a, b in edges:                  # a must come before b
        graph[a].append(b)
        indeg[b] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else []     # [] means a cycle exists

def dijkstra(graph, src):
    dist = {src: 0}
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist.get(u, float("inf")):
            continue                           # stale entry
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist

Basic Conceptual Adjacency list vs adjacency matrix?

List: O(V + E) space, fast to iterate neighbours, good for sparse graphs. Matrix: O(V^2) space, O(1) edge check, good for dense graphs.

Basic Conceptual What is the difference between directed and undirected graphs?

In a directed graph edges have a direction (a -> b). In an undirected graph an edge works both ways.

Basic Conceptual What is a connected component?

A group of nodes where every node can reach every other node in the group, and no edge leaves the group.

Basic Conceptual How do you represent a grid as a graph?

Each cell is a node; its neighbours are the 4 (or 8) adjacent cells inside the bounds. No explicit adjacency list is needed.

Basic Conceptual What is the difference between a tree and a graph?

A tree is a connected graph without cycles (n nodes, n - 1 edges). A general graph can have cycles and multiple components.

Basic Conceptual Why are most graph algorithms O(V + E)?

Each vertex is processed once and each edge is examined once or twice (once per endpoint in undirected graphs).

Basic Conceptual Difference between BFS and DFS?

BFS uses a queue and explores level by level (shortest path in unweighted graphs). DFS uses a stack/recursion and goes deep first. Both O(V + E).

Basic Conceptual Why does BFS find the shortest path?

It visits nodes in increasing order of distance from the start, so the first visit to a node is via a shortest path.

Basic Conceptual When do you mark nodes visited in BFS?

When adding them to the queue, so each node is queued once.

Basic Conceptual How do you detect a cycle in an undirected graph?

During DFS, if you reach a visited node that is not the parent you found a cycle. Or use Union-Find.

Basic Conceptual What is the time complexity of BFS?

O(V + E) time, O(V) space.

Basic Conceptual Write BFS.
from collections import deque
def bfs(graph, start):
    seen, order = {start}, []
    q = deque([start])
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            if v not in seen:
                seen.add(v)
                q.append(v)
    return order
Basic Conceptual Why does BFS give shortest paths but DFS does not?

BFS explores nodes in increasing distance order; DFS may reach a node first through a long path.

Basic Conceptual How do you count the islands in a grid?

Loop over cells; at each unvisited land cell increment the count and DFS/BFS to mark the whole island. O(rows x cols).

Basic Conceptual How do you find the shortest path in a maze?

BFS from the start with distances, stopping at the exit. If the queue empties, there is no path.

Basic Conceptual What is multi-source BFS?

BFS that starts with several nodes in the queue at the same time, useful when everything spreads simultaneously (rotting oranges, fire spreading).

Basic Conceptual How do you detect a cycle in a directed graph?

DFS with states (unvisited, in recursion stack, finished). Reaching an 'in stack' node means a cycle. Or run Kahn's topological sort and check if all nodes were processed.

Basic Conceptual DFS recursion fails on a huge grid. What do you do?

Use BFS or an iterative DFS with an explicit stack to avoid RecursionError.

Basic Conceptual How do you detect a cycle in a directed graph?

DFS with colours (white, grey, black); an edge to a grey node means a cycle. Or Kahn's algorithm: if not all nodes are processed there is a cycle.

Basic Conceptual What is topological sorting and when is it possible?

A linear ordering of nodes so that every directed edge u -> v has u before v. Possible only for a directed acyclic graph (DAG).

Basic Conceptual Explain Kahn's algorithm.

Compute in-degrees, queue all nodes with in-degree 0, repeatedly pop a node, output it and decrease the in-degree of its neighbours, queueing those that reach 0. If the output has fewer than V nodes there is a cycle.

Basic Conceptual How does Dijkstra's algorithm work?

Start with dist[src] = 0 and a min-heap. Pop the nearest node, and relax its outgoing edges; push improved neighbours. O(E log V). Requires non-negative weights.

Basic Conceptual Why does Dijkstra fail with negative edges?

A node's distance is considered final when it is popped, but a later negative edge could create a shorter path, so results can be wrong.

Basic Conceptual What is a minimum spanning tree and how does Kruskal find it?

A set of V - 1 edges connecting all nodes with minimum total weight. Kruskal sorts edges by weight and adds an edge if it connects two different components (Union-Find).

Basic Conceptual BFS vs Dijkstra?

BFS finds shortest paths when all edges cost the same (1). Dijkstra handles different non-negative edge weights using a priority queue.

Basic Conceptual Why does Dijkstra need non-negative weights?

It finalises a node's distance when popped. A later negative edge could provide a cheaper path to it, breaking the assumption.

from collections import deque
def shortest(graph, s, t):
    parent, q = {s: None}, deque([s])
    while q:
        u = q.popleft()
        if u == t:
            path = []
            while u is not None:
                path.append(u)
                u = parent[u]
            return path[::-1]
        for v in graph[u]:
            if v not in parent:
                parent[v] = u
                q.append(v)
    return []

Medium Coding Iterative DFS.
def dfs(graph, start):
    seen, stack, order = set(), [start], []
    while stack:
        u = stack.pop()
        if u in seen:
            continue
        seen.add(u)
        order.append(u)
        stack.extend(reversed(graph[u]))
    return order
