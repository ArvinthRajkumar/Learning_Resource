Heaps & Priority Queues

Always know the smallest or largest element quickly. The right tool for top-K and merge problems. Topics in this module: Min-heaps, max-heaps and Python's heapq; top-k, kth largest and merging sorted lists.

Start from scratch: why this module exists

When you repeatedly need the smallest or largest item while new items arrive, scanning is slow and keeping a sorted list is slow to update. A heap keeps just enough order to give you the extreme item in O(1) and repair itself in O(log n).

Heaps power priority queues, top-K queries, scheduling and shortest-path algorithms.

Who needs it: Operating systems, search/recommendation engines, network routers, and interviewers.

Min-heaps, max-heaps and Python's heapq

Important Topic 13.1

Simple definition

A heap is a complete binary tree stored in an array where each parent is <= its children (min-heap) or >= (max-heap). The root is always the minimum (or maximum).

Why it matters

A heap gives O(1) access to the min, and O(log n) insert and remove - much faster than re-sorting or scanning.

Real-world analogy

A tournament bracket where the winner always floats to the top; when the winner leaves, the next best rises.

From scratch: why this idea exists and how you could invent it

An emergency room does not treat patients in arrival order; it treats the most urgent first. A program with the same need repeatedly asks for 'the smallest item' while new items keep arriving. A list needs O(n) to find the minimum each time. A sorted list makes finding the minimum O(1) but inserting O(n). We want both to be cheap.

A heap gives O(log n) for both by relaxing the goal: it does not keep everything sorted, only enough order to know the minimum. The rule 'every parent is smaller than its children' is a weaker rule than 'fully sorted', so repairing it after a change touches only one path from leaf to root, which has length log n.

Storing the tree in an array removes pointers: for a complete binary tree the layout is determined by index arithmetic. That makes heaps compact and cache friendly.

Push adds at the next free spot and sifts up. Pop removes the root, moves the last item to the root and sifts down. Each is a walk along one path: O(log n).

Heap sort and 'top K' problems follow directly: if you can always extract the best item cheaply, repeating gives sorted order or the K best.

Step-by-step walkthrough

  1. Array layout: for index i, the children are 2i + 1 and 2i + 2; the parent is (i - 1) // 2.
  2. Push: add at the end, then sift UP (swap with parent while smaller).
  3. Pop min: take the root, move the last element to the root, then sift DOWN (swap with the smaller child).
  4. heapq.heapify(list) builds a heap in O(n). heappush/heappop are O(log n).
  5. Max-heap trick: push negative numbers. For tuples (priority, item) the heap compares the first element.
  6. Insert values in the visualiser and watch sift-up; then extract to watch sift-down.

Deep dive in simple words

A heap is a special tree used when you repeatedly need the smallest (or largest) item. In a min-heap every parent is smaller than or equal to its children, so the smallest item is always at the top (the root). Unlike a BST the left and right children have no order between them.

A heap is stored in a plain array. For the item at index i, the children are at 2i + 1 and 2i + 2 and the parent is at (i - 1) // 2. No pointers are needed. The tree is 'complete': all levels are full except maybe the last, which fills from the left.

Push: add the new item at the end, then 'sift up' - swap it with its parent while it is smaller. Pop: take the root, move the last item to the root, then 'sift down' - swap it with its smaller child while it is bigger. Both take O(log n), the height of the tree.

heapq.heapify(list) builds a heap in O(n). Peeking at the smallest is O(1). Python only has a min-heap. For a max-heap, push negative values.

Heap sort is just: build a heap, then pop everything out. O(n log n).

Under the hood: what really happens inside Python

  • heapq functions work on a plain list in place. heapify turns a list into a heap in O(n) using sift-down from the middle backward; most nodes are near the leaves and move very little.
  • A heap is not sorted: only the parent/child relation holds. Reading the heap list does not give sorted order; popping repeatedly does.
  • To change priority of an item in place you either remove-and-reinsert (O(n) search) or use lazy deletion: mark old entries as stale and skip them when popped (as in Dijkstra).

Python implementation

import heapq

class MinHeap:
    def __init__(self):
        self.a = []

    def push(self, x):
        a = self.a
        a.append(x)
        i = len(a) - 1
        while i > 0 and a[(i - 1) // 2] > a[i]:     # sift up
            a[(i - 1) // 2], a[i] = a[i], a[(i - 1) // 2]
            i = (i - 1) // 2

    def pop(self):
        a = self.a
        top, a[0] = a[0], a[-1]
        a.pop()
        i = 0
        while True:                                  # sift down
            small, l, r = i, 2 * i + 1, 2 * i + 2
            if l < len(a) and a[l] < a[small]: small = l
            if r < len(a) and a[r] < a[small]: small = r
            if small == i:
                return top
            a[i], a[small] = a[small], a[i]
            i = small

h = [5, 1, 8, 3]
heapq.heapify(h)               # O(n)
smallest = heapq.heappop(h)    # 1

Why? and Why not?

Why use a heap instead of a sorted list?

A sorted list makes inserts O(n); a heap makes insert and extract-min O(log n).

Why store a heap in an array?

A complete tree can be addressed by index arithmetic, so no pointers are needed.

Only the parent-child rule is kept, which is enough to find the minimum and is cheaper to maintain.

Most nodes are near the leaves and move very little; the total work sums to a linear series.

Top-K, Kth largest and merging sorted lists

Important Topic 13.2

Simple definition

Keep a small heap of the best K items seen so far. Its root is the "worst of the best", so it is the threshold a new item must beat.

Why it matters

It reduces sorting O(n log n) to O(n log k) and handles streaming data where you cannot hold everything.

Real-world analogy

The leaderboard of the top 10 players: when a new score arrives, compare it with the 10th place only.

From scratch: why this idea exists and how you could invent it

Problem: from a stream of a million scores, report the 10 highest. Sorting all of them is O(n log n) and needs all data in memory. A simpler thought: if you already hold the 10 best, a new score only matters if it beats the 10th best. So keep the 10 best in a structure that tells you the weakest of them instantly.

That structure is a MIN-heap of size 10: the root is the smallest of the 10 best, i.e. the current threshold. A new score smaller than the root is ignored; a bigger one replaces the root. Each update is O(log 10). Total time O(n log K) and memory O(K).

It feels backwards to use a min-heap for the largest values, so it is a common interview mistake. The reason is that you want to eject the worst of the best quickly.

Merging K sorted lists uses the same insight differently: at any moment only the front of each list could be the next smallest, so a heap of K fronts always yields the next output in O(log K).

Running median uses two heaps meeting in the middle: a max-heap of the smaller half and a min-heap of the larger half give instant access to the middle values.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Kth largest: min-heap of size k; push every element; if size > k pop the smallest. The root is the answer.
  2. Top K frequent: count with Counter, then take the k keys with the highest counts (heapq.nlargest(k, counts, key=counts.get)).
  3. Merge k sorted lists: heap of (value, list_id, index) holding the current front of each list; pop the smallest and push that list's next item.
  4. heapq.nlargest(k, nums) and nsmallest(k, nums) are shortcuts (about O(n log k)).
  5. Median of a stream: a max-heap for the lower half plus a min-heap for the upper half.

Deep dive in simple words

Top-K problems share one trick: keep a heap of size K. To find the K LARGEST items use a MIN-heap of size K. The root of that heap is the smallest of the big ones, so it is the item that a new candidate must beat. When the heap grows past K, pop the smallest.

Cost: each of n items does a push and maybe a pop on a heap of size K, so O(n log K). Compare with sorting everything: O(n log n). For K much smaller than n, the heap is faster, and it works on streams where you cannot keep all data.

Kth largest = the root of that size-K min-heap at the end. Top K frequent = count with a Counter first, then take the K keys with the biggest counts.

Merge K sorted lists: put the first item of every list in a heap (value, which list, which index). Pop the smallest, add it to the output and push the next item of the same list. Total O(N log K) where N is the total number of items.

Running median uses two heaps: a max-heap for the smaller half and a min-heap for the larger half. Keep their sizes balanced; the median is at the top of one or between both tops.

Under the hood: what really happens inside Python

  • nlargest(k, data) internally uses a heap when k is small compared to n and sorts when k is close to n.
  • Counter.most_common(k) uses heapq.nlargest under the hood.
  • Heap operations compare tuples lexicographically: (priority, id, item) avoids comparing unorderable items when priorities tie.

Python tips and shortcuts for this topic

  • heapq.nlargest(k, nums) for K largest; heapq.nsmallest(k, nums) for K smallest.
  • Counter(nums).most_common(k) returns the top K by count.
  • Squared distance avoids the square root: x * x + y * y.
  • Use (value, list_index, item_index) tuples so equal values never compare lists.

Python implementation

import heapq

def kth_largest(nums, k):
    heap = []                          # min-heap holding the k largest
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)        # discard the smallest
    return heap[0]

Interview questions: Heaps & Priority Queues

36 questions: try to answer aloud in under a minute, then reveal. All questions from every module are also in the interview bank.

Basic Conceptual What is a heap?

A complete binary tree stored in an array where each parent is smaller (min-heap) or larger (max-heap) than its children. The root is the minimum or maximum.

Basic Conceptual Complexity of heap operations?

Push and pop O(log n), peek O(1), build from a list O(n).

Basic Conceptual How do you create a max-heap in Python?

heapq is a min-heap, so store negated values and negate again when you pop.

Basic Conceptual What is the difference between a heap and a BST?

A heap only orders parent versus children and gives fast min/max. A BST orders the whole tree (left < node < right) and supports sorted traversal and search.

Basic Conceptual Explain sift-up and sift-down.

Sift-up: after inserting at the end, swap with the parent while smaller. Sift-down: after replacing the root, swap with the smaller child while bigger.

Basic Conceptual Why is heapify O(n) and not O(n log n)?

Most nodes are near the bottom and sift only a short distance; the total work sums to a series that is O(n).

Basic Conceptual How do you find the k-th largest element efficiently?

Keep a min-heap of size k. Push each number and pop the smallest when the size exceeds k. The root is the answer. O(n log k).

Basic Conceptual Why a min-heap for the K largest?

The root is the smallest of the K best so far, so it is the one to throw out when a better item arrives.

Basic Conceptual How do you merge K sorted lists?

Use a heap of the current front item of each list; repeatedly pop the smallest and push the next item from the same list. O(N log K).

Basic Conceptual How do you find the median of a stream?

Two heaps: max-heap for the lower half, min-heap for the upper half, balanced in size. Median is the top of the bigger heap or the average of both tops.

Basic Conceptual Top K frequent elements - approach?

Counter + heap (or sort). O(n log k) with a heap of size k.

Basic Conceptual Why use a min-heap to track the K largest?

Its root is the smallest of the current top K, which is the first one to discard when a better candidate arrives.

Medium Coding Implement a max-heap class using heapq.
import heapq
class MaxHeap:
    def __init__(self):
        self.h = []
    def push(self, x):
        heapq.heappush(self.h, -x)
    def pop(self):
        return -heapq.heappop(self.h)
    def peek(self):
        return -self.h[0]

Medium Coding Sort a list using heapq.
import heapq
def heap_sort(a):
    h = a[:]
    heapq.heapify(h)
    return [heapq.heappop(h) for _ in range(len(h))]

import heapq
class KthLargest:
    def __init__(self, k, nums):
        self.k, self.h = k, []
        for x in nums:
            self.add(x)
    def add(self, x):
        heapq.heappush(self.h, x)

        return self.h[0]
