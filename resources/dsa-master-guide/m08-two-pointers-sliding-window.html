Module 8

Two Pointers & Sliding Window

Two patterns that replace O(n^2) loops with O(n) scans over arrays and strings. Topics in this module: Two pointers: opposite and same direction; fixed-size sliding window; variable-size sliding window.

Essential3 topics11 problems54 interview questions

Start from scratch: why this module exists

Many array and string problems look like they need two nested loops. Two pointers and sliding windows show that moving two indices carefully, each only forward, gives the same answer in one pass because every move provably discards possibilities.

The skill is spotting when the structure (sortedness, contiguous ranges, monotonic validity) allows it.

Who needs it: Streaming and monitoring systems (moving windows), text tools, database merge joins and interviewers.

Before you start: Modules 3 and 4.

After this module you can

  • Apply opposite-end and same-direction pointers.
  • Write fixed and variable sliding windows.
  • Recognise when the technique is valid.
  • Prove O(n) by the 'each pointer moves forward only' argument.

Common pitfalls: Using windows with negative numbers and sum targets, forgetting to skip duplicates, moving the wrong pointer.

Typical interview questions here: Pair sum, 3Sum, container with most water, remove duplicates, max sum of k elements, longest substring without repeats, minimum window substring.

Two pointers: opposite and same direction

Essential Topic 8.1

Simple definition

Two pointers means keeping two indices that move through the data according to a rule. Opposite-direction pointers start at both ends; same-direction pointers (slow/fast, reader/writer) both start near the left.

Why it matters

Checking every pair costs O(n^2). Moving pointers cleverly examines each element a constant number of times: O(n).

Real-world analogy

Two people walking toward each other along a corridor until they meet, adjusting their pace depending on what they see.

From scratch: why this idea exists and how you could invent it

Take the sorted pair-sum problem. A beginner checks all pairs. But sortedness gives free information: if the sum of the smallest and the largest is too big, the largest number can never be part of any valid pair (it is too big even with the smallest partner). So discard it. If the sum is too small, the smallest number can never work (too small even with the largest partner). Discard that.

Every comparison therefore eliminates one element permanently, so after at most n steps the pointers meet. That is the key reasoning behind two pointers: each step proves some candidate can be dropped. If you cannot justify a drop, the technique does not apply.

Same-direction pointers come from a different observation: when filtering an array in place, you read faster than you write. A write pointer that never overtakes the read pointer lets you overwrite already-processed cells safely, so no extra array is needed.

Why is this a big deal in interviews? It converts O(n^2) to O(n) and O(n) space to O(1) using only logic, no extra data structure. Interviewers love problems where a short, clean pointer loop beats a heavy solution.

Step-by-step walkthrough

  1. Sorted pair sum: lo = 0, hi = n - 1. If nums[lo] + nums[hi] is too small, lo += 1; too big, hi -= 1; equal -> found.
  2. Why it is correct: if the sum is too small, nums[lo] cannot pair with any smaller hi, so it can be discarded.
  3. Same direction: a write pointer w marks where the next kept element goes while r scans (remove duplicates, move zeroes).
  4. Fast/slow pointers: used for linked lists and for finding the middle.
  5. Watch the pair-sum animation: lo and hi move inwards.

Deep dive in simple words

Two pointers means you use two index variables instead of one nested loop. The trick is to move them smartly so you never look at the same pair twice. There are two common shapes: pointers that start at opposite ends and walk toward each other, and pointers that both start on the left and move at different speeds (reader and writer, slow and fast).

Opposite ends works when the data is sorted or when the answer depends on both ends (palindrome, pair sum, container with most water). Rule of thumb: if the current choice is too small, move the pointer that can make it bigger; if too big, move the other one. Each move permanently rules out some pairs, so the total steps are at most n.

Reader/writer works for in-place filtering: the reader scans every item, the writer marks the next place to store a kept item. Examples: remove duplicates, move zeroes, remove a value, partition. At the end the writer index is the new length.

Three pointers (like Dutch flag) split the array into regions: items already placed at the front, items still unknown in the middle and items placed at the back.

To use it for sums with three numbers (3Sum): sort, fix one number, then run the pair-sum two pointers on the rest. Skip duplicates to avoid repeated answers. Time O(n^2).

Under the hood: what really happens inside Python

  • Correctness proofs use an invariant: 'all pairs involving elements outside [lo, hi] have been proven not to work'. Each move keeps the invariant true.
  • Sorting first costs O(n log n) and dominates; the pointer pass itself is O(n). 3Sum becomes O(n log n + n^2) = O(n^2).
  • Reader/writer: the writer index always satisfies w <= r, so no unread element is overwritten.

Python tips and shortcuts for this topic

  • lo, hi = 0, len(nums) - 1; while lo < hi: ...
  • Skip duplicates: while lo < hi and nums[lo] == nums[lo - 1]: lo += 1.
  • Sorting first: nums.sort() is O(n log n); the whole solution is then dominated by the sort or the scan.

Python implementation

def is_pair_sum(nums, target):      # nums must be sorted
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return True
        if s < target:
            lo += 1                 # need a bigger sum
        else:
            hi -= 1                 # need a smaller sum
    return False

Stage 2 - binary search for the partner

Because the list is sorted, the partner can be found in O(log n): O(n log n) total.

from bisect import bisect_left

def has_pair(nums, target):
    for i, x in enumerate(nums):
        j = bisect_left(nums, target - x, i + 1)
        if j < len(nums) and nums[j] == target - x:
            return True
    return False

Check: has_pair([1, 3, 4, 6, 9], 10) returns True

Stage 3 - two pointers

Each comparison discards one element for good, so one pass is enough: O(n), O(1) space.

Why? and Why not?

Why can you discard an element when the pair sum is too small?

In a sorted list the left value is the smallest, so even paired with the largest it is too small; it can never be part of an answer.

Why does two pointers need a sorted array?

Sortedness tells you which pointer to move to increase or decrease the sum.

Why not use a nested loop?

It checks pairs that were already ruled out, costing O(n^2).

Why skip duplicates in 3Sum?

Otherwise the same triplet is reported more than once.

Why does the reader/writer pointer never overwrite unread data?

The writer index is always less than or equal to the reader index.

  • Even length

  • Move hi left
  • Move lo right
  • Stop
  • Move both

You need a larger sum; only moving lo right can increase it.

Fixed-size sliding window

Essential Topic 8.2

Simple definition

A sliding window is a range of elements that moves across the data. In a fixed-size window of size k you add the element entering on the right and remove the element leaving on the left.

Why it matters

It avoids recomputing the whole window each time: O(n*k) becomes O(n).

Real-world analogy

Looking through a train window at a fixed-width stretch of scenery: as the train moves, one tree enters and one leaves.

From scratch: why this idea exists and how you could invent it

A weather station wants the hottest 7-day stretch in a year of daily readings. Summing 7 numbers for each of 358 stretches repeats most of the work: consecutive stretches share 6 days. The new stretch is the old one minus one day plus one day.

That observation is the whole technique. Reuse the previous answer and fix only what changed. It is the same instinct as prefix sums (reuse partial totals) and dynamic programming (reuse subproblem answers).

Cost drops from O(n x k) to O(n). The saving grows with k: for k = 10^4 and n = 10^5 you avoid 10^9 operations.

Fixed windows fit questions with a defined length: averages, counts of vowels in every length-k substring, k consecutive days, permutations in a string (window length = pattern length).

Visual explanation (interactive)

Step-by-step walkthrough

  1. Compute the first window sum of k elements.
  2. For each next index i: window += nums[i] - nums[i - k]. Update the best.
  3. Example [2,1,5,1,3,2] with k=3: windows 8, 7, 9, 6 -> max 9.
  4. Works for sums, counts of vowels in a substring, number of distinct values in each window (with a dict), averages...

Deep dive in simple words

A sliding window is a range of fixed size k that moves one step at a time across the data. Instead of re-adding k numbers every step, you update the total: add the new number that just entered and subtract the old number that just left. That makes each step O(1).

Typical questions: maximum sum of k consecutive numbers, maximum average, number of vowels in every substring of length k, count windows with at least m distinct values, whether any window contains a permutation of a pattern.

Setup in three steps: (1) build the first window, (2) record its answer, (3) slide: add nums[i], remove nums[i - k], update the answer. Test k equal to 1 and k equal to n, where bugs hide.

For text windows keep a Counter (or 26-slot list) of letters inside the window. Add the new letter, subtract the leaving letter and compare maps.

If the window size changes, you need the variable window technique (next topic).

Under the hood: what really happens inside Python

  • The window sum update window += a[i] - a[i - k] touches two elements per step, so total work is 2n. Keeping a Counter for characters is similar: add the incoming letter, decrement the outgoing letter.
  • For window maximum a plain sum update does not work (max is not invertible); a monotonic deque keeps candidates in decreasing order.

Python tips and shortcuts for this topic

  • window = sum(nums[:k]) builds the first window in O(k).
  • for i in range(k, len(nums)): window += nums[i] - nums[i - k].
  • Counter equality: window_counter == need_counter.
  • deque is used for sliding window MAXIMUM (monotonic deque).

Python implementation

def max_window_sum(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]   # slide: add new, drop old
        best = max(best, window)
    return best

Why? and Why not?

Why is the sliding window faster than re-summing?

Consecutive windows share k - 1 elements, so only one number enters and one leaves.

Why build the first window separately?

The update rule subtracts nums[i - k], which exists only after k elements have been added.

Why check k > n first?

No window of size k exists, and slicing or indexing would give a wrong or empty result.

Why does a plain sum update not work for window maximum?

You cannot 'subtract' a maximum. A monotonic deque is used instead.

Why is the answer O(1) space?

Only the running window value and the best value are stored.

  • O(n)
  • O(nk)
  • O(n^2)
  • O(k)

Each element is added once and removed once.

Variable-size sliding window

Essential Topic 8.3

Simple definition

A variable window expands on the right until a condition breaks (or is satisfied), then shrinks from the left until the condition is valid again.

Why it matters

Longest/shortest substring or subarray satisfying a rule are classic questions; the window method solves them in O(n).

Real-world analogy

An accordion: you stretch it to the right, and when it gets too wide you squeeze it from the left.

From scratch: why this idea exists and how you could invent it

What if the window length is not given and you must find the longest stretch with a property, like 'no repeated letters'? You cannot slide a fixed window. But notice two facts: if a window is valid, shrinking it keeps it valid (a smaller piece of a no-repeat substring has no repeats); if a window is invalid, making it bigger keeps it invalid.

That monotonic behaviour allows a two-finger strategy: extend the right end while valid; when it becomes invalid, advance the left end until valid again. Both fingers only move forward, so you never re-examine the same pair of positions.

Contrast with sum targets: for 'subarray sum equal to k' with negative numbers, extending a window can raise OR lower the sum, so validity is not monotonic and the window method breaks. Understanding the monotonic requirement tells you when this technique is allowed.

The mental template: right expands (adds data), a while loop on left restores validity (removes data), and the answer is updated at the right moment (after restoring for 'longest', inside the loop for 'shortest').

Visual explanation (interactive)

Step-by-step walkthrough

  1. Longest substring without repeating characters: expand right; if s[right] already inside the window, move left past its previous index.
  2. Template for "longest": for right in range(n): add s[right]; while window invalid: remove s[left]; left += 1; record right - left + 1.
  3. Template for "shortest": for right: add; while window valid: record length; remove s[left]; left += 1.
  4. Each index enters once and leaves once, so the total is O(n) despite the nested while.
  5. The animation shows left, right and the dictionary of last seen indices.

Deep dive in simple words

A variable window grows and shrinks. The right edge moves forward one step at a time (expanding). Whenever the window breaks a rule, the left edge moves forward until the window is valid again (shrinking). The best length seen along the way is the answer.

Two templates. For LONGEST valid window: expand right, shrink left while invalid, then record the length. For SHORTEST window that satisfies a condition: expand right, and while the condition is satisfied record the length and shrink left.

Why it is O(n): the left pointer never moves backwards and the right pointer never moves backwards. Each can move at most n times, so the total moves are at most 2n even though there is a while loop inside a for loop.

What you store inside the window depends on the rule: a set or dictionary of letters (no repeats), a running sum (sum at least target), a count of zeros (at most k flips), a Counter and a 'missing count' (minimum window substring).

When it fails: window logic needs 'removing an item always moves you toward valid'. With negative numbers and sum targets that is false, so use prefix sums with a hash map instead.

Under the hood: what really happens inside Python

  • Amortised analysis: left moves at most n times in total and right moves exactly n times, so the whole thing is O(n) even though a while loop sits inside a for loop.
  • The state kept in the window depends on the rule: last seen index (no repeats), counts (at most k distinct), running sum (>= target), count of zeros (at most k flips).

Python tips and shortcuts for this topic

  • last = {} to store the last index of each character for 'no repeats' windows.
  • left = 0; for right, x in enumerate(nums): ... while bad: left += 1.
  • Window length is right - left + 1.

Python implementation

def longest_without_repeat(s):
    last = {}                       # char -> last index
    left = best = 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1     # jump past the duplicate
        last[ch] = right
        best = max(best, right - left + 1)
    return best

Build it step by step: from the simplest idea to the best

Stage 1 - try every start

From each start extend until a repeat appears. O(n^2) in the worst case.

def longest(s):
    best = 0
    for i in range(len(s)):
        seen = set()
        for j in range(i, len(s)):
            if s[j] in seen:
                break
            seen.add(s[j])
        best = max(best, len(seen))
    return best

Check: longest('abcabcbb') returns 3

Stage 2 - window with a set

Grow right; when a repeat appears shrink from the left until it is gone. O(n) because each index enters and leaves once.

def longest(s):
    seen, left, best = set(), 0, 0
    for right, ch in enumerate(s):
        while ch in seen:
            seen.remove(s[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best

Check: longest('abcabcbb') returns 3

Stage 3 - jump the left pointer

Remember the last index of each letter and move left straight past the duplicate instead of one step at a time.

def longest(s):
    last, left, best = {}, 0, 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best

Why? and Why not?

Why is a variable window O(n) despite a nested while?

Left and right only move forward, so together they move at most 2n steps.

Why use while and not if for shrinking?

One new element may require removing several old ones before the window is valid again.

Why does the last-index dictionary jump straight past a duplicate?

Everything before the earlier copy of that character must be excluded, so left can move directly beyond it.

Why does window fail with negative numbers for sums?

Removing a number might increase the sum, so shrinking no longer moves toward validity.

Why record the answer after restoring validity (for longest)?

Only valid windows count, so measure after the shrink loop.

Interview questions: Two Pointers & Sliding Window

54 questions: try to answer aloud in under a minute, then reveal. All questions from every module are also in the interview bank.

Basic Conceptual When can you use the two pointer technique?

When the data is sorted or has structure that tells you which pointer to move: pair sums in sorted arrays, palindromes, merging sorted lists, removing items in place, partitioning.

Basic Conceptual Explain pair sum in a sorted array with two pointers.

Put lo at the start and hi at the end. If nums[lo] + nums[hi] equals the target you are done; if it is smaller move lo right; if bigger move hi left. O(n) time, O(1) space.

Basic Conceptual Solve 3Sum.

Sort, then for each i skip duplicates and use two pointers lo = i + 1, hi = n - 1 to find pairs summing to -nums[i]. Skip duplicates after a hit. O(n^2).

Basic Conceptual How does Container With Most Water work?

Start with the widest container. Area = width x min(height). Move the pointer at the shorter line inward, because moving the taller one can never improve the area.

Basic Conceptual What is the difference between two pointers and sliding window?

Two pointers is the general idea of two moving indices. Sliding window is a special case where the two pointers define a contiguous range (a window) whose contents you keep track of.

Basic Conceptual Why does the container-with-most-water pointer move the shorter side?

The area is limited by the shorter line. Moving the taller line can only shrink the width without improving the height limit, so the shorter side is the only move that might increase the area.

Basic Conceptual What is the sliding window technique?

Maintain a window (range) over the data and move it step by step, updating the result incrementally instead of recomputing from scratch.

Basic Conceptual Maximum sum of k consecutive elements - complexity?

O(n) time and O(1) space using the sliding window. Brute force would be O(n k).

Basic Conceptual How do you check if s2 contains a permutation of s1?

Slide a window of size len(s1) over s2 and compare letter counts with s1 (Counter equality). Update counts by adding the entering letter and removing the leaving one.

Basic Conceptual How do you find the maximum in every window of size k?

Use a monotonic deque of indices whose values decrease. The front is the maximum; pop from the back while the back is smaller than the new element; pop from the front when it leaves the window. O(n).

Basic Conceptual What edge cases should you test for fixed windows?

k = 1, k = n, k > n, negative numbers, and an empty list.

Basic Conceptual Why does the sliding window avoid recomputing?

Consecutive windows share k - 1 elements, so only the entering and leaving elements change the result.

Basic Conceptual Find the length of the longest substring without repeating characters.
def longest(s):
    last, left, best = {}, 0, 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best
Basic Conceptual Smallest subarray with sum at least target (all positive numbers)?

Expand right adding to a sum; while sum >= target record the length and subtract nums[left], left += 1. O(n).

Basic Conceptual Why is the complexity O(n) with a nested while?

Both pointers only move forward, so in total they move at most 2n steps.

Basic Conceptual Longest run of 1s if you may flip at most k zeros?

Keep a window with at most k zeros: when zeros exceed k, move left until a zero leaves the window. Answer is the maximum window length.

Basic Conceptual When does the window method not work?

When values can be negative and the condition is about a sum, because shrinking does not necessarily reduce the sum. Use prefix sums + hash map.

Basic Conceptual Give a case where sliding window fails.

Longest subarray with sum exactly k when numbers can be negative; use prefix sums with a hash map.

Medium Coding Check whether a sorted array has a pair with difference exactly d (d >= 0).
def has_diff(a, d):
    i = 0
    for j in range(len(a)):
        while a[j] - a[i] > d:
            i += 1
        if i != j and a[j] - a[i] == d:
            return True
    return False

Medium Real-world Where is a two-pointer merge used in databases?

Sort-merge joins walk two sorted inputs together to find matching keys in one pass.

Medium Why / Why not Why can you discard an element when the pair sum is too small?

In a sorted list the left value is the smallest, so even paired with the largest it is too small; it can never be part of an answer.

Medium Why / Why not Why does two pointers need a sorted array?

Sortedness tells you which pointer to move to increase or decrease the sum.

Medium Why / Why not Why not use a nested loop?

It checks pairs that were already ruled out, costing O(n^2).

Medium Why / Why not Why skip duplicates in 3Sum?

Otherwise the same triplet is reported more than once.

Medium Why / Why not Why does the reader/writer pointer never overwrite unread data?

The writer index is always less than or equal to the reader index.

Medium Why / Why not Why can't two pointers solve pair sum on an unsorted array directly?

Without order you cannot tell which pointer to move. Sort first (O(n log n)) or use a hash map.

Medium Coding Merge two sorted arrays in place when the first has extra space at the end.

Fill from the back using three pointers (last of each array and the write position) so no unread element is overwritten.

Medium Tricky output For [1, 2, 3, 4, 5] and target 9, which pair do two pointers find?

(4, 5) at indices 3 and 4: starting at 1 + 5 = 6 (too small) the left pointer moves until 4 + 5.

Medium Coding Find the maximum average of any k consecutive numbers.
def max_avg(a, k):
    w = sum(a[:k])
    best = w
    for i in range(k, len(a)):
        w += a[i] - a[i - k]
        best = max(best, w)
    return best / k
Medium Tricky output What is the answer if k > len(a)?

Undefined for the problem; handle it explicitly (return -1 or raise) before the loop. This is a common hidden test.

Medium Real-world How does an API rate limiter implement 'at most 100 requests per minute'?

A sliding window of timestamps (deque): drop timestamps older than 60 seconds and reject if the remaining count is 100.

Medium Why / Why not Why is the sliding window faster than re-summing?

Consecutive windows share k - 1 elements, so only one number enters and one leaves.

Medium Why / Why not Why build the first window separately?

The update rule subtracts nums[i - k], which exists only after k elements have been added.

Medium Why / Why not Why check k > n first?

No window of size k exists, and slicing or indexing would give a wrong or empty result.

Medium Why / Why not Why does a plain sum update not work for window maximum?

You cannot 'subtract' a maximum. A monotonic deque is used instead.

Medium Why / Why not Why is the answer O(1) space?

Only the running window value and the best value are stored.

Medium Why / Why not Why not use prefix sums for fixed windows?

You can: window sum = prefix[i + k] - prefix[i]. It costs O(n) memory but supports any range; the window uses O(1) memory.

Medium Coding Count the number of windows of size k with sum at least t.

Slide the window and increment a counter whenever the running sum >= t.

Medium Tricky output For nums = [1, 2, 3] and k = 3, how many windows exist?

Exactly one: n - k + 1 = 1.

Medium Coding Find the length of the longest substring with at most k distinct characters.
from collections import defaultdict
def longest_k_distinct(s, k):
    cnt, left, best = defaultdict(int), 0, 0
    for right, ch in enumerate(s):
        cnt[ch] += 1
        while len(cnt) > k:
            cnt[s[left]] -= 1
            if cnt[s[left]] == 0:
                del cnt[s[left]]
            left += 1
        best = max(best, right - left + 1)
    return best
Medium Tricky output Why is the answer for 'abba' 2, not 3, in no-repeat substring?

When the second 'a' arrives, its previous index is before the window's left edge, so left must not move backwards; the window stays [b, a] length 2.

Medium Real-world How would you find the busiest 5-minute window in a server log?

Sort timestamps, move a left pointer so the window spans at most 5 minutes, and track the maximum number of events in the window.

Medium Why / Why not Why is a variable window O(n) despite a nested while?

Left and right only move forward, so together they move at most 2n steps.

Medium Why / Why not Why use while and not if for shrinking?

One new element may require removing several old ones before the window is valid again.

Medium Why / Why not Why does the last-index dictionary jump straight past a duplicate?

Everything before the earlier copy of that character must be excluded, so left can move directly beyond it.

Medium Why / Why not Why does window fail with negative numbers for sums?

Removing a number might increase the sum, so shrinking no longer moves toward validity.

Medium Why / Why not Why record the answer after restoring validity (for longest)?

Only valid windows count, so measure after the shrink loop.

Medium Why / Why not Why check last[ch] >= left?

Old entries from before the current window must be ignored; otherwise left could jump backwards.

Medium Coding Longest subarray of 1s after deleting one element.

Keep a window with at most one zero; answer is the longest window length minus 1.

Advanced Follow-up How do you solve 4Sum?

Sort, fix two numbers with two loops and use two pointers for the rest: O(n^3). Skip duplicates at every level.

Advanced Follow-up How do you find the maximum in every window of size k?

Monotonic deque of indices with decreasing values; O(n).

Advanced Follow-up Minimum window substring: smallest part of s containing all letters of t.

Counter of needed letters, a 'formed' counter of satisfied letters, expand right until formed equals required, then shrink left while still valid, recording the smallest window. O(n).

Advanced Follow-up Smallest window containing all characters of t?

Counter of needed letters and a 'formed' counter; expand right until satisfied, then shrink left while still satisfied.
