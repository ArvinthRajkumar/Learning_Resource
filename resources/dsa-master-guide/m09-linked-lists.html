Linked Lists

Nodes connected by pointers. Pointer manipulation questions are common and tricky until you draw them. Topics in this module: Nodes, pointers and basic operations; reversing a linked list; fast/slow pointers: middle node and cycle detection.

Arrays make insertion slow because items must shift. Linked lists store items in separate nodes joined by pointers, so insertion only changes arrows. The price is slow access by position.

Nodes, pointers and basic operations

Important Topic 9.1

Simple definition

A singly linked list is a chain of nodes; each node stores a value and a reference (pointer) to the next node. The first node is the head; the last points to None.

Why it matters

Linked lists support O(1) insertion/deletion at a known position without shifting elements, and they teach pointer thinking used in trees and graphs.

Real-world analogy

A treasure hunt: each clue tells you where the next clue is. You cannot jump to clue 5 directly; you must follow the chain.

From scratch: why this idea exists and how you could invent it

Arrays have a weakness: inserting in the middle forces every later element to shift. What if each item remembered where the next one lives instead of relying on neighbouring memory? Then to insert, you create the new item and change two arrows. No shifting at all. This is the linked list, born from fixing the array's insertion cost.

The price: you lose instant access by position. To reach the 10th item you follow 9 arrows. You also pay memory for the arrows and lose the cache-friendliness of contiguous memory. Every data structure is a trade; linked lists trade access for flexible insertion.

To work with them you must think in pointers. Variables like cur and prev are not items; they are fingers pointing at items. Assigning cur = cur.next moves a finger. cur.next = something changes an arrow inside the list. Mixing those two up is the source of most bugs.

Dummy nodes solve the 'head is special' problem. Without one, inserting or deleting the first node needs separate code. With a dummy in front of the head, every node has a predecessor and one rule works for all.

Linked lists matter in interviews less because you will use them in Python, and more because they train pointer reasoning, which also applies to trees and graphs.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Node: ListNode(val, next). Traversal: cur = head; while cur: ...; cur = cur.next.
  2. Insert at head: new.next = head; head = new -> O(1). Insert at tail: walk to the end -> O(n) (or keep a tail pointer).
  3. Delete a value: find the node BEFORE it (prev) and set prev.next = prev.next.next. Deleting the head needs special care - use a dummy node in front.
  4. Access the i-th node: O(n). Search: O(n).
  5. Doubly linked list: each node also has prev, enabling O(1) deletion given the node and backward traversal. Circular list: the tail points back to the head.
  6. Use the visualiser to insert/delete and watch the arrows change.

Deep dive in simple words

A linked list stores items in separate boxes called nodes. Each node has a value and a pointer to the next node. You only know where the list starts (the head). To reach the 5th item you must walk through the first four. That is why access by position is O(n), unlike arrays.

What linked lists are good at: inserting or removing at a known place by just changing pointers, without shifting other items. Insert at head: new.next = head; head = new. Delete a node: make the node before it skip over it.

The dummy node trick: create a fake node before the head (dummy.next = head). Now the head is no longer a special case: inserting or deleting at the front works like any other position. Return dummy.next at the end. It removes many 'if head is None' branches.

Variants: doubly linked lists have a prev pointer too (easy to go backwards and delete a known node in O(1)); circular lists have the tail pointing to the head. Python's collections.deque is built from blocks and is what you should use in real code.

Pointer safety: before you change node.next, save the old next node in a variable, otherwise you lose the rest of the list. Always think: 'what are the four things that change?' and draw boxes and arrows.

Under the hood: what really happens inside Python

  • Each Python node is an object with val and next attributes (stored in a small dict or slots). The list itself is just a reference to the head node. A node is garbage collected when no references remain.
  • A cycle keeps nodes alive in reference counting; Python's cyclic garbage collector handles them, but interview code should avoid creating accidental cycles.
  • collections.deque is implemented as a doubly linked list of blocks, giving O(1) at both ends with good memory locality.

Python tips and shortcuts for this topic

  • class ListNode: def __init__(self, val=0, next=None): self.val = val; self.next = next.
  • while cur: ...; cur = cur.next is the standard walk. while cur and cur.next: when you look two ahead.

  • Convert a list to a linked list using a loop with a dummy node (helper build()).

Python implementation

def delete_value(head, val):
    dummy = ListNode(0, head)          # dummy handles deleting the head
    prev, cur = dummy, head
    while cur:
        if cur.val == val:
            prev.next = cur.next       # unlink cur
            break
        prev, cur = cur, cur.next
    return dummy.next

Why? and Why not?

Why use a linked list at all?

Insertion and deletion at a known node change only pointers, with no shifting. It also teaches pointer reasoning.

Why not use it for lookup by position?

Reaching index i needs i steps: O(n).

Why use a dummy node?

It removes the special case for the head, so insertion and deletion use the same code everywhere.

Why save node.next before changing it?

The only reference to the rest of the list is node.next; overwriting it first loses the rest.

Why compare nodes with 'is'?

Two different nodes can hold equal values. 'is' checks they are the same node object.

Reversing a linked list

Important Topic 9.2

Simple definition

Reversing means flipping every arrow so the last node becomes the head. You do it by walking once and re-pointing each node to the one before it.

Why it matters

List reversal is a building block for palindrome checks, reorder problems and block reversals.

Real-world analogy

A conga line turning around: each dancer turns to hold the shoulders of the person who was behind them.

From scratch: why this idea exists and how you could invent it

Reversing an array is easy: swap from both ends. For a singly linked list you cannot jump to the end or step backward, so you must reverse the DIRECTION of every arrow as you walk forward once.

Think of a train where each car is hooked to the next. To reverse the train you disconnect each coupling and hook it the other way, one car at a time, never losing the remaining cars. You need one finger on the car you are flipping (cur), one on the part already reversed (prev) and one remembering the rest (nxt).

Why are three variables essential? When you flip cur.next to point backwards, the only pointer to the rest of the list is destroyed unless you saved it first. That single sentence explains the whole algorithm and its most common bug.

Reversal is a building block: palindromes (reverse half), reorder lists, reverse in groups of k, add numbers stored most-significant-first.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Use three names: prev (starts None), cur (starts head), nxt.
  2. Loop: nxt = cur.next (save the rest); cur.next = prev (flip); prev = cur; cur = nxt (advance).
  3. When cur becomes None, prev is the new head.
  4. 1 -> 2 -> 3: after step 1: None <- 1 2 -> 3; step 2: None <- 1 <- 2 3; step 3: None <- 1 <- 2 <- 3. Head = 3.
  5. The animation highlights prev, cur and nxt as arrows flip.

Deep dive in simple words

To reverse a list you flip every arrow. You walk once with three names: prev (the part already reversed, starting as None), cur (the node you are working on) and nxt (the node after cur). For each node: save nxt, point cur backwards to prev, move prev and cur one step forward.

Order matters! Step 1 save, step 2 flip, step 3 move prev, step 4 move cur. If you flip before saving, you lose the remaining list forever.

When cur becomes None you have flipped everything and prev is the last node you handled - the new head. Return prev, not cur.

Reversal is a building block: palindrome list (reverse the second half and compare), reorder list, reverse nodes in groups of k, add two numbers stored in forward order.

There is also a recursive version: reverse the rest of the list, then make the next node point back to the current one and set current.next = None. It uses O(n) stack space.

Under the hood: what really happens inside Python

  • Iterative reversal makes n pointer changes in one pass, O(n) time O(1) space. Recursive reversal reaches the last node first and sets each node.next.next = node on the way back, using O(n) stack.
  • After reversing, the old head's next must be None; otherwise a cycle forms. In the iterative version this happens automatically because prev starts as None.

  • Test an empty list and a one-node list.

Python implementation

def reverse_list(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next      # 1. remember the rest
        cur.next = prev     # 2. flip the arrow
        prev = cur          # 3. move prev forward
        cur = nxt           # 4. move cur forward
    return prev

Fast/slow pointers: middle node and cycle detection

Important Topic 9.3

Simple definition

Floyd's algorithm moves a slow pointer one step and a fast pointer two steps at a time. It finds the middle of a list and detects (and locates) cycles without extra memory.

Why it matters

Cycle detection is a favourite question. The technique also appears in finding duplicates and in numerical cycles.

Real-world analogy

Two runners on a track at different speeds: if the track is a loop, the faster runner eventually laps the slower one; on a straight road the faster one just reaches the end.

From scratch: why this idea exists and how you could invent it

How do you tell if a list loops back on itself? A person walking the list would eventually notice a repeated node, but remembering every visited node costs O(n) memory. Is there a way with no memory?

Picture two runners on a track. If the track is a straight road, the faster runner reaches the end. If it is a circular track, the faster runner keeps lapping and must catch the slower one. The catch-up happens because the gap between them changes by exactly one step each round, so it cannot jump over zero.

That is Floyd's algorithm: move slow by one and fast by two. If they ever stand on the same node, there is a cycle. If fast reaches None, there is no cycle. It uses two pointers and no extra memory.

Where does the cycle start? Let the head be a distance a from the cycle start, and let the meeting point be b steps inside the cycle. Slow travelled a + b, fast travelled 2(a + b), so fast went an extra a + b which is a whole number of laps. This gives a = (laps x cycle length) - b: walking a steps from the meeting point returns to the cycle start. Therefore a pointer from the head and another from the meeting point, both moving one step at a time, meet exactly at the start.

The same idea (fast/slow) finds the middle (fast covers twice the distance) and the k-th node from the end (a fixed gap).

Visual explanation (interactive)

Step-by-step walkthrough

  1. Middle: when fast reaches the end, slow is at the middle (for even length, the second middle).
  2. Cycle: if there is a cycle, fast gains one step on slow every round, so they meet. If fast hits None, no cycle.
  3. Cycle start: after they meet, put one pointer back at head and move both one step at a time; they meet at the cycle start.
  4. Merging sorted lists: dummy node + tail pointer, attach the smaller head each time.
  5. Run the animation on a list with a cycle: watch the pointers meet.

Deep dive in simple words

Slow and fast pointers are two walkers on the same list. Slow takes one step each time; fast takes two. When fast reaches the end, slow is exactly in the middle. That finds the middle node in one pass without knowing the length.

Cycle detection: if the list has a loop, fast and slow both end up running around the loop. Because fast gains one step on slow each round, they must meet inside the loop. If there is no loop, fast reaches None and you stop. Space needed: O(1), compared with O(n) for a set of visited nodes.

Finding where the loop starts: after they meet, restart one pointer at the head. Move both one step at a time. They meet at the first node of the loop. (Math reason: distance from head to loop start equals distance from the meeting point to loop start, going around.)

Gap pointers: to find the n-th node from the end, move fast n steps ahead first. Then move both together. When fast reaches the end, slow is at the right spot.

Always check fast and fast.next in the while condition; checking only one causes 'NoneType has no attribute next' errors.

Under the hood: what really happens inside Python

  • Slow enters the cycle after a steps; fast is already inside. The gap (in cycle terms) closes by one each iteration, so they meet within the cycle length steps: total O(n).
  • The visited-set method is simpler (O(n) memory) and appropriate when memory is not constrained.
  • Comparing nodes uses identity (is). Two different nodes with the same value are not the same node.

Python implementation

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next             # 1 step
        fast = fast.next.next        # 2 steps
        if slow is fast:             # met inside the cycle
            return True
    return False

A set of visited nodes finds a repeat. O(n) time but O(n) memory.

def has_cycle(head):
    seen = set()
    while head:
        if id(head) in seen:
            return True
        seen.add(id(head))
        head = head.next
    return False

Why? and Why not?

Why must fast and slow meet if a cycle exists?

Inside the loop fast gains exactly one node per step on slow, so the gap shrinks by one and must reach zero.

Why check fast and fast.next?

fast moves two nodes; if fast.next is None, fast.next.next would crash.

Why does restarting one pointer at the head find the cycle start?

The distance from the head to the cycle start equals the distance from the meeting point to the cycle start going around.

Why not just store visited nodes?

It works but uses O(n) memory; Floyd uses O(1).

Why use a gap of n for 'nth from the end'?

When the leading pointer reaches the end, the trailing pointer is exactly n nodes behind.

How this gets asked

In Floyd's algorithm the fast pointer moves...

  • 1 step
  • 2 steps

Interview questions: Linked Lists

54 questions: try to answer aloud in under a minute, then reveal. All questions from every module are also in the interview bank.

Basic Conceptual Array vs linked list - when do you use which?

Array (Python list): fast random access O(1), cache friendly, slow insert/delete in the middle O(n). Linked list: O(1) insert/delete when you already hold the node, slow access O(n), extra memory for pointers.

Basic Conceptual How do you delete a node from a singly linked list?

Find the node before it (prev) and set prev.next = prev.next.next. For the head, set head = head.next (or use a dummy node).

Basic Conceptual What is a dummy node and why use it?

A fake node placed before the head. It makes inserting/deleting at the head the same as anywhere else, and you return dummy.next.

Basic Conceptual How do you find the length of a linked list?

Walk with a counter until the node is None. O(n).

Basic Conceptual What is the difference between singly, doubly and circular linked lists?

Singly: one pointer (next). Doubly: next and prev. Circular: the last node points back to the first.

Basic Conceptual Why is inserting at the front O(1) for a linked list but O(n) for an array?

A linked list only changes two pointers; an array must shift every element to make room.

Basic Conceptual Reverse a linked list iteratively.
def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    return prev
Basic Conceptual What is the time and space complexity?

O(n) time and O(1) space for the iterative version. Recursive version uses O(n) stack space.

Basic Conceptual How do you check if a linked list is a palindrome in O(1) space?

Find the middle with slow/fast pointers, reverse the second half, compare both halves node by node (optionally restore the list).

Basic Conceptual What goes wrong if you flip the pointer before saving next?

You lose the reference to the rest of the list and cannot continue.

Basic Conceptual How do you reverse only a part of the list (positions m to n)?

Walk to the node before position m, reverse n - m + 1 nodes with the same prev/cur logic, and reconnect the two ends.

Basic Conceptual How can you reverse a linked list recursively?

Reverse the rest (head.next), then set head.next.next = head and head.next = None, returning the new head.

Basic Conceptual How do you detect a cycle in a linked list?

Floyd's tortoise and hare: slow moves 1, fast moves 2. If they meet there is a cycle; if fast hits None there is none. O(n) time, O(1) space.

Basic Conceptual How do you find the middle of a linked list?

Slow/fast pointers. When fast reaches the end, slow is at the middle (second middle for even length).

Basic Conceptual How do you find where the cycle begins?

After the pointers meet, reset one pointer to the head and move both one step at a time; the meeting node is the start of the cycle.

Basic Conceptual How do you remove the N-th node from the end?

Use a dummy node. Move fast n steps ahead, then move slow and fast together until fast.next is None. Then slow.next = slow.next.next.

Basic Conceptual How do you merge two sorted linked lists?

Use a dummy node and a tail pointer. Repeatedly attach the smaller of the two current nodes, then attach the remaining list.

Basic Conceptual Why does fast moving by 2 guarantee meeting?

Relative speed is 1 node per step inside the loop, so the gap decreases by one each iteration and must reach zero rather than jump over it.

Medium Coding Insert a value in a sorted linked list.
def insert_sorted(head, val):
    dummy = ListNode(0, head)
    cur = dummy
    while cur.next and cur.next.val < val:
        cur = cur.next
    cur.next = ListNode(val, cur.next)

Medium Tricky output What happens if you set cur.next = None while traversing without saving next?

The rest of the list becomes unreachable (lost) because the only reference to it was cur.next.

Medium Real-world Why do operating systems use linked lists for free memory blocks?

Blocks are allocated and freed in arbitrary places; linking them allows O(1) insertion/removal without moving memory.

Medium Why / Why not Why use a linked list at all?

Insertion and deletion at a known node change only pointers, with no shifting. It also teaches pointer reasoning.

Medium Why / Why not Why not use it for lookup by position?

Reaching index i needs i steps: O(n).

Medium Why / Why not Why use a dummy node?

It removes the special case for the head, so insertion and deletion use the same code everywhere.

Medium Why / Why not Why save node.next before changing it?

The only reference to the rest of the list is node.next; overwriting it first loses the rest.

Medium Why / Why not Why compare nodes with 'is'?

Two different nodes can hold equal values. 'is' checks they are the same node object.

Medium Why / Why not Why doesn't Python include a built-in linked list?

list and deque cover almost every need with better performance and memory layout.

def reverse_first_k(head, k):

Medium Tricky output After reversal why is head.next sometimes still pointing to the old second node?

Because you forgot to set it; the iterative template sets cur.next = prev, so the old head gets prev = None. If you reuse the old head variable without relinking you can create a cycle.

Medium Real-world How would you add two numbers stored as linked lists in most-significant-digit order?

Reverse both, add with carry as in the reversed-digit problem, then reverse the result (or use stacks).

Medium Why / Why not Why three pointers for reversal?

prev holds the reversed part, cur the node being flipped, nxt remembers the rest so it is not lost.

Medium Why / Why not Why return prev?

When cur becomes None, prev is the last real node, the new head.

Medium Why / Why not Why is iterative reversal O(1) space but recursive O(n)?

Recursion keeps one stack frame per node.

Medium Why / Why not Why not copy values into a Python list and rebuild?

It works but uses O(n) extra memory and defeats the point of in-place pointer reasoning.

Medium Why / Why not Why does the old head end up with next = None?

prev starts as None, and the first flip sets head.next = prev.

Medium Why / Why not Why is recursion elegant for reversal but risky in Python?

Each node adds a frame, so a list of 10^5 nodes exceeds the recursion limit.

Medium Coding Reverse a linked list recursively.
def rev(head):
    if not head or not head.next:
        return head
    new_head = rev(head.next)
    head.next.next = head
    head.next = None
    return new_head
Medium Coding Find the length of the cycle.
def cycle_length(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            n, cur = 1, slow.next
            while cur is not slow:
                n += 1
                cur = cur.next
            return n
    return 0
Medium Tricky output In a list of 5 nodes with the tail pointing to node 1, what do slow and fast do?

They eventually meet inside the cycle, since a cycle exists; the loop terminates when slow is fast.

Medium Real-world Where else does Floyd's algorithm show up?

Detecting repeated states in iterative functions (like 'happy numbers'), finding duplicates in arrays treated as functional graphs and Pollard's rho factorisation.

Medium Why / Why not Why must fast and slow meet if a cycle exists?

Inside the loop fast gains exactly one node per step on slow, so the gap shrinks by one and must reach zero.

Medium Why / Why not Why check fast and fast.next?

fast moves two nodes; if fast.next is None, fast.next.next would crash.

Medium Why / Why not Why does restarting one pointer at the head find the cycle start?

The distance from the head to the cycle start equals the distance from the meeting point to the cycle start going around.

Medium Why / Why not Why not just store visited nodes?

It works but uses O(n) memory; Floyd uses O(1).

Medium Why / Why not Why use a gap of n for 'nth from the end'?

When the leading pointer reaches the end, the trailing pointer is exactly n nodes behind.

Medium Why / Why not Why not move fast by 3?

It can still detect cycles but the correctness argument is less clean and may skip over slow in some cycle lengths.

def middle(head):
    slow = fast = head

Medium Real-world Where do you meet cycle detection outside linked lists?

Detecting infinite loops in state machines, repeated states in iterated functions and deadlock-like waits.

Advanced Follow-up How do you implement an LRU cache?

A dict from key to node plus a doubly linked list ordered by recency; move a node to the front on access, remove from the tail on eviction. All operations O(1).

Advanced Follow-up Reverse nodes in groups of k.

Reverse each group of k with the same loop and reconnect the tail of the previous group to the new head; leave the final group as is if shorter than k.

Advanced Follow-up Reverse a sublist between positions m and n.

Walk to the node before m, reverse n - m + 1 nodes with the same loop, then reconnect both ends.

Advanced Follow-up Why not move fast by 3?

It can still work in some cases, but the gap changes by 2 per step; if the cycle length shares a factor with the gap, fast might skip over slow for several laps. Using 2 guarantees correctness and the simple proof.
