DP framework: overlapping subproblems, memoisation and tabulation

Important Topic 16.1

Simple definition

Dynamic programming solves a problem by breaking it into overlapping subproblems, solving each only once and storing the result. It applies when the problem has optimal substructure (the best answer is built from best answers to subproblems).

Why it matters

It turns exponential recursion into polynomial time. Many "count the ways", "minimum cost", "maximum value" questions are DP.

Real-world analogy

Writing down the answer to 12 x 12 on a sticky note so you never recompute it.

From scratch: why this idea exists and how you could invent it

Take Fibonacci. The definition fib(n) = fib(n-1) + fib(n-2) translates straight into recursion, but the program takes forever for n = 50. Why? Draw the calls: fib(50) asks for fib(49) and fib(48); fib(49) asks for fib(48) and fib(47)... fib(48) is computed twice, fib(47) three times, and the repeats multiply. The work is exponential even though there are only 51 distinct questions.

The fix is obvious once seen: write each answer down the first time and reuse it. That notebook is memoisation. The runtime drops from exponential to linear because each of the n distinct questions is answered once and each answer takes constant time to combine.

Dynamic programming is this idea applied systematically. You need to see (1) overlapping subproblems and (2) optimal substructure (the answer to the big question can be assembled from answers to smaller ones). The creative step is defining the STATE: what the notebook's index means (the number of ways to reach step i; the minimum coins for amount a).

Top-down keeps the recursive form and lets the cache do the work. Bottom-up fills the notebook in an order where every dependency is already known, avoiding recursion altogether and often allowing you to keep only the last few entries.

The name 'dynamic programming' comes from the 1950s (Richard Bellman) and is a bit misleading: 'programming' means planning (as in 'linear programming'), not coding.

Step-by-step walkthrough

  1. Framework: (1) Define the STATE: what does dp[i] mean in words? (2) Write the TRANSITION: how does dp[i] come from smaller states? (3) Set the BASE cases. (4) Choose the ORDER of iteration so dependencies are ready. (5) Identify the ANSWER cell.
  2. Top-down (memoisation): write the recursion, add a cache (dict or functools.lru_cache).
  3. Bottom-up (tabulation): fill a table from the smallest subproblem upward with loops.
  4. Fibonacci: state dp[i] = fib(i); transition dp[i] = dp[i-1] + dp[i-2]; base dp[0]=0, dp[1]=1; answer dp[n]. Only the last two values are needed, so space can drop from O(n) to O(1).
  5. Climbing stairs is the same recurrence. Recognise the pattern: "number of ways to reach step n" -> sum of the ways to reach the previous steps.
  6. Use the DP visualiser to watch each cell being filled and which cells it depends on.

Deep dive in simple words

Dynamic programming (DP) is 'recursion with a notebook'. If a recursive solution solves the same small problems again and again, write each answer in a notebook (a dictionary or list) the first time, and look it up afterwards. That alone turns exponential time into polynomial time.

Two conditions: overlapping subproblems (the same smaller problems repeat) and optimal substructure (the best answer to the big problem uses best answers to smaller ones). If both hold, DP is possible.

Two styles. Top-down (memoisation): write the recursion, add a cache. Easy to write, uses recursion depth. Bottom-up (tabulation): fill a table from the smallest cases to the answer with loops. No recursion limit problems and often allows space savings.

The five-step recipe: (1) State: say in words what dp[i] (or dp[i][j]) means. (2) Transition: how does it depend on smaller states? (3) Base cases. (4) Order: iterate so the needed states are ready. (5) Answer: which cell holds it? Write the state sentence before any code; most wrong DP solutions have a fuzzy state.

Space saving: if dp[i] only needs dp[i-1] and dp[i-2], keep two variables instead of a whole list (Fibonacci, climbing stairs, house robber).

Under the hood: what really happens inside Python

  • lru_cache stores results in a dict keyed by the call's arguments. Arguments must be hashable. For very deep recursion, bottom-up avoids the stack.
  • Space optimisation: if dp[i] depends only on a few previous values, keep variables instead of the whole table (O(n) to O(1)).
  • Complexity of DP = number of states x work per state. State count is the table size.

DP vs plain recursionRecursion repeats work (exponential); DP stores results (polynomial).
DP vs greedyGreedy picks one path; DP considers all via subproblems. Use DP when greedy lacks a proof.

Python tips and shortcuts for this topic

  • from functools import lru_cache; @lru_cache(maxsize=None) above the recursive function.
  • dp = [0] * (n + 1); dp = [[0] * (m + 1) for _ in range(n + 1)].
  • INF = float('inf') for minimisation problems.
  • Use enumerate and range(1, n + 1) carefully with 1-based DP tables.

Python implementation

from functools import lru_cache

def fib_tab(n):
    if n < 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]     # transition
    return dp[n]

@lru_cache(maxsize=None)
def fib_memo(n):
    if n < 2:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)

Common mistakes and edge cases

  • Vague state definition.
  • Wrong iteration order (using a cell before it is computed).
  • Forgetting base cases.
  • Trying DP when greedy is enough (or vice versa).

  • "Number of ways", "minimum/maximum cost", "can we reach/make..." with choices at each step; brute force recursion repeats subproblems -> DP.

Why? and Why not?

Why does DP help?

It stores answers to repeated subproblems, turning exponential recursion into polynomial time.

Why define the state in words first?

A vague state leads to a wrong transition. If you cannot say what dp[i] means, you cannot compute it.

Why prefer bottom-up sometimes?

It avoids recursion limits and allows space reduction.

Why prefer top-down sometimes?

It is easier to write and computes only the states actually needed.

Why not use DP for everything?

It costs memory and is overkill when a greedy or a formula works.

How this gets asked

What turns plain recursive Fibonacci from O(2^n) to O(n)?

  • Using a loop only
  • Storing computed values (memoisation)
  • Sorting
  • Using a stack

Each fib(i) is computed once.

Which is NOT part of the DP recipe?

  • State definition
  • Transition
  • Base case
  • Random guessing

DP is systematic: state, transition, base, order.

1D DP: house robber and coin change

Important Topic 16.2

Simple definition

In 1D DP the state is a single number (index, amount, step) and the table is one row.

Why it matters

Many linear decision problems (rob or skip, take a coin or not) reduce to one dimension.

Real-world analogy

Deciding each day whether to work (earn but cannot work the next day) or rest, maximising total earnings.

From scratch: why this idea exists and how you could invent it

House robber: houses in a row, no two adjacent. Ask the DP question: what do I need to know to decide about house i? The best total from the previous houses with two possibilities: I skipped house i-1 (so I may rob i), or I robbed house i-1 (so I cannot). Two numbers carry all the information: best up to i-1 and best up to i-2.

Notice that you stopped asking 'which houses?' and started asking 'what is the best value up to here?'. That shift from remembering choices to remembering VALUES is the heart of DP.

Coin change: to make amount a with fewest coins, the last coin used is some coin c; before it you had made a - c optimally. So dp[a] = 1 + min over coins of dp[a - c]. The state is the amount; the transition tries every last coin; the base is dp[0] = 0.

Why does this succeed where greedy fails? Greedy commits to the biggest coin; DP evaluates every possible last coin using the already-known optimal answers for smaller amounts, so it cannot be tricked.

Variations come from changing the question: count ways (use +), include/exclude (knapsack), or forbid adjacency (robber).

Step-by-step walkthrough

  1. House robber: dp[i] = max(dp[i-1], dp[i-2] + nums[i]) - skip house i, or rob it and take the best up to i-2.
  2. Coin change (minimum coins): dp[a] = min over coins c of dp[a - c] + 1; dp[0] = 0; use infinity for unreachable.
  3. Why not greedy? coins [1,3,4], amount 6: greedy = 3 coins, DP = 2.
  4. Dry run for coins [1,3,4], amount 6: dp = [0,1,2,1,1,2,2].

Deep dive in simple words

1D DP means the state is a single number: an index in a list or an amount of money. The table is a single row. Most 'linear' decision problems look like this.

House robber: for each house you either skip it (best so far stays dp[i-1]) or rob it (you get dp[i-2] + value). dp[i] = max of the two. Only the last two values matter, so two variables are enough.

Coin change (minimum coins): dp[a] = fewest coins that make amount a. For each amount try every coin: dp[a] = min(dp[a - coin] + 1). Start with dp[0] = 0 and infinity for the rest. If dp[amount] is still infinity, the answer is -1. This is the example where greedy fails but DP works.

Counting ways (instead of minimum): add instead of min. Number of ways to make an amount using coins in ANY order vs a fixed order differ by the loop order: coins outside and amounts inside counts combinations; amounts outside and coins inside counts permutations.

More 1D DP: decode ways, word break, min cost climbing stairs, longest increasing subsequence (O(n^2) with dp[i] = best ending at i, or O(n log n) with bisect).

Under the hood: what really happens inside Python

  • Coin change dp has O(amount) states and O(coins) transitions per state: O(amount x coins).
  • Counting combinations vs permutations depends on loop order: coins outer, amount inner counts combinations; amount outer, coins inner counts ordered sequences.
  • Initialising unreachable states to infinity ensures they never win a min comparison; then convert infinity to -1 at the end.

Python tips and shortcuts for this topic

  • dp = [0] + [float('inf')] * amount.
  • for a in range(1, amount + 1): for c in coins: if c <= a: dp[a] = min(dp[a], dp[a - c] + 1).
  • skip, take = take, max(take, skip + x) is a neat two-variable update.
  • bisect_left makes LIS O(n log n).

Python implementation

def house_robber(nums):
    skip, take = 0, 0
    for x in nums:
        skip, take = take, max(take, skip + x)
    return take

def coin_change(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return -1 if dp[amount] == INF else dp[amount]

Stage 1 - recursion on the choice

At each house rob it (skip the next) or skip it. Exponential.

def rob(nums, i=0):
    if i >= len(nums):
        return 0
    return max(nums[i] + rob(nums, i + 2), rob(nums, i + 1))

Check: rob([2, 7, 9, 3, 1]) returns 12

Stage 2 - a table of best values

dp[i] is the best total using houses up to i. O(n) time and space.

def rob(nums):
    if not nums:
        return 0
    dp = [0] * (len(nums) + 1)
    dp[1] = nums[0]
    for i in range(2, len(nums) + 1):
        dp[i] = max(dp[i - 1], dp[i - 2] + nums[i - 1])
    return dp[-1]

Check: rob([2, 7, 9, 3, 1]) returns 12

Stage 3 - two variables

dp[i] needs only dp[i-1] and dp[i-2]: O(1) space.

def rob(nums):
    skip, take = 0, 0
    for x in nums:
        skip, take = take, max(take, skip + x)
    return take

Why? and Why not?

Why does house robber use only two variables?

dp[i] depends only on dp[i-1] and dp[i-2].

Why does greedy fail for coin change?

The biggest coin first can lead to a worse total; DP tries every last coin.

Why initialise unreachable states to infinity?

So they never win a minimum comparison and can be detected at the end.

Why does loop order change counting combinations vs permutations?

Coins outside means each combination is built in a fixed coin order; amounts outside counts ordered sequences.

Why does dp[0] = 0 for coin change?

Zero coins make amount zero, and every other amount builds on it.

  • dp[i] = dp[i-2]

  • 0
  • -1
  • Infinity
  • 1

2D DP: grid paths, LCS and 0/1 knapsack

Important Topic 16.3

Simple definition

In 2D DP the state has two parameters (row and column, or position in two strings, or item and capacity), so the table is a grid.

Why it matters

These patterns cover grid paths, string comparison (LCS, edit distance) and selection under a capacity (knapsack).

Real-world analogy

Filling out a spreadsheet where each cell is computed from the cells above and to the left.

From scratch: why this idea exists and how you could invent it

Some questions have TWO moving parts. Comparing two strings: how far have I read in A and how far in B? A knapsack: which items have I considered and how much capacity remains? Grid paths: which row and which column? When the state needs two numbers, the notebook becomes a table.

LCS: to compare 'abcde' and 'ace', look at the last characters. If they match, that letter is part of the answer and you solve the problem for both strings without it (diagonal cell + 1). If they differ, at least one of them is not used: drop either A's last letter or B's last letter and take the better result (cell above or left).

Edit distance follows the same logic with three operations. 0/1 knapsack's two choices are 'take this item' (use the row above with reduced capacity) or 'skip it' (row above, same capacity).

The table's order of filling is dictated by dependencies: each cell depends on cells above, to the left or diagonal, so filling row by row left to right always works.

A habit that prevents most bugs: add a zero row and column representing 'empty' so that base cases are part of the table, and write down what dp[i][j] MEANS in words before coding.

Step-by-step walkthrough

  1. Grid paths: paths[r][c] = paths[r-1][c] + paths[r][c-1], first row and column = 1.
  2. LCS of a and b: dp[i][j] = dp[i-1][j-1] + 1 if a[i-1] == b[j-1], else max(dp[i-1][j], dp[i][j-1]). Row 0 and column 0 are 0.
  3. 0/1 knapsack: dp[w] = max(dp[w], dp[w - weight] + value), iterating w downward so each item is used once.
  4. Every cell takes O(1) work so the cost is rows x cols. Often only the previous row is needed, saving space.
  5. Pick LCS or knapsack in the visualiser; arrows show which earlier cells produced the current value.

Deep dive in simple words

2D DP has two things changing: for example row and column, or position in string A and position in string B, or item number and remaining capacity. The table is a grid, and each cell is built from neighbouring cells (usually above, left and diagonal).

Grid paths: the number of ways to reach a cell is the ways to reach the cell above plus the ways to reach the cell on the left. The first row and column are 1. Minimum path sum is the same shape using min instead of +.

LCS (longest common subsequence): dp[i][j] is the LCS of the first i letters of A and the first j letters of B. If the last letters match, take dp[i-1][j-1] + 1. If not, take the best of dp[i-1][j] and dp[i][j-1]. Edit distance has the same grid with three options: insert, delete or replace.

0/1 knapsack: dp[i][w] is the best value using the first i items with capacity w. Either skip item i (dp[i-1][w]) or take it (dp[i-1][w - weight] + value). With a 1D array iterate the capacity from high to low so an item is not used twice.

Table tips: add an extra row and column for the 'empty' case so you avoid special code. Check the order of loops so every cell you read is already filled. Watch indices: table index i refers to string index i - 1.

Under the hood: what really happens inside Python

  • Time = number of cells x O(1) work each. Space can often be reduced to one or two rows when the next row depends only on the previous row.
  • 0/1 knapsack in 1D must iterate capacity downward so dp[w - wt] still holds the previous item's row. Unbounded knapsack iterates upward.
  • To reconstruct an LCS, walk back from dp[n][m]: diagonal when letters match, otherwise move toward the larger neighbour.

Python implementation

def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1           # extend a match
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])  # skip a character
    return dp[-1][-1]

def knapsack(weights, values, capacity):
    dp = [0] * (capacity + 1)
    for wt, val in zip(weights, values):
        for w in range(capacity, wt - 1, -1):    # backwards: use each item once
            dp[w] = max(dp[w], dp[w - wt] + val)
    return dp[capacity]

Build it step by step: from the simplest idea to the best

Every stage is runnable and was checked against its stated result.

Stage 1 - recursion on the ends of both strings

If the last letters match take 1 + the rest; otherwise try dropping a letter from either string. Exponential.

def lcs(a, b):
    if not a or not b:
        return 0
    if a[-1] == b[-1]:
        return 1 + lcs(a[:-1], b[:-1])
    return max(lcs(a[:-1], b), lcs(a, b[:-1]))

Check: lcs('abcde', 'ace') returns 3

Stage 2 - memoise on the two lengths

The state is (i, j). There are only n x m distinct states.

from functools import lru_cache

def lcs(a, b):
    @lru_cache(maxsize=None)
    def go(i, j):
        if i == 0 or j == 0:
            return 0
        if a[i - 1] == b[j - 1]:
            return 1 + go(i - 1, j - 1)
        return max(go(i - 1, j), go(i, j - 1))
    return go(len(a), len(b))

Check: lcs('abcde', 'ace') returns 3

Same recurrence, no recursion.

Time and space complexity

LCS O(n*m) time and space; knapsack O(n * capacity) time, O(capacity) space.

Common mistakes and edge cases

  • Off-by-one between dp indices (1-based) and string indices (0-based).
  • Iterating capacity upward in 0/1 knapsack (reuses items).
  • Forgetting the zero row/column.

How to recognise problems that use this technique

  • Two strings/sequences compared -> 2D DP. Items + capacity -> knapsack. Grid with right/down moves -> 2D DP.

Basic Conceptual What is dynamic programming?

A technique that solves a problem by breaking it into overlapping subproblems, solving each once and storing the result (memoisation or tabulation).

Basic Conceptual Memoisation vs tabulation?

Memoisation is top-down recursion with a cache. Tabulation is bottom-up iteration filling a table. Same complexity; tabulation avoids recursion limits.

Basic Conceptual How do you recognise a DP problem?

Keywords like 'count the ways', 'minimum/maximum cost', 'can we reach/make', plus a brute-force recursion with repeated subproblems.

Basic Conceptual Explain the steps to solve a DP problem.

Define state, write the transition, set base cases, choose iteration order, find the answer cell, then optimise space if possible.

Basic Conceptual Solve climbing stairs.
def climb(n):
    a, b = 1, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b
Basic Conceptual What are optimal substructure and overlapping subproblems?

Optimal substructure: an optimal solution contains optimal solutions of its subproblems. Overlapping subproblems: the same subproblems are needed repeatedly, so caching helps.

Basic Conceptual Solve the house robber problem.

dp[i] = max(dp[i-1], dp[i-2] + nums[i]). Keep two variables. O(n) time, O(1) space.

Basic Conceptual Why does greedy fail for coin change but DP works?

Greedy takes the biggest coin first and may get stuck with a worse total (coins 1, 3, 4, amount 6). DP tries all coins for every smaller amount and finds the true minimum.

Basic Conceptual What is the time complexity of coin change DP?

O(amount x number of coins) time and O(amount) space.

Basic Conceptual How do you count the number of ways to make an amount with coins?

dp[0] = 1; for each coin, for a from coin to amount: dp[a] += dp[a - coin]. Coins in the outer loop counts combinations.

Basic Conceptual What is the Longest Increasing Subsequence complexity?

O(n^2) with the simple DP, O(n log n) with the 'tails' array and binary search.

Basic Conceptual What is the state and transition for house robber?

State: best money using houses up to i. Transition: dp[i] = max(dp[i-1], dp[i-2] + nums[i]).

Basic Conceptual Explain the LCS DP.

dp[i][j] = LCS length of A[:i] and B[:j]. If A[i-1] == B[j-1]: dp[i-1][j-1] + 1 else max(dp[i-1][j], dp[i][j-1]). O(nm).

Basic Conceptual Explain the 0/1 knapsack DP.

dp[w] = best value with capacity w. For each item loop w from capacity down to weight: dp[w] = max(dp[w], dp[w - weight] + value). O(n x capacity).

Basic Conceptual Why iterate the capacity backwards in 1D knapsack?

So that each item is used at most once. Going upward would let it be added many times (unbounded knapsack).

Basic Conceptual How many paths in an m x n grid moving right or down?

C(m + n - 2, m - 1), or fill the DP table with paths[r][c] = paths[r-1][c] + paths[r][c-1].

Basic Conceptual What is edit distance?

The minimum number of insertions, deletions and replacements to turn one string into another, solved with a 2D DP.

Basic Conceptual How can you reduce DP space?

If a row only depends on the previous row (or the last few values), keep only those instead of the entire table.

Basic Conceptual What does dp[i][j] mean in edit distance?

The minimum edits to turn the first i characters of A into the first j characters of B.
