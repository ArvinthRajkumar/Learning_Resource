Module 7

Hashing

Dictionaries and sets turn many O(n^2) searches into O(n). The single most useful optimisation in coding rounds. Topics in this module: Hash tables, dictionaries, sets and collisions; frequency maps and the two sum pattern; grouping with canonical keys and longest consecutive sequence.

Essential3 topics14 problems56 interview questions

Start from scratch: why this module exists

Hashing answers the question 'can lookup be instant?'. Instead of searching for a key, compute where it must live from the key itself. Dictionaries and sets in Python are hash tables, and they are the single most useful tool for removing nested loops.

Whenever you catch yourself scanning a list repeatedly to find something, a hash table usually turns O(n^2) into O(n).

Who needs it: Compilers (symbol tables), web caches, databases, security tools and almost every real application; interviewers love it for Two Sum style questions.

  • Choose hash map vs sorting.

Hash tables, dictionaries, sets and collisions

Essential Topic 7.1

Simple definition

A hash table stores key-value pairs. A hash function converts a key into a number, which (mod table size) picks a bucket where the value lives. A set is a hash table with keys only.

Why it matters

Lookup, insert and delete take O(1) on average, while a list needs O(n) to search.

Real-world analogy

A library with a code for each book: the code tells you the shelf immediately, instead of scanning every shelf.

From scratch: why this idea exists and how you could invent it

Searching a list is O(n) because the items are in no useful order. Searching a sorted list is O(log n) but keeping it sorted makes inserting O(n). Can we get lookup, insert and delete all fast at once? The answer is hashing: compute from the KEY itself where the item should live.

Think of a coat check: you hand over a coat, receive ticket number 47 and the coat goes on hook 47. To retrieve it you do not search the hooks; you walk straight to hook 47. A hash function is the machine that turns a key (any text or number) into a hook number.

The catch: there are far more possible keys than hooks, so two keys can map to the same hook (a collision). A good hash function spreads keys evenly, and a good table handles collisions (chaining: a small list on each hook; open addressing: look for the next free hook). With an evenly spread hash and a table that grows when it gets crowded, each hook holds about one item on average, so operations are O(1) on average.

Why only unchangeable keys? If a key's content changes after insertion, its hash changes and the table could never find it again. That is why Python allows str, int, tuple (of hashables) and frozenset but not list or dict as keys.

Hash tables power dictionaries, sets, caches, symbol tables, database indexes and counting. It is arguably the most useful single data structure in everyday programming and the main source of O(n^2) to O(n) speedups in interviews.

Deep dive in simple words

A dictionary (hash table) works like a coat-check desk. You give your coat (value) and get a number (key); later you hand over the number and the coat is retrieved at once. Internally a hash function turns the key into a number, and that number (mod the table size) picks a bucket (a slot) where the pair is stored.

A collision happens when two different keys land in the same bucket. Two common fixes: chaining (the bucket holds a list of all pairs) and open addressing (look for the next free bucket). Python uses open addressing and resizes the table when it gets too full, so collisions stay rare and lookups stay O(1) on average.

Only hashable (unchangeable) things can be keys: numbers, strings, tuples of hashables. A list cannot be a key because it can change, and its hash would change too. If you need a list as a key, convert it to a tuple.

A set is a dictionary that stores only keys. Use it for 'have I seen this?' and for removing duplicates. Set operations are handy: a | b (union), a & b (common items), a - b (in a but not b).

When to reach for a hash map: any time you catch yourself scanning a list again and again to look for something. Replace that scan with a dictionary lookup and an O(n^2) solution often becomes O(n).

Under the hood: what really happens inside Python

  • CPython's dict stores entries in a compact array and an index table of slots; the slot is computed from hash(key) and collisions are resolved with probing. When the table is about two-thirds full it grows (resizes) and all keys are re-inserted, which is why single inserts are amortised O(1).
  • hash(x) must be consistent with ==: if a == b then hash(a) == hash(b). Python randomises string hashes per process (hash randomisation) to prevent attackers from crafting collision floods, so iteration order of a set of strings can differ between runs. Dict preserves insertion order (a language guarantee since 3.7) but sets do not.
  • Worst case: if many keys collide into one chain or probe sequence, operations degrade to O(n). Good hash functions and resizing make this extremely unlikely in practice.

def simple_hash(key, size=7):

        total += ord(ch)        # add up character codes
    return total % size         # bucket index

Why? and Why not?

Why is dictionary lookup O(1) on average?

A hash function turns the key into a slot number, so Python jumps straight to it instead of scanning.

Why can't lists be dictionary keys?

Lists can change, so their hash would change. Keys must be unchangeable (hashable).

Why does resizing keep dictionaries fast?

When the table gets crowded Python rebuilds it bigger, so each slot holds about one item and collisions stay rare.

'x in set' is O(1) on average; 'x in list' is O(n).

Why not use a dictionary when you need sorted order?

Hash tables do not keep keys in sorted order. Use a sorted list or tree for ordered queries.

Frequency maps and the Two Sum pattern

Essential Topic 7.2

Simple definition

The complement pattern: while scanning, store what you have seen in a dictionary so that for each new value you can ask "have I already seen the partner I need?" in O(1).

Why it matters

Two Sum and its relatives (pair with a difference, count pairs) are among the most common interview questions.

Real-world analogy

At a dance, each person remembers who is waiting. When a new person arrives, they check if their ideal partner is already on the list.

From scratch: why this idea exists and how you could invent it

Two Sum asks for two numbers adding to a target. Start as a beginner: check every pair. For each number x you scan the whole list looking for target - x. The second scan is the expensive part: it is searching for a specific value.

Searching for a specific value is exactly what a hash table is good at. So replace the inner scan with a dictionary lookup. But which numbers should the dictionary contain? Everything seen so far; the partner is either already seen or will see us later when it arrives (and finds us). That means we only need to look backwards, one pass.

Notice the general lesson: a nested search often means 'for each item, find a partner with property P'. If P can be turned into a key (target - x, remainder, sorted letters), store items by that key and look up directly.

The 'check before insert' rule is not a trick but a consequence: when processing x we want a DIFFERENT earlier element, so x must not be in the table yet.

The same approach counts pairs, finds pairs with a given difference, finds pairs summing to a multiple of m (using remainders as keys) and, extended with prefix sums, finds subarrays with a given sum.

Step-by-step walkthrough

  1. Goal: find i, j with nums[i] + nums[j] = target.
  2. For each x compute need = target - x. If need is in seen, we found the pair. Otherwise store seen[x] = index.
  3. Check BEFORE inserting so the same element is not used twice.
  4. Example [2, 7, 11, 15], target 9: x=2 need 7 (not seen) store 2; x=7 need 2 (seen at 0) -> answer [0, 1].
  5. Step through the visualiser to watch the dict grow.

Deep dive in simple words

Two Sum is the best example of 'use memory to save time'. Brute force checks every pair, which is n x n. But for each number x you are really asking one question: 'Has the number (target - x) appeared before?'. A dictionary answers that in one step.

The loop: for each index i and value x, compute need = target - x. If need is in the dictionary, return its stored index and i. Otherwise store x with its index. Check BEFORE storing so that you never pair a number with itself unless it really appears twice (like [3, 3] with target 6).

The same 'complement' idea solves many variants: count pairs with a given sum or difference, check if two numbers differ by k, find pairs that sum to a multiple of m (store remainders), and subarray problems (store prefix sums).

Frequency maps are also the answer to: 'most frequent', 'top k frequent', 'is there an element that appears more than n/2 times', 'first element that repeats'.

Remember what the problem returns: indices or values, one answer or all answers, 0-indexed or 1-indexed. Many wrong answers come from returning the wrong thing.

Under the hood: what really happens inside Python

  • The dictionary maps value to index. Each iteration does one O(1) average lookup and one O(1) insert, so the loop is O(n). Memory grows to O(n).
  • With duplicates only the latest index is kept in the map when the same value appears again; for 'return indices' problems that is fine because the first occurrence is found when the second arrives.

  • seen = {}; for i, x in enumerate(nums): if target - x in seen: return [seen[target - x], i]; seen[x] = i.

  • Use a set instead of a dict when you do not need indices.

Python implementation

def pair_exists(nums, target):
    seen = set()
    for x in nums:
        if target - x in seen:     # partner already seen
            return True
        seen.add(x)
    return False

Why? and Why not?

Why check the dictionary before inserting?

So an element is never paired with itself; the partner must be an earlier element.

The answer needs indices, and the lookup key is the value we are searching for.

In the worst case it stores every element before finding a pair.

When the second 3 arrives, the first 3 is already stored, and 6 - 3 = 3 is found.

Grouping with canonical keys and longest consecutive sequence

Important Topic 7.3

Simple definition

A canonical key is a value that is identical for all items you want grouped (for example, the sorted letters of a word). A hash set can also test "is the next value present?" in O(1).

Why it matters

It generalises hashing: group anagrams, group by pattern, or detect sequences in unsorted data.

Real-world analogy

Sorting mail by postcode: the postcode is the canonical key that sends similar letters to the same box.

From scratch: why this idea exists and how you could invent it

To group things you need a way to say 'these two belong together'. Comparing every pair of items is O(n^2). A smarter idea is a canonical label: compute from each item a label that is IDENTICAL for items in the same group, then bucket by label. For anagrams the label is the sorted letters.

Choosing a good label is the creative part and shows up everywhere: group numbers by remainder modulo k, group strings by their pattern (egg and add), group points by slope, group files by hash of contents (duplicate file finder).

Longest consecutive sequence teaches a different trick: use the structure of the question to avoid redundant work. If x - 1 exists then x is not the start of a streak, so we skip it. Only starts are expanded, so every number is touched about twice. The lesson: look for a cheap test that tells you when work would be redundant.

Sets answer relationships between collections: intersection (both), union (either), difference (one but not the other). Whenever a problem says 'common', 'in A but not in B' or 'unique', think sets.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Group anagrams: key = "".join(sorted(word)). groups[key].append(word).
  2. Longest consecutive sequence: put numbers in a set; only start counting at x if x - 1 is NOT in the set (x starts a run); extend upward while x + 1 exists.
  3. Each number is visited at most twice, so the whole algorithm is O(n) even though there is a while loop inside a for loop.
  4. Counter(nums).most_common(k) returns the k most frequent elements.

Deep dive in simple words

Grouping with a signature: find something that is the same for every member of a group and use it as the dictionary key. For anagrams the signature is the sorted letters. For numbers that differ by a multiple of m it is the remainder. For words with the same pattern it is a normalised form ('egg' and 'add' both become 'abb').

Longest consecutive sequence in O(n) looks hard but has a neat trick. Put all numbers in a set. A number x is the START of a streak only if x - 1 is NOT in the set. From each start, count upward while x + 1 is in the set. Every number is counted at most once, so the nested loops are still O(n) overall.

Sets are great for comparing two collections: common items (a & b), items in one but not the other (a - b) and all items (a | b). They also test 'is every item of A inside B' with a <= b.

Hash maps can store lists, sets, counts or indices as values. Choose the value that lets you answer the question later in one lookup.

A warning: Counter and dict order does not matter for correctness, but your output may need sorting to match what the judge expects.

Under the hood: what really happens inside Python

  • A tuple of 26 counts or a sorted-letter string is hashable, so it can be a dict key. A list is not.
  • defaultdict(list) calls list() the first time a missing key is accessed, saving the 'if key not in d' check.
  • Set operations are implemented by hashing: a & b iterates over the smaller set and checks membership in the other, O(min(len(a), len(b))).

Python implementation

from collections import defaultdict

def group_by_signature(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())

Stage 1 - sort and scan

Sort and count runs of consecutive values: O(n log n).

def longest(nums):
    nums = sorted(set(nums))
    best = cur = 1 if nums else 0
    for i in range(1, len(nums)):
        cur = cur + 1 if nums[i] == nums[i - 1] + 1 else 1
        best = max(best, cur)
    return best

Check: longest([100, 4, 200, 1, 3, 2]) returns 4

Stage 2 - use a set and only start at run starts

A number x starts a run only if x - 1 is absent. Each number is visited about twice: O(n).

def longest(nums):
    s = set(nums)
    best = 0
    for x in s:
        if x - 1 not in s:
            y = x
            while y + 1 in s:
                y += 1
            best = max(best, y - x + 1)
    return best

Check: longest([100, 4, 200, 1, 3, 2]) returns 4

Interview questions: Hashing

Basic Conceptual How does a hash table work?

A hash function converts a key into an integer. The integer picks a bucket where the key-value pair is stored. Lookup recomputes the hash and goes straight to the bucket, so it is O(1) on average.

Basic Conceptual What is a hash collision and how is it handled?

Two keys map to the same bucket. Handled by chaining (store several items in one bucket) or open addressing (probe for the next free slot).

Basic Conceptual Why can't a list be a dictionary key?

Lists are mutable, so their hash would change when they change. Use a tuple instead.

Basic Conceptual What is the worst-case time of a dict lookup?

O(n) if all keys collide into one bucket, but with a good hash function and resizing this practically never happens; average is O(1).

Basic Conceptual What is the difference between a set and a dict?

A set stores only unique keys. A dict stores key-value pairs. Both use hashing and have O(1) average lookup.

Basic Conceptual How do you count word frequencies?
from collections import Counter
freq = Counter(text.split())
Basic Conceptual Explain how a hash table handles collisions.

Chaining stores all colliding entries in a list at that slot. Open addressing probes other slots (linear, quadratic or double hashing) until it finds an empty one. Both rely on resizing so load stays low.

Medium Coding Implement a simple hash map with chaining.
class HashMap:
    def __init__(self, size=8):
        self.b = [[] for _ in range(size)]
    def put(self, k, v):
        slot = self.b[hash(k) % len(self.b)]
        for pair in slot:
            if pair[0] == k:
                pair[1] = v
                return
        slot.append([k, v])
    def get(self, k, default=None):
        for kk, v in self.b[hash(k) % len(self.b)]:
            if kk == k:
                return v
        return default

def count_pairs(a, k):
    seen, total = {}, 0
    for x in a:
        total += seen.get(k - x, 0)
        seen[x] = seen.get(x, 0) + 1
    return total
