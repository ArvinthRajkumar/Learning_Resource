Trees & Binary Search Trees

Hierarchical data. Traversals and recursion on trees appear in many assessments. Topics in this module: Tree terminology and traversals; binary search trees: search, insert, delete; height, balance, lowest common ancestor and heaps as trees.

Important3 topics17 problems56 interview questions

Start from scratch: why this module exists

Hierarchies (folders, organisation charts, HTML) cannot be expressed with flat lists. Trees give each item one parent and any number of children, and their self-similar structure makes recursion natural. Binary search trees add ordering for fast search.

Most tree solutions reduce to one template: handle None, get answers from the left and right subtrees, combine them.

Who needs it: File systems, browsers (DOM), databases (indexes), compilers (syntax trees) and interviewers.

Tree terminology and traversals

Important Topic 12.1

Simple definition

A tree is a set of nodes connected by edges with one root and no cycles. In a binary tree each node has at most two children (left and right). A traversal visits every node in a defined order.

Why it matters

Trees model hierarchies (file systems, organisation charts) and make searching efficient. Traversals are the base of nearly every tree problem.

Real-world analogy

A family tree: the oldest ancestor is the root; children branch downward; a person without children is a leaf.

From scratch: why this idea exists and how you could invent it

Lists are flat, but much real data is hierarchical: a company (CEO, managers, staff), a folder structure, an HTML page (tags inside tags), a family. A list cannot show 'belongs to'. A tree can: each item has one parent and any number of children.

Why a TREE and not a general graph? Because the restriction (one parent, no cycles) gives us powerful guarantees: there is exactly one path from the root to any node, recursion never loops, and every node's subtree is itself a tree. That self-similarity is why tree code is so short and recursive.

A binary tree limits each node to two children. This is enough for searching (go left or right), expression parsing and heaps, and it keeps code simple (node.left, node.right).

Traversal is the first skill: how do you visit every node without missing any? Depth-first goes down a branch fully before the next; breadth-first goes level by level. The three DFS orders differ only in when the node is processed relative to its children, and each suits a different task: preorder copies a tree (parents before children), inorder reads a BST in sorted order, postorder deletes or evaluates (children before parents).

Height matters because it controls cost. Operations that walk root-to-leaf cost O(height): log n for a balanced tree, n for a degenerate one.

Step-by-step walkthrough

  1. Terms: root (top), leaf (no children), parent/child, depth of a node (edges from root), height of the tree (edges on the longest root-to-leaf path), level (all nodes at one depth).
  2. Inorder: left, node, right. Preorder: node, left, right. Postorder: left, right, node. Level-order: level by level using a queue.
  3. For a BST, inorder gives sorted order.
  4. All three DFS traversals are recursion on the left and right subtrees; they only differ in WHEN you record the node.
  5. Pick a traversal in the visualiser and watch the current node highlight.

Deep dive in simple words

A tree is like a family tree or a folder structure. There is one top node (the root). Each node can have children below it. A node with no children is a leaf. A binary tree allows at most two children: left and right. Trees have no loops, and there is exactly one path between any two nodes.

Words you must know: depth of a node = number of edges from the root to it (root has depth 0). Height of a tree = number of edges (or nodes, check the problem!) on the longest path down. Level = all nodes at the same depth. Subtree = a node together with everything below it.

Traversal means visiting every node once. DFS goes deep first and has three flavours that differ only in WHEN you record the node: preorder (before the children), inorder (between left and right children), postorder (after both children). BFS (level order) visits level by level using a queue.

Almost all tree recursion has the same shape: if node is None return something simple; otherwise get answers from node.left and node.right and combine them with node.val. Memorise this shape and tree questions become easy.

Complexity: visiting all nodes is O(n). Recursion uses space equal to the tree height h: O(log n) for a balanced tree, O(n) for a skewed tree that looks like a linked list.

Under the hood: what really happens inside Python

  • Each node object stores val, left and right references. A leaf has both as None. The recursion stack depth equals the current depth, hence O(h) space.
  • Preorder + inorder (or postorder + inorder) uniquely determine a binary tree, which is a classic reconstruction question.
  • Level-order traversal uses a queue; the queue holds at most one level plus children, so O(width).

Python implementation

def inorder(node, out):
    if node is None:
        return out
    inorder(node.left, out)       # 1. left subtree
    out.append(node.val)          # 2. this node
    inorder(node.right, out)      # 3. right subtree
    return out

def preorder(node, out):
    if node is None:
        return out
    out.append(node.val)
    preorder(node.left, out)
    preorder(node.right, out)
    return out

def postorder(node, out):
    if node is None:
        return out
    postorder(node.left, out)
    postorder(node.right, out)
    out.append(node.val)
    return out

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
    def __repr__(self):
        return "Node(%r)" % (self.val,)

def build_tree(vals):
    """Build a binary tree from a level-order list; None means 'no node'."""
    if not vals or vals[0] is None:
        return None
    root = TreeNode(vals[0])
    queue, i = [root], 1
    while queue and i < len(vals):
        node = queue.pop(0)
        if i < len(vals) and vals[i] is not None:
            node.left = TreeNode(vals[i]); queue.append(node.left)
        i += 1
        if i < len(vals) and vals[i] is not None:
            node.right = TreeNode(vals[i]); queue.append(node.right)
        i += 1
    return root

def find_node(root, val):
    if not root:
        return None
    if root.val == val:
        return root
    return find_node(root.left, val) or find_node(root.right, val)

Why? and Why not?

Why use a tree instead of a list for hierarchies?

A list cannot express 'belongs to'. A tree gives every item one parent and shows containment directly.

Why is tree recursion so short?

Every subtree is itself a tree, so one function handles the node and trusts recursive calls for the children.

Why are there three DFS orders?

They differ in when the node is processed: before children (copy), between children (sorted order in a BST), after children (delete or evaluate).

Why does BFS need a queue?

It must serve the oldest discovered node first to go level by level.

Why can recursion fail on a skewed tree?

Depth equals the number of nodes, which can exceed Python's recursion limit. Use an iterative traversal.

  • Sorted ascending order
  • Level order
  • Random order

Left < node < right, so inorder is sorted.

Which traversal visits the root first?

  • Inorder
  • Preorder
  • Postorder
  • None

Preorder = node, left, right.

Binary search trees: search, insert, delete

Important Topic 12.2

Simple definition

A binary search tree (BST) keeps every left-subtree value smaller than the node and every right-subtree value larger. This lets you search by choosing left or right at each node.

Why it matters

A balanced BST supports search, insert and delete in O(log n); it is the idea behind ordered maps.

Real-world analogy

A guessing game where each question halves the options, except the "array" is a tree of questions.

From scratch: why this idea exists and how you could invent it

We want a structure that supports fast search, insert and delete, while keeping data ordered. Sorted arrays search fast but insert slowly. Linked lists insert fast but search slowly. A binary search tree combines the two ideas: each node is a decision 'smaller goes left, bigger goes right', so a search is a short walk down one path.

The BST rule is local but powerful: the rule at each node guarantees the global order. An inorder walk (left, node, right) therefore lists all values in sorted order for free.

The weakness is shape. The tree's speed depends on its height. Inserting 1, 2, 3, 4 in order produces a chain, so operations become O(n). The fix is balancing: AVL and Red-Black trees rotate nodes after changes to keep height near log n. Python's standard library has no built-in balanced tree; sorted lists with bisect or the sortedcontainers package fill that role.

Deletion is the hardest case: removing a node with two children breaks the ordering unless you replace it with the next value in order (the inorder successor), which is the smallest node of the right subtree.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Search: if target == node.val found; if smaller go left; else go right; None means absent.
  2. Insert: search for the position and attach a new leaf there.
  3. Delete: leaf -> remove; one child -> replace by the child; two children -> replace its value with the inorder successor (smallest in the right subtree) and delete that node.
  4. Insert 8, 3, 10, 1, 6, 14 in order to get a balanced tree. Insert 1, 2, 3, 4 in order and you get a skewed "linked list" with O(n) operations.
  5. Self-balancing trees (AVL, Red-Black) rotate to keep height O(log n). Python's sortedcontainers or sorted lists with bisect are alternatives.
  6. The search mode in the visualiser shows the path from the root.

Deep dive in simple words

A binary search tree (BST) follows one simple rule for EVERY node: everything in the left subtree is smaller, everything in the right subtree is bigger. That rule lets you search like binary search: compare with the current node and go left or right, throwing away a whole subtree each time.

Insert: search for where the value would be and attach a new leaf. Delete is the tricky one: a leaf is just removed, a node with one child is replaced by that child, and a node with two children is replaced by its inorder successor (the smallest value in the right subtree) after which that successor is deleted.

If you insert sorted data (1, 2, 3, 4, ...) the BST becomes a long line and every operation costs O(n). Self-balancing trees (AVL, Red-Black) rotate nodes to keep the height about log n. In Python we usually use a sorted list with bisect, or just a dictionary plus sorting.

Validating a BST is a classic trap. Checking only 'left child < node < right child' is not enough, because a deeper node may break the rule for an ancestor. Pass down the allowed range (low, high) as you recurse.

Useful facts: inorder of a BST is sorted; the smallest value is the left-most node; the largest is the right-most node; the k-th smallest is the k-th item of the inorder walk.

Under the hood: what really happens inside Python

  • Validation needs bounds: every node must be inside (low, high) derived from its ancestors. Equivalently, an inorder traversal must be strictly increasing.
  • Red-Black trees guarantee height at most 2 log2(n + 1); AVL trees are more strictly balanced (faster lookups, slower updates).
  • Without balancing, random insertion order gives expected height about O(log n); sorted insertion gives O(n).

  • Build a BST from a list by inserting values one by one.
  • For sorted data and range queries use bisect on a list.

Python implementation

def bst_search(node, target):
    while node:
        if target == node.val:
            return True
        node = node.left if target < node.val else node.right
    return False

def bst_insert(node, val):
    if node is None:
        return TreeNode(val)           # found the empty spot
    if val < node.val:
        node.left = bst_insert(node.left, val)
    elif val > node.val:
        node.right = bst_insert(node.right, val)
    return node

Stage 1 - check parent and children only (WRONG idea)

Looks right and even says True for this tree, but the tree is NOT a valid BST: 3 sits in the right subtree of 5. A deep node can break the rule for a far ancestor. Never stop here.

def is_valid_bst(root):
    if not root:
        return True
    if root.left and root.left.val >= root.val:
        return False
    if root.right and root.right.val <= root.val:
        return False
    return is_valid_bst(root.left) and is_valid_bst(root.right)

Check: is_valid_bst(build_tree([5, 4, 6, None, None, 3, 7])) returns True

Stage 2 - pass down allowed bounds

Each node must lie inside (low, high) inherited from all ancestors. Correct and O(n).

def is_valid_bst(root, low=float('-inf'), high=float('inf')):
    if not root:
        return True
    if not (low < root.val < high):
        return False
    return (is_valid_bst(root.left, low, root.val) and
            is_valid_bst(root.right, root.val, high))

Why does a BST give sorted order by inorder traversal?

Everything on the left is smaller and on the right larger, so left, node, right visits values in ascending order.

Height, balance, lowest common ancestor and heaps as trees

Important Topic 12.3

Simple definition

Many tree questions are solved by letting each recursive call return information about its subtree (height, size, whether it is balanced) and combining the answers from the left and right children.

Why it matters

This "post-order information passing" pattern solves depth, diameter, balance, LCA, path sum and more in a single O(n) pass.

Real-world analogy

A manager asks each team lead for a report (their team's height/size) and combines the reports into the department's report.

From scratch: why this idea exists and how you could invent it

Many tree questions ask for a single fact about the whole tree: its height, whether it is balanced, its diameter, the maximum path sum. Looking at the whole tree at once is hard, but looking at one node with the facts about its two child subtrees is easy. The recursion lets you assume the children's facts are available and combine them.

This is the 'post-order information passing' pattern: each call returns a summary of its subtree (height, size, a boolean, a tuple). The parent combines the summaries and returns its own. Think of managers reporting up the chain.

A second pattern passes information DOWN: the allowed range for BST validation, the remaining sum for path sum, the current depth for level-based work. Many problems combine both: pass something down and return something up.

Sometimes the answer is not the return value. Diameter returns height but updates a best variable with left + right at each node. Recognising 'the quantity I need differs from what I return' is a key step in hard tree problems.

Lowest common ancestor uses the same shape: each call reports whether it found p or q in its subtree; the first node that receives reports from both sides is the LCA.

Visual explanation (interactive)

Step-by-step walkthrough

  1. Height: 1 + max(height(left), height(right)); empty tree = 0 (counting nodes).
  2. Count nodes: 1 + count(left) + count(right).
  3. Balanced: for every node the heights of its subtrees differ by at most 1. Compute heights bottom-up and return -1 early if unbalanced.
  4. LCA in a binary tree: if the current node is p or q return it; if both sides return non-null the current node is the LCA. In a BST: go left if both are smaller, right if both bigger, else the current node is the LCA.
  5. A (binary) heap is a complete binary tree stored in an array where the parent is always smaller (min-heap) or larger (max-heap) than its children - see Module 13.
  6. Use the level-order mode in the visualiser to see levels.

Deep dive in simple words

The most powerful tree pattern: let each recursive call RETURN something about its subtree, and combine results from the two children. Height: 1 + max(left, right). Size: 1 + left + right. Sum: val + left + right. Balanced: return height, or -1 if some subtree is unbalanced.

Sometimes the answer is not what you return. Diameter is the longest path between any two nodes. Each call returns its height, but while doing so it updates a 'best' variable with left_height + right_height (the longest path passing through that node). This 'return one thing, record another' trick is common.

Lowest common ancestor (LCA) in a general binary tree: if the current node is one of the targets return it; recurse on both sides; if both sides return something, this node is the LCA; otherwise return whichever side is not None. In a BST it is even simpler: walk down; if both targets are smaller go left, if both bigger go right, otherwise stop.

Path problems (root-to-leaf sum, longest path) pass a running value DOWN the recursion (remaining sum) and decide at the leaf.

Heaps are trees too: a complete binary tree stored in an array. You will use them in the next module.

Under the hood: what really happens inside Python

  • A global/nonlocal variable or a returned tuple carries side results out of the recursion. Python closures with nonlocal are the clean way.
  • Efficient balance checking returns -1 as a sentinel for 'unbalanced' to stop work early; calling height at every node would be O(n^2) on a skewed tree.
  • All these algorithms visit each node once: O(n) time and O(h) stack space.

Python implementation

def height(node):
    if node is None:
        return 0
    return 1 + max(height(node.left), height(node.right))

def count_nodes(node):
    if node is None:
        return 0
    return 1 + count_nodes(node.left) + count_nodes(node.right)

def is_balanced(node):
    def check(n):                       # returns height or -1 if unbalanced
        if n is None:
            return 0
        l, r = check(n.left), check(n.right)
        if l == -1 or r == -1 or abs(l - r) > 1:
            return -1
        return 1 + max(l, r)
    return check(node) != -1

        return "Node(%r)" % (self.val,)

def build_tree(vals):
    """Build a binary tree from a level-order list; None means 'no node'."""
    if not vals or vals[0] is None:
        return None
    root = TreeNode(vals[0])
    queue, i = [root], 1
    while queue and i < len(vals):
        node = queue.pop(0)
        if i < len(vals) and vals[i] is not None:
            node.left = TreeNode(vals[i]); queue.append(node.left)
        i += 1
        if i < len(vals) and vals[i] is not None:
            node.right = TreeNode(vals[i]); queue.append(node.right)
        i += 1
    return root

def find_node(root, val):
    if not root:
        return None
    if root.val == val:
        return root
    return find_node(root.left, val) or find_node(root.right, val)

def is_balanced(root):
    if not root:
        return True
    return (abs(height(root.left) - height(root.right)) <= 1 and
            is_balanced(root.left) and is_balanced(root.right))

Stage 2 - return height or -1 in one pass

Each node reports its height upward, or -1 if some subtree is unbalanced: O(n).

def is_balanced(root):
    def check(n):
        if not n:
            return 0
        l, r = check(n.left), check(n.right)
        if l == -1 or r == -1 or abs(l - r) > 1:
            return -1
        return 1 + max(l, r)
    return check(root) != -1

Interview questions: Trees & Binary Search Trees

56 questions: try to answer aloud in under a minute, then reveal. All questions from every module are also in the interview bank.

Basic Conceptual What are the tree traversals and their orders?

Inorder: left, node, right. Preorder: node, left, right. Postorder: left, right, node. Level order: level by level with a queue.

Basic Conceptual What does inorder traversal of a BST give?

The values in sorted ascending order.

Basic Conceptual How do you find the height of a binary tree?

height(node) = 0 if None else 1 + max(height(left), height(right)). O(n).

Basic Conceptual Difference between depth and height?

Depth is measured from the root down to a node; height is measured from a node down to its deepest leaf.

Basic Conceptual How do you do level order traversal?

Use a queue. Process the number of nodes currently in the queue as one level and add their children for the next level.

Basic Conceptual What is the space complexity of recursive DFS on a tree?

O(h) for the call stack, where h is the height.

Basic Conceptual What is the maximum number of nodes in a binary tree of height h (counting edges)?

2^(h+1) - 1.

Basic Conceptual What is a binary search tree?

A binary tree where for every node, all values in the left subtree are smaller and all values in the right subtree are larger.

Basic Conceptual Time complexity of BST operations?

O(h): O(log n) when balanced and O(n) when skewed.

Basic Conceptual How do you validate a BST?

Recurse with the allowed range: left child must be within (low, node.val) and right child within (node.val, high). Checking only the parent is wrong.

Basic Conceptual How do you delete a node with two children?

Replace its value with its inorder successor (smallest in the right subtree) and then delete that successor node.

Basic Conceptual How do you find the k-th smallest element in a BST?

Do an inorder traversal and stop at the k-th visited node (iterative stack solution is O(h + k)).

Basic Conceptual Why can a BST become O(n)?

If values are inserted in sorted order the tree becomes a chain.

Basic Conceptual Why can a BST degrade to O(n)?

Inserting sorted data produces a one-sided chain, so height is n and operations walk the whole chain. Self-balancing trees fix this.

Basic Conceptual How do you check if a tree is height balanced efficiently?

Compute heights bottom-up. A helper returns the height or -1 when unbalanced. This is O(n) instead of calling height at every node (O(n^2)).

Basic Conceptual What is the diameter of a binary tree and how do you compute it?

The number of edges on the longest path between any two nodes. For each node the longest path through it is height(left) + height(right); take the maximum while computing heights. O(n).

Basic Conceptual Find the lowest common ancestor of two nodes.

Recurse: if node is None or equals a target return node; get left and right answers; if both are non-null return node; else return whichever is non-null.

Basic Conceptual How do you check if a tree is symmetric?

Compare the left and right subtrees as mirrors: left.left with right.right and left.right with right.left, recursively.

Basic Conceptual How do you check if a root-to-leaf path has a given sum?

Subtract each node's value from the target while going down; at a leaf the remaining target must be 0.

Basic Conceptual What does 'post-order information passing' mean?

Each node computes its result after its children and returns it to its parent, combining the children's results.

Medium Coding Iterative inorder traversal.
def inorder(root):
    res, st, cur = [], [], root
    while st or cur:
        while cur:
            st.append(cur)
            cur = cur.left
        cur = st.pop()
        res.append(cur.val)
        cur = cur.right
    return res

It parses HTML into a DOM tree; styling and layout walk the tree, and events bubble up from child to parent.

A list cannot express 'belongs to'. A tree gives every item one parent and shows containment directly.

Every subtree is itself a tree, so one function handles the node and trusts recursive calls for the children.

Medium Why / Why not Why are there three DFS orders?

They differ in when the node is processed: before children (copy), between children (sorted order in a BST), after children (delete or evaluate).

Medium Why / Why not Why does BFS need a queue?

It must serve the oldest discovered node first to go level by level.

Medium Why / Why not Why can recursion fail on a skewed tree?

Depth equals the number of nodes, which can exceed Python's recursion limit. Use an iterative traversal.

You can (heaps do, using index arithmetic), but for general trees node objects are clearer.

Medium Coding Find the lowest common ancestor in a BST.
def lca_bst(root, p, q):
    while root:
        if p < root.val and q < root.val:
            root = root.left
        elif p > root.val and q > root.val:
            root = root.right
        else:
            return root

Medium Coding Maximum path sum in a binary tree (path may start and end anywhere).
def max_path_sum(root):
    best = float('-inf')
    def gain(n):
        nonlocal best
        if not n:
            return 0
        l, r = max(gain(n.left), 0), max(gain(n.right), 0)
        best = max(best, n.val + l + r)
        return n.val + max(l, r)
    gain(root)
    return best
