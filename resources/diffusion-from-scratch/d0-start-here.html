Words you'll see constantly, up front

These four words will appear in almost every paragraph from here on. Read this section slowly, everything else is easier once these are solid. Don't worry about memorizing them; you can scroll back any time, and there's a full glossary at the bottom of the page.

Model

Term: Model

A model is just a big function with adjustable numbers inside it (called parameters or weights). You feed it an input, it does a bunch of arithmetic using its current parameters, and it produces an output. "Training" means automatically adjusting those numbers so the outputs get better over time.

Neural network

Term: Neural network

A neural network is a specific kind of model: it's built out of stacked layers, where each layer takes in numbers, multiplies them by weights, adds them up, and passes the result through a simple non-linear function (this non-linearity is what lets the network learn curved, complex patterns instead of only straight-line relationships). "Deep learning" just means a network with many layers stacked on top of each other.

Training

Term: Training

Training is the process of showing the model examples, checking how wrong its output was (this "wrongness" is called the loss), and nudging every weight in the network very slightly in the direction that would have made that output less wrong. Do this thousands or millions of times, over many examples, and the network gets progressively better at the task.

Analogy

Imagine adjusting hundreds of tiny knobs on a mixing desk. You play a sound, compare it to a target sound, and turn each knob a tiny bit toward "closer to the target." Repeat this a few million times with different sounds, and eventually the knob positions produce good sound generally. Training a neural network is exactly this, except there can be millions of knobs (parameters) and a computer does the tiny turning automatically, using math called gradient descent, don't worry about the details of that yet, just know it's the "automatic knob-turning" procedure.

Inference

Term: Inference

Inference just means "using an already-trained model to produce an output," with no more learning happening. When you type a prompt into an image generator and get a picture back, that's inference, the knobs are frozen, and you're just running the function forward once.

That's it for now. Everything else in this page is really just: "what shape should the model take (Phase 2, the U-Net), and what should we show it during training so it learns to generate images (Phase 2, the diffusion process)." Phase 1 is just getting your laptop ready to run any of this at all.

Python constructs used later: a quick primer

This page assumes you can write basic Python, but the code in Phase 3 uses a handful of specific Python-the-language features (not PyTorch features, plain Python) that are easy to half-know or forget. Rather than explain each one the first time it appears buried inside a large code block, they're all collected here, once, so you can skip this section if you already know them, or read it now so nothing in Phase 3 is a surprise.

Classes, self, and __init__

Term: Class

A class is a blueprint for creating objects that bundle together data and the functions that act on that data. class ResBlock: defines a new blueprint named ResBlock; writing ResBlock(64, 128, 512) later actually creates one real object from that blueprint (called an instance).

Term: self

Inside a class, self refers to "this particular instance of the object." Every method (function defined inside a class) takes self as its first parameter, so it can access and store data specific to that one instance. Writing self.conv1 = nn.Conv2d(...) inside __init__ stores that layer as an attribute on this specific instance, retrievable later as my_block.conv1 from outside the class, or simply self.conv1 from inside any other method of the same class.

Term: __init__

__init__ (two underscores on each side, pronounced "dunder init," short for "double underscore") is a special method automatically called once, the moment you create a new instance of a class. ResBlock(64, 128, 512) automatically calls __init__(self, 64, 128, 512) behind the scenes. Any arguments you pass when creating the instance are received here and typically stored onto self for later use.

Term: super().__init__()

When a class inherits from another class (as every nn.Module subclass does, see the earlier nn.Module section), super() gives you access to the parent class's own version of a method. Calling super().__init__() as the very first line of your own __init__ runs nn.Module's own setup code first (which sets up the internal bookkeeping that tracks your layers' weights), before your own initialization code adds anything on top. Skipping this line is a common bug that causes confusing errors about missing attributes.

zip() and enumerate()

Term: zip()

zip() takes two (or more) lists and pairs up their elements by position, so you can loop over both at once. zip(self.down_blocks, self.downsamples) (used in the U-Net's forward method) pairs the first ResBlock with the first Downsample, the second with the second, and so on, letting for block, downsample in zip(...) process one matched pair per loop iteration, instead of needing two separate index variables and manual lookups into each list.

Term: enumerate()

enumerate() loops over a list while also giving you each item's position (index), without you having to track a separate counter variable by hand. for i, out_ch in enumerate(reversed_channels): (used when building the U-Net's decoder) gives you both the position i (0, 1, 2, ...) and the value out_ch at each step.

Both together, compared to the manual version 
# Without zip/enumerate - more code, easier to get an index wrong
i = 0
for block in blocks:
    downsample = downsamples[i]
    print(i, block, downsample)
    i += 1

# With zip and enumerate - shorter, and impossible to mis-index
for i, (block, downsample) in enumerate(zip(blocks, downsamples)):
    print(i, block, downsample)

List comprehensions

Term: List comprehension

A list comprehension is a compact way to build a new list by transforming every item of an existing one, in a single line. [base * m for m in mults] (used in unet.py to compute channel counts) means "build a new list containing base * m, for every m found in mults." It's exactly equivalent to writing a full for-loop that appends to an empty list, just shorter and more common in real Python code you'll read.

The long way versus the list comprehension 
# Long way
channels = []
for m in mults:
    channels.append(base * m)

# List comprehension - identical result, one line
channels = [base * m for m in mults]

Decorators (@)

Term: Decorator

A decorator is a line starting with @, placed directly above a function definition, that wraps the function with extra behavior without you having to write that behavior inside the function itself. @torch.no_grad() placed above def sample(...): means "run this entire function with gradient tracking turned off", it has exactly the same effect as indenting the whole function body inside a with torch.no_grad(): block, just written once at the top instead of wrapping every line.

Context managers (the "with" keyword)

Term: Context manager / with

with sets up something before a block of code runs and automatically tears it down afterward, even if an error happens partway through, guaranteeing the cleanup always happens. with torch.no_grad(): turns gradient tracking off for everything indented underneath it, and automatically turns it back on afterward. with torch.autocast(...): similarly turns mixed-precision behavior on for its block and off afterward. You'll recognize this pattern anywhere you see with something: followed by an indented block, it always means "temporarily change some setting for this block only."

f-strings

Term: f-string

An f-string is a string literal prefixed with f, letting you embed variable values directly inside curly braces without manually joining pieces of text together. f"Epoch {epoch+1}/{config.EPOCHS}" automatically inserts the current values of epoch+1 and config.EPOCHS into the string. {avg_loss:.4f} additionally means "format this number to exactly 4 decimal places", the part after the colon is a formatting instruction, useful for keeping printed loss values readable instead of showing fifteen digits of floating-point noise.

Python's os module

Term: os.makedirs() / os.path.join()

os is Python's built-in module for talking to the operating system, creating folders, building file paths, and so on. os.makedirs(path, exist_ok=True) creates a folder (and any missing parent folders needed along the way), without erroring if it already exists. os.path.join(a, b) combines path pieces into a single valid path using the correct separator for whatever operating system the code is running on (\ on Windows, / on Linux/macOS), os.path.join(config.CHECKPOINT_DIR, "model.pt") is safer than manually writing config.CHECKPOINT_DIR + "/model.pt", since the manual version can silently build an invalid path on Windows.

None, True, False, and is

Term: None

None is Python's way of representing "no value at all", different from zero, an empty string, or false; it means the absence of any value. def sample(checkpoint_path=None): uses None as a default, meaning "if the caller doesn't provide a checkpoint path, assume there isn't one." Checking if checkpoint_path: afterward relies on the fact that None is treated as "falsy" (behaves like False in an if check), so the block only runs when an actual path was given.
