Part D1

Phase 1: Setup

Get your laptop ready. No model-building yet, just making sure the tools work and your GPU is actually being used.

Basic~1 hour

Step 1: Check your GPU and driver

Your laptop has an RTX 2050. That's an NVIDIA graphics card with 4GB of VRAM.

Term: VRAM

VRAM (video RAM) is memory that lives physically on the graphics card itself, separate from your laptop's main 16GB of system RAM. When you train a neural network on a GPU, the model's weights, the data currently being processed, and a lot of temporary working numbers all have to fit inside VRAM at the same time. Your system RAM (16GB) barely matters for GPU training, 4GB of VRAM is your real, tight constraint, and almost every design decision later in this project comes back to respecting that number.

Term: GPU vs CPU

Your CPU (the Intel i5) is good at doing a few complex things quickly, one after another. Your GPU (the RTX 2050) is good at doing thousands of simple things, mostly multiplication and addition, all at the same time. Neural networks are almost entirely multiplication and addition on grids of numbers, so GPUs train them 10 to 50 times faster than a CPU would. You want every part of training to run on the GPU, not the CPU.

Before installing anything, find out what driver and CUDA version your GPU currently supports.

Term: Driver

A driver is the software that lets your operating system talk to a piece of hardware. An NVIDIA driver is what lets Windows or Linux even see the RTX 2050 exists and send work to it.

Term: CUDA

CUDA is NVIDIA's platform that lets normal programs (like PyTorch) send instructions to run on the GPU. Think of it as a translator: your Python code says "multiply these two grids of numbers," and CUDA is what actually hands that job to the thousands of tiny cores on your graphics card. Every GPU driver version supports up to a certain CUDA version, so you need to check yours before picking which PyTorch to install.

  1. Open a terminal

    On Windows, that's Command Prompt or PowerShell. On Linux, any terminal app.

  2. Run the driver check command

    Command

    nvidia-smi

    If this prints a table with your GPU name, temperature, and memory usage, your driver is installed and working. If you get "command not found," you need to install the NVIDIA driver for your GPU first, search "RTX 2050 driver download" on NVIDIA's own site and install that before continuing.

  3. Read the CUDA version from the output

    In the top-right of the nvidia-smi table you'll see something like CUDA Version: 12.4. That is the maximum CUDA version your current driver supports, write this number down, you'll need it in Step 4 (installing PyTorch). You do not need to separately install a CUDA Toolkit for this project; PyTorch ships its own CUDA internally, matched to the version you choose when installing it.

Watch out

Don't confuse "CUDA Version" shown by nvidia-smi (your driver's ceiling) with a CUDA Toolkit you'd install separately. For this project you only need the driver to already support a CUDA version equal to or newer than whatever PyTorch build you install. You almost never need to install the full NVIDIA CUDA Toolkit by hand for plain PyTorch use.

Step 2: Install Python properly

You likely already have Python from other work, but let's make sure the version is compatible with current PyTorch releases.

  1. Check your current version

    Command

    python --version

    You want Python 3.10, 3.11, or 3.12. If you're on something much older (3.8 or earlier) or don't have Python at all, install a fresh Python 3.11 from the official python.org installer (on Windows, tick "Add python.exe to PATH" during install, this is what makes the python command work from any terminal).

Step 3: Virtual environments

Term: Virtual environment

A virtual environment (often shortened to "venv") is an isolated folder containing its own copy of Python and its own set of installed libraries, separate from the rest of your system. You create one per project.

Analogy

Think of it like separate toolboxes for separate jobs. If you installed every tool you ever bought into one giant shared toolbox, you'd eventually get conflicts, two different wrenches both claiming to be "the 10mm wrench," incompatible with each other. A virtual environment is a fresh toolbox just for this project, so nothing from any other Python project you've done (or will do) can quietly break this one, and vice versa.

Why this matters specifically for you: PyTorch with GPU support needs very exact-matching versions of several libraries. If you install this project's libraries into your "main" Python (no virtual environment), you risk breaking some other project you have, or having some other project's older library silently break this one. Always make a new virtual environment per project.

  1. Create a project folder

    Command

    mkdir diffusion-project
cd diffusion-project

  2. Create the virtual environment

    Command

    python -m venv venv

    This creates a folder named venv inside your project folder containing a private copy of Python. Nothing has changed system-wide yet, you have to explicitly turn this environment "on" (that's called activating it) before it does anything.

  3. Activate it

    Command (Windows, PowerShell)

    venv\Scripts\Activate.ps1

    Command (Windows, cmd.exe)

    venv\Scripts\activate.bat

    Command (Linux / macOS)

    source venv/bin/activate

    After activating, your terminal prompt will show (venv) at the start of the line. Every pip install you now run goes into this isolated folder, not your system Python. You need to re-run the activate command every time you open a new terminal window for this project.

Watch out

If Activate.ps1 gives a "running scripts is disabled" error on Windows, open PowerShell as Administrator once and run Set-ExecutionPolicy RemoteSigned, then try activating again. This is a one-time fix for your whole machine.

Step 4: Install PyTorch, with CUDA support

Term: PyTorch

PyTorch is the library you'll use to build and train the neural network. It gives you tensors (grids of numbers, explained properly in Phase 2), the ability to run operations on those grids on the GPU via CUDA, and automatic differentiation, meaning PyTorch automatically works out how to adjust every weight during training, so you never have to hand-derive that calculus yourself.

The exact install command depends on your CUDA version from Step 1. Rather than copy a command from anywhere else (these change over time), always get the current command from PyTorch's own site.

  1. Go to the official PyTorch install page

    Visit pytorch.org and find the "Install" / "Get Started" section. Select: Stable build, your OS, Pip as the package manager, Python as the language, and a CUDA version at or below the number you saw from nvidia-smi earlier. The page will generate the exact pip install command for that combination.

  2. Run the generated command inside your activated venv

    Make sure you see (venv) in your prompt first. Then paste and run the command the site gave you. This will download a few hundred MB, with 200GB free, disk space is not a concern anywhere in this project.

Step 5: Verify PyTorch actually sees your GPU

This is the single most important check in Phase 1. It's very common to successfully install PyTorch but accidentally get the CPU-only version, and not notice until training is mysteriously 30x slower than expected.

  1. Open Python inside your venv

    Command

    python

    This drops you into an interactive Python prompt (you'll see >>>).

  2. Run this check

    Python

    import torch
print(torch.__version__)
print(torch.cuda.is_available())
print(torch.cuda.get_device_name(0))

    You want to see your PyTorch version, then True, then something like NVIDIA GeForce RTX 2050. If cuda.is_available() prints False, you installed the CPU-only build by mistake, go back to Step 4 and re-select a CUDA version on the PyTorch site, then reinstall inside this same venv.

Checkpoint: Phase 1, halfway
  • nvidia-smi runs and shows my GPU
  • Python 3.10-3.12 is installed
  • Virtual environment created and activated
  • PyTorch installed with matching CUDA version
  • torch.cuda.is_available() prints True

Step 6: Install the other libraries you'll need

A short list, each with one job. Install all of these inside the same activated venv.

LibraryWhat it's for
torchAlready installed in Step 4, the core deep learning engine.
torchvisionReady-made tools for working with images: loading standard datasets, resizing, cropping, converting images to tensors.
numpyGeneral-purpose numerical arrays. PyTorch tensors and numpy arrays interoperate constantly.
matplotlibFor plotting, you'll use this to look at generated images and loss curves while training.
tqdmAdds a simple progress bar to loops, so a training run shows you a live percentage and time estimate instead of a silent frozen terminal.
einopsA small library for reshaping and rearranging tensors using readable names instead of confusing index juggling. Very commonly used inside U-Net code you'll read.
diffusersHugging Face's library of pre-built diffusion model components. You're writing your own U-Net to learn, but you'll read this library's source code as a reference several times, install it now.

Command (run once, inside your activated venv)

pip install torchvision numpy matplotlib tqdm einops diffusers
Analogy

diffusers here is like keeping a well-written reference textbook on your desk while you do your own homework by hand. You're not going to copy its U-Net wholesale, the whole point is building your own so you understand every piece, but when you're unsure "wait, how does a real implementation handle this part," it's the best place to look.

Step 7: Set up somewhere to write and run code

You need an editor and a way to run code interactively (so you can inspect a tensor's shape immediately after creating it, rather than re-running an entire script each time). Two good, simple options:

Option A: Jupyter Notebook

Term: Jupyter Notebook

A notebook is a document made of "cells" you run one at a time in any order, each cell showing its output directly underneath it, including images and plots, inline. This is extremely useful for a diffusion project because you can, for example, run the "add noise to an image" cell and immediately see the noisy image appear right there, without writing separate plotting scripts.

Install

pip install notebook
jupyter notebook

The second command opens a notebook interface in your browser.

Option B: VS Code

If you already use VS Code, install the official "Python" and "Jupyter" extensions from its marketplace. This lets you open .ipynb notebook files directly inside VS Code, get the same cell-by-cell running, plus proper code autocomplete. This is the setup most people settle into long-term, recommended if you're comfortable installing VS Code extensions.

Watch out

Whichever you pick, make sure the notebook's Python "kernel" (the Python process actually running your code) is the one from your venv, not a different system Python. In VS Code, click the kernel picker in the top-right of the notebook and select the interpreter path inside your project's venv folder. In Jupyter, run pip install ipykernel inside the venv first, then the venv's Python will appear as a selectable kernel.

Phase 1 complete: final checklist

Checkpoint: Phase 1 done
  • GPU driver confirmed working via nvidia-smi
  • Virtual environment created for this project
  • PyTorch installed and confirmed using CUDA (GPU), not CPU
  • torchvision, numpy, matplotlib, tqdm, einops, diffusers installed
  • Notebook environment (Jupyter or VS Code) set up and kernel pointed at the venv
  • Ran a test cell and confirmed no import errors

Once every box above is ticked, your laptop is fully ready.
