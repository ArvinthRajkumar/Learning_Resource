Part DX9

Flow matching, diffusion transformers and modern architectures: the exact math in one dimension

Recent image and video models (Stable Diffusion 3, Flux, Sora-style systems) replace the U-Net with a transformer and the noise-prediction recipe with flow matching. Both are easiest to understand where everything can be written down exactly. This part works the ideas out in one dimension, then connects them to the large-scale architecture.

Advanced~5 hours

Flow matching in one paragraph

Diffusion corrupts data with noise along a curved schedule and trains a network to undo each step. Flow matching takes a more direct view: define a path that connects a noise sample x0 (Gaussian) to a data sample x1, for example the straight line x_t = (1 - t) x0 + t x1 for t from 0 to 1. Its velocity is simply x1 - x0. Train a network v(x, t) to predict that velocity, and generate by integrating the ODE dx/dt = v(x, t) from t = 0 (noise) to t = 1 (data) with a few Euler steps. The training loss is a plain regression, ||v(x_t, t) - (x1 - x0)||^2, with no noise schedule to tune. Rectified flow is exactly this straight-line version.

Why does regressing onto x1 - x0 work, when the network cannot know which x0 and x1 produced a given x_t? The best prediction is the average of x1 - x0 over all pairs that could have produced that point: the marginal velocity field, which is the field that moves the whole noise distribution into the data distribution.

The exact velocity field for a Gaussian mixture

Take one-dimensional data that is a mixture of Gaussians, x1 ~ sum_k w_k N(m_k, s_k^2), with noise x0 ~ N(0, 1). For each component k, the point x_t = (1 - t) x0 + t x1 is Gaussian with mean t m_k and variance v_k(t) = (1 - t)^2 + t^2 s_k^2. Then, for that component:

  • E[x1 | x_t] = m_k + t s_k^2 / v_k (x - t m_k)
  • E[x0 | x_t] = (1 - t) (x - t m_k) / v_k

and the true velocity is the posterior-weighted average over components of E[x1 | x_t, k] - E[x0 | x_t, k], with weights proportional to w_k N(x; t m_k, v_k). Because this is exact, we can integrate it and see precisely how the number of Euler steps affects sample quality, with no training noise in the way.

import math, random
random.seed(1)
comps = [(-2.0, 0.3, 0.5), (2.5, 0.4, 0.5)]            # (mean, std, weight): a bimodal target
def velocity(x, t, comps=comps):
    weights, vels = [], []
    for m, s, w in comps:
        var = (1 - t) ** 2 + t * t * s * s
        weights.append(w * math.exp(-0.5 * (x - t * m) ** 2 / var) / math.sqrt(var))              # posterior weight of this component
        ex1 = m + t * s * s / var * (x - t * m); ex0 = (1 - t) * (x - t * m) / var
        vels.append(ex1 - ex0)
    z = sum(weights); return sum(w * v for w, v in zip(weights, vels)) / z
def sample(steps, n=4000, comps=comps):
    out = []
    for _ in range(n):
        x = random.gauss(0, 1)
        for i in range(steps): x += velocity(x, i / steps, comps) / steps                           # Euler integration of dx/dt = v
        out.append(x)
    return out
def target(n=4000, comps=comps):
    return [random.gauss(m, s) for m, s, _ in (random.choice(comps) for _ in range(n))]
def wasserstein1(a, b): a, b = sorted(a), sorted(b); return sum(abs(x - y) for x, y in zip(a, b)) / len(a)       # 1-D optimal transport distance
reference = target()
print("W1 distance between generated samples and the target (smaller is better):")
for steps in (1, 2, 4, 8, 32):
    print(f"  {steps:>2} Euler steps: {wasserstein1(sample(steps), reference):.3f}")

Output

W1 distance between generated samples and the target (smaller is better):
   1 Euler steps: 2.244
   2 Euler steps: 0.667
   4 Euler steps: 0.253
   8 Euler steps: 0.142
  32 Euler steps: 0.027

Few steps fail on a bimodal target because the velocity field curves (points near the middle must choose a side), and a single Euler step moves in a straight line using the velocity at the start. Many steps follow the curved flow accurately.

What a single step returns: the average

Take the simplest target, a single Gaussian, and look at one Euler step. At t = 0 the exact velocity is m - x, so one step maps every noise value to the data mean m:

import math, random
random.seed(2)
single = [(2.0, 0.5, 1.0)]
def velocity(x, t, comps):
    m, s, w = comps[0]; var = (1 - t) ** 2 + t * t * s * s
    return (m + t * s * s / var * (x - t * m)) - (1 - t) * (x - t * m) / var
def run(steps, comps, n=4000):
    out = []
    for _ in range(n):
        x = random.gauss(0, 1)
        for i in range(steps): x += velocity(x, i / steps, comps) / steps
        out.append(x)
    return out
ref = sorted(random.gauss(2.0, 0.5) for _ in range(4000))
for steps in (1, 2, 8):
    out = sorted(run(steps, single)); w1 = sum(abs(a - b) for a, b in zip(out, ref)) / len(ref)
    print(f"single Gaussian target, {steps} Euler step(s): W1 distance {w1:.3f}, sample mean {sum(out) / len(out):.2f}, sample std {(sum((x - sum(out) / len(out)) ** 2 for x in out) / len(out)) ** 0.5:.2f}")

Output

single Gaussian target, 1 Euler step(s): W1 distance 0.397, sample mean 2.00, sample std 0.00
single Gaussian target, 2 Euler step(s): W1 distance 0.239, sample mean 2.00, sample std 0.20
single Gaussian target, 8 Euler step(s): W1 distance 0.065, sample mean 2.01, sample std 0.41

One step produces no variation at all (sample standard deviation 0.00): every noise input lands on the average of the data. On real images that average is a blurry mean image, the same failure as regressing with MSE in one shot. More steps restore the spread (the standard deviation climbs toward the target 0.5 as the step count grows), because each step uses the velocity at the current point and the current time. This is the motivation for reflow (rectified flow): train a model, generate (noise, data) pairs with it, and train again on those coupled pairs. The new paths are straighter, so a single velocity evaluation is a better guide and fewer steps suffice. Real data is far from Gaussian, so real flows still curve and 20 to 50 steps remain common; distillation squeezes them further.

They are closely related: with the right parameterisation, a diffusion ODE and a flow are the same family (Gaussian paths differ only in their time and scale reparameterisation). The practical differences are simplicity, the straightness of the paths and the choice of weighting across noise levels.

Timestep shifting

At high resolution, neighbouring pixels are more redundant, so noise destroys less information at a given level. Models therefore shift the timestep distribution toward noisier levels when training and sampling at larger sizes (t' = s t / (1 + (s - 1) t) with shift s > 1).

def shift(t, s): return s * t / (1 + (s - 1) * t)
for s in (1.0, 3.0):
    print(f"shift s = {s}: t = " + ", ".join(f"{t:.1f}->{shift(t, s):.2f}" for t in (0.1, 0.3, 0.5, 0.7, 0.9)))
print("with s = 3 half of the steps (t <= 0.5) are spent where the shifted time is below", round(shift(0.5, 3.0), 2), "that is, there is more emphasis on high-noise levels where global structure forms")

Distillation and consistency models

Fast generation compresses many steps into few.

MethodIdea
Progressive distillationTrain a student to match two teacher steps in one; repeat to halve steps
Consistency modelsTrain f(x_t, t) to map any point on a trajectory to the same clean output: f(x_t, t) = f(x_s, s) for points on one ODE path; enables 1 to 4 step sampling
Latent consistency (LCM)Consistency distillation in latent space with guidance folded in
Adversarial distillation (SDXL-Turbo, Lightning)Add a discriminator so few-step samples look sharp
Distribution matching (DMD)Match the generated distribution to the teacher's with score differences
Guidance distillationTeach the student to output the guided prediction directly, halving cost

Costs: lower diversity, less control from guidance, and a fidelity loss versus the multi-step teacher; quality is often judged by human preference rather than FID.

For a deterministic flow, a consistency function exists: integrate the ODE from t to the end. In 1-D with the exact flow above we can compute it directly and check the defining property:

import math
comps = [(-2.0, 0.3, 0.5), (2.5, 0.4, 0.5)]
def velocity(x, t):
    ws, vs = [], []
    for m, s, w in comps:
        var = (1 - t) ** 2 + t * t * s * s
        ws.append(w * math.exp(-0.5 * (x - t * m) ** 2 / var) / math.sqrt(var))
        vs.append((m + t * s * s / var * (x - t * m)) - (1 - t) * (x - t * m) / var)
    z = sum(ws); return sum(w * v for w, v in zip(ws, vs)) / z
def integrate(x, t0, t1, steps=2000):                      # fine Euler integration of the ODE along the flow
    dt = (t1 - t0) / steps
    for i in range(steps): x += velocity(x, t0 + i * dt) * dt
    return x
def consistency(x, t): return integrate(x, t, 0.999)       # where the trajectory through (x, t) ends up
x_start = 0.7
points = [(x_start, 0.0)]
for t in (0.2, 0.4, 0.6):                                   # walk along the trajectory, then ask the consistency function from each point
    points.append((integrate(x_start, 0.0, t), t))
print("points on one trajectory:", [(round(x, 2), t) for x, t in points])
print("consistency function output at each point:", [round(consistency(x, t), 2) for x, t in points], "(the same endpoint, up to integration error)")

Output

points on one trajectory: [(0.7, 0.0), (0.7, 0.2), (1.03, 0.4), (1.52, 0.6)]
consistency function output at each point: [2.51, 2.51, 2.51, 2.51] (the same endpoint, up to integration error)

Diffusion transformers (DiT)

A U-Net's convolutions are replaced by a transformer over patches of the latent, which scales predictably with parameters and data and shares tooling with language models.

Design points:

  • Patchify: a 128 x 128 x 4 latent with 2 x 2 patches becomes 64 x 64 = 4096 tokens of dimension 2 x 2 x 4 = 16, projected to the model width.
  • adaLN-Zero: the timestep (and class or pooled text) embedding predicts per-block scale, shift and gate parameters for layer norm; gates are initialised to zero so each block starts as the identity and training is stable.
  • Cross-attention versus joint attention: older models attend from image tokens to text tokens (cross-attention). MM-DiT (SD3) keeps separate weights for image and text streams but concatenates the tokens for one joint self-attention, letting information flow both ways.
  • Positional information: learned or rotary (2-D RoPE) embeddings; support for several resolutions and aspect ratios by training with bucketed shapes.
  • Text encoders: combine CLIP (pooled summary, good for style) with a large language-model-like encoder such as T5 for detailed prompts.
  • VAE with more channels (16 instead of 4) retains finer detail and helps small text.
def dit_stats(width, layers, tokens, mlp_ratio=4):
    params_per_layer = (4 + 2 * mlp_ratio) * width * width + 6 * width * width      # attention (4w^2) + MLP (2*r*w^2) + adaLN modulation (6w^2)
    params = layers * params_per_layer
    flops_forward = 2 * params * tokens + layers * 4 * tokens * tokens * width        # matmuls + attention score and value products
    return params, flops_forward
for name, w, L in [("DiT-S", 384, 12), ("DiT-B", 768, 12), ("DiT-XL", 1152, 28), ("a 12B-class model", 4096, 48)]:
    p, f = dit_stats(w, L, tokens=4096)
    print(f"{name:>18}: about {p / 1e9:6.2f}B parameters | one forward pass over 4096 tokens: {f / 1e12:7.2f} TFLOPs | 30 steps with CFG: {60 * f / 1e12:8.0f} TFLOPs per image")

At 4096 tokens the quadratic attention term is already comparable to the matrix multiplications for smaller widths, which is why high-resolution generation leans on FlashAttention, windowed or sparse attention, and token reduction.

Training objectives in modern recipes

  • Velocity or flow-matching loss with logit-normal timestep sampling, which spends more training on mid-noise levels where learning is hardest, instead of uniform t.
  • EMA weights for sampling; bf16 training; mixed-resolution and aspect-ratio bucketing; caption quality (synthetic detailed captions improve prompt following markedly; mix them with original alt text).
  • Noise offset or zero-terminal-SNR fixes so the model can produce very dark and very bright images (DX1).
  • Preference optimisation (DPO, reward-weighted training) on human-ranked pairs to improve aesthetics and prompt faithfulness; RLHF-style fine-tuning for diffusion exists but is easy to over-optimise (reward hacking).
  • Data: filtering for quality, de-duplication, and balanced concepts matter as much as architecture (DX5).
Key idea

Flow matching trains a network to predict the velocity along a chosen path from noise to data, and generates by integrating an ODE; paths that are straight need few steps, curved ones need more, and distillation or consistency training collapses steps further. Diffusion transformers patchify the latent, condition through adaptive layer norm and joint attention, and scale like language models, with attention cost growing quadratically in tokens.

Self-check

Why logit-normal timestep sampling?

It concentrates training on intermediate noise levels where the model gains the most, rather than sampling uniformly.

Interview questions: Flows and transformers

14 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic What is flow matching?

Train a network to predict the velocity along a path from noise to data (for rectified flow x1 - x0 on a straight line) and generate by integrating the ODE.

Basic What does a diffusion transformer do differently from a U-Net?

It patchifies the latent into tokens and processes them with transformer blocks conditioned on time and text, scaling like language models.

Medium What is rectified flow and reflow?

Straight-line interpolation between noise and data; reflow retrains on the model's own (noise, sample) pairs to straighten paths so fewer steps suffice.

Medium Why do flow models need fewer hyperparameters than DDPM?

The loss is plain regression on velocity with no noise schedule or variance parameterisation to tune, though timestep sampling and shifting still matter.

Medium What is adaLN-Zero?

Adaptive layer norm where the time and condition embedding predicts scale, shift and gate, with gates initialised to zero so blocks start as identity for stable training.

Medium Explain MM-DiT.

Separate weights for text and image token streams with joint self-attention over the concatenated tokens, allowing two-way information flow.

Medium What is timestep shifting?

A reparameterisation moving training and sampling toward noisier levels at higher resolutions because neighbouring pixels are more redundant.

Medium How do consistency models enable one-step generation?

They learn a function mapping any point on an ODE trajectory to the same clean sample, so a single evaluation jumps to the end.

Advanced Why do real flows still need 20 to 50 steps?

The marginal velocity field is curved, and one Euler step uses only the initial velocity, which points at the average of the data and gives a blurry result; more steps or higher-order solvers follow the curve.

Advanced What is the marginal velocity field and why can a network learn it?

The conditional expectation of x1 - x0 given x_t over all consistent pairs. Regression to the per-pair velocity has this field as its minimiser.

Advanced Compare progressive, consistency, adversarial and distribution-matching distillation.

Progressive halves steps repeatedly; consistency enforces trajectory consistency; adversarial distillation adds a discriminator for sharpness; distribution matching aligns the student's distribution with the teacher's through score differences.

Advanced How does attention cost scale with image size in a DiT?

Tokens grow with area, and self-attention cost grows with the square of the token count, so doubling both sides raises attention cost about 16 times.

Advanced Why use logit-normal timestep sampling?

It concentrates training on intermediate noise levels where the model benefits most instead of uniform sampling.

Advanced How are diffusion models and flow models related?

With Gaussian paths the probability-flow ODE of a diffusion model and a flow-matching flow are the same family, differing in time and scale parameterisation and in the training weighting.
