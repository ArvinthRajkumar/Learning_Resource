Training lab: a tiny diffusion model, then training at scale

The best way to trust the theory is to train something and check it against the exact answer. This part trains a real denoiser from scratch in plain Python, then covers what changes when the model has a billion parameters and the data a billion images.

MediumAdvanced~4 hours

A diffusion model you can train and verify

The setup

Data: one-dimensional numbers from Normal(0, s^2) with s = 2. Model: for every timestep, a single weight w_t with prediction eps_hat = w_t x_t. The training procedure is exactly the loop of the main guide: draw x_0, a random timestep and noise, form x_t, predict, take a gradient step on the squared error. Because the data is Gaussian, the optimal weight is known: w_t* = sqrt(1 - ab_t) / (ab_t s^2 + 1 - ab_t) (DX1), so we can check what training finds.

import math, random
random.seed(0)
T, s = 40, 2.0
betas = [0.005 + (0.2 - 0.005) * i / (T - 1) for i in range(T)]
alphas = [1 - b for b in betas]
ab, p = [], 1.0
for a in alphas:
    p *= a
    ab.append(p)

w = [0.0] * T                              # the "network": one weight per timestep
N = 200000
for step in range(N):
    lr = 0.01 * (1 - step / N) + 1e-4      # learning rate decays to nearly zero
    t = random.randrange(T)                # random timestep, as in training
    x0 = random.gauss(0, s)
    e = random.gauss(0, 1)
    xt = math.sqrt(ab[t]) * x0 + math.sqrt(1 - ab[t]) * e
    pred = w[t] * xt
    w[t] -= lr * 2 * (pred - e) * xt       # gradient of (pred - e)^2 with respect to w[t]

best = [math.sqrt(1 - ab[t]) / (ab[t] * s * s + 1 - ab[t]) for t in range(T)]
print("t    learned  optimal")
for t in (0, 10, 20, 30, 39):
    print("%2d   %.3f    %.3f" % (t, w[t], best[t]))

def sample(weights):
    x = random.gauss(0, 1)                 # start from pure noise
    for t in reversed(range(T)):
        eps = weights[t] * x
        x = (x - betas[t] / math.sqrt(1 - ab[t]) * eps) / math.sqrt(alphas[t])
        if t > 0:
            x += math.sqrt(betas[t]) * random.gauss(0, 1)
    return x

for name, weights in (("learned", w), ("optimal", best)):
    xs = [sample(weights) for _ in range(6000)]
    m = sum(xs) / len(xs)
    sd = math.sqrt(sum((x - m) ** 2 for x in xs) / len(xs))
    print("%s model: generated mean %.2f, std %.2f (data: mean 0.00, std %.2f)" % (name, m, sd, s))

t    learned  optimal

10   0.190    0.170
20   0.435    0.439
30   0.786    0.791
39   0.960    0.959
learned model: generated mean -0.03, std 1.95 (data: mean 0.00, std 2.00)
optimal model: generated mean -0.02, std 1.98 (data: mean 0.00, std 2.00)

After 200,000 stochastic steps the learned weights sit close to the exact optimum: gradient descent on the simple loss really does recover the noise predictor. The decaying learning rate matters: with a constant rate the weights keep jittering around the optimum because each step uses one noisy example.

Sample with the trained model

The second half of the program runs the DDPM sampler of the main guide with the learned weights. Pure noise with standard deviation 1 becomes samples with standard deviation close to 2 using forty small denoising steps, using nothing but the learned predictor and the schedule. The model using the exact optimal weights shows what a perfect predictor would give. That is the whole mechanism of diffusion, in miniature. Real models differ in having a vastly more expressive network, conditioning, and images instead of numbers.

Techniques that make real training work

EMA: why averaged weights sample better

The weights jump around with each noisy batch. An exponential moving average keeps a smooth copy: ema = decay x ema + (1 - decay) x weights. The simulation shows how averaging cancels noise.

import random
random.seed(1)
true_w = 1.0
w, ema, decay = 0.0, 0.0, 0.999
errs_w, errs_ema = [], []
for step in range(20000):
    g = 2 * (w - true_w) + random.gauss(0, 3)      # noisy gradient of (w - true)^2
    w -= 0.02 * g
    ema = decay * ema + (1 - decay) * w
    if step > 5000:
        errs_w.append(abs(w - true_w)); errs_ema.append(abs(ema - true_w))
print("mean error of raw weight : %.3f" % (sum(errs_w) / len(errs_w)))
print("mean error of EMA weight : %.3f" % (sum(errs_ema) / len(errs_ema)))

Output

mean error of raw weight : 0.181
mean error of EMA weight : 0.025

Typical decay values: 0.999 for small runs, 0.9999 for large ones (the effective window is about 1 / (1 - decay) steps); warm up the decay at the start. Use EMA weights for sampling and evaluation, and keep both in checkpoints.

Mixed precision and loss scaling

Half-precision (fp16) numbers have a smaller range: values below about 3e-8 round to zero (the smallest positive fp16 number is about 6e-8). Small gradients underflow. The fix is to multiply the loss by a large factor before the backward pass and divide the gradients afterwards. bf16 has the range of fp32 and needs no scaling, at lower precision.

import struct
def to_fp16(x):
    return struct.unpack("e", struct.pack("e", x))[0]
grad = 1e-8
print("fp16 of tiny gradient     :", to_fp16(grad))
scale = 1024.0
scaled = to_fp16(grad * scale)
print("fp16 of scaled gradient   :", scaled)
print("recovered after unscaling :", scaled / scale)
print("fp16 largest finite value :", to_fp16(65504.0), " overflow ->", end=" ")
try:
    print(to_fp16(70000.0))
except OverflowError:
    print("OverflowError")

Output

fp16 of tiny gradient     : 0.0
fp16 of scaled gradient   : 1.0251998901367188e-05
recovered after unscaling : 1.0011717677116394e-08
fp16 largest finite value : 65504.0  overflow -> OverflowError

Dynamic loss scaling raises the factor until an overflow appears, then backs off. Keep master weights and optimiser states in fp32, and some operations (softmax, normalisation, losses) in fp32.

Gradient clipping

Clip the global gradient norm (typically 1.0): if the norm exceeds the threshold, scale all gradients down so the direction is kept and the step size is capped (D5). Log the gradient norm: spikes predict divergence.

import math
def clip(grads, max_norm):
    norm = math.sqrt(sum(g * g for g in grads))
    scale = min(1.0, max_norm / (norm + 1e-6))
    return [g * scale for g in grads], norm
g, n = clip([30.0, 40.0], 1.0)
print("norm was", n, "-> clipped gradient", [round(x, 3) for x in g])

Output

norm was 50.0 -> clipped gradient [0.6, 0.8]

A compute estimate

Training FLOPs per image are about 6 x parameters x tokens for transformers (the main-guide U-Net is lighter but the same idea). The estimate below uses a transformer-style rule of thumb.

params = 2e9                  # a 2-billion-parameter denoiser
tokens_per_image = 1024       # latent patches
images = 1e9                  # images seen during training (e.g. many epochs over a dataset)
flops = 6 * params * tokens_per_image * images
a100 = 312e12 * 0.4           # about 40 percent utilisation of an A100 in bf16
gpu_seconds = flops / a100
print("total FLOPs: %.2e" % flops)
print("A100 GPU-days: %.0f" % (gpu_seconds / 86400))
print("on 512 GPUs: %.1f days" % (gpu_seconds / 86400 / 512))

Output

total FLOPs: 1.23e+22
A100 GPU-days: 1140
on 512 GPUs: 2.2 days

That is about a thousand GPU-days of A100 for a mid-sized model, which is why most practitioners fine-tune (DX4) rather than train from scratch. The main-guide 4 GB model is millions of times smaller.

Data loading

Storing images as thousands of small files is slow. Use sharded formats (WebDataset tars, Parquet, Mosaic streaming), precompute latents and text embeddings once (the VAE and text encoder are frozen), prefetch with several workers, and monitor GPU utilisation. A starved GPU is the most common waste.

Debugging checklist

Process: overfit a tiny dataset (8 images) first. If the model cannot memorise 8 images, the pipeline is broken. Add data and capacity only after that works. Keep fixed seeds and a fixed grid of validation prompts so you can compare checkpoints visually and with metrics (DX5).

Key idea

Most diffusion bugs are in the data and sampling code, not the network. Verify the data range, the noise schedule indexing and the sampling formula with a toy case like the one in this part before blaming the architecture.

Interview questions: Training diffusion

12 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic What is EMA and why do diffusion models use it?

An exponential moving average of the weights smooths batch noise; sampling with EMA weights produces visibly better and more stable images.

Basic What does gradient clipping do?

It caps the global gradient norm so a single bad batch cannot cause a huge step, preventing loss spikes and nan.

Medium Why does fp16 training need loss scaling and bf16 does not?

fp16 has a small exponent range so tiny gradients underflow to zero; scaling the loss moves them into range. bf16 has fp32's range with lower precision.

Medium How would you debug 'loss decreases but samples are noise'?

Check sampling code (coefficients, timestep indexing, noise at the last step), use EMA weights, verify data normalisation matches between train and sample, and run a toy overfit test.

Medium What is the quickest sanity test for a new diffusion pipeline?

Overfit eight images. If the model cannot memorise them, the data, schedule or training loop is broken.

Medium What is min-SNR weighting?

A loss weighting that caps the weight at high SNR (min(SNR, gamma)), reducing conflicting gradient directions across timesteps and speeding convergence.

Medium What is noise offset?

Adding a small per-channel constant to the noise so the model learns to change the mean brightness, fixing the difficulty with very dark or very bright images.

Advanced How does resolution change the best noise schedule?

Higher resolution images keep recognisable structure at the same noise level for longer, so the schedule is shifted toward more noise (or the timestep distribution is shifted) at higher resolutions.

Advanced What parallelism strategies exist for big diffusion models?

DDP for data parallelism, FSDP or ZeRO to shard states, tensor and pipeline parallelism for huge transformers, activation checkpointing and gradient accumulation.

Advanced Why precompute latents and text embeddings?

The VAE and text encoders are frozen, so encoding once removes their cost from every epoch and frees GPU memory.

Advanced Estimate training cost for a 2B parameter denoiser.

About 6 x parameters x tokens x images FLOPs; for 2e9 parameters, 1,024 tokens and 1e9 images that is 1.2e22 FLOPs, roughly a thousand A100 GPU-days at realistic utilisation.

Advanced What is zero terminal SNR?

Rescaling the schedule so alpha_bar_T = 0 exactly, typically with v-prediction, so the model trains on the pure noise it will start from at sampling time.
