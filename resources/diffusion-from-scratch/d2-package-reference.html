Python package reference

Every library from Phase 1, broken down into the specific functions and classes you'll actually call, what each one does, what arguments it takes, and a tiny example of it in use.

BasicMedium~1.5 hours

torch: core tensor operations

This is the foundation everything else sits on: creating tensors, moving them to the GPU, and doing basic math on them.

torch.tensor(data)

Converts ordinary Python data (a list, or nested lists) into a PyTorch tensor. This is the most basic way to manually create a tensor from scratch, mostly used for quick tests rather than real training data (which comes from torchvision datasets instead).

Example: x = torch.tensor([1.0, 2.0, 3.0]) creates a 1-dimensional tensor holding those three numbers.

torch.zeros(shape) / torch.ones(shape) / torch.randn(shape)

Three ways to create a new tensor of a given shape, filled a specific way:

  • torch.zeros((3, 64, 64)), every value set to 0. Useful for initializing placeholders.
  • torch.ones((3, 64, 64)), every value set to 1.
  • torch.randn((3, 64, 64)), every value randomly sampled from a standard Gaussian (bell-curve) distribution, mean 0, spread 1. This is exactly the function you use to generate the random noise tensors described throughout Phase 2, both the noise added during training and the starting point for sampling.

tensor.shape

Not a function you call with parentheses, a property you read. Tells you the exact dimensions of a tensor. You will check this constantly while debugging, since the single most common bug in any deep learning code is a tensor being the wrong shape somewhere.

Example: a batch of 16 RGB 64×64 images has tensor.shape equal to torch.Size([16, 3, 64, 64]).

tensor.to(device)

Moves a tensor to a specific device, either the CPU or the GPU. Every tensor involved in a computation must live on the same device, or PyTorch will raise an error. You'll typically define device = torch.device("cuda") once near the top of your script, and call .to(device) on your model and on every batch of data as it's loaded.

Example: images = images.to(device) moves a batch of images from CPU memory (where they were loaded) onto your RTX 2050's VRAM.

torch.device("cuda") / torch.device("cpu")

Creates a device object representing where computation should happen. Best practice is to detect automatically: device = torch.device("cuda" if torch.cuda.is_available() else "cpu"), this way your code doesn't crash if run on a machine with no GPU, it just falls back to (much slower) CPU execution.

torch.cat(tensors, dim)

Concatenates (joins end-to-end) a list of tensors along a chosen dimension. This is exactly the operation used to implement skip connections in the U-Net, the encoder's saved output and the decoder's current output are concatenated along the channel dimension before continuing.

  • tensors, a list of tensors to join, which must match in every dimension except the one you're joining along.
  • dim, which dimension to join along. For skip connections, this is the channel dimension, dim=1 (since shape order is batch, channel, height, width).

Example: torch.cat([encoder_output, decoder_output], dim=1), if encoder_output has 64 channels and decoder_output has 64 channels, the result has 128 channels, same height and width.

tensor.view(shape) / tensor.reshape(shape)

Both change a tensor's shape without changing its actual data, just how it's organized into dimensions. reshape is the safer default (it works even in cases where view would fail due to how the tensor is laid out in memory). You'll use this occasionally, for example when preparing a timestep embedding vector to be added onto a 4-dimensional feature grid.

torch.sqrt(x) / torch.exp(x) / torch.sin(x) / torch.cos(x)

Standard mathematical functions applied element-by-element across an entire tensor at once. Directly used in: the one-step shortcut formula (torch.sqrt(alpha_bar_t)), and the sinusoidal timestep embedding (torch.sin, torch.cos, torch.exp for the frequency scaling).

torch.save(obj, path) / torch.load(path)

Saves a Python object (almost always your model's weights, via model.state_dict()) to a file on disk, and loads it back later. This is how you avoid retraining from scratch every time you restart your notebook, you save a checkpoint periodically during training, and can resume or run inference later from that saved file. With 200GB free, saving frequent checkpoints is not a space concern.

Example: torch.save(model.state_dict(), "checkpoint.pt") then later model.load_state_dict(torch.load("checkpoint.pt")).

torch.no_grad()

Used as a context manager (with a with block) to temporarily turn off gradient tracking. During sampling/inference, you're not training, so there's no need for PyTorch to record how to compute gradients, skipping this bookkeeping saves both memory and time. You will wrap your entire sampling loop in this.

Example:

with torch.no_grad():
    predicted_noise = model(noisy_image, timestep)

torch.manual_seed(n)

Fixes the randomness generator to a specific starting point, so random operations (noise generation, weight initialization, data shuffling) become reproducible, running the same code twice gives identical results. Extremely useful while debugging, so you can tell whether a change you made actually changed the outcome, rather than it just being different random luck.

torch.randint(low, high, size, device=None)

Generates random whole numbers (integers), each one at least low and strictly less than high, arranged into a tensor of the given size. This is exactly how you sample a random timestep per image in the training loop.

  • low, smallest possible value, inclusive.
  • high, upper bound, exclusive (so torch.randint(0, 1000, ...) can produce 0 through 999, never 1000).
  • size, a tuple giving the output shape, e.g. (batch_size,) for one random integer per image in a batch.

Example: torch.randint(0, 1000, (16,), device=device) gives 16 random timesteps, one per image in a batch of 16.

torch.full(size, fill_value, device=None, dtype=None)

Creates a tensor of the given shape where every single value is the same, specified number. Used in sampling to create a batch where every image is being processed at the identical current timestep.

Example: torch.full((8,), 500, dtype=torch.long) gives a tensor of 8 copies of the number 500.

torch.randn_like(tensor) / torch.zeros_like(tensor)

Shortcut versions of torch.randn(...) and torch.zeros(...) that automatically copy the shape (and device, and dtype) of an existing tensor, instead of you having to type the shape out manually. torch.randn_like(clean_images) generates fresh noise exactly matching the batch of images it's shaped after.

tensor.clamp(min, max)

Forces every value in a tensor into a given range, any value below min becomes min, any value above max becomes max, everything in between is left unchanged. Used at the end of sampling to force pixel values back into a valid, displayable range after many steps of arithmetic that could otherwise drift slightly outside it.

tensor.item()

Pulls a single number out of a tensor that contains exactly one value, returning it as a plain Python float (or int) instead of a tensor. Loss values are tensors (so they can support gradient tracking), but you can't directly print or log a tensor as cleanly as a plain number, loss.item() is the standard way to get a printable number out of a loss tensor.

model.eval() / model.train()

Switches a model between evaluation mode and training mode. Some layer types (not used in this project's specific U-Net, but common enough elsewhere to know about, like Dropout, or certain normalization variants) behave differently depending on this setting. Calling .eval() before sampling and .train() before resuming training is good, safe habit regardless of whether your specific layers are affected.

model.state_dict() / model.load_state_dict(state_dict)

state_dict() returns a Python dictionary containing every learnable weight in the model, each paired with a name describing where it belongs (e.g. "down_blocks.0.conv1.weight"). This is what you actually pass to torch.save(), you save the weights, not the model object itself. load_state_dict(state_dict) does the reverse: given a matching dictionary of weights (usually just loaded back with torch.load()), it copies every value into the correct place inside an already-created model of the same architecture.

Watch out

You must create a model with the exact same architecture (UNet(), with the same config settings used during training) before calling load_state_dict, it fills in an existing model's weights, it does not reconstruct the architecture from scratch.

torch.load(path, map_location=device)

Loads a previously saved file back into memory. map_location tells PyTorch which device to put the loaded tensors on, important if, for example, you trained on a GPU but are later loading the checkpoint on a machine with no GPU (or a different GPU), since without this argument PyTorch would try to place the weights back on the exact original device and could error if that device isn't available.

sum(p.numel() for p in model.parameters())

A common one-liner (not a single PyTorch function, but a standard combination) for counting a model's total number of learnable numbers. model.parameters() gives every weight tensor; .numel() ("number of elements") counts how many individual numbers are in one tensor; wrapping the whole thing in a generator expression and sum() (both plain Python) adds them all up across every weight tensor in the model.

torch.nn: the building blocks of your network

This sub-package contains every ready-made layer type you'll assemble into your U-Net. You will not write the internal math of a convolution or an activation function by hand, you create one of these classes and PyTorch handles the computation (and, importantly, the gradient calculation for it).

class MyNetwork(torch.nn.Module): ...

The base class every custom network or layer inherits from. Explained fully in its own dedicated section below (nn.Module, how every PyTorch network is built) since it's central enough to deserve a full walkthrough rather than a quick card.

nn.Conv2d(in_channels, out_channels, kernel_size, stride=1, padding=0)

A 2D convolution layer, the fundamental operation inside every U-Net block. Slides a learnable kernel across the input grid, producing an output grid.

  • in_channels, how many channels the input has (e.g. 3 for an RGB image, or however many channels the previous layer output).
  • out_channels, how many channels you want the output to have. This is a design choice, more channels means more capacity to learn different patterns, at the cost of more compute and VRAM.
  • kernel_size, the size of the sliding kernel, almost always 3 (meaning 3×3) in modern U-Nets.
  • stride, how many pixels the kernel moves at each step. stride=1 keeps the same spatial size (with proper padding); stride=2 roughly halves height and width, this is exactly how downsampling is implemented.
  • padding, how many extra zero-value pixels to add around the border before sliding the kernel, so the output size comes out to a clean, predictable value. padding=1 with kernel_size=3 and stride=1 keeps height and width unchanged.

Example: nn.Conv2d(64, 128, kernel_size=3, stride=1, padding=1) takes a 64-channel feature grid and outputs a 128-channel grid of the same height and width.

nn.ConvTranspose2d(in_channels, out_channels, kernel_size, stride=2, padding=1)

A "transposed" convolution, the most common way to implement upsampling (growing spatial size back up) in the decoder half of the U-Net. With stride=2, it roughly doubles height and width, the mirror opposite of a stride-2 Conv2d. An alternative approach some U-Nets use instead is nn.Upsample (simple resizing) followed by a regular Conv2d, both are valid; transposed convolution is slightly more common in diffusion U-Nets.

nn.GroupNorm(num_groups, num_channels)

The normalization layer discussed in the U-Net section, rescales values to a stable range. It splits the channels into num_groups groups and normalizes within each group separately.

  • num_groups, how many groups to split channels into. A common default is 32, though it must evenly divide num_channels; for smaller channel counts (e.g. 32 or 64 total channels) you might use 8 or 16 groups instead.
  • num_channels, the number of channels in the input, must match whatever layer feeds into it.

Example: nn.GroupNorm(8, 64) normalizes a 64-channel feature grid by splitting it into 8 groups of 8 channels each.

nn.SiLU()

The activation function layer (also known as Swish). Takes no meaningful arguments, you just create one and reuse it, or make a fresh one per block. Applies the same smooth non-linear function to every number in its input, without changing its shape.

nn.Linear(in_features, out_features)

A fully-connected ("dense") layer, every input number is connected to every output number through a learnable weight. Not used on the image grid itself (that's what convolutions are for), but used for the small "time MLP" that processes the sinusoidal timestep embedding vector into a richer representation before injecting it into the U-Net's blocks.

  • in_features, length of the input vector.
  • out_features, length of the output vector.

nn.Sequential(layer1, layer2, ...)

A convenience container that chains a list of layers together, automatically feeding each layer's output into the next layer's input. Useful for defining a simple straight-line stack (like the time MLP: Linear → SiLU → Linear) without writing a full custom class for it.

Example:

time_mlp = nn.Sequential(
    nn.Linear(32, 128),
    nn.SiLU(),
    nn.Linear(128, 128),
)

nn.MultiheadAttention(embed_dim, num_heads) / manual attention

PyTorch provides a ready-made attention layer, though many diffusion U-Net implementations write a small custom attention block by hand (it's a short amount of code once you understand the Q/K/V mechanics covered in the dedicated attention section below) so it integrates cleanly with the image-shaped tensors flowing through the U-Net. Either approach is valid; using the built-in layer is perfectly reasonable for your first version.

nn.functional.mse_loss(input, target)

Computes Mean Squared Error between two tensors of the same shape, this is your entire training loss, comparing predicted noise to real noise. Usually accessed via the shorthand import import torch.nn.functional as F, then called as F.mse_loss(predicted_noise, real_noise).

torch.optim: optimizers

torch.optim.AdamW(model.parameters(), lr=1e-4)

Creates the optimizer object responsible for updating your model's weights during training.

  • model.parameters(), a built-in method every nn.Module provides, returning every learnable weight in the model. This is how the optimizer knows which numbers it's allowed to adjust.
  • lr, the learning rate, discussed in the training loop section. 1e-4 (0.0001) is a reasonable starting point for a small diffusion U-Net.

Once created, you call two methods on it repeatedly during training: optimizer.zero_grad() and optimizer.step(), both explained in detail in the dedicated backward() and step() section, since understanding what they do requires first understanding autograd.

torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max)

An optional add-on that gradually changes the learning rate over the course of training, typically starting higher and smoothly decreasing (following a cosine curve) toward the end. This is a refinement you can add after your first version trains successfully with a fixed learning rate, not required to get a first working model, but a common improvement once things are stable.

Autograd: the functions behind automatic learning

These three calls, always used together in this exact order, are what makes training actually work, full mechanical explanation is in the dedicated section further down, once you've seen the full training loop. Quick reference here:

loss.backward()

Called on the final loss tensor. Triggers PyTorch to automatically compute how much every single weight in the model contributed to this loss (called the gradient for each weight), by working backward through every operation that was used to compute the loss.

optimizer.step()

Called right after loss.backward(). Uses the gradients just computed to actually update every weight, according to the optimizer's rule (AdamW's adaptive rule, in this project).

optimizer.zero_grad()

Clears out the gradients from the previous step. PyTorch accumulates (adds to) gradients by default rather than replacing them, so if you forget this call, gradients from old batches would incorrectly pile up on top of new ones. Called once per batch, typically right before loss.backward().

Mixed precision functions

The specific calls that implement the mixed-precision VRAM savings discussed in the hardware-fitting section.

torch.autocast(device_type="cuda", dtype=torch.float16)

A context manager wrapped around your forward pass (the model computing its output). Inside this block, PyTorch automatically picks which operations are safe to run in the smaller float16 format and which need to stay in float32 for numerical stability, you don't have to decide this yourself, it's handled automatically per-operation.

Example:

with torch.autocast(device_type="cuda", dtype=torch.float16):
    predicted_noise = model(noisy_image, timestep)
    loss = F.mse_loss(predicted_noise, real_noise)

torch.cuda.amp.GradScaler()

float16 numbers have a much smaller representable range than float32, so gradients computed in float16 can sometimes underflow to zero and vanish. A GradScaler temporarily multiplies ("scales up") the loss by a large factor before calling backward(), so gradients stay in a safe numeric range, then un-scales them back down before the optimizer applies them. You create one scaler object before your training loop starts, and call scaler.scale(loss).backward(), scaler.step(optimizer), and scaler.update() in place of the plain versions of those calls.

torchvision

Tools specifically for working with image data and standard datasets.

torchvision.transforms.Compose([...])

Chains together a list of image transformations, applied in order to every image as it's loaded. This is where you define your entire image preprocessing pipeline in one place.

Example:

transform = transforms.Compose([
    transforms.Resize((64, 64)),
    transforms.ToTensor(),
])

transforms.Resize((height, width))

Resizes every image to a fixed size. Necessary because your dataset likely has images of varying original sizes, but your U-Net expects a single fixed input size (32×32 or 64×64, per the hardware-fitting recommendations).

transforms.ToTensor()

Converts a loaded image (originally in a raw pixel format, values 0-255) into a PyTorch tensor with values rescaled to the 0-1 range, and reorders the dimensions into PyTorch's expected (channels, height, width) order. You'll use this in nearly every image pipeline you ever write, not just this project.

transforms.Normalize(mean, std)

Rescales tensor values further, typically from the 0-1 range to a -1 to 1 range, which many diffusion model implementations use as their working range for the "clean image" (matching the roughly-zero-centered range that Gaussian noise naturally occupies, so image and noise are on comparable scales when mixed by the shortcut formula).

Example: transforms.Normalize(mean=[0.5, 0.5, 0.5], std=[0.5, 0.5, 0.5]) maps 0-1 values to roughly -1 to 1, applied per RGB channel.

torchvision.datasets.ImageFolder(root, transform)

A ready-made dataset class that automatically loads every image inside a folder (optionally organized into subfolders by class label) and applies your transform pipeline to each one. If you're training on your own custom collection of images (rather than a standard built-in dataset), this is likely the class you'll use, just point root at your image folder.

torchvision.datasets.MNIST / CIFAR10 (etc.)

Ready-made classes for well-known standard datasets, calling them automatically downloads the dataset (if not already present) and gives you a dataset object. Recommended for your very first end-to-end test, per the Phase 2 hardware guidance, since they need no manual data collection at all.

Example: torchvision.datasets.MNIST(root="./data", download=True, transform=transform).

torch.utils.data.DataLoader(dataset, batch_size, shuffle=True)

Technically part of core torch rather than torchvision, but always used together with a dataset object, so covered here. Wraps a dataset object and automatically handles splitting it into batches, shuffling the order each epoch, and (optionally) loading data in parallel using background worker processes.

  • dataset, the dataset object (from ImageFolder, MNIST, etc).
  • batch_size, how many images per batch, per the hardware-fitting guidance (8-16 to start).
  • shuffle=True, randomizes image order each epoch, important so the network doesn't learn any accidental pattern from a fixed ordering.

Once created, you loop over it directly in your training loop: for images, labels in dataloader: ..., each iteration hands you one ready-to-use batch tensor.

torchvision.utils.save_image(tensor, path)

Saves a tensor (or batch of tensors, arranged into a grid automatically) directly as a viewable image file. Extremely useful for periodically saving what your model generates during training, so you can watch its progress across epochs without writing your own image-saving code.

numpy

A general numerical array library that predates and partly inspired PyTorch's tensor design. You'll use it far less than torch itself in this project, mainly for small precomputations before anything touches the GPU.

numpy.linspace(start, stop, num)

Generates num evenly spaced values between start and stop, inclusive. This is exactly how you'll build a linear noise schedule, generating the list of β values evenly spaced between a small starting value and a larger ending value, one per timestep.

Example: np.linspace(0.0001, 0.02, 1000) produces 1000 beta values, evenly spaced from 0.0001 up to 0.02, a standard linear schedule range used in the original DDPM paper.

numpy.cumprod(array)

Computes the running (cumulative) product of an array, element i of the output is the product of all elements from index 0 through i of the input. This is precisely how you compute alpha-bar from the list of individual alphas: alpha_bar = np.cumprod(alphas).

torch.from_numpy(array)

Converts a numpy array into a PyTorch tensor (sharing the same underlying memory, so it's an efficient, cheap conversion). You'll use this once, right after precomputing your beta/alpha/alpha-bar schedule with numpy, to bring those values into PyTorch so they can be used directly in tensor formulas alongside your image tensors.

matplotlib

For visually inspecting what's happening, noisy images, generated samples, and loss curves.

matplotlib.pyplot.imshow(image)

Displays an image directly in your notebook. Expects a numpy array (or array-like) in (height, width, channels) order, the opposite channel order from PyTorch's (channels, height, width), so you'll typically need to rearrange a tensor's dimensions before displaying it (commonly with .permute(1, 2, 0), and moving it off the GPU first with .cpu(), plus .numpy() to convert from tensor to array).

Example: plt.imshow(image_tensor.permute(1, 2, 0).cpu().numpy()).

matplotlib.pyplot.plot(values)

Draws a line graph from a list of numbers. You'll use this to plot your loss value over training steps or epochs, watching whether the loss trends downward over time is your main signal that training is actually working.

matplotlib.pyplot.show() / plt.savefig(path)

show() renders whatever you've plotted so far. savefig(path) saves the current plot to an image file on disk instead of (or as well as) displaying it, useful for keeping a permanent record of a loss curve from a specific training run.

tqdm

A single-purpose library: progress bars for loops.

tqdm(iterable)

Wraps any loop you're iterating over, and automatically displays a live progress bar with a percentage, elapsed time, and estimated time remaining. You wrap it directly around your DataLoader loop.

Example: for images, labels in tqdm(dataloader): ..., replacing tqdm(dataloader) for plain dataloader is the entire change needed; everything else about the loop stays identical.

progress_bar.set_description(text) / set_postfix(dict)

If you assign the tqdm-wrapped loop to a variable, you can update the text shown alongside the bar live during training, commonly used to show the current loss value updating in real time next to the progress bar.

Example:

loop = tqdm(dataloader)
for images, labels in loop:
    ...
    loop.set_postfix(loss=loss.item())

einops

Makes tensor reshaping and rearranging readable, by naming dimensions instead of remembering their numeric position.

einops.rearrange(tensor, pattern)

Reshapes/transposes a tensor according to a pattern string written using letters for each dimension, rather than numeric indices, reads much more like a description of what you want than tensor.permute(...).reshape(...) chains would.

Example: preparing a feature grid for the attention layer often requires flattening the height and width into one dimension: rearrange(x, "b c h w -> b (h w) c"), read literally as "take a tensor with batch, channel, height, width, and rearrange it into batch, (height times width combined), channel." This single readable line replaces several harder-to-read manual reshape/transpose calls.

einops.repeat(tensor, pattern, **sizes)

Repeats a tensor's values along new or existing dimensions, again described with a readable pattern string. Occasionally useful when you need to broadcast a per-batch value (like a timestep embedding) across every spatial position of a feature grid explicitly, though PyTorch's automatic broadcasting (covered in the tensor operations section) often handles this without needing an explicit repeat.

diffusers (reference library)

Recall from Phase 1: you're building your own U-Net and training loop by hand to actually learn this, not using this library's pre-built pipeline directly. Still, two things from it are worth knowing how to find, purely as reference material while you build your own version.

diffusers.UNet2DModel

The library's own ready-made U-Net class, built specifically for diffusion models. Reading its source code (available on GitHub, or via import inspect; print(inspect.getsource(UNet2DModel)) in a notebook) is a good way to compare your own hand-built version against a well-tested professional implementation, once yours is working, a good sanity check, not a starting template to copy from directly.

diffusers.DDPMScheduler

The library's ready-made implementation of exactly the noise schedule and forward/reverse formulas covered in Phase 2. Useful as a reference to check your own hand-written schedule code produces the same beta/alpha/alpha-bar numbers, if you ever want to double-check your implementation against a trusted source.
