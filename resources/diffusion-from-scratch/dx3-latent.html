Latent diffusion and how Stable Diffusion is built

The model in the main guide works on pixels, which limits it to small images. Almost every practical text-to-image system works in a compressed latent space instead. This part builds Stable Diffusion piece by piece, with the shapes and the numbers.

Advanced~5 hours

The problem with pixels

Cost scales with pixels

A U-Net costs time and memory in proportion to the number of spatial positions, and attention is quadratic in that number. A 512 by 512 RGB image has 786,432 values; a 1024 by 1024 image has four times as many, and its attention cost is sixteen times as large. Most of those pixels carry detail that is nearly invisible to the eye (sensor noise, tiny texture), yet the model spends capacity predicting it.

Latent diffusion (Rombach et al., 2022) splits the job:

  1. A perceptual compression model (an autoencoder) removes imperceptible detail and keeps semantics, producing a much smaller latent.
  2. The diffusion model works in that latent space, learning the content and layout.
  3. The decoder turns the final latent back into pixels.
pixel = 512 * 512 * 3
latent = 64 * 64 * 4
print("pixel values:", pixel, " latent values:", latent, " ratio: %.0fx fewer" % (pixel / latent))
tokens_pixel, tokens_latent = 512 * 512, 64 * 64
print("attention pairs ratio: %.0fx fewer" % ((tokens_pixel / tokens_latent) ** 2))
for size in (256, 512, 768, 1024):
    side = size // 8
    print(size, "px image -> latent", side, "x", side, "x 4 =", side * side * 4, "values")

Why latent diffusion?

The autoencoder

Structure

An autoencoder has an encoder E that maps an image to a latent z = E(x) and a decoder D that reconstructs x_hat = D(z). Stable Diffusion's is a KL-regularised VAE: the encoder outputs a mean and variance, a latent is sampled from that Gaussian, and a small KL penalty keeps latents close to a standard normal so the space is well behaved. It is trained before the diffusion model and then frozen.

Loss termPurpose
Pixel reconstruction (L1 or L2)Faithful colours and layout
Perceptual loss (LPIPS)Sharp, natural-looking detail
Adversarial (patch GAN) lossRealistic texture, avoids blur
KL penalty (tiny weight)Keeps the latent space smooth

Scaling factor

Latents have a different standard deviation from unit Gaussian noise, so Stable Diffusion multiplies encoder output by a constant (0.18215 for SD 1.x) before diffusion and divides by it before decoding. Forgetting it is a classic bug: colours come out wrong.

Limits of the VAE

The decoder is a bottleneck for fine detail: small faces, text and thin lines can be damaged by an 8x compression. Remedies: more latent channels (16 in SD3 and Flux), better decoders, and refiner or upscaler stages.

Training in latent space

The training loop of the main guide is unchanged except that the image is first encoded: z0 = E(x) * scale, then noise is added to z0, and the network predicts that noise. Because the encoder is frozen, you can precompute latents once and reuse them every epoch, saving time.

How this gets asked

  • To encrypt them No.
  • To bring their scale close to unit variance so it matches the diffusion noise Correct.
  • To change the image size No.
  • To speed up the decoder No.

Diffusion assumes roughly unit-variance data; the constant normalises latent scale.

Conditioning: text, cross-attention and CLIP

Text encoder

The prompt is tokenised and passed through a pretrained text encoder that produces a sequence of vectors, one per token. SD 1.x uses CLIP ViT-L/14 (77 tokens, 768 dimensions). SDXL uses two CLIP encoders. Newer models (SD3, Flux, Imagen) add or use a large language-model encoder such as T5 for better understanding of long and compositional prompts.

Cross-attention

Inside each U-Net block, image features ask the text what to draw. Let Q be computed from image features (one query per spatial position) and K, V from the text embedding:

Cross-attention
Attention(Q, K, V) = softmax( Q K^T / sqrt(d_k) ) V
Q
from the image latent
K, V
from the text tokens

Each pixel position receives a weighted mix of word vectors. This is how "a red ball on a blue table" can paint red where the ball is: the pixels over the ball attend to "red" and "ball". Visualising these attention maps shows an object-by-word heat map, which prompt-to-prompt editing exploits.

import math
# Tiny cross-attention with 3 words and 2 pixels, d = 2
text = {"red": [1.0, 0.0], "ball": [0.5, 0.5], "table": [0.0, 1.0]}
words = list(text)
K = [text[w] for w in words]
V = K
pixels = {"pixel on ball": [1.0, 0.2], "pixel on table": [0.0, 1.0]}
def softmax(xs):
    m = max(xs); e = [math.exp(x - m) for x in xs]; s = sum(e); return [x / s for x in e]
for name, q in pixels.items():
    scores = [sum(a * b for a, b in zip(q, k)) / math.sqrt(2) for k in K]
    w = softmax(scores)
    print(name, dict(zip(words, [round(x, 2) for x in w])))

Output

pixel on ball {'red': 0.43, 'ball': 0.32, 'table': 0.24}
pixel on table {'red': 0.22, 'ball': 0.32, 'table': 0.46}

The pixel on the ball puts most weight on "red" and "ball"; the pixel on the table puts most weight on "table".

Shapes through the U-Net

For a 512 px image: latent 4 x 64 x 64; the first self-attention layer sees 64 x 64 = 4,096 positions; the lowest resolution is 8 x 8 with 64 positions. Text conditioning enters at every cross-attention layer, at several resolutions. The timestep still enters through the embedding added to every ResBlock, as in the main guide.

Blocks in a typical down stage: ResBlock, SpatialTransformer (self-attention + cross-attention + feed-forward), ResBlock, ..., Downsample. The "spatial transformer" flattens the feature map into a sequence, applies attention layers, then reshapes it back.

Diffusion transformers (DiT) and MMDiT

Replace the convolutional U-Net with a transformer over patches of the latent: cut the latent into p x p patches, embed each as a token, add position encodings, and run standard transformer blocks, with the timestep and conditioning injected by adaptive layer norm (a scale and shift predicted from the conditioning). Transformers scale predictably with size and data. MMDiT (SD3) uses two token streams, text and image, with separate weights, that attend to each other in joint attention, so text can be updated by image content as well as the reverse.

The full text-to-image pipeline

  1. Encode the prompt (and an empty or negative prompt for guidance) with the text encoder.
  2. Sample a random latent z_T from Normal(0, I) of shape 4 x H/8 x W/8. The seed fixes it.
  3. For each scheduler timestep: run the denoiser on the latent twice (conditional and unconditional), combine with CFG, and take a scheduler step.
  4. Decode z_0 / scale with the VAE decoder to get pixels. Clamp and convert to 8-bit.
  5. Optionally run a safety checker and upscale.
# With the diffusers library (display only; needs a GPU and model weights)
import torch
from diffusers import StableDiffusionPipeline, DPMSolverMultistepScheduler
pipe = StableDiffusionPipeline.from_pretrained("runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16).to("cuda")
pipe.scheduler = DPMSolverMultistepScheduler.from_config(pipe.scheduler.config)
generator = torch.Generator("cuda").manual_seed(42)
image = pipe("a watercolor fox in a forest", num_inference_steps=25, guidance_scale=7.5,
             negative_prompt="blurry, low quality", generator=generator).images[0]
image.save("fox.png")

Negative prompts

A negative prompt replaces the empty unconditional prompt in classifier-free guidance: eps = eps(negative) + w (eps(prompt) - eps(negative)). The sampler is pushed away from the negative direction and toward the prompt.

Interview questions: Latent diffusion

12 questions. Try to answer aloud in under a minute, then reveal. Tags show the level.

Basic Why do diffusion models work in a latent space?

Pixel space is large and mostly imperceptible detail. A VAE compresses 8 times per side (about 48 times fewer values), making the denoiser far cheaper and enabling high resolution on ordinary GPUs.

Basic What are the main components of Stable Diffusion?

A VAE (encoder and decoder), a text encoder (CLIP), a denoiser (U-Net or transformer) with cross-attention to the text, and a scheduler.

Medium How does text condition the image?

Prompt tokens are encoded to a sequence of vectors; cross-attention layers use image features as queries and text vectors as keys and values, so each position gathers relevant words.

Medium What is the VAE scaling factor?

A constant (0.18215 for SD 1.x) that normalises latent variance so it matches the unit-variance noise assumption; omitting it gives wrong colours.

Medium What does a negative prompt do?

It replaces the empty prompt in classifier-free guidance so the sampler is pushed away from the negative description and toward the positive one.

Medium Why is the VAE decoder a quality bottleneck?

8x compression loses fine detail such as small faces, text and thin lines; later models use more latent channels and better decoders.

Medium U-Net versus diffusion transformer?

U-Nets use convolutions and multi-scale structure; DiTs use patch tokens, transformer blocks and adaLN conditioning, scaling more predictably with data and parameters and handling variable sizes naturally.

Advanced What is MMDiT?

A multimodal diffusion transformer with separate weights for text and image tokens that attend to each other in joint attention, used in SD3.

Advanced Why does attention cost grow so fast with resolution?

Self-attention is quadratic in the number of positions; doubling image side quadruples positions and multiplies attention cost by sixteen, hence latents and efficient attention kernels.

Advanced Describe the inference pipeline step by step.

Encode the prompt and an unconditional or negative prompt, sample a seeded latent, run scheduler steps with the denoiser and classifier-free guidance, divide by the scale factor, decode with the VAE, post-process.

Advanced How would you run Stable Diffusion on 4 GB of VRAM?

fp16 weights, attention slicing, VAE tiling, CPU offloading of idle components, memory-efficient attention (xformers or SDPA), smaller resolution, or quantised models.

Advanced How does SDXL differ from SD 1.5?

A larger U-Net (about 2.6B parameters), two text encoders, 1024 px native resolution, size and crop micro-conditioning and an optional refiner stage.
